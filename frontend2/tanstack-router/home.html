Tanstack Router

What is Tanstack Router?
  • Routing is a critical part of any web application; Whether you’re building a simple blog or a complex and data-driven platform, a reliable and feature-rich router can make your job easier;
  • Tanstack Router is a routing library for React;
  • It provides a way to define and manage navigation, routes, loaders, and data fetching in React apps;
  • It’s considered a type-safe, file-based alternative to React Router and other traditional routers;
Why Tanstack Router?
  • Full Type-Safety
    • The IDE warns you if you mistype a path param ($postId vs $postID) or forget required query params;
    • Both path and query parameters are parsed and type-validated automatically;
    • Automatic Navigation
    • When you navigate to a route, the router automatically handles URL updates, history management and state transitions;
    • Data Loading
    • Routes can define loaders to fetch data before rendering components;
    • This ensures that components have the necessary data when they mount;
    • Error Handling
    • Routes can specify error components to display when data loading fails;
    • This provides a consistent way to handle errors across the app;
    • Nested Routes and Layouts
    • Supports deeply nested route hierarchies with shared layouts and context;
    • File-Based Routing
    • Routes can be defined based on the file system structure, making it easy to organize and manage routes;
    • Performance
    • Features like lazy loading and smooth integration with TanStack Query optimize app scalability;
    • Developer Experience
    • Comprehensive TypeScript support, detailed documentation, and an active community;
Key Features of Tanstack Router
  • Type-Safe Routing – Full TypeScript support for routes, params, and query strings
  • Data Loaders – Route-level data fetching with built-in support for async operations
  • Error Boundaries – Route-specific error handling and fallback UI
  • Nested Routes – Deeply structured route hierarchies with shared layouts and context
  • Layout Routes – Layouts that wrap groups of routes
  • Grouped Routes – Logical route organization without affecting the URL path structure
  • File-based Routing – A file system approach to routing
  • Parallel Data Loading – Data fetching for multiple routes in parallel to speed up rendering
  • Prefetching – Loading of route data and components ahead of time
  • Error Boundaries and Handling – Route-based error boundaries and fallbacks
  • SSR (Server-Side Rendering) – Rendering of pages on the server with support for streaming
  • Route Masking – Customization and mapping of internal route structure to different URL paths
Types of Routing
  • Code based routing
    • Routes are defined programatically using functions like createRoute, createRootRoute;
  • File based routing
    • Routes are generated automatically, based on file structure and specific naming conventions;
    • For example, about.jsx in a pages folder becomes the /about route;
    • Here are the rules:
      • Root route - Use __root.tsx in the root directory for the app's root route;
      • Dot Separator - denotes nested root; For eg, blog.post.tsx becomes /blog/post
      • Dynamic segments - Add $ for parameterized routes; For eg, blog.$id.tsx for /blog/:id
      • Layouts - Prefix files or folders with _ to create layouts not matched directly in URLs;
      • Index Routes - Use index for exact parent path matching; dashboard.index.tsx for /dashboard
      • Lazy Loading - Use .lazy.tsx to enable code splitting;
      • Reserved routes - Routes starting with /api are reserved for API usage. Adjust via the apiBase option if needed;
      • Ignored Files - Files/folders prefixed with - are ignored by default, configurable in tsr.config.json;
API Explaination
  • createRootRoute
    • It defines entry point of your applicaiton;
    • You should pass it to the RouterProvider;
    • It returns a RootRoute instance that has methods like: addChildren(), useLoaderData() etc;
    • You need to nest all other routes under it;
    • Config:
      • path -> Path is implicit for root route;
      • component -> react component to render;
      • loader -> data fetching logic;
      • errorComponent -> error boundary for that route;
      • pendingComponent -> loading state handler;
    • API:
  • createFileRoute
    • Use it for file based routing, never mix file-based routing with manual addChildren();
  • Route, RootRoute, FileRoute, Link
    • getParentRoute -> returns parent root(for children, not needed for root);
    • addChildren -> to add child routes;
    • useLoaderData -> to access data fetched by loader;
    • useRouteError -> to access error thrown by loader or action;
    • useMatch -> to get match object for the route;
    • useParams -> to get params for the route;
    • useSearch -> to get search params for the route;
    • useNavigate -> to navigate programmatically;
    • useLocation -> to get current location object;
    • useIsPending -> to check if a navigation is in progress;
    • useIsRouting -> to check if the router is currently routing;
    • useRouter -> to get the router instance;
  • TanStack offers 4 type-safe navigations: Link component, useNavigate hook, Navigate component, router.navigate() method;
  • Outlet
    • It is a placeholder component;
    • It tells the router: when a child render it here inside the parent’s layout; Otherwise, nested routes would never appear;
  • Link
    • It is a component to create links;
    • Link component generates the traditional tag with a valid href, which can be clicked to navigate to a new page.
    • Eg: <Link to="/">Home</Link>
    • You can pass parameters and search values to the target route;
    • Eg: <Link to="/books/$bookId" params={{ bookId: "1" }}>Books</Link>
  • useNavigate
    • It is used to navigate across the application programmatically;
    • It is useful when you need to navigate based on some user action, like a button click or after form submission.
    • The useNavigate() hook returns a navigate function that can be called to imperatively navigate to a different route;
      •                         import { useNavigate } from "@tanstack/react-router";

function Books() {
  const navigate = useNavigate();

  return (
    <div>
      <button onClick={() => navigate({ to: "/books" })}>Books</button>
    </div>
  );
}
  • Navigate component
    • Navigate component provides a great way to handle client-side redirections;
    • It comes in handy in cases where we want to navigate immediately when a component renders;
    • Rather than relying on the useNavigate() hook and then bringing in useEffect, we can just use the Navigate component;
      •                         function Books() {
  return <Navigate to="/books/$bookId" params={{ bookId: "1" }} />;
}
  • router.navigate()
    • router.navigate() method works just like the navigate function returned by useNavigate() hook;
    • In addition that it is available anywhere the router instance is available;
    • Therefore, it is a great way to navigate imperatively from anywhere within the application;
    • Eg: router.navigate({ to: "/books" });
    • Dynamic Routing
    • Defining URL segments that act like a variable, which enables the rendering of different content based on the dynamic parameter;
    • In file-based routing with TanStack Router, dynamic segments are created by starting the parameter name with a $ inside the filename; The dynamic parameter can then be accessed inside the route using the useParams method or in a loader;
