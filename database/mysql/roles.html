What is a Role?

  • It is a named collection of privileges, that can be assigned to users;
  • Instead of granting privileges directly to each user, you grant them to a role and then assign the role to users;

Purpose of Roles?

  • Without Roles, you need to assign permissions directly to users; Hard to manage users and their permissions;
  • With Roles, you can assign permissions to a role and then assign the role to users; Eg: Developer Role → SELECT, INSERT, UPDATE; Analyst Role → SELECT; DBA Role → ALL PRIVILEGES

GRANT
  • Grant privilieges on specified object to a Role - GRANT priv1,priv2 ON object TO role1,role2;
  • Grant one role to another role - GRANT role1 TO role2;
  • Grant role to user - GRANT role1 TO user1,user2;
  • GRANT priv ON object TO user WITH GRANT OPTION - Allows recipient to further grant privileges to others;
  • GRANT role1 TO role2 WITH ADMIN OPTION; - Receiver can assign/remove this role to others;
ON Clause
  • ON can be: entire server, database, table, column, stored procedure, function;
  • | Format              | Meaning                     |
| ------------------- | --------------------------- |
| `*.*`               | All databases and tables    |
| `database.*`        | All tables in one database  |
| `database.table`    | Specific table              |
| `table`             | Specific table (current DB) |
| SELECT(column)      | Specific column             |
| `FUNCTION db.func`  | Specific function           |
| `PROCEDURE db.proc` | Specific procedure          |
REVOKE
  • REVOKE priv1,priv2 ON object FROM role/user; - Used to revoke privileges;
  • REVOKE role1 FROM user; - Used to revoke role from user;
Inspecting a Role
  • SHOW GRANTS FOR role/user; - View all priviliges/roles granted to a role/user;
Activating Roles
  • User may have multiple roles assigned to him, but only default roles are active, when he login;
  • You can't specify a default role using GRANT; So, user doesn't have any roles active, until he specifies a default role;
  • SET DEFAULT ROLE role1 TO user1,user2; -> Changes are saved and applies to future sessions as well;
  • SET ROLE role1 TO user1,user2; -> Current session only; not saved;
  • SET DEFAULT ROLE NONE TO user1,user2; -> Remove default roles; User still have that role, but not activated by default;
  • SELECT CURRENT_ROLE() -> Displays currently active roles for the logged in user;
  • SET GLOBAL activate_all_roles_on_login = ON; -> If you set this global variable, all assigned roles automatically activate at login;

Assigning Roles to Users

  • Once a role is configured, it can be "granted" to one or more user accounts.
  • A user can have multiple roles assigned to them.

Linking Users and Roles
-- Assign the role to a specific user
GRANT 'app_read_only' TO 'analyst_user'@'localhost';

-- Assign multiple roles to a user
GRANT 'app_developer', 'app_read_only' TO 'dev_lead'@'%';

Activating Roles

  • By default, granted roles are not active when a user logs in.
  • Users must use SET ROLE to activate them, or the administrator can set a default role.

Role Activation Example
-- Set default role so it's active on login
SET DEFAULT ROLE 'app_read_only' TO 'analyst_user'@'localhost';

-- Manually activate all granted roles in current session
SET ROLE ALL;
