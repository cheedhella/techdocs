Best Practices
  1. Design schema carefully
    • Start with normalized tables(split the tables into multiple tables to prevent redundancy), denormalize later after measuring bottlenecks(normalized tables often require many joins, complex queries, extra lookups);
    • Every table should have a primary key: indexed integer or UUID;
    • Prefer smaller datatype, wherever possible; Eg: INT instead of BIGINT, VARCHAR(100) instead of TEXT, DECIMAL for money values(never float);
  2. Index intelligently
    • Index columns used in: WHERE, JOIN, ORDER BY, GROUP BY; Avoid over indexing, too many indexes take disk space and can slow insert/updates;
    • Order matters in a composite index; Eg: (customer_id, status)
  3. Optimize queries
    • Never use select * in production, fetch only required columns;
    • Use EXPLAIN and analyze query plan regularly; Look for full table scans, missing indexes, temporary tables etc;
    • Avoid N+1 queries: Rather than querying users and then querying posts for each user separately, use joins;
  4. Use transactions properly
  5. Transactions protect data consistency; Keep transactions short; Long transactions hold locks for longer, increases contention and reduces throughput;
  6. Use right storage engine
    • MyISAM - older;
    • InnoDB - newer; It supports row-level locking, transactions, better concurrency;
  7. Use Connection Pooling
    • It is expensive to open DB connections repeatedly;
    • Use HikariCP (Java), SQLAlchemy pooling (Python), mysql2 pools (Node.js);
    • Set connection limits; It protects database from overload; Monitor for max connections, slow queries;
  8. Secure the database
    • Use prepared statements, they prevent SQL injection;
    • Bad: SELECT * FROM users WHERE email = '" + email + "'
    • Good: SELECT * FROM users WHERE email = ?

    • Principle of least privilege - Users should only have required permissions; Eg: app user → SELECT/INSERT/UPDATE, admin user → schema changes;
    • Encrypt sensitive data - hash passwords/API tokens with bcrypt/argon2;
    • Enable TLS for production connections;
  9. Backup and Restore
  10. Monitor Performance
    • Track Slow Queries, CPU usage, buffer pool hit rate, Replication Lag, Lock waits etc;
    • Use tools like: Percona Monitoring and Management, Grafana, Prometheus;
  11. Plan for scalability - Use read replicas for analytics and other read-heavy workloads;
  12. Partition large tables carefully - Helpful for time-series data;
  13. Maintain application level Cache - Don't hit database for every request, use cache like Redis;
  14. Use migrations - Never manually edit production schemas; Use tools like Flyway, liquibase;
  15. ORM best practices - If you are using ORM, understand the generated SQL; They don't replace SQL knowledge;
  16. Character set - use either utf8mb4 or utf8mb4_unicode_ci;
