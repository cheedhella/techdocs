What is a Stored Procedure?
  • It is a block of SQL that you can save in the database and execute whenever needed;
  • It can accept input parameters, return output parameters and include error-handling mechanisms;
  • It supports control structures like if, loop etc;
Benefit of Stored Procedures?
  • Faster execution - precompiled;
  • Reusable
  • Better Security - we can limit direct table access and provide permission to execute stored procedures;
  • Centralized logic - Reduces network traffic(with just 1 query);
  • Transaction Management - It is used to run multiple SQL statements in a single transaction and rolling back modifications as needed;
Why DELIMITER $$ is used?
  • By default, MySQL uses ; as delimiter(end of procedure);
  • A stored procedure contains many SQL statements, and each statement already ends with ;
  • DELIMITER $$ is used to change the delimiter to $$; Otherwise, It thinks the procedure ends at the first ;
  • After procedure creation, we usually restore normal delimiter to semicolon;
CRUD Operations using stored procedures
  • > cat emp_procedures.sql
CREATE TABLE emp (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100),
    age INT,
    gender VARCHAR(10)
);

# ----------- Create Employee ----------------------
DELIMITER $$

CREATE PROCEDURE InsertEmployee(
    IN emp_name VARCHAR(100),
    IN emp_age INT,
    IN emp_gender VARCHAR(10)
)
BEGIN
    INSERT INTO emp(name, age, gender)
    VALUES(emp_name, emp_age, emp_gender);
END $$

# ----------- Get All Employees --------------------
CREATE PROCEDURE GetEmployees()
BEGIN
    SELECT * FROM emp;
END $$

# ----------- Get Employee By ID --------------------
CREATE PROCEDURE GetEmployeeById(
    IN emp_id INT
)
BEGIN
    SELECT * FROM emp
    WHERE id = emp_id;
END $$


# ----------- Update Employee --------------------
CREATE PROCEDURE UpdateEmployee(
    IN emp_id INT,
    IN emp_name VARCHAR(100),
    IN emp_age INT,
    IN emp_gender VARCHAR(10)
)
BEGIN
    UPDATE emp
    SET
        name = emp_name,
        age = emp_age,
        gender = emp_gender
    WHERE id = emp_id;
END $$

# ----------- Delete Employee --------------------
CREATE PROCEDURE DeleteEmployee(
    IN emp_id INT
)
BEGIN
    DELETE FROM emp
    WHERE id = emp_id;
END $$

DELIMITER ;
# ------ OUT parameters ---------------------------
DELIMITER //

CREATE PROCEDURE GetEmployeeNameById(
    IN emp_id INT,
    OUT emp_name VARCHAR(50)
)
BEGIN
    SELECT name INTO emp_name
    FROM emp
    WHERE id = emp_id;
END //

DELIMITER ;

# ------ INOUT parameters ---------------------------
# Same variable is used for both input and output;

DELIMITER $$
CREATE PROCEDURE IncreaseSalary(
    INOUT salary INT,
    IN inc INT
)
BEGIN
    SET salary = salary + inc;
END $$
DELIMITER ;

OUT vs INOUT variables
  • In case of OUT variable, procedure can't read from OUT variable, procedure can only write to it;
  • In case of INOUT variable, procedure can read from and write to it;
What happens if you WRITE to an IN variable?
  • MySQL allows modification of IN parameters inside the procedure;
  • However, the modifications are local to the procedure; Caller doesn't receive the updated value;
What happens if you READ an OUT variable?
  • OUT variable is initialized to NULL inside the procedure, even if the caller initializes it to a value outside the procedure;
Drop Procedure
  • DROP PROCEDURE sp_name - It is used to delete the stored procedure; It throws error, if it doesn't exist;
  • DROP PROCEDURE IF EXISTS sp_name - It is used to delete the stored procedure; It doesn't throw error, rather it throws a WARNING, if it doesn't exist;
Alter Procedure
  • It is used to modify certain properties of existing stored procedure, like: comments, SQL security code, procedure characterstics;
  • Note that, you can't change the body of the procedure; To change the body, you must recreate it;
  • What is SQL Security? It controls what permissions are used during execution:
    • DEFINER - Run with creator's permissions; ALTER PROCEDURE InsertEmployee SQL SECURITY DEFINER;
    • INVOKER - Run with caller's permissions; ALTER PROCEDURE InsertEmployee SQL SECURITY INVOKER;

DECLARE HANDLER
  • It is used for error/exception handling;
  • It is used to tell MySQL: If a specific condition/error happens, run this block of code;
  • Handlers must be declared: after variables and before executable statements;
  • Without handler, procedure stops immediately, in case of any error;
  • With handler, you can: catch error and show custom message, rollback transaction, continue execution;
  • With EXIT handler, handler get executed and procedure stops gracefully, in case of any error;
  • DECLARE handler_type HANDLER
FOR condition1[, condition2...]
handler_action;
  • handler_type
    • EXIT -> stored procedure will terminate;
    • CONTINUE -> stored procedure will continue executing;
  • condition - It specifies 1 or more conditions that activate the handler;
    • MySQL error often have either error code OR SQLSTATE code;
    • mysql_error_code - any MySQL error code such as 1051;
    • SQLWARNING - any SQLSTATE that begins with 01;
    • NOT FOUND - any SQLSTATE that begins with 02;
    • SQLEXCEPTION - any SQLSTATE that doesn't begin with 00, 01, 02;
    • SQLSTATE sqlstate
      • SQLSTATE is a five-character that provides information about the result of an SQL operation;
      • First 2 chars - indicate the general category of the error;
      • Next 3 chars - It provides more specific information about the error within general category;
      • 42000 - Syntax error;
      • 42S01 - Table already exist;
      • 42S02 - Table doesn't exist;
      • 23000 - Constraint violation;
      • 45000 - User defined exceptin(using SIGNAL);
      • 28000 - Access denied error;
      • 02000 - No data found/cursor no rows error;
  • # Rollback Example
DELIMITER $$
CREATE PROCEDURE TransferMoney()
BEGIN
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        SELECT 'Transaction failed';
    END;
    START TRANSACTION;
    UPDATE accounts SET balance = balance - 100
    WHERE id = 1;
    UPDATE accounts SET balance = balance + 100
    WHERE id = 2;
    COMMIT;
END $$
DELIMITER ;

Named error handler - DECLARE CONDITION
  • error or SQLSTATE codes in condition are not human-readble;
  • So, instead of handling error or SQLSTATE code directly, we can give them a human readable name;
  • Syntax: DECLARE condition_name CONDITION FOR condition_value;
  • 
DECLARE duplicate_key CONDITION FOR SQLSTATE '23000';

DECLARE EXIT HANDLER FOR duplicate_key
BEGIN
    SELECT 'Duplicate entry';
END;
SIGNAL
  • It is used to manually throw an error/exception(similar throw in java);
  • # Custom exception example
DELIMITER $$
CREATE PROCEDURE AddEmployee(
    IN emp_name VARCHAR(100),
    IN emp_age INT
)
BEGIN
    IF emp_age < 18 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Age must be 18 or above';
    END IF;
    INSERT INTO emp(name, age)
    VALUES(emp_name, emp_age);
END $$
DELIMITER ;

What is a Trigger?
  • It is a named collection of privileges, that can be assigned to users;
  • Instead of granting privileges directly to each user, you grant them to a role and then assign the role to users;
Why Use Stored Procedures? Simplicity: Instead of writing complex SQL queries repeatedly, you write them once and save them as a stored procedure. Efficiency: Stored procedures are precompiled, which means they run faster than executing the same SQL statements separately. Security: You can restrict access to the data by granting permissions to execute the stored procedure without allowing direct access to the tables.
