Charset and Collation
  • Charset - It specifies what characters you are planning to store in database; Eg: English/Hindi/Chinese chars, emojis etc;
    • lantin1 - basic english characters;
    • utf8 - unicode characters;
    • utf8mb4 - unicode characters + emojis;
  • Why charset is important? Without proper charset: emojis may fail, Hindi text may break, special symbols become ????, multilingual apps fail;
  • Collation - It defines how string comparison is performed in the database; Eg: case sensitivity, accent sensitivity etc;
  • Why collation is important? Collation effects searching and sorting;
  • Searching(WHERE name = 'rahul'); Case insensitive collation finds 'Rahul', 'RAHUL', 'rahul' etc;
  • Sorting(ORDER BY name); Different collations produce different sorting orders;
    • utf8mb4_general_ci - case-insensitive;
    • utf8mb4_unicode_ci - case-insensitive, accent-insensitive;
    • utf8mb4_bin - case-sensitive;
  • MySQL allows charset settings at multiple levels: Server -> Database -> Table -> Column; Lower levels can override higher levels;
  • Default values depends on mysql version; In MySQL 8.0, default charset is utf8mb4 and default collation is utf8mb4_0900_ai_ci;
