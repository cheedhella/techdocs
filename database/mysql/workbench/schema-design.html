Schema Design
  • Create and alter tables, views, indexes, procedures and triggers visually;
  • Define primary keys, foreign keys and constraints with guided dialogs;
  • Generate SQL preview before applying changes to review impact;
  • Maintain naming conventions for consistency across environments;
Design best practices
  • Always script schema changes instead of ad-hoc production edits;
  • Add indexes based on query patterns, not assumptions;
  • Document object purpose with comments where supported;
  • Validate foreign key actions for update and delete behavior;
