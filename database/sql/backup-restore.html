Backup & Restore

What is a Database Backup?

  • A backup is a copy of data from a database that can be used to reconstruct that data in case of loss or corruption.
  • Logical Backups: Store data as SQL statements (CREATE TABLE, INSERT). Flexible but can be slower for very large DBs. Example: mysqldump.
  • Physical Backups: Copy the actual data files. Very fast for large DBs but usually tied to a specific database version/engine.

How do you use mysqldump?

  • mysqldump is the most common command-line utility for logical backups in MySQL.
  • It exports the database structure and data into a single .sql file.

Backing up with mysqldump
# Backup a single database
mysqldump -u username -p database_name > backup_file.sql

# Backup all databases
mysqldump -u username -p --all-databases > full_backup.sql

# Backup only specific tables
mysqldump -u username -p database_name table1 table2 > tables_backup.sql

How do you restore a database?

  • Restoring is done by piping the .sql backup file back into the mysql client.
  • The target database must usually exist before running the restore command.

Restoring Data
# Restore to a specific database
mysql -u username -p database_name < backup_file.sql

# Restore from an all-databases dump
mysql -u username -p < full_backup.sql

Best Practices for Backups

  • Automation: Use tools like cron (Linux) or Task Scheduler (Windows) to run backups daily.
  • Offsite Storage: Always keep a copy of your backups on a different server or cloud storage.
  • Verification: Periodically test your backups by performing a restore to a test environment to ensure they work.
