User Management & Security

How do you create a User?

  • The CREATE USER statement creates a new account in the database.
  • Users are typically identified by a username and a host (e.g., 'localhost' or '%').
  • It is a best practice to use strong passwords and restrict host access to specific IP ranges where possible.

Creating a New User
-- Syntax: CREATE USER 'username'@'hostname' IDENTIFIED BY 'password';
CREATE USER 'dev_user'@'localhost' IDENTIFIED BY 'StrongPass123!';

-- Create a user that can connect from any host
CREATE USER 'reporting_app'@'%' IDENTIFIED BY 'AppPassword!456';

What is GRANT and REVOKE?

  • GRANT: Assigns specific permissions (privileges) to a user or role. These can range from SELECT on a single table to ALL PRIVILEGES on the entire server.
  • REVOKE: Removes previously granted permissions.
  • Common privileges include: SELECT, INSERT, UPDATE, DELETE, CREATE, and DROP.

Managing Privileges
-- Grant read-only access to a specific database
GRANT SELECT ON shop_db.* TO 'dev_user'@'localhost';

-- Grant multiple privileges on a specific table
GRANT SELECT, INSERT, UPDATE ON shop_db.orders TO 'dev_user'@'localhost';

-- Revoke a specific permission
REVOKE UPDATE ON shop_db.orders FROM 'dev_user'@'localhost';

-- Apply changes (often required in MySQL)
FLUSH PRIVILEGES;

How do Roles work?

  • Roles are collections of privileges that can be assigned to multiple users.
  • They simplify user management: instead of granting permissions to 50 individual users, you grant them to one role and assign the role to those users.
  • Users can have multiple roles, allowing for modular permission structures.

Implementing Roles
-- 1. Create the role
CREATE ROLE 'app_read_only';

-- 2. Assign privileges to the role
GRANT SELECT ON shop_db.* TO 'app_read_only';

-- 3. Assign the role to a user
GRANT 'app_read_only' TO 'dev_user'@'localhost';

-- 4. Set the default role for the user (MySQL specific)
SET DEFAULT ROLE 'app_read_only' TO 'dev_user'@'localhost';

Best Practices for Security

  • Principle of Least Privilege: Only give users the minimum level of access they need to perform their jobs.
  • Never use 'root' for applications: Create dedicated application users with limited scope.
  • Audit Permissions: Periodically review SHOW GRANTS FOR 'user'@'host'; to ensure no unnecessary privileges exist.
