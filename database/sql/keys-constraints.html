SQL Constraints & Keys

What are SQL Constraints?

  • Constraints are rules applied to table columns to limit the type of data that can go into a table.
  • They ensure the accuracy and reliability of the data in the database.
  • If there is any violation between the constraint and the data action, the action is aborted.

NOT NULL and UNIQUE

  • NOT NULL: Ensures that a column cannot have a NULL value.
  • UNIQUE: Ensures that all values in a column are different.

NOT NULL and UNIQUE Example
CREATE TABLE Employees (
    ID int NOT NULL UNIQUE,
    LastName varchar(255) NOT NULL,
    FirstName varchar(255),
    Email varchar(255) UNIQUE
);

PRIMARY KEY and FOREIGN KEY

  • PRIMARY KEY: Uniquely identifies each record in a table. It must contain unique values and cannot contain NULLs. A table can have only one primary key.
  • FOREIGN KEY: A field in one table that refers to the PRIMARY KEY in another table. It is used to prevent actions that would destroy links between tables.

Key Relationships
CREATE TABLE Orders (
    OrderID int NOT NULL,
    OrderNumber int NOT NULL,
    EmployeeID int,
    PRIMARY KEY (OrderID),
    FOREIGN KEY (EmployeeID) REFERENCES Employees(ID)
);

CHECK and DEFAULT

  • CHECK: Ensures that the values in a column satisfy a specific condition (e.g., Age >= 18).
  • DEFAULT: Provides a default value for a column when no value is specified during an INSERT.

Check and Default Example
CREATE TABLE Products (
    ID int NOT NULL,
    Price decimal(10,2) CHECK (Price > 0),
    Status varchar(20) DEFAULT 'Available',
    CreatedDate datetime DEFAULT CURRENT_TIMESTAMP
);

AUTO_INCREMENT

  • AUTO_INCREMENT: Allows a unique number to be generated automatically when a new record is inserted into a table.
  • Often used for the Primary Key field so the user doesn't have to manually track IDs.

Auto Increment Example
CREATE TABLE Users (
    UserID int NOT NULL AUTO_INCREMENT,
    Username varchar(50) NOT NULL,
    PRIMARY KEY (UserID)
);
