Decorator VS Proxy 
	Similar to decorators, proxies can be chained together. The client, and each proxy, thinks it is delegating
	the requests to real object;
	Both patterns forward method calls to real object. Difference being, with Proxy pattern, the relationship 
	between a proxy and the real subject is typically set at compile time, whereas decorators can be recursively 
	constructed at runtime;
	Decorators focus on adding responsibilities, but proxies focus on controlling the access to an object;

Adapter VS Decorator VS Proxy 
	Adapter provides a different interface than the original, while Proxy provides same interface as that of 
	it's original, while decorator provides an enhanced interface(it adds behaviors at rum time);

Decorator vs Proxy
	Decorator Pattern focuses on dynamically adding functionality to an object, while Proxy Pattern focuses on controlling access to an object - intent is different.
	When using Proxy Pattern, we usually create an instance of original object inside the proxy class. When using Decorator Pattern, we typically pass the original object as a parameter to the constructor of the decorator.
	With the Proxy pattern, the relationship between a proxy and the real subject is typically set at compile time, whereas decorators can be recursively constructed at runtime.

	Similar to Decoarator, you can chain the proxies.

Proxy vs Adapter 
	Proxy has same interface as that of real object where as Adapter exposes a different interface(to allow interoperability) than the real object.

{
    private PrintStream m_out;
    private static LogManager sm_instance;
   
    private LogManager(PrintStream out)
    {
        m_out = out;
    }

    public static LogManager getInstance()
    {
        if ( sm_instance == null )

    }
}

Iterator Pattern
	Designers use data structures such as arrays, linked lists and hash tables to organize data in a program. 
	The Iterator design pattern allows objects to access individual objects from any data structure without “knowing” the data structure’s behavior (such as traversing the structure or removing an element from that structure) or how that data structure stores objects. Instructions for traversing the data structure and accessing its elements are stored in a separate object called an iterator. Each data structure can create an iterator—each iterator implements methods of a common interface to traverse the data structure and access its data. A client can traverse two differently structured data structures—such as a linked list and a hash table—in the same manner, because both data structures provide an iterator object that belongs to a class implementing a common interface. Java provides interface Iterator from package java.util, which we used in Fig. 20.2.

Behavioral Patterns - .  behavioral design patterns (assign responsibilities to objects, how objects collaborate)
	Chain of Responsibility. Provides a way for a request to be handled by multiple objects.
	Interpreter. Interprets a language. Best for simple grammars.
	Iterator. A way to sequentially access the elements of an aggregate object without revealing the object’s implementation.
	Mediator. Create an object that encapsulates the ways a set of objects interact (promotes loose coupling).
	Memento. A way to provide persistence for an object.
	Observer. A way for an object to notify other objects when its state has changed so they can take the appropriate actions.
	State. A way for an object to metamorphose its behavior when its internal state changes.
	Strategy. A way to encapsulate a family of related algorithms (perform same function) and make them interchangeable.
	Template Method. Allows subclasses to redefine certain steps of an algorithm without changing the structure.

Bridge Pattern
	This pattern is used to separate an interface from its implementation so that they can be varied easily and independently. 
	-----
	The Bridge Pattern is used to separate out the interface from its implementation. Doing this gives the flexibility so that both can vary independently.
	The best example for this is like the electric equipments you have at home and their switches.
	For e.g., the switch of the fan. The switch is the interface and the actual implementation is the Running of the fan once its switched-on. 
	Still, both the switch and the fan are independent of each other. Another switch can be plugged in for the fan and this switch can be connected to light bulb.
