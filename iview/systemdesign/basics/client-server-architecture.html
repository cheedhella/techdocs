1. What is Client-Server Architecture?
  • A distributed application structure that partitions tasks or workloads between the providers of a resource or service, called servers, and service requesters, called clients.
  • The client initiates a request, and the server provides a response.
  • Communication usually happens over a network (like the Internet) using protocols like HTTP/HTTPS.
2. Key Components
  • Client: The user-facing part of the system (e.g., Web Browser, Mobile App, IoT device). It handles user interaction and presentation logic.
  • Server: The backend part that processes requests, performs business logic, and manages data. It can be a Web Server, Application Server, or Database Server.
  • Network: The medium through which the client and server communicate.
3. How it Works?
  • User performs an action on the Client (e.g., clicks a button).
  • Client sends a request (e.g., HTTP GET) to the Server's IP address/domain.
  • Server receives the request, processes it (may query a database), and prepares a response.
  • Server sends the response (e.g., HTML, JSON, or Image) back to the Client.
  • Client renders the response for the user.
4. Advantages
  • Centralization: Data and business logic are managed in one place (the server), making it easier to update and secure.
  • Scalability: You can upgrade the server (vertical scaling) or add more servers (horizontal scaling) to handle more clients.
  • Security: Access control can be strictly enforced on the server side.
5. Common Patterns
  • 2-Tier: Client directly communicates with the Database Server.
  • 3-Tier: Client -> Application Server -> Database Server (Most common).
  • N-Tier: Multiple layers of services (Microservices).
