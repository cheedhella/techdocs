1. The Core Conflict
  • In distributed systems, when data is replicated across multiple nodes, we face a choice: Do we want everyone to see the exact same data immediately (Consistency), or do we want the system to always respond even if some data is slightly old (Availability)?
2. Types of Consistency
  • Strong Consistency: After a write, any subsequent read will see that write. High latency, lower availability.
  • Eventual Consistency: If no new updates are made, eventually all accesses will return the last updated value. High availability, low latency. (e.g., DNS, Social Media likes).
  • Causal Consistency: Operations that are causally related are seen by all processes in the same order.
3. Availability Patterns
  • Failover: Active-Passive or Active-Active setups to ensure service continues if a node fails.
  • Replication: Master-Slave or Multi-Master replication to keep data available across regions.
4. How to Choose?
  • Choose Consistency: For financial transactions, inventory management, or any system where stale data causes critical errors.
  • Choose Availability: For social media feeds, search engines, or systems where a few seconds of lag in data synchronization is acceptable.
