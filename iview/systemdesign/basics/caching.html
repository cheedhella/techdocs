1. What is Caching?
  • A technique of storing copies of data in a temporary storage location (cache) so that future requests for that data can be served faster.
  • Goal: Reduce latency, decrease load on the primary database, and improve system performance.
2. Where can we Cache?
  • Client-side: Browser cache (HTML, CSS, JS).
  • CDN (Content Delivery Network): Static assets (images, videos) cached geographically close to users.
  • API/Web Server: Caching full responses or fragments.
  • Application/Distributed Cache: Using tools like Redis or Memcached to store frequently accessed data (e.g., user sessions, product details).
  • Database: Internal buffers and query caches.
3. Caching Strategies
  • Cache-Aside: Application checks cache first. If "miss", it reads from DB and writes to cache. (Most common).
  • Read-Through: Cache sits in line with DB. Application always asks cache; cache fetches from DB if missing.
  • Write-Through: Data is written to cache and DB simultaneously.
  • Write-Behind (Write-Back): Data is written to cache first, and later asynchronously synced to DB.
4. Cache Eviction Policies
  • LRU (Least Recently Used): Discard the least recently accessed items first.
  • LFU (Least Frequently Used): Discard items used the least often.
  • FIFO (First In First Out): Discard the oldest items.
  • TTL (Time To Live): Data expires after a set duration.
