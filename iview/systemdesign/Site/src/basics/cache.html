What is Cache?

  • Cache is a temporary data storage; It need not to be RAM in all cases;
  • By storing frequently accessed data in cache, we can improve the response time;

Caching Applications

  • Web browsers cache JS/CSS/Images in order to load websites more quickly;
  • DNS servers cache DNS records for faster lookups;
  • CDN servers cache content to reduce latency;

How Caching Works?

  • When the client needs data, it first checks the Cache;
  • If the data is found in the cache(cache hit), it proceeds further with that data;
  • If the data is not found in the cache(cache miss), client fetches the data from original data source, stores a copy of it in the cache, before using it;

  • Caching Strategy - when the Cache is initialized with data?
    • Lazy Loading or Read Through
      • In this case, cache is intially empty;
      • Data is loaded into the cache, after the cache-miss;
      • Pros
        • It caches only the data that is needed;
      • Cons
        • Since data is loaded into the cache, when there is a cache miss, first read takes more time;
        • When the data in the database is updated/deleted, the data in cache will become stale;

    • Write Through
      • When the user insert/update/delete data in the database, same operation is performed on cache as well;
      • Pros
        • Data in the cache is never stale;
      • Cons
        • Write takes little bit longer than usual;

    • Write Behind
      • When the user insert/update/delete data in the database, it is first written only to the cache and successful acknowledgement is sent to the client;
      • After configured delay, the data in the cache is synched to underlying data source asynchronously;
      • Pros
        • Read and Write happens directly on the cache, thus faster;
      • Cons
        • any chances of data loss?

    • Refresh Ahead
      • Refresh-ahead offers reduced latency compared to read-through, but only if you could acurately predict which items are needed in the future;

    • When to use which Caching Strategy?
      • While a designing a system, identify whether it is read-heavy, write-heavy or a mix of both;
      • Different systems have different requirements - It is hard to come up with full-proof strategy;
      • You can choose one or a combination of more strategies as per your requirement;

      • So, which strategy to use? There is no definite answer; You should choose one based on the nature of the data and needs of your application;
      • What is the nature of data? frequently updated etc;
      • Needs of application? More reads, more writes etc;

  • How big the cache can be?
    • You cannot expect cache to hold all of your data;
    • There is a limit on the amount of data that a cache can store;

  • Cache Eviction Policies - On what basis, to delete the data from Cache?
    • First In First Out
      • It follows insertion order;
      • First written record is evicted before others, without any any regard to how often or how many times it was accessed before;

    • Last In First Out
      • Most recently written record is evicted before others, without any any regard to how often or how many times it was accessed before;

    • LRU - Least Recently Used - Most Popular!
      • Discards the least recently used items first;

    • MRU - Most Recently Used
      • In contrast to LRU, MRU discards the most recently used items first;

    • LFU - Least Frequently Used
      • Counts how often an item is needed; Those that are used least often are discarded first;

    • Time to Live
      • Data gets deleted after specified time;
