3Sum Closest (#16)

Problem: Given an integer array nums of length n and an integer target, find three integers in nums such that the sum is closest to target. Return the sum of the three integers.

Why Sorting is Needed:

  • Enables Two-Pointer Strategy: The two-pointer approach ($O(n^2)$) relies on the array being sorted. When the currentSum is less than the target, we know that incrementing the left pointer will increase the sum. If it's greater, decrementing the right pointer will decrease it. Without sorting, we wouldn't know which direction to move the pointers to get closer to the target.
  • Pruning the Search Space: Sorting allows us to skip unnecessary combinations. Instead of checking every possible triplet ($O(n^3)$), we can intelligently narrow down the search in linear time for each fixed element.

Golden Rule

Condition What to do
sum < target move left++ (increase sum)
sum > target move right-- (decrease sum)

Why this works:

Because the array is sorted:

  • Moving left → right → increases sum
  • Moving right → left → decreases sum

So we don’t need to try all combinations (like brute force)!

Algorithm:

  • Brute Force Approach: Use three nested loops to check every possible triplet (i, j, k) and calculate their sum. Keep track of the sum that has the minimum absolute difference from the target.
    • Time Complexity: O(n3)
    • Space Complexity: O(1)
  • Optimized Approach (Sorting + Two Pointers):
    • We pick one element and reduce the problem:

      👉 “Find 2 numbers whose sum is closest to (target - fixed element)”

    • After fixing nums[i], we do:
      • left = i + 1 (next element)
      • right = end
    • 👉 Now we try combinations efficiently:
      • Sort the input array.
      • Iterate through the array, fixing one element nums[i].
      • Use two pointers, left = i + 1 and right = n - 1, to find the sum closest to the target for the remaining two elements.
      • In each step, calculate the current sum and update the closestSum if the difference to target is smaller than the current minimum difference.
      • If the current sum is less than the target, move the left pointer forward; otherwise, move the right pointer backward.
      • Time Complexity: O(n2) due to the nested loop and two-pointer traversal.
      • Space Complexity: O(1) or O(log n) depending on the sorting algorithm's space requirements.

Comparison: The brute force method is simple but inefficient for large arrays as it checks all combinations. The Sorting + Two Pointers approach significantly reduces the time complexity from cubic to quadratic by leveraging the sorted property of the array to prune the search space.

3Sum Closest (#16)

import java.util.Arrays;

public class ThreeSumClosest {
    public static void main(String[] args) {
        int[] nums = {-1, 2, 1, -4};
        int target = 1;
        System.out.println("Closest sum: " + threeSumClosest(nums, target));
    }

    /**
     * Time Complexity: O(n^2)
     * Space Complexity: O(1) or O(log n) depending on sorting algorithm
     */
    public static int threeSumClosest(int[] nums, int target) {
        Arrays.sort(nums);
        int closestSum = nums[0] + nums[1] + nums[2];

        for (int i = 0; i < nums.length - 2; i++) {
            int left = i + 1;
            int right = nums.length - 1;

            while (left < right) {
                int currentSum = nums[i] + nums[left] + nums[right];
                
                if (Math.abs(currentSum - target) < Math.abs(closestSum - target)) {
                    closestSum = currentSum;
                }

                if (currentSum < target) {
                    left++;
                } else if (currentSum > target) {
                    right--;
                } else {
                    return currentSum; // Found exact match
                }
            }
        }

        return closestSum;
    }
}

Output:
Closest sum: 2
