1. How it works?
  • you just defined a schema, generated Go code, and used Protobuf to serialize and deserialize structured data.
  • Install Protobuf
    • Install protoc: brew install protobuf (Mac); check protoc --version;
    • Install protobuf for go: go install google.golang.org/protobuf/cmd/protoc-gen-go@latest
    • Install protobuf for gRPC: go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@latest
    • By default, Go installs binaries to $GOPATH/bin; Add protoc to path;
    • Edit ~/.zshrc; export PATH="$PATH:$(go env GOPATH)/bin"; reload: source ~/.zshrc; Test: which protoc-gen-go
  • Define Schema
    • It acts as a contract b/w Client and Server;
  • Compile Schema
  • Generate Code
    • gRPC compiler takes .proto file and generates code for both client and server;
    • Generated code contains: Classes for the message, client stub and server interace;
    • Client stub/inteface -> It allows you to call remote methods as if they are local;
    • server interface -> It is an abstract class the server must implement to handle the incoming requests;
  • Serialize Data on sender side
    • When a client calls a remote method, the generated code uses Protobuf to serialize the data into a compact binary format.
    • This binary data is then sent over the network using HTTP/2.
  • DeSerialize Data on receiver side
    • The server receives the binary data and uses the generated Protobuf code to deserialize it back into a usable object. 
  • syntax = "proto3";
