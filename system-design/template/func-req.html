1. What are Functional Requirements?
  • It defines the core functionality of a system - operations, inputs and outputs;
2. Things to consider when designing Functional Requirements?
  • Stakeholders
  • Use cases or actions
  • Inputs and outputs
  • Workflow - What happens from end to end?
  • Data handling - How data is stored, retrieved, updated, deleted?
  • Edge cases OR Error handling - What happens if an error occurs?
  • Permissions and Access Control - Who can do what?
  • External dependencies - What external services are used by the system?
  • Optional Features
3. What are Stakeholders?
  • It defines different type of users using a system;
  • End Users - People using the system(normal user, admin, operator etc);
  • Developers - People who will be developing the system;
  • Operators - People who keep the system running and monitoring it(like DBA, Devops, SRE etc);
  • Security Team - prevent spam/malicious links, data breaches, etc;
  • External Entities - External services/APIs that the system integrates with; People/systems outside your system;
  • At high level, you can categorize stakeholders into 3 groups: Primary Users, Internal users, External entities;
4. Why Stakeholders matter?
  • Different stakeholders often have different needs;
  • End Users - want speed & simplicity;
  • Business - wants more features;
  • Engineers - want maintainable system;
  • Security - wants strict controls;
  • Good system design = balancing all of these;
