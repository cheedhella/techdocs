1. Non-Functional Requirements - Performance, Scalability, Availability, Reliability, Security, Observability, Compliance;
  • Performance: How fast the system responds and how much load it can handle?
    • Latency: How fast the system responds to a request? Time for one request (Eg: < 200 ms);
    • Throughput: Requests per second(Eg: 1000 requests/second);
  • Scalability: How easy the system can be scaled to handle more requests?
    • Horizontal Scaling: Add more servers to handle more requests;
    • Vertical Scaling: Add more resources to a single server;
  • Availability:
    • Unavailability of services can cause loss of revenue and reputation; So, services should be as much UP as possible;
    • | Availability | Downtime per Year |
| ------------ | ----------------- |
| 90%          | 36.5 days/year    |
| 99%          | 3.65 days/year    |
| 99.9%        | 8.76 hours/year   | acceptable
| 99.99%       | 52 minutes/year   | high availability
| 99.999%      | 5 minutes/year    | mission-critical (e.g., banking, payments)
| 99.9999%     | 31 seconds/year   |
    • Reasons behind unavailability:
      • Hardware failure
      • Software failure - server crashes due to cpu/memory overload, disk full, etc; database failure; DNS failure; deployment bugs;
      • Network failure
      • Power failure
      • Natural disaster
      • Human error
      • Security breach
    • Achieved via: Redundancy, Failover;
  • Reliability: System should be reliable and can handle failures?
    • Fault Tolerance:System works correctly under failures;
    • Error Recovery:System recovers from failures;
    • Availability -> system is up; Reliability -> system is correct;
  • Security: How safe the system is from security threats?
    • Authentication: Verifying user identity before allowing them to use the system;
    • Authorization: Controlling access to resources based on user's role or permissions;
    • Encryption: Protecting data in transit and at rest;
    • Compliance: Adhering to relevant laws and regulations (Eg: GDPR, HIPAA);
2. Detailed Non-Functional Requirements
  • | Category                        | Type               | Description                           |
| ------------------------------- | ------------------ | ------------------------------------- |
| **Performance**                 | Latency            | Time taken to respond to a request    |
|                                 | Throughput         | Number of requests handled per second |
|                                 | Resource Usage     | CPU, memory, bandwidth usage          |
| **Scalability**                 | Horizontal Scaling | Adding more machines                  |
|                                 | Vertical Scaling   | Increasing machine power              |
| **Reliability**                 | Fault Handling     | System works correctly under failures |
|                                 | Error Recovery     | Ability to recover from crashes       |
| **Availability**                | Uptime             | % time system is operational          |
|                                 | Failover           | Backup systems take over on failure   |
| **Security**                    | Authentication     | Verifying user identity               |
|                                 | Authorization      | Controlling access                    |
|                                 | Encryption         | Protecting data                       |
| **Usability**                   | Ease of Use        | User-friendly interface               |
|                                 | Accessibility      | Works for all users/devices           |
| **Maintainability**             | Modularity         | Easy to update components             |
|                                 | Debugging          | Easy to identify/fix issues           |
| **Portability / Compatibility** | Platform Support   | Works on different OS/devices         |
|                                 | Interoperability   | Works with other systems              |
| **Extensibility**               | Feature Addition   | Easy to add new features              |
| **Testability**                 | Test Support       | Easy to test system behavior          |
| **Observability**               | Logging            | Track system events                   |
|                                 | Monitoring         | Measure system health                 |
| **Compliance**                  | Legal/Regulatory   | GDPR, data laws, etc.                 |
| **Durability**                  | Data Persistence   | Data is not lost                      |
| **Fault Tolerance**             | Resilience         | Continues working during failures     |
3. Functional vs Non-Functional Requirements
  • Functional = features -> what a system should do;
  • Non-functional = quality & performance -> how well a system should perform;
