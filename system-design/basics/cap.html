1. What is Consistency?
  • All users should see the same data at a given point of time, no matter to which node they are connected to;
  • To achieve Consistency, whenever data is written to one node, it must be instantly replicated to all the other nodes in the system, before the write is deemed successful;
2. What is Availability?
  • Any client making a request for data gets a response, not an error, even if one or more nodes are down, though it might not be the latest;
3. What is Partition Tolerance?
  • Partition means communication breakdown b/w 2 nodes;
  • Partition Tolerance means System should continue to work, despite node failures and network breakdown b/w any number of nodes in the system;
  • Data records are sufficiently replicated across combinations of nodes and networks, to keep the system up through intermittent outages;
4. What is CAP Theorem?
  • It says: It is impossible to build a distributed system, that guarantees all 3; It only guarantees 2 out of 3;
  • If you choose CP: it will gives you correct data, but it will reject requests when network partitioning occurs; Eg: MongoDB, HBase, Redis;
  • If you choose AP: it will gives you data, may be not correct data, but it will not reject requests when network partitioning occurs; Eg: Cassandra, DynamoDB, CouchDB;
  • If you choose CA: it works well only when there are no network failures; Not practical for distributed systems; Eg: Traditional RDBMS like MySQL/Postgres on a single server;
  • So, in distributed systems, P is not optional, you must handle network failures; So, you need to choose b/w Consistency and Availability;
  • If you choose CP, everyone will see the same and latest data(writes are failed when network partitioning occurs); If you choose AP, you can always send/read messages(read may not be latest);
