1. What is a Hash Collision?
  • A collision occurs when two different keys produce the same hash value (index) after passing through a hash function;
  • Since a hash table has a finite size but the number of possible keys is often infinite, collisions are inevitable;
  • Collision resolution techniques are strategies used to handle these situations and ensure data can still be stored and retrieved correctly;
2. Separate Chaining (Open Hashing)
  • How it works: Each slot in the hash table points to a linked list (or another data structure) of all items that hash to the same index;
  • Advantages: Simple to implement; the hash table never "fills up" (it just gets slower);
  • Disadvantages: Uses extra memory for pointers; performance degrades to O(n) if many items hash to the same slot;
3. Open Addressing (Closed Hashing)
  • How it works: All items are stored directly in the hash table. If a collision occurs, the algorithm "probes" for the next available slot;
  • Common Probing Methods:
    • Linear Probing: Check the next slot (index + 1, index + 2, etc.); can lead to "primary clustering";
    • Quadratic Probing: Check slots at increasing intervals (index + 1^2, index + 2^2, etc.); reduces primary clustering;
    • Double Hashing: Use a second hash function to determine the step size for probing; very effective at reducing clustering;
  • Advantages: Better cache performance as data is stored contiguously; no extra memory for pointers;
  • Disadvantages: Table can get full; sensitive to the "load factor";
4. Comparison of Techniques
  • Separate Chaining: Best when the number of elements is unknown or could be much larger than the table size;
  • Open Addressing: Best when the number of elements is known and fits within the table, and when memory/cache efficiency is critical;
