1. What is Database Sharding?
  • Sharding is a database architecture pattern that involves breaking a large database into smaller, faster, and more easily managed parts called shards;
  • Each shard is a separate database that contains a subset of the total data;
  • It is a form of horizontal scaling for databases;
2. Why Shard?
  • Handle Large Datasets: When a single database instance can no longer hold all the data or handle the traffic;
  • Improve Performance: Queries run faster on smaller datasets;
  • Increase Availability: If one shard fails, the other shards remain accessible;
3. Sharding Strategies
  • Key-Based (Hash) Sharding: Uses a hash of a column (like User ID) to determine the shard;
  • Range-Based Sharding: Divides data based on ranges of values (e.g., A-M in Shard 1, N-Z in Shard 2);
  • Directory-Based Sharding: Uses a lookup table to track which data is in which shard;
