1. What is Liskov Substitution Principle?
  • It says objects of a superclass should be replaceable with objects of its subclasses without breaking the application;
  • In other words, it says subclasses should behave like their parent classes;
  • For eg, in a remote, If you replace AA battery with another battery, it still should work;
  • In microservices, if you replace payment service A with another payment service B, it should work;
  • # Bad design 
class Payment {
    void pay() {}
}

class FreePayment extends Payment {
    void pay() {
        throw new Exception("No payment needed");
    }
}

# Better design 
interface Payment {
    void pay();
}

class CardPayment implements Payment {}
class FreePayment implements Payment {}
2. Why is it important?
  • When you replace Payment service A with Payment service B, If you follow LSP, everything will work; Otherwise, the system breaks;
