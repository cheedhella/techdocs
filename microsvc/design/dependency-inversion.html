1. What is Dependency Inversion Principle?
  • Instead of depending on specific implementations, always depend on interfaces / abstractions;
  • # Bad design 
# User service is tightly coupled to MySQLDatabase;
# If we want to use another database, we need to change the UserService class;
class MySQLDatabase {
    void save(String data) {}
}

class UserService {
    MySQLDatabase db = new MySQLDatabase();

    void saveUser() {
        db.save("user");
    }
}

# Better design 
interface Database {
    void save(String data);
}

class MySQLDatabase implements Database {
    void save(String data) {}
}

class MongoDatabase implements Database {
    public void save(String data) {}
}
    • Instead of: depending on specific implementations ❌ You depend on: interfaces / abstractions
