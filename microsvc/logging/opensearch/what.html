1. What is Opensearch?
  • It is a open-source, distributed, scalable full-text search and analytics engine that allows you store, search and analyze large volumes of data(using aggregation queries) in near real-time(not immediate);
2. New Terms
  • Cluster
    • A collection of one or more nodes working together;
  • Node
    • A single instance of Opensearch;
  • Document
    • A basic unit of data stored in JSON format;
  • Index
    • A logical namespace that contains documents (like a database);
    • Inverted index - Instead of storing documents by (ID → content), Opensearch stores term → list of documents that contain it;
  • Shard
    • A subdivision of an index that allows horizontal scaling;
  • Replica
    • A copy of a shard for fault tolerance and load balancing;
3. How it stores data?
  • User inserts data(a JSON document) to an index via a REST API, such as:
  • POST /my_index/_doc/1   # If you don't specify document id, it is auto-generated;
{
  "Name": "Chris",
  "Age": "seven",
  "parents": {
    "father_name": "Robert",
    "mother_name": "stella"
  }
}
  • Elasticsearch decides which shard will hold the document (using a hash of the document ID)
  • Ealsticsearch indexes the document using inverted indices;
  • Text fields goes through an analyzer:
    • Character filters (e.g., remove punctuation)
    • Tokenizer (split text into tokens)
    • Token filters (lowercasing, stemming, synonyms, etc.)
  • The processed tokens are written to Lucene’s inverted index — a structure optimized for text search;
4. How search works?
  • You can query data using a powerful RESTful API or the Elasticsearch Query DSL (Domain Specific Language);
  • Your query (in JSON) is sent to any node (a coordinating node);
  • That node forwards the query to all relevant shards;
  • Each shard searches its local data using Lucene and returns top matching documents with scores;
  • The coordinating node merges results, sorts them, and returns the final list;
  • Relevance scoring (default algorithm: BM25) determines how well each document matches your query;
5. Features
  • Full-text search
  • Fuzzy search - It provides the ability to handle typos in the input;
  • Faceted search
  • Elasticsearch provides a feature called fuzzy search that allows us to find an instance that approximately matches the searched text. This helps Elasticsearch handle user typos in the search.
  • It allows us to search for various data types such as textual, numerical, geospatial (GeoQuery), structured, and unstructured data types;
  • Elasticsearch provides aggregation requests that help us explore trends and patterns in our data;
