1. What is Full Text Search?
  • It’s allows you to type few words into a search box and instantly get the most relevant results, even if the exact phrase doesn’t match perfectly;
  • It doesn't just look for exact matches; It searches through all the text to find documents that best match the user’s query;
  • For example, if you search for "quick brown fox", a full-text search engine can find documents like:
    • The quick brown fox jumps over the lazy dog
    • A brown animal ran quickly into the forest
2. How Indexing works?
  • When you add text to full-text search engine, it goes through several steps:
  • Tokenization
    • Breaks text into words (tokens);
    • Example: “The quick brown fox” → ["the", "quick", "brown", "fox"]
  • Normalization
    • Converts all text to lowercase, removes punctuation, handles accents etc; Eg: Quick and quick are treated the same;
  • Stemming/Lemmatization(similar words) - Not the case with normal SQL Like search
    • Reduces words to their root form; Eg: Running, runs, ran → run
  • Inverted Index
    • Builds a map of which words appear in which documents;
    • "quick" → [Doc1, Doc3], "fox" → [Doc1, Doc2]
  • Relevance Scoring - Not the case with normal SQL Like search
    • When you search, it calculates a relevance score for each document using BM25 (a modern ranking algorithm), which consider:
      • How often the word appears in the document (term frequency)?
      • How rare the word is across all documents (inverse document frequency)?
      • Field weights, proximity, etc.
