🏗️ 2. Architecture & Internals

Understand how Elasticsearch works internally:

Cluster — A collection of nodes.

Node — A single instance of Elasticsearch.

Index — Logical namespace for documents (like a database).

Document — A JSON object (like a row in SQL).

Shard — Data partition; can be primary or replica.

Replica — Copy of a shard for fault tolerance and read scaling.

Segment — Low-level Lucene data storage unit.

Cluster state — Metadata maintained by the master node.

Distributed architecture concepts — Quorum, routing, consistency.

Query Processing & Relevance

Elasticsearch’s Query DSL lets you mix:

Full-text queries (match, match_phrase, multi_match)

Structured filters (term, range, bool)

Aggregations (for analytics)

Boolean logic (must, should, must_not)

Relevance scores consider:

Term frequency (how often a term appears in a document),

Inverse document frequency (how rare it is across all documents),

Field length normalization (shorter fields rank higher for matches).

📊 5. Aggregations (Analytics Engine)

Elasticsearch can also do real-time analytics using aggregations (like SQL GROUP BY):

Metric aggregations: avg, sum, min, max, count.

Bucket aggregations: terms, date_histogram, range.

Pipeline aggregations: moving averages, derivatives.

These run in parallel on each shard and are merged across nodes — very efficient at scale.

🚀 6. Distribution & Scalability

Because indices are split into shards:

Indexing can be parallelized (multiple shards handle inserts).

Search can be parallelized (each shard searches its part of data).

Adding more nodes lets Elasticsearch scale horizontally.

Data is automatically replicated for fault tolerance and load balancing:

If a node fails, replicas serve requests.

When a node joins, shards are rebalanced automatically.

🧰 7. Resiliency & Cluster Management

Elasticsearch maintains a cluster state, managed by a master node:

Tracks which nodes exist.

Tracks which indices and shards exist.

Decides shard placement.

Handles node failures and shard recovery.

The data nodes do the actual indexing and search work.

🧮 8. Updates & Deletes

Elasticsearch is near real-time, not immediate:

When you update a document, a new version is indexed; the old one is marked deleted.

The index is refreshed every second (configurable) — making changes visible.

This is handled through Lucene segments:

New data is written to new segments.

Old segments are merged periodically (background process called merge or force merge).

🔐 9. Security & Extensions (X-Pack)
