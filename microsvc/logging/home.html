Distributed Logging

1. Purpose of Distributed or Centralised Logging?
  • Imagine you are managing a large-scale application that consists of multiple microservices, each handling different aspects of your system, such as user authentication, payment processing etc;
  • As your application grows, tracking down issues becomes increasingly challenging;
  • When a user reports a problem, you need to sift through logs from various services to identify the root cause;
  • If each service logs data independently, finding relevant information can feel like searching for a needle in a haystack;
  • Distributed Logging provides a robust solution to above problem by centralizing log data from all microservices into a single system;
2. Centralized Logging Solutions
  • ELK (Elasticsearch, Logstash, Kibana) Stack
    • Log shippers (like Filebeat, Fluent Bit) run on each VM/container and send logs;
    • Logstash aggregates, parses, and transforms logs;
    • Elasticsearch stores and indexes logs;
    • Kibana visualizes and queries logs in real time;
    • Pros:
      • Open-source and mature ecosystem;
      • Highly customizable (filters, pipelines, dashboards);
    • Cons:
      • Can be heavy to manage at scale;
      • Needs tuning for performance and storage;
  • Grafana Loki Stack
    • Promtail agents ship logs;
    • Loki stores them in an efficient, label-based way;
    • Grafana visualizes;
    • Pros:
      • Lightweight compared to ELK;
      • Highly customizable (filters, pipelines, dashboards);
    • Cons:
      • Less powerful full-text search (optimized for structured logs);
Distributed logging is the process of collecting, storing, and analysing logs from multiple microservices in a centralised manner.

        Logging in distributed systems means recording what happens across different parts of a system that work together.
        Unlike traditional monolithic applications where logs are stored in a single place, microservices architectures spread logs across numerous services, each running in isolated environments. This distribution poses challenges in tracing requests, debugging issues, and monitoring system health.


        Tracing 
        Traceability: In a microservices architecture, a single user request may traverse multiple services. Distributed logging enables developers to trace the entire path of a request across these services, making it easier to identify where issues arise.

        Debugging: When something goes wrong, having logs from all services in one place allows for faster diagnosis and troubleshooting. Without centralised logs, developers would have to manually gather logs from each service, which is time-consuming and error-prone.

        Monitoring and Alerting: Centralised logs can be integrated with monitoring tools to detect anomalies and trigger alerts. This proactive approach helps in identifying potential issues before they impact the end-user.

        Compliance and Auditing: Many industries have regulations requiring detailed logs for auditing purposes. Distributed logging ensures that logs from all microservices are available for compliance checks.
