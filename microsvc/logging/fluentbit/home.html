FluentBit

1. What is FluentBit?
  • It collects logs, optionally parses/enriches them, and sends them to systems like OpenSearch;
2. How it works?
  • It has a simple, but powerful pipeline - [ INPUT ] → [ FILTER ] → [ OUTPUT ];
  • Input
    • [INPUT] Name tail # Name of the plugin Path /var/log/syslog # Tag system.logs # Tag is used to match this data to a [FILTER] or [OUTPUT] Mem_Buf_Limit # It Prevents Fluent Bit from consuming too much memory if the output is slow. It forces the engine to stop reading until the buffer clears; Alias # A human-readable name for the input instance (useful for monitoring); Parsers # Many inputs (like tail or tcp) allow a Parser field to immediately convert raw text into structured JSON; Storage Type # You can set storage.type filesystem to buffer data to the disk instead of memory, which prevents data loss if the service restarts.
    • Fluent Bit supports over 100 plugins;
      • tail - Reads text files, tracks checkpoints (offsets), and supports multiline parsing;
      • Systemd - Specifically designed to read from journald;
      • CPU / Mem - Collects local system resource usage metrics;
    • Every input plugin can be assigned a Tag, which is essential for routing that specific data to a specific output later;
3. FluentBit Config?
It continas 4 sections:
[SERVICE]   -> It contains global settings for the running service;
[INPUT]     -> It specifies sources of log records to collect;
[FILTER]    -> It applies transformations to log records;
[OUTPUT]    -> It determines the destination where Fluent Bit sends the processed logs;

SERVICE = Fluent Bit itself
INPUT = where logs come from
FILTER = transform(modify/enrich/drop) logs
OUTPUT = where logs go
PARSER = structure logs

You can have: 1 [SERVICE], Many [INPUT], Many [FILTER], Many [OUTPUT];

[SERVICE]
    Flush           1                   # How often (seconds) data is flushed to outputs
    Log_Level       info                # error, warn, info, debug, trace
    Daemon          off                 # Run in background(usually off with systemd)
    Parsers_File    parsers.conf        # External file with parsers
    HTTP_Server     On                  # Enables metrics & health endpoint
    HTTP_Listen     0.0.0.0             # 
    HTTP_Port       2020                # Exposes /api/v1/metrics

[INPUT]
    Name    tail                        # Name of the plugin; Fluentbit supports over 100 plugins;
    Path    /var/log/syslog             # Files to read;
    DB      /var/lib/fluent-bit/tail.db # Keeps track of read offsets; Prevents log duplication on restart; Always set DB in production(over Path);
    Tag     syslog                      # Logical name for records; Used by filters & outputs (Match);

Parsers 
    Parsers are the magic that turns messy text logs into structured, searchable fields. 
    Without parsers, OpenSearch just gets a blob of text; with parsers, you get real fields like level=ERROR, user_id=123, etc.
    Eg: 
      Raw log: 2026-01-25 10:15:32 ERROR user=42 login failed
      After parsing:
      {
        "timestamp": "2026-01-25 10:15:32",
        "level": "ERROR",
        "user": 42,
        "message": "login failed"
      }
    
    Parsers are not automatic.
    You must apply them via: [FILTER] parser or or directly in [INPUT] (some plugins)

    Where parsers live?
      Parsers are defined in a separate file, usually: parsers.conf and referenced in [SERVICE] -> Parsers_File

    Types of Parsers 
      JSON parser 
      Regex parser -> Used for nginx/apache logs
        [PARSER]
            Name   nginx
            Format regex
            Regex  ^(?[^ ]*) - (?[^ ]*) \[(?[^\]]*)\] "(?\S+) (?\S+) \S+" (?\d+)
      LTSV parser -> Used for Key:value log formats; Eg: time:2026-01-25 level:info user:42
      Logfmt parser -> 
      Multiline parsers (stack traces) 
          - Used when one logical log = multiple lines.
      
      Time_Key time         @# Specifies which field contains the timestamp.
      Time_Format %Y-%m-%d %H:%M:%S     # Without this, Fluent Bit uses ingestion time.


[FILTER]
    Name   modify
    Match  *                            # Applies the filter to only matching tags;
    Add    env prod

[FILTER]
    Name      parser
    Match     *
    Key_Name  log
    Parser    nginx

Common filter plugins
| Filter            | Purpose                    |
| ----------------- | -------------------------- |
| `parser`          | Parse raw text into fields |
| `modify`          | Add/remove fields          |
| `kubernetes`      | Add pod metadata           |
| `grep`            | Include/exclude logs       |
| `lua`             | Custom logic               |
| `record_modifier` | Add static fields          |


[OUTPUT]                                      # It defines the destination(OpenSearch, Kafka, S3 etc); You can have multiple [OUTPUT] blocks to send different logs to different destinations;
    Name   opensearch                         #

    Host   opensearch.example.com             #  
    Port   9200
    TLS       On                              # Use TLS if target is running on HTTPS;
    TLS.Verify On
    Index  logs-%Y.%m.%d                      # Indexes based on event timestamp(not system timestamp);

3. How it works?
  • It has mainly 2 components: Inputs and Harvesters;
  • Inputs -> It defines what logs to read(For eg, specific files or directories);
  • Harvesters
    • For each log that Filebeat locates, It starts a new harvester;
    • Harvester is a lightweight thread, that monitors a single log file for new entries and sends the content to the output that you’ve configured;
4. Install Filebeat
  • curl -L -O https://artifacts.elastic.co/downloads/beats/filebeat/filebeat-8.15.2-linux-x86_64.tar.gz
  • tar -xzf filebeat-8.15.2-linux-x86_64.tar.gz
  • cd filebeat-8.15.2-linux-x86_64
  • vi filebeat.yml
  • filebeat.inputs:

      - /var/log/*.log

  • Test config: ./filebeat test config
  • Start: sudo ./filebeat -e -c filebeat.yml # -e → logs to stdout (useful for debugging)
  • Stop: sudo ./filebeat stop
  • Restart: sudo ./filebeat restart
  • Status: sudo ./filebeat status
  • Delete: sudo ./filebeat delete
  • To run it in background: nohup sudo ./filebeat > filebeat.log 2>&1 &
  • Run as a Systemd Service: 
    sudo vi /etc/systemd/system/filebeat.service
[Unit]
Description=Filebeat Service
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/filebeat/filebeat -c /usr/local/filebeat/filebeat.yml
Restart=always
User=root
WorkingDirectory=/usr/local/filebeat

[Install]
WantedBy=multi-user.target

5. Configure Filebeat
// /etc/filebeat/filebeat.yml
##########################################
# FILEBEAT CONFIGURATION TEMPLATE
# ----------------------------------------
# Works for: manual installs, Docker, or systemd service
# Purpose: collect logs (e.g., Spring Boot apps) and ship to ELK
##########################################

# =========================================
# Filebeat Inputs — what logs to read
# =========================================
filebeat.inputs:

  # --- Log input example ---
  - type: log
    enabled: true
    # Paths to your application logs
    paths:
      - /opt/spring/logs/*.log
      - /var/log/*.log

    # Optional: exclude compressed or rotated logs
    exclude_files: ['\.gz$']

    # Optional custom fields
    fields:
      app: spring-boot-demo
      environment: production
    fields_under_root: true

    # If your logs are in JSON format (Spring Boot JSON logging)
    json.keys_under_root: true
    json.add_error_key: true
    json.message_key: message

    # Handle multi-line logs (e.g., Java stack traces)
    multiline.pattern: '^[[:space:]]'
    multiline.negate: false
    multiline.match: after

    # Performance / cleanup
    ignore_older: 24h
    clean_inactive: 72h
    close_inactive: 5m

# =========================================
# Filebeat Modules — prebuilt configs
# =========================================
filebeat.config.modules:
  path: ${path.config}/modules.d/*.yml
  reload.enabled: true
  reload.period: 10s
  # Example: enable system logs → sudo filebeat modules enable system

# =========================================
# Autodiscover — dynamic log discovery (optional)
# =========================================
# For Docker/Kubernetes environments
# filebeat.autodiscover:
#   providers:
#     - type: docker
#       hints.enabled: true
#     - type: kubernetes
#       hints.enabled: true
#       include_annotations: ["co.elastic.logs/enabled"]

# =========================================
# Processors — add metadata or modify events
# =========================================
processors:
  - add_host_metadata: ~
  - add_cloud_metadata: ~
  - add_docker_metadata: ~
  - add_kubernetes_metadata: ~
  # Drop unwanted fields
  - drop_fields:
      fields: ["agent.ephemeral_id", "ecs.version"]

# =========================================
# Outputs — where logs go
# =========================================

# --- Elasticsearch (direct output) ---
output.elasticsearch:
  enabled: true
  hosts: ["http://localhost:9200"]
  index: "filebeat-%{[agent.version]}-%{+yyyy.MM.dd}"
  username: "elastic"        # optional
  password: "changeme"       # optional
  # ssl.certificate_authorities: ["/etc/pki/root/ca.pem"]

# --- Logstash output (if using Logstash as a buffer/parser) ---
# output.logstash:
#   enabled: true
#   hosts: ["localhost:5044"]
#   loadbalance: true
#   ssl.certificate_authorities: ["/etc/pki/root/ca.pem"]

# --- Kafka output (alternative) ---
# output.kafka:
#   hosts: ["localhost:9092"]
#   topic: "filebeat"
#   codec.json:
#     pretty: false

# --- Console output (for testing/debug) ---
# output.console:
#   enabled: false
#   pretty: true

# =========================================
# Logging — Filebeat's own logs
# =========================================
logging:
  level: info           # debug, info, warning, error
  to_files: true
  to_syslog: false
  files:
    path: /var/log/filebeat
    name: filebeat
    keepfiles: 7
    permissions: 0644
  selectors: ["*"]      # use ["*"] for all, or ["publish", "output"] for less noise

# =========================================
# Monitoring — send internal metrics to Elasticsearch
# =========================================
monitoring:
  enabled: true
  elasticsearch:
    hosts: ["http://localhost:9200"]
  metrics_period: 10s

# =========================================
# Kibana Setup — for dashboards
# =========================================
setup.kibana:
  host: "http://localhost:5601"

# =========================================
# Index Template & Dashboard Setup
# =========================================
setup.template.enabled: true
setup.template.name: "filebeat"
setup.template.pattern: "filebeat-*"
setup.dashboards.enabled: true

# =========================================
# General Runtime Settings
# =========================================
name: "filebeat-node1"
tags: ["spring", "prod"]
max_procs: 1
queue.mem:
  events: 4096
  flush.min_events: 512
  flush.timeout: 5s
7. Configuration Description
| Category         | Key Setting                                                                 | Description                                              |
| ---------------- | --------------------------------------------------------------------------- | -------------------------------------------------------- |
| **Inputs**       | `filebeat.inputs`                                                           | Defines log sources (files, containers, syslog, etc.)    |
| **Modules**      | `filebeat.config.modules`                                                   | Prebuilt configs for popular apps (nginx, system, mysql) |
| **Autodiscover** | `filebeat.autodiscover`                                                     | Dynamically discover containers/pods                     |
| **Processors**   | `processors`                                                                | Add metadata or modify events                            |
| **Outputs**      | `output.elasticsearch`, `output.logstash`, `output.kafka`, `output.console` | Send events to destinations                              |
| **Logging**      | `logging.*`                                                                 | Configure Filebeat’s own logging                         |
| **Monitoring**   | `monitoring.*`                                                              | Send Filebeat internal metrics to Elasticsearch          |
| **Setup**        | `setup.kibana`, `setup.template`, `setup.dashboards`                        | Preload templates and dashboards                         |
| **General**      | `max_procs`, `name`, `tags`, `queue.mem`                                    | Miscellaneous runtime options                            |
8. Minimal Configuration
filebeat.inputs:                                        # Each input tells Filebeat where to read logs from and how to process them; 
  - type: log                                           # Plain log file on the disk; Other values: stdin - read from standard input; container - read from docker container logs; syslog - read from syslog; journald - read from journald; 
    enabled: true                                       # Set it to false, to temporarily disable it;
    paths:                                              # Filebeat tails these files and reads new lines as they’re written;
      - /path/to/your/spring-boot-app/logs/*.log
    fields:                                             # Custom fields you want to attach to every log event from this input; Fields are extremely useful for filtering and searching logs in Elasticsearch or Kibana (e.g., app:custom-webserver AND env:production);
      app: "custom-webserver"
      env: "production"
    fields_under_root: true                             # By default, Filebeat puts custom fields under a fields object, like this: {"fields":{"app":"custom-webserver","env":"production"}}; When set to true, filebeat merges them into root of the event, like this: {"app":"custom-webserver","env":"production"};
                                                        # It makes filtering and querying in Kibana much simpler (app:custom-webserver instead of fields.app:custom-webserver);
    json.keys_under_root: true                          # Tells Filebeat to parse the log line as JSON and merge all keys from that JSON object directly into the event; Use this only if your logs are in JSON format (Spring Boot JSON logging);
    json.add_error_key: true                            # When set, Filebeat adds a field "error.message" if a log line fails JSON parsing; This helps you debug malformed log lines and avoid silent data loss;
    ignore_older: 24h                                   # Filebeat ignores files that haven’t been modified in the last 24 hours;
    clean_inactive: 72h 
    close_inactive: 5m

# ignore_older
# It is used to avoids re-sending old archived logs when Filebeat restarts.
# How it works?
# When Filebeat starts, it checks the modification time (mtime) of each file that matches the paths: patterns.
# If the file was modified within the last ignore_older duration → ✅ Filebeat starts or continues reading it.
# If the file was last modified before that duration → 🚫 Filebeat ignores it entirely.
# ignore_older: 0           Disable ignoring — read all logs (⚠️ careful: may re-ship old data)

# clean_inactive	How long before Filebeat forgets an old file completely from its registry; If a file hasn’t been seen for 48h, remove it from Filebeat’s internal state;
# close_inactive	How long after last read before Filebeat closes a file handle; Close a file handle after 10 minutes of inactivity;
# scan_frequency	How often Filebeat rescans the directory for new files.

output.elasticsearch:
  hosts: ["http://localhost:9200"]
  index: "spring-boot-logs-%{+yyyy.MM.dd}"
