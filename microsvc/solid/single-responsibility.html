1. What is Single Responsibility Principle?
  • A class should have one and only one responsibility;
  • It means a class should have only one reason to change;
  • For eg, UserService is used only for managing users; You can't have sendEmail() method in UserService; It is the responsibility of EmailService to send emails;
  • In microservices, a service should have one and only one responsibility;
  • For eg, Authentication service should only be responsible for authentication; It should not be responsible for authorization;
2. Why is it important?
  • Better Maintainability - Easy to understand and maintain;
  • Better Scalability - Without SRP, you will have to scale everything; With SRP, you can scale only what is needed;
  • Better Resilence(or fault tolerance) - Faults are inevitable; Without SRP, one failure can bring down everything; With SRP, failures are contaiend; For eg, even if notification service is down, orders service still works;
