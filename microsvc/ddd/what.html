1. What is Domain Driven Design?
  • DDD = Model your software the way the business thinks;
  • Eg:
  • Entity: Order
  • Value Object: Address
  • Aggregate: Order + Items
  • Domain Event: OrderPlaced
  • Repository: OrderRepository
  • Domain Driven Design (DDD) is a software development approach that focuses on modeling the domain of the application in a way that is easy to understand, maintain, and extend;
  • https://dev.to/leapcell/domain-driven-design-explained-a-real-world-example-581j
2. DDD works best when:
  • Business logic is complex
  • Domain knowledge is critical
  • Frequent changes happen
3. Avoid if:
  • Simple CRUD app
  • No complex domain rules
4. Bounded Contexts, Aggregates, and Ubiquitous Language
  • Bounded Contexts are the boundaries of the domain;
  • Aggregates are the clusters of domain objects that are treated as a single unit for the purpose of data changes;
  • Ubiquitous Language is the shared language that is used by developers (in code and documentation) and business experts, to communicate about the domain;
