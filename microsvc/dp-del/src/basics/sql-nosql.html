SQL vs NoSQL

  • In SQL, tables have predefined schema;
  • NoSQL is schemaless;

  • SQL is used for storing structured data;
  • NoSQL is used for both structured and unstructured data;

  • SQL is fit for joins and complex queries;
  • NoSQL is not fit for complex multi table queries;

  • SQL follows ACID properties: Atomicity, Consistency, Isolation, Durability;
  • NoSQL follows CAP properties; Consistency, Availability, Partition Tolerance;

  • SQL databases scale vertically;
  • NoSQL databases scale horizontally;

  • Eg of SQL databases: Oracle, MySQL, PostgresQL, Amazon Aurora, Amazon RDS etc;
  • Eg of NoSQL databases: MongoDB, Cassandra, AWS DynamoDB etc;

NoSQL database types

  • Key-Value Stores:
    • It stores data as an array of key-value pairs; key is the name of the attribute, which is linked to the value;
    • Eg: Redis, DynamoDB;

  • Document Stores:
    • It stores data in the form of a JSON document; Each document can have an entirely different structure;
    • Eg: CouchDB, MongoDB;

  • Wide-column databases:
    • It stores data in the form of a JSON document; Each document can have an entirely different structure;
    • Eg: Cassandra, HBase;
    • Columnar databases are best suited for analyzing large datasets;

  • Graph databases:
    • It stores data in the form of a JSON document; Each document can have an entirely different structure;
    • Eg: Neo4J, InfiniteGraph;
