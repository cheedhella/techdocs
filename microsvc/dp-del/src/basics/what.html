What is System Design?

  • System design is the process of defining the components, their integration, data model, API of a distributed system, that meets specified functional and non-functional requirements;
  • System design uses the concepts of computer networking, parallel computing and distributed systems to craft systems that scale well and are performant;

Non-functional Characteristics

  • Availability
  • Reliability
  • Scalability
  • Maintainability
  • Fault Tolerance

What is Reliability?

  • A system is considered reliable, if it keeps performing consistently well, without any service disruption and drop in performance, even when one or several of it's components fail;

  • Why is Reliability important?
    • If you don't focus on Reliability, it will increase the chances of outage in one or more components, thus causing interruptions in service;
    • According to Gartner, companies lose an average of $336,000 per hour of downtime, with top ecommerce sites risking up to $13 million in lost sales per hour of downtime;
    • This doesn't include other harmful effects such as loss of brand reputation and indirect cost of fixing outages(engineer's salaries, resotring from backups, spinning up additional infrastructure etc);

  • How do you improve Reliability?
    • Reliability is not a short-term thing; Reliability is a journey; We can distill the journey into 3 main elements: People, Monitoring, Technology;
    • People
      • When we think about reliability, we typically think of reliability in terms of systems; The reality is that reliability starts with people;
      • Educate site reliability engineers, incident responders, developers to proactively think about reliability and better prepared for failures;
    • Use monitoring system to detect failures and get alerts;
    • Use technology to detect failure and recover from it;

What is Scalability?

  • It is the capability of a system to grow and support the increasing amount of work;

  • Generally, although designed (or claimed) to be scalable, sometimes the performance of a system declines with the system size due to various factors;
  • For instance, network speed may become slower because machines tend to be far apart from one another;

  • Horizontal Scaling VS Vertical Scaling

High Availability

  • High availability describe systems which continues functioning even when some of its components fail;
  • It is achieved by having redundant components in the system design;
  • Because of this redundancy, the system guarantees a certain percentage of uptime;
  • To make a system highly available, it is important to identify all single point of failures;

  • Generally, Amazon Elastic Load Balancer is inherently highly available under the hood;
  • However, a single Amazon ec2 is not highly available;

  • You can put your ec2 in auto scaling group, with desired number of replicas as 1;
  • Any time your ec2 machine goes down, ASG brings up another ec2;
  • But, that doesn't make the system highly available;
  • Between the time when an instance goes down and another instance coming up, the system will not server any requests;

  • you can put 2 ec2 machines in auto scaling group, each machine in a different availability zone, with desired number of replicas as 2;
  • When one of machine goes down, another instance can still serve the requests, while ASG bringing up another instance;

  • AWS Lambda is a compute option, that is highly available under the hood;
  • Each lambda function is deployed in multiple availability zones, so even if one of the availability zone goes down, your system will be up and running;

  • So, high availability comes at a cost;

Fault Tolerance

  • you can put 2 ec2 machines in auto scaling group, each machine in a different availability zone, with desired number of replicas as 2;
  • When one of machine goes down, another instance can still serve the requests, while ASG bringing up another instance;

  • In above case, the system is highly available;
  • But, say, each ec2 can handle only 50 requests/sec and there are 100 requests/sec coming in and load balancer is distributing 50requests to each ec2;
  • When one of the ec2 goes down, while ASG is bringing up another ec2, load balancer routes all 100requests/sec to the only available ec2;
  • But, it can handle only 50requests/sec, thus causing performance issue;

  • In fault tolerant architecture, system is not only highly available, but also the performance won't degrade, if some of the components goes down;

  • You could have 3rd ec2 in 3rd availability zone; But, that adds more cost;
  • You could have 2 ec2 machines, in 2 of the availability zones; But, that is even costlier;

  • So in general, fault tolerance system is more expensive than highly available system;

  • So, in system design interviews, pay attention to whether you need to design highly available system or fault-tolerant system;

Reliability Vs Availability

  • If a system is reliable, it is available; However, if it is available, it is not necessarily reliable;
  • it is possible to achieve a high availability even with an unreliable product by minimizing repair time and ensuring that spares are always available when they are needed;

Efficiency

  • To measure the Efficiency of a distributed system, there 2 parameters used:
    • Throughput
      • It means the number of requests processed, within a specific period of time;
      • It is a measure of system performance - higher the throughput, better the performance;
    • Latency OR Response Time
      • In messaging systems, it is amount of time(in milliseconds) it takes to deliver a single message;
      • In database, it is the amount of time it takes to return the results of a query;

Maintainability or Servicability

  • It is all about:
    • Early detection of faults, so that we can avoid or reduce system downtime;
    • How quickly we can fix the failure; More the time you take, downtime increases;
