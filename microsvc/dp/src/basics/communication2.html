These are common patterns used in distributed systems for 2 or more services to communicate with one another:
  • Message Queues
  • Publishers-Subscribers

What is a Message Queue?

  • In case of Message queues, the system usually consists of a publishing service and multiple consumer services that communicate via a queue;
  • Typically, that communication is one way!
  • Publisher will create a command/message, put it on the queue;
  • Another single consumer will consume that message and perform an action based on it;
  • Eg: Amazon MQ, Amazon SQS;

Where to Use Message Queues?

  • Message queues are often used where one service wants to delegate work to another service OR one service issuing a command to another service;
  • In doing so, we want to ensure that the command is handled only one time;
  • Using message queues in microservices architecture based cloud applications, as it allows us to horizontally scale our application based on load;
  • For example:
    • If there are many messages on the queue waiting to be processed, we can spin up multiple consumers, which listen to the same queue and handle the influx in messages;
    • Once the messages have been handled/consumed, the services can then be turned off, when traffic is minimal, to save on running costs;

What is Publisher Subscriber Architecture?

  • In this architectural pattern, just like message queue, there are multiple producers and multiple consumers;
  • Producers produce messages of different categories and Consumers can subscribe to the category of messages in which they are interested in;
  • In case of a message queue, a message is deleted as soon as it is consumed by a subscriber;
  • In case of prod-sub,
    • It ensures that a message in a given topic is received by all it's subscribers;
    • It also ensure that subscriber receives the messages in the order in which they were produced;
  • Eg: Amazon Simple Notification Service, Amazon Event Bridge;

Where to Use Pub-Sub?

  • Think of stock ticker!
  • There many people want to know the latest price changes on the stocks, they're following;
  • It is also important that they get the information in the right order;
  • For eg, it'd make a big difference to know if a low price came in before a high price and vice versa;

When to which one? Message Queue VS Pub-Sub?

  • Both the architectural patterns are a great way to break up an application to make it more horizontally scalable;
  • In both the cases, messages are more durable than traditional synchronous mode of communication;
  • Go for pub-sub, if you want a message to be processed by all subscribers; Otherwise, go for message queue;
