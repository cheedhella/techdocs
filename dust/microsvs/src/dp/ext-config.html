Why we need to externalize microservices configuration?

  • It's not easy, if you want to modify the configuration of a service that is replicated hundred times, when the configuration packaged with service itself;
  • It can result in some instances using the old configuration, and some using the new one, at some point;
  • Continuous delivery best practice say build once and deploy the same every time;
  • So, we need to externalize the configuration, if we have any of below expectations:
    • We need to have different configuration for different environnement;
    • A service must run in multiple environments - dev, test, qa, staging, production - without modification and/or recompilation;
    • We need to have different configuration for same environment over the time;
    • We need to authorize user that can manage the configuration;
    • We need to log configuration properties changes;
    • We need pushing configuration properties changes at live;

How to externalize configuration?

  • You can store the configuration in a GIT repository, Vault, database, file system etc;
  • At startup, microservices load the configuration from the external store;
  • During runtime, microservices provide an option to reload the configuration without having to restart the service;

  • What is more important it is, whichever store you use, it must be reliable and highly available; This is usually accomplished by replicating the configuration server itself;
