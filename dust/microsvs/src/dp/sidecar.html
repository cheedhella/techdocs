What is Sidecar Pattern?

  • It is made up of 2 containers: Primary and Sidecar containers;
  • Primary container contains the core logic of the applicaiton; Eg: provisioning.war
  • Sidecar container extends/augments the core logic in Primary container; Eg: Content-as-a-Service provisioning;
  • Sidecar container runs on the same Pod as the main applicaiton container; Both share resources such as disk, network etc;
  • Note: All containers in a pod are scheduled on the same node in a multi-node cluster;
  • Note: Containers in the same Pod can connect to each other using localhost, and then the port number exposed by the other container - So, no network latency;
  • Your Primary container works perfectly well without the sidecar, but with it, it can perform some extra functions;

Where it is useful?

  • It is extremely useful when both Primary and Sidecar containers are implemented with different technologies OR different versions;
  • Log aggregator - Primary writes logs to shared volume, Sidecar container reads from it and pushes the logs to centralized log server;
  • In other words, Primary container focuses on business logic, where as Sidecar container focuses on cross cutting concerns such as Caching, Configuration and Secret management, Monitoring, Logging etc;
