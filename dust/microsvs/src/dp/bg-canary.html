What is Blue-Green Deployment?

  • It is a deployment technique to release new code into the production environment;
  • It makes use of 2 identical production environments — one of these is active and the other environment is set to idle;
  • New updates are pushed to the active environment where it is monitored for bugs, while the idle environment serves as a backup where traffic can be routed in case an error occurs;
  • Pros
    • Rollback is straightforward, as we just need to simply flip traffic back to the old environment in case any issue arises;
  • Cons
    • Quality assurance and user acceptance testing may not be enough to identify all of the anomalies or regressions;
    • Cost is the major drawback to blue-green deployments; Replicating a production environment can be complex and expensive;

What is Canary Deployment?

  • It is a technique to reduce the impact of software update, by slowly rolling out the change to a small subset of users, before making it available for everyone;
  • Pros
    • It allows us to test our code in production with real users and use cases;
    • It is cheaper than blue-green deployment because it does not require 2 production environments;
