Challenges with Monolithic Architecture?

  • Large codebase makes it difficult to understand, especially for the new developer;
  • Scaling is challenging;
  • Because, everything is tightly coupled, it is hard to change technology or language;
  • Any code change in one module would require the entire application to be deployed again;

What is a Micro Service?

  • A microservices architecture consists of a collection of small, autonomous services;
  • Each service is self-contained and should implement a single business capability;
  • Microservices are the small services that work together — Sam Newman
  • Microservices embrace concerns like single responsibility, separation of concerns, modularity etc;

Microservice Characteristics

  • Services are small, independent and loosely coupled;
  • Each service is a separate codebase, which can be managed by a small development team;
  • Each service has its own database, in order to be decoupled from other services;
  • Services can be deployed independently; A team can update an existing service without rebuilding and redeploying the entire system;
  • Services communicate with each other by using well-defined APIs; Internal implementation details of each service are hidden from other services;
  • Services communicate using either synchronous protocols such as HTTP/REST, gRPC or asynchronous protocols such as AMQP;
  • Services don’t need to share the same technology stack, libraries, or frameworks - Polyglot;
  • You should have well written documentation for each microservice which covers all the apis;
  • Note: It is not required for a microservice to adhere to all above characterstics;
  • Main characterstic is scaling and independent;
  • Sometime you see same database being used by more than one microservice;
