Strategy Pattern
	Sometimes, there are several ways of doing the same thing and you don't know which approach to use until runtime.
	Strategy pattern is allows you to select one of several strategies or algorithms dynamically.
	Some examples are:
		Different sorting or compression or hashing algorithms.
		Different plotting formats such as line, bar, pie etc.
		The Strategy pattern is to be used where you want to choose the algorithm to use at runtime. A good use of the Strategy pattern would be saving files in different formats, running various sorting algorithms, or file compression.

	Where is it used in JDK source?
	java.awt.Container implements the Strategy pattern using different LayoutManager objects as strategy objects.
	Each concrete LayoutManager implementation uses a different algorithm to display the GUI components.
	A FlowLayout displays them in a left-to-right sequence, a BorderLayout displays them in five regions and a GridLayout displays them in row-column format.
	Container class contains a reference to a LayoutManager object(strategy object) and allows to select any layout/strategy at run-time using setLayout().
	

The Strategy pattern is known as a behavioural pattern - it's used to manage algorithms, relationships and responsibilities between objects. 

https://alvinalexander.com/java/java-strategy-design-pattern-in-java/
	
	Example:
	interface Strategy {
		int execute(int a, int b); 
	}
 
	class Add implements Strategy {
		public int execute(int a, int b) {
			System.out.println("Called Add's execute()");
			return a + b;  // Do an addition with a and b
		}
	}
 
	class Subtract implements Strategy {
		public int execute(int a, int b) {
			System.out.println("Called Subtract's execute()");
			return a - b;  // Do a subtraction with a and b
		}
	}
 
	class Multiply implements Strategy {
		public int execute(int a, int b) {
			System.out.println("Called Multiply's execute()");
			return a * b;   // Do a multiplication with a and b
		}    
	}
 
	// Use of the Context from the client may vary - your client could tell the Context which strategy it would like to use, or the Context could decide on behalf of the client. In my opinion, it's better to leave this decision to the Context.
	class Context {
		private Strategy strategy;
 
		public Context(Strategy strategy) {
			this.strategy = strategy;
		}
 
		public void setStrategy(Strategy strategy) {
			this.strategy = strategy;
		}
		
		public int executeStrategy(int a, int b) {
			return this.strategy.execute(a, b);
		}
	}
 
	/** Tests the pattern */
	class StrategyExample {
		public static void main(String[] args) {
			Context context;
 
			// Three contexts following different strategies
			context = new Context(new Add());
			int resultA = context.executeStrategy(3,4);
			
			context.setStrategy(new Subtract());
			int resultB = context.executeStrategy(3,4);
 
			context.setStrategy(new Multiply());
			int resultC = context.executeStrategy(3,4);
 
			System.out.println("Result A : " + resultA );
			System.out.println("Result B : " + resultB );
			System.out.println("Result C : " + resultC );
		}
	}
