What is FlyWeight Pattern?
	It is useful when you want to create a large number of similar objects, most of the properties are same across all objects, while 
	only a few properties are unique;

	Intrinsic Properties - properties which are same across all objects;
	Extrinsic Properties - properties which change thier value from one object to another;
	
	Flyweight - A shared object that contains only intrinsic properties;
		Another important feature of flyweight object is that it must be immutable(it can't be modified, once constructed);
	Flyweight Factory 
		As you know, a new object is created each time a constructor is called;
		So, to avoid duplicates, you should use a factory, which is backed by a HashMap to recycle the created objects;
		Each time an object is requested, factory checks if any object of that kind is already created and present in the HashMap;
		If it has, it returns the existing object. Otherwise, it creates a new one and stores it before returning;

		FlyweightFactory is responsible for the creation and management of the flyweights, ensuring that they are shared properly;
		If the desired Flyweight isn't created yet it will create and return one; 
		Otherwise, it will return one from the current pool of flyweights;

	Example 1:
		Suppose that you have pen, You can replace different refills to write with different colors;
		So, a pen without refills is considered as a flyweight with intrinsic data, and a pen with refills is considered as extrinsic data;

	Example 2:
		Suppose that a company needs to print visiting cards for its employees;
		So, where does the process start? The company can create a common template with the company logo, address, and 
		so forth (intrinsic) and later it adds each employee’s particular contact information (extrinsic) on the cards;

	Example 3: Representation of character in a word processor
		Rather than each character having seperate glyph objects that represent the font and formatting data, each character 
		could have a reference to a flyweight glyph object shared by every instance of the same cahracter in the document;
		In this case, the character need only store it's position in the the document, rather than it's entire formatting information;

	Example 4: Angry Birds Game
		In Angry birds game assume, if we want to create 20000 red colour angry birds, what we will do is that we will create 
		20000 angry bird objects and fill it with red colour. Because, we are creating 20000 objects, it will definitely take 
		more memory and affect the performance of the game. 
		To avoid it, what we can do is according to flyweight design pattern, we can create only one angry bird object without 
		any color and push it into hashmap. Everytime you need a blue color angry bird, fetch the object from HashMap and fill 
		it with blue color and use it;

	Example 5: Some of Wrapper Classes in Java
		Some of the wrapper classes such as Byte, Character, Short, Integer have a static valueOf() method;
		Note: Float and Double don't follow this pattern;

	Example 6: String literals are an example of flyweights
		String s1 = "hello";
		String s2 = "hello";
		System.out.println(s1 == s2); // true
		----
		String s1 = new String("hello");
		String s2 = new String("hello");
		System.out.println(s1 == s2); // false
		----
		String s1 = new String("hello").intern();
		String s2 = new String("hello").intern();
		System.out.println(s1 == s2); // true

	Example 7: Starting from Java 5.0, Auto-boxing caches are another example of flyweights
		Integer i1 = 1;
		Integer i2 = 1;
		System.out.println(i1 == i2); // true, they are the same object.
		----
		Integer i3 = -200;
		Integer i4 = -200;
		System.out.println(i3 == i4); // false, they are not the same object.

Why flyweight is a Structural pattern, not Creational pattern?
	Flyweight pattern is not about creation of objects but about sharing of them;
	What makes the pattern structural is the use of factory-like class to obtain the flyweights;
