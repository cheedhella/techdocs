What is Distributed Cache?

  • Distributed Cache is a Cache that spans across multiple nodes;
  • In some cases, amount of data to be stored is too large to fit in the memory of a single machine;
  • In such cases, Distributed Cache internally splits/parititions your data and stores it across several nodes;

Functional Requirements

  • put(key, value)    -> It stores data in the cache;
  • get(key)           -> It retrieves data from the cache;
  • delete(key)        -> It is used to Invalidate/delete the data from the cache;

Non-Functional Requirements

  • Performance/Fast - Whole point of having a cache is for faster lookups; All reads/writes to cache should be very fast, with as much minimum latency as possible;
  • Highly Available - Data in the cache should be available, even in case of network/hardware failures; Otherwise, it will cause lot of load on source-of-truth data store;
  • Fault Tolenrant  - Solution should be fault tolerant;
  • Consistency      - We want our cache to be strongly consistent, not eventual consistency; For eg, whichever node you read from, you should get same data, for a given key;
  • Scalable         - Should be easily scalable, so that it handles ever increasing data;
  • Cost             - Minimum cost;

How it works?

  • First, let's think about a Local cache - A cache with limited memory available in a single node;
  • But, does it fullfil all your requirements?
    • It fullfils all functional requirements;
    • It is not highly available and fault-tolerant, as single node can go down at any point of time;
    • It serves the strong consistency requirement;
    • It is not horizontally scalable, with increasing load;
    • It is affordable;

  • How can we improve the Availability?
    • Approach #1 - Increase replicas;
      • Let's introduce more nodes, which are replicas of actual node;
      • It improves availability, but what about scalability? It's not easy to replicate entire data;

    • Approach #2 - Sharding;
      • Start with multiple nodes;
      • Split the whole data into multiple shards/partitions and store each partition in a separate node; How?
      • It makes the system scalable easily; But, what about availability?
      • If any of the nodes goes down, partitions stored in that system are not available; So, the system is still not highly available;
      • How can we improve availability? Solution is Data Replication!
      • Replication is all about having one or more replicas for each shard;
      • It makes the system highly available!

      • If strong consistency is a must requirement, use synchronous replication with master-slave replication;
