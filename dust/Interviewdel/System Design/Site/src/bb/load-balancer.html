What is Load Balancer?

  • Load balancing is the process of distributing the load across a group of servers, to make sure that no individual server is overloaded or underloaded;
  • Apart from distributing load uniformly, modern load balancers perform a continuous health check on all the servers to make sure they are healthy;
  • If the load balancer finds if a server is down or unhealthy, load balancer removes that server from the pool of servers until it is restored;

Advantages of the Load Balancer?

  • Availability - If a server goes down, load balancer will send the incoming requests to another server;
  • Improved Performance - It distributes the load evenly across all available servers, thus minimizing the response time and maximizing the throughput;
  • Improved Maintanance - If any of the server needs to updated/repaired, bring it down or remove it from list of servers;

Where to place Load Balancers in a system?

  • Between Clients and Application servers;
  • Between Application Servers and database servers;
  • Between Application Servers and Cache servers;

Load Balancing Algorithms

  • Round Robin Method
    • This method cycles through a list of servers and sends each new request to the next server;
    • When it reaches the end of the list, it starts over at the beginning;
    • It is most useful when the servers are of equal specification;
  • Weighted Round Robin Method
    • It is designed to better handle servers with different processing capacities;
    • Each server is assigned a weight (an integer value that indicates the processing capacity);
    • Servers with higher score receive more requests than others;
  • Least Connection Method
    • In this method, the request will be directed to the server with the fewest number of requests or active connections;
    • For this, load balancer needs to do some additional computing to identify the server with the least number of requests;
    • This may be a little bit costlier compared to the round-robin method but the evaluation is based on the current load on the server;
    • This algorithm is most useful when there is a huge number of requests, unevenly distributed between the servers;
  • Least Response Time Method
    • In this method, the request is forwarded to the server with least number of requests and lowest average response time;
  • IP Hash
    • In this method, load balancer uses a hash function to map the client's IP address to a serer;

Elastic Load Balancer

  • ECB automatically distributes the incoming traffic across multiple ec2 machines;
  • Each ELB will have a unique DNS, so that you can access the application using it;
  • When a new ec2 instance is added, load balancer automatically discovers the new ec2 instance and starts distributing traffic to it;
  • ELB also the tracks the health of the ec2 machines;
  • If any ec2 machine goes down, it stops sending requests that ec2 machine;
  • Similarly, ELB can distribute traffic across multiple pods and in this case, load balancer acts as ingress or service;
  • Even if your application is running lambda, ELB can distribute traffic to it as well;

  • What if your application should be exposed with a website that you already have, such as www.store.com?
    • But, ELB gives you it's own DNS, how do you solve the problem?
    • Solution is, use ELB with a DNS service such as Amazon Route 53;
    • So, when user access www.store.com, the request goes to Amazon Route 53;
    • From Route 53, using an alias, that request gets forwarded to the load balancer;

  • Elastic means as the traffic goes up, load balancer will also scale up; This part is managed by AWS; we don't have to do anything;

  • Is AWS ELB available all the time, with no downtime?
    • ELB is highly availabile out-of-the-box; Under the hood, it runs in multiple availabile zones;

Type of the Load Balancers

  • Application Load Balancer
    • It routes the requests based on the URL path;
    • All backends need not to be of the same type; It can route the traffic to different backends;
    • It supports ec2 instance, IP address, lamda, k8s pod as backends;
    • It can validate and terminate the SSL;
    • With ALB, you can scale each target group independantly, without impacting other groups;
  • Network Load Balancer
    • It routes the traffic based on the protocol and port of the incoming traffic;
    • All backends must be of same type; It can't route the traffic to different backends;
    • It supports ec2 instance, IP address, k8s pod as backends; It doesn't support Lambda;
    • It supports SSL passthrough - It means, it will not validate the SSL certificate; It just passes it to the backend server;
    • Newer versions of network load balancer support SSL termination as well;
  • When to use which one?
    • NLB handles spiky traffic better;
    • NLB exposes static IP; If you need static IP with ALB, use Global Accelerator;

Load Balancer VS Reverse Proxy

A reverse proxy accepts a request from a client, forwards it to a server that can fulfill it, and returns the server's response to the client. A load balancer distributes incoming client requests among a group of servers, in each case returning the response from the selected server to the appropriate client. AWS Application Load Balancer can be used as a reverse proxy, but it only supports static targets (fixed IP address), no dynamic targets (domain name).
