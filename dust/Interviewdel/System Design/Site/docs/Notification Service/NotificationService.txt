Problem Statement
	In the world of webservices, there are many scenarios when messages need to be sent as a reaction to some event;
	For eg, when a credit card transaction amount exceeds limit, card holder needs to be notified;
	When there are more number of API failures, on-call engineer needs to notified;


	Let's say there is a producer, which produces messages to a group of other components called subscribers;
	We could have setup a synchronous communication b/w publisher and subscribers, where publisher calls each subscriber in some order and waits for the response;
	But, this introduces many challenges: 
		It is hard to scale such system when number of subscribers and messages grow, hard to extend such solution to support different types of subscribers;

	Instead, we can introduce a new system that can register arbitary number of publishers and subscribers and coordinates message delivery b/w them;

	The problem statement is ambiguous, as usual;
	To make it less vague, we need to ask questions;
	We need to scope both functional and non-functional requirements;

Functional Requirements
	We need to define a set of operations the system will support;

	Requirements:
	create a topic
	publish(topic, message)
	subscribe(topic, endpint) 

	Topic represents a named resource to which messages are sent to; 
	You can think of it as a bucket that stores messages from a publisher and all subscribers receive a copy of the message from the bucket;
	
NonFunctional Requirements
	Scalable
	highly available
	highly performable
	durable - every subscribe must receive every message atleast once; no loss of messages;

1. Requirement
	Functional Requirements
		- Convert a long URL to short URL;
		- Redirect the users to long URL, when they access short URL;
		- Short URLs should expire after default timespan; Allow user to set custom expiry for a short URL;

	NonFunctional Requirements
		- System should be highly available. This is required because, if our service is down, all the URL redirections will start failing;
		- URL redirection should happen in real-time with minimal latency;

	Extended Requirements
		- Allow user to choose custom short URL for a long URL;
		- Expose API for generating short URL for a long URL;
		- Analytics, how many times a redirection happened?
