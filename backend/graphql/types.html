1. What is a Type?
  • GraphQL has a strong type system; Every field in a schema must declare its type;
  • It majorly supports 6 types:
    • Scalar Types
    • Object Types
    • Enum Types
    • Interface Types
    • Union Types
    • Input Object Types
  • It also a has couple of Type Modifiers:
    • Non-Null
    • List
2. What are Scalar Types?
# It represents primities;
| Type      | Description                           | Example    |
| --------- | ------------------------------------- | ---------- |
| `Int`     | 32-bit signed integer                 | 42         |
| `Float`   | Double precision number               | 3.14       |
| `String`  | UTF-8 text                            | "Hello"    |
| `Boolean` | true / false                          | true       |
| `ID`      | Unique identifier (string serialized) | "user_123" |


What is Custom Scalar?
    - It is a user-defined primitive type;
    - For eg, sometimes we need more specific datatypes like: DateTime, Email, URL, JSON, PhoneNumber;
    - This is where custom scalars can help;

    - In other words, A strongly-typed, validated primitive value defined by you instead of using generic String.

    - GraphQL allows you to define your own scalar types in the schema — and implement validation/serialization logic in your server;
    - Eg:
    # Wihtout custom scalar -> weakly typed 
    type User {
      email: String
      createdAt: String
    }

    # With custom scalar
    # Clients know exactly what type to expect and Server enforces validation - Stronger contracts;
    scalar Email
    scalar DateTime
    type User {
      email: Email!
      createdAt: DateTime!
    }

    # Implementating Custom Scalar in Apollo Server?
    # A custom scalar must define three behaviors:
    #     serialize → How server sends data to client
    #     parseValue → How client input is validated
    #     parseLiteral → How hard-coded query values are parsed
    
    #  
      const { GraphQLScalarType, Kind } = require('graphql');
      const DateTime = new GraphQLScalarType({
        name: 'DateTime',

        serialize(value) {
          if (!(value instanceof Date)) {
            throw new Error("Expected Date object");
          }
          return value.toISOString();
        },

        parseValue(value) {
          const date = new Date(value);
          if (isNaN(date.getTime())) {
            throw new Error("Invalid DateTime");
          }
          return date;
        },

        parseLiteral(ast) {
          if (ast.kind !== Kind.STRING) {
            throw new Error("DateTime must be a string");
          }
          return this.parseValue(ast.value);
        }
      });

  query: Query
  mutation: Mutation

# Every schema has at least a Query type.
type Query {
  users: [User!]!
  user(id: ID!): User

type Mutation {
  createUser(input: CreateUserInput!): User!

type User {

5. List Type and Type modifiers
| Type         | Meaning                           |
| ------------ | --------------------------------- |
| `String`     | Nullable string                   |
| `String!`    | Required string                   |
| `[String]`   | List of nullable strings          |    // List can be null, element can be null;
| `[String!]`  | List of required strings          |    // List can be null, no null element;
| `[String!]!` | Required list of required strings |    // List can't be null, no null element;
6. Enums
# Enum -> Restricted set of values;
enum Role {
  ADMIN
  USER
  GUEST
}
type User {
  role: Role!
}
7. Interfaces
# Interface -> Define shared fields across multiple types;
interface Node {
  id: ID!
}

type User implements Node {
  id: ID!
  name: String!
}

type Post implements Node {
  id: ID!
  title: String!
}
8. Union
# Union -> When a field can return multiple object types;
union SearchResult = User | Post

Example:
{
  search(text: "GraphQL") {
    ... on User {
      name
    }
    ... on Post {
      title
    }
  }
}
8. Input Types
# Input Types -> Used for arguments in mutations;
input CreateUserInput {
  name: String!
  email: String!
}

type Mutation {
  createUser(input: CreateUserInput!): User!
}

Why not reuse User?
    Because input types:
        Cannot have resolvers
        Cannot reference interfaces/unions
        Are strictly for input
9. Arguments in Fields
# Fields can accept arguments;
type Query {
  posts(limit: Int, offset: Int): [Post!]!
}

# Arguments can also have default values:
posts(limit: Int = 10): [Post!]!
10. Directives
# Directives -> Special instructions prefixed with @
# Built-in directives:
#       @include(if: Boolean)
#       @skip(if: Boolean)
#       @deprecated(reason: String)

Eg:
type User {
  oldField: String @deprecated(reason: "Use newField instead")
}

# You can also define custom directives.
10. Introspection
GraphQL schemas are self-documenting;
Clients can query the schema:
{
  __schema {
    types {
      name
    }
  }
}

This powers tools like: GraphQL Playground, Apollo Studio;
10. Schema Stitching & Federation
Large systems can split schemas:
    Schema Stitching → Combine multiple schemas
    Federation → Microservices share a unified graph
10. Resolver
# Schema -> It defines only structure of the data;
# Resolver -> It defines how to fetch the data;
Eg:
const resolvers = {
  Query: {
    user: (_, { id }) => db.users.find(id)
  }
}
13. Tip when designing a production-ready schema
  • Non-null where required
  • Using generic JSON scalars everywhere
  • Timestamps included
  • Relationships defined
  • Pagination built-in
  • Strong typing - Prevent runtime errors
  • Never return raw types directly in mutations;
  • Avoid exposing internal fields
  • Never expose passwords
  • Avoid overexposing nested relationships
  • Use role-based access in resolvers
  • Deprecation Strategy
Performance Considerations Design for: ✔ DataLoader batching Avoid N+1 problems. ✔ Query depth limiting Prevent malicious deep queries. ✔ Complexity analysis Score queries based on cost. ✔ Caching strategy Response caching Resolver-level caching CDN caching Federation (Microservices Ready) For large systems, split by domain: User service Post service Comment service Federation allows services to extend types: extend type User @key(fields: "id") { id: ID! @external posts: [Post!]! } Used heavily in distributed GraphQL architectures.
