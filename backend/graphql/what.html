1. What is GraphQL?
  • GraphQL is a query language that allows you to retrieve exactly data(no more, no less) that you want;
  • You can use it to get the data, modify data and delete data;
  • You can query not only databases, but also REST APIs, websockets, and other GraphQL APIs!

  • It is also called as a declarative data-fetching language;
  • It means that developers will state the data that they want and it doesn’t matter to them how it is done;
  • That is to say that GraphQL doesn’t care which language you set up the GraphQL server in;
  • GraphQL server libraries: C#/.NET (graphql-dotnet), Java (graphql-java), PHP (graphql-php), Python (graphene), JavaScript (apollo-server);
2. REST vs GraphQL
  • Self documented;
  • No overfetching(returning too much data), underfetching(require multiple requests to gather related data);
  • No need to manage API endpoints; GraphQL only requires a single API endpoint(/graphql) for all your queries (GET requests) and mutations(POST, PUT, and DELETE requests). This single endpoint acts as a portal and can orchestrate several data sources;
  • Strongly typed;

4. How it works?
  • Client sends a query describing the data it wants;
  •                     {
                        user(id: "1") {
                            name
                            email
                        }
                    }
  • server responds with JSON matching the requested structure;
  •                 {
                    "data": {
                        "user": {
                        "name": "Alice",
                        "email": "alice@example.com"
                        }
                    }
                }
  • All requests typically go to one endpoint;
When a client sends a request, GraphQL: Parses the query into an AST (Abstract Syntax Tree) Extracts variables (if any) Validates against schema Executes resolvers introspection query → Read mutation → Create/Update/Delete subscription → GraphQL supports real-time updates via subscriptions.
