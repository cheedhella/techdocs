1. The Problem Facebook Faced
  • Mobile App Challenges (2012)
    • Slow network connections on mobile devices;
    • Multiple REST endpoints required many round trips;
    • Over-fetching wasted bandwidth;
    • Under-fetching required additional requests;
  • News Feed Complexity
    • News feed needed data from many sources;
    • Different views needed different data shapes;
    • REST endpoints became numerous and complex;
2. REST API Limitations
  • Over-Fetching
    • Endpoints return all fields, even if not needed;
    • Wastes bandwidth, especially on mobile;
    • Example: GET /users returns 20 fields, need only 3;
  • Under-Fetching
    • One endpoint doesn't provide all needed data;
    • Requires multiple requests;
    • Example: Get user, then get their posts, then comments;
  • Versioning Complexity
    • API changes require new versions (/v1/, /v2/);
    • Multiple versions to maintain;
    • Clients stuck on old versions;
  • Frontend-Backend Coupling
    • Backend defines what data frontend gets;
    • New UI requirements need backend changes;
    • Slows down development;
3. GraphQL's Solutions
  • Precise Data Fetching
    • Client specifies exactly what fields needed;
    • No over-fetching or under-fetching;
    • Single request for all related data;
  • No Versioning Needed
    • Add new fields without breaking existing queries;
    • Deprecate old fields gradually;
    • Clients request only what they understand;
  • Frontend Empowerment
    • Frontend developers query what they need;
    • Less backend changes for UI updates;
    • Faster iteration;
  • Strong Typing
    • Schema provides clear API contract;
    • Validation at query time;
    • Better tooling and documentation;
4. Evolution and Adoption
  • 2012 - Facebook creates GraphQL for internal use;
  • 2015 - Open-sourced and specification released;
  • 2016+ - Rapid adoption by GitHub, Twitter, Shopify;
  • Today - Industry standard for modern APIs;
