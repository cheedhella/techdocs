1. JWT (JSON Web Tokens)
  • How It Works
    • User logs in with credentials;
    • Server generates signed JWT;
    • Client stores JWT (localStorage, cookie);
    • Client sends JWT in Authorization header;
  • JWT Structure
    • Header: algorithm, type;
    • Payload: user info, roles, expiry;
    • Signature: verifies authenticity;
  • Advantages
    • Stateless - no server-side session;
    • Scalable - works across multiple servers;
    • Self-contained - includes user info;
2. OAuth 2.0
  • What It Is
    • Authorization framework;
    • Delegate authentication to providers (Google, GitHub);
    • User grants permissions to your app;
  • Flow
    • User clicks "Login with Google";
    • Redirected to Google login;
    • User authorizes your app;
    • Google returns access token;
    • Your app uses token to access user info;
  • Benefits
    • No password management;
    • Trusted authentication;
    • Single sign-on;
3. Implementation with GraphQL
  • Login Mutation
    • mutation { login(email: "...", password: "...") { token, user { id, name } } };
    • Verify credentials;
    • Generate and return JWT;
  • Token Verification
    • Extract token from Authorization header;
    • Verify signature;
    • Decode payload;
    • Add user to context;
  • Protected Queries
    • Use @auth directive or check context.user;
    • Return error if not authenticated;
4. Security Best Practices
  • Use HTTPS - Always encrypt in transit;
  • Short Expiry - JWT should expire (15min-1hr);
  • Refresh Tokens - Long-lived tokens for getting new JWTs;
  • Secure Storage - HttpOnly cookies or secure storage;
  • Validate Everything - Check signature, expiry, issuer;
