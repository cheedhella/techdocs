1. Why Limit Queries?
  • Security Concerns
    • Malicious users can craft expensive queries;
    • Deeply nested or wide queries can DoS server;
    • Need protection against abuse;
  • Performance Protection
    • Some queries are legitimately expensive;
    • Prevent accidental server overload;
    • Maintain quality of service;
2. Query Depth Limiting
  • What It Is
    • Limits how many levels deep a query can go;
    • { user { friends { friends { friends } } } } - depth 4;
  • Implementation
    • Use graphql-depth-limit package;
    • Set maximum depth (e.g., 5-7 levels);
    • Reject queries exceeding limit;
  • Considerations
    • Too strict limits break legitimate queries;
    • Too loose allows expensive queries;
    • Balance based on your data model;
3. Query Complexity Analysis
  • What It Is
    • Assigns cost to each field in query;
    • Calculates total cost;
    • Rejects if exceeds maximum;
  • Cost Calculation
    • Scalar field: cost 1;
    • Object field: cost of nested fields;
    • List field: multiplier based on limit;
  • Implementation
    • Use graphql-query-complexity package;
    • Define cost per field type;
    • Set maximum complexity;
4. Other Protection Strategies
  • Pagination Requirements
    • Force pagination on list fields;
    • Require first/limit argument;
    • Prevent unbounded lists;
  • Timeout Limits
    • Set maximum query execution time;
    • Kill queries that run too long;
  • Rate Limiting
    • Limit requests per user/IP;
    • Prevent abuse;
  • Query Whitelisting
    • Only allow pre-approved queries;
    • Used with persisted queries;
    • Maximum security;
