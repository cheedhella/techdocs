1. What Is Cypher Injection?
  • Definition
    • Attack where malicious Cypher code is injected;
    • Similar to SQL injection;
    • Can read, modify, or delete data;
  • Example Attack
    • Input: "123") MATCH (u:User) DETACH DELETE u //";
    • Unsafe query: `MATCH (u:User {id: "${input}"}) RETURN u`;
    • Result: Deletes all users;
2. Prevention with Parameterized Queries
  • Always Use Parameters
    • session.run('MATCH (u:User {id: $id}) RETURN u', {id: userInput});
    • Driver handles escaping;
    • Input treated as data, not code;
  • Neo4j GraphQL Library
    • Automatically uses parameters;
    • No injection risk with auto-generated queries;
    • Safe by default;
3. Risks with @cypher Directive
  • Dynamic Cypher
    • @cypher with user input can be vulnerable;
    • Never concatenate user input;
    • Use $argumentName for parameters;
  • Safe Example
    • @cypher(statement: "MATCH (u:User {name: $name}) RETURN u");
    • $name is safely parameterized;
  • Unsafe Example
    • Don't build Cypher strings in resolvers;
    • Don't use template literals with user input;
4. Additional Safeguards
  • Input Validation
    • Validate format before using;
    • Whitelist allowed characters;
    • Reject suspicious input;
  • Least Privilege
    • Database user should have minimal permissions;
    • Read-only for read operations;
    • Limit what injection can do;
  • Code Review
    • Review all custom Cypher;
    • Look for string concatenation;
    • Ensure parameters used correctly;
