1. Auto-Generated Resolvers
  • What They Do
    • Neo4j GraphQL Library creates resolvers automatically;
    • Handle CRUD operations, filtering, pagination;
    • Traverse relationships;
  • Advantages
    • Zero code required;
    • Optimized Cypher generation;
    • Consistent behavior;
    • Faster development;
  • Limitations
    • Limited to what library supports;
    • Can't add custom business logic;
    • May not fit all use cases;
2. Custom Resolvers
  • When to Use
    • Complex business logic;
    • Integration with external services;
    • Custom validation;
    • Performance optimizations;
  • Implementation
    • Define resolver functions;
    • Pass to Neo4jGraphQL constructor;
    • Access driver via context;
  • Example Use Cases
    • Send email after user creation;
    • Calculate complex derived fields;
    • Call external APIs;
    • Custom authentication logic;
3. Mixing Both Approaches
  • Best Practice
    • Use auto-generated for standard operations;
    • Add custom resolvers where needed;
    • Override specific fields/operations;
  • Example Pattern
    • Auto-generated: users query, createUsers mutation;
    • Custom: login mutation, sendPasswordReset mutation;
    • Hybrid: users query with custom computed field;
4. Decision Guide
  • Use Auto-Generated When:
    • Simple CRUD operations;
    • Standard filtering and pagination;
    • Direct graph traversals;
    • No external dependencies;
  • Use Custom When:
    • Need side effects (emails, logs, webhooks);
    • Complex validation rules;
    • Integration with other systems;
    • Performance-critical paths;
    • Business logic that doesn't fit in @cypher;
