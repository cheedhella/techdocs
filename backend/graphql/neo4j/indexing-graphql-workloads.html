1. Why Index for GraphQL?
  • GraphQL Query Patterns
    • Often start with specific node lookup (user(id: "123"));
    • Filter by properties (users(where: {email: "..."}));
    • Need fast starting points for traversals;
  • Without Indexes
    • Neo4j scans all nodes with label;
    • Slow for large datasets;
    • Poor user experience;
2. Essential Indexes
  • ID Fields
    • CREATE CONSTRAINT FOR (u:User) REQUIRE u.id IS UNIQUE;
    • Most common lookup pattern;
    • Constraint automatically creates index;
  • Unique Fields
    • Email, username, external IDs;
    • Used for authentication and lookups;
    • CREATE CONSTRAINT FOR (u:User) REQUIRE u.email IS UNIQUE;
  • Frequently Filtered Fields
    • Status, type, category fields;
    • CREATE INDEX FOR (p:Post) ON (p.status);
3. Index Strategy
  • Analyze Query Patterns
    • Look at WHERE clauses in GraphQL queries;
    • Identify commonly filtered properties;
    • Index those properties;
  • Composite Indexes
    • For queries filtering on multiple properties;
    • CREATE INDEX FOR (u:User) ON (u.lastName, u.firstName);
    • Order matters - most selective first;
  • Full-Text Search
    • For text search functionality;
    • CREATE FULLTEXT INDEX searchPosts FOR (p:Post) ON EACH [p.title, p.content];
4. Index Maintenance
  • Monitor Performance
    • Use PROFILE to check if indexes are used;
    • Look for NodeIndexSeek in query plans;
  • Don't Over-Index
    • Indexes have overhead on writes;
    • Only index frequently queried properties;
    • Remove unused indexes;
  • Update Statistics
    • Neo4j maintains statistics automatically;
    • Can manually trigger: CALL db.stats.retrieve();
