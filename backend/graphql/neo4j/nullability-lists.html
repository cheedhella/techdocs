1. Nullability
  • Nullable by Default
    • Fields can return null unless marked with !;
    • name: String - can return string or null;
    • name: String! - must return string, never null;
  • Why Nullable?
    • Flexibility - partial failures don't break entire query;
    • Optional fields - not all data always available;
    • Backwards compatibility - can add fields without breaking clients;
  • Best Practices
    • Use ! for required fields (id, createdAt);
    • Keep nullable for optional fields (middleName, bio);
    • Consider client expectations;
2. Lists
  • List Syntax
    • [String] - nullable list of nullable strings;
    • [String]! - non-null list of nullable strings;
    • [String!] - nullable list of non-null strings;
    • [String!]! - non-null list of non-null strings;
  • Examples
    • tags: [String] - can be null, or array with null items;
    • tags: [String]! - must be array (can be empty), items can be null;
    • tags: [String!]! - must be array, all items must be strings;
3. Combining Nullability and Lists
  • Common Patterns
    • posts: [Post!]! - always return array, never null posts;
    • friends: [User] - can be null if not loaded;
    • emails: [String!] - nullable array, but if present, no null emails;
  • Error Handling
    • If non-null field fails, parent becomes null;
    • Can cascade up to nearest nullable field;
    • Design schema to contain failures;
