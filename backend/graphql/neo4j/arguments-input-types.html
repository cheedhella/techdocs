1. Field Arguments
  • Purpose
    • Pass parameters to fields for filtering, sorting, pagination;
    • Make queries flexible and dynamic;
  • Example
    • type Query { users(limit: Int, role: String): [User] }
    • Query: { users(limit: 10, role: "admin") { name } }
  • Common Patterns
    • Pagination: limit, offset, first, after;
    • Filtering: where, filter;
    • Sorting: orderBy, sortBy;
2. Input Types
  • Definition
    • Special object types used as arguments;
    • Defined with 'input' keyword instead of 'type';
    • Can only contain scalar fields and other input types;
  • Example
    • input CreateUserInput { name: String!, email: String!, age: Int }
    • mutation { createUser(input: CreateUserInput): User }
  • Why Use Input Types?
    • Group related arguments together;
    • Reusable across multiple mutations;
    • Cleaner, more maintainable schema;
3. Default Values and Validation
  • Default Values
    • users(limit: Int = 10): [User];
    • If no argument provided, use default;
  • Required Arguments
    • user(id: ID!): User;
    • Exclamation mark makes argument mandatory;
  • Custom Validation
    • Implement in resolvers;
    • Check business rules, constraints;
    • Return meaningful error messages;
