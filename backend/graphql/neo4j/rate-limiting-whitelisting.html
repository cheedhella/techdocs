1. Rate Limiting
  • What It Is
    • Limit number of requests per time period;
    • Prevents abuse and DoS attacks;
    • Ensures fair resource usage;
  • Strategies
    • Per IP address - limit anonymous users;
    • Per user - limit authenticated users;
    • Per API key - for third-party integrations;
    • Sliding window or token bucket algorithms;
  • Implementation
    • Use middleware (express-rate-limit);
    • Redis for distributed rate limiting;
    • Return 429 Too Many Requests;
2. Query Whitelisting
  • What It Is
    • Only allow pre-approved queries;
    • Reject any query not on whitelist;
    • Maximum security;
  • How It Works
    • Client sends query ID instead of full query;
    • Server looks up query from approved list;
    • Executes only if found;
  • Benefits
    • Prevents malicious queries;
    • Smaller request size;
    • Can optimize approved queries;
3. Persisted Queries
  • Automatic Persisted Queries (APQ)
    • Client sends query hash;
    • Server caches query by hash;
    • Subsequent requests use hash only;
  • Build-Time Persisted Queries
    • Extract queries during build;
    • Generate query IDs;
    • Server only accepts these IDs;
    • True whitelisting;
  • Tools
    • Apollo Client - built-in APQ support;
    • graphql-persisted-queries;
    • Relay - built-in persisted queries;
4. Combining Strategies
  • Layered Security
    • Rate limiting + query complexity limits;
    • Whitelisting for production;
    • Allow arbitrary queries in development;
  • Different Limits for Different Users
    • Higher limits for authenticated users;
    • Premium users get even higher limits;
    • Admins bypass limits;
