1. @id Directive
  • Purpose
    • Marks field as unique identifier;
    • Auto-generates value if not provided;
    • Creates uniqueness constraint in Neo4j;
  • Usage
    • type User { id: ID! @id };
    • Generates UUID by default;
  • Custom ID Generation
    • @id(autogenerate: false) - provide your own IDs;
    • Useful for external IDs or custom schemes;
2. @unique Directive
  • Purpose
    • Ensures field value is unique across all nodes;
    • Creates uniqueness constraint in Neo4j;
    • Prevents duplicate values;
  • Usage
    • type User { email: String! @unique };
    • No two users can have same email;
  • Common Use Cases
    • Email addresses;
    • Usernames;
    • External IDs;
    • SKUs, serial numbers;
3. @timestamp Directive
  • Purpose
    • Auto-populates field with current timestamp;
    • Tracks creation and update times;
  • Usage
    • type User { createdAt: DateTime! @timestamp(operations: [CREATE]) };
    • type User { updatedAt: DateTime! @timestamp(operations: [UPDATE]) };
  • Operations
    • CREATE - set on node creation;
    • UPDATE - update on node modification;
    • [CREATE, UPDATE] - both;
4. Combining Directives
  • Example Schema
    • type User {
    • id: ID! @id
    • email: String! @unique
    • createdAt: DateTime! @timestamp(operations: [CREATE])
    • updatedAt: DateTime! @timestamp(operations: [UPDATE])
    • }
  • Benefits
    • Declarative constraints;
    • No manual implementation needed;
    • Database-level enforcement;
    • Consistent behavior across API;
