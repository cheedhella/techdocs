1. What Is the N+1 Problem?
  • Definition
    • Making N additional queries for N items;
    • 1 query to get list + N queries for related data;
    • Common performance issue in GraphQL;
  • Example
    • Query: { users { name, posts { title } } };
    • Bad: 1 query for users, then 1 query per user for posts;
    • 10 users = 11 queries total;
2. How Neo4j GraphQL Library Solves It
  • Automatic Query Optimization
    • Library generates single Cypher query;
    • Traverses relationships in one database operation;
    • No N+1 problem with auto-generated resolvers;
  • Example
    • GraphQL: { users { name, posts { title } } };
    • Cypher: MATCH (u:User) OPTIONAL MATCH (u)-[:POSTED]->(p:Post) RETURN u, collect(p);
    • Single query, no matter how many users;
3. N+1 in Custom Resolvers
  • The Problem
    • Custom resolvers can reintroduce N+1;
    • If resolver makes database query per item;
    • Need batching solution;
  • DataLoader Solution
    • Batches multiple requests into one;
    • Caches results within single request;
    • Standard solution for GraphQL N+1;
  • Implementation
    • Create DataLoader instance per request;
    • Pass in context;
    • Use in resolvers instead of direct queries;
4. Best Practices
  • Use Auto-Generated Resolvers
    • They handle batching automatically;
    • No N+1 problem;
  • For Custom Resolvers
    • Always use DataLoader or similar batching;
    • Never query database in loop;
  • Monitor Queries
    • Log Cypher queries in development;
    • Check for repeated similar queries;
    • Profile performance;
  • Use @cypher for Complex Cases
    • Single Cypher query for complex logic;
    • Better than multiple resolver calls;
