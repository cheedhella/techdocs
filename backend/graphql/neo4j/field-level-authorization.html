1. What Is Field-Level Authorization?
  • Definition
    • Control access to individual fields, not just types;
    • Some fields visible to some users;
    • Fine-grained access control;
  • Use Cases
    • Hide sensitive fields (email, phone) from non-owners;
    • Admin-only fields (internal notes, flags);
    • Role-based field visibility;
2. Implementation
  • Using @auth on Fields
    • type User {
    • id: ID!
    • name: String!
    • email: String! @auth(rules: [{allow: {id: "$jwt.sub"}}])
    • };
    • Email only visible to owner;
  • Role-Based Field Access
    • internalNotes: String @auth(rules: [{roles: ["admin"]}]);
    • Only admins can see this field;
3. Patterns
  • Public vs Private Fields
    • Public: name, avatar - no @auth;
    • Private: email, phone - @auth with owner check;
  • Computed Field Authorization
    • Check permissions in @cypher directive;
    • Return null if unauthorized;
  • Relationship Authorization
    • Control who can see relationships;
    • friends: [User] @auth(rules: [{allow: {id: "$jwt.sub"}}]);
4. Best Practices
  • Default Deny - Make fields private by default, explicitly allow access;
  • Consistent Rules - Use same patterns across schema;
  • Test Thoroughly - Verify unauthorized users can't access fields;
  • Document Permissions - Clear which fields require which permissions;
