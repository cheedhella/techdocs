1. Relationships as Fields
  • Basic Pattern
    • Neo4j relationships become GraphQL fields;
    • Neo4j: (u:User)-[:POSTED]->(p:Post);
    • GraphQL: type User { posts: [Post] };
  • Naming Conventions
    • Use descriptive field names (posts, author, friends);
    • Singular for one-to-one (profile, company);
    • Plural for one-to-many (posts, comments);
2. Relationship Properties
  • Edge Types
    • Create separate types for relationships with properties;
    • Neo4j: (u)-[:FRIENDS_WITH {since: 2020}]->(f);
    • GraphQL: type Friendship { since: DateTime!, friend: User! };
    • GraphQL: type User { friendships: [Friendship] };
  • When to Use Edge Types
    • Relationship has meaningful properties;
    • Need to query or filter by relationship data;
    • Example: ratings, timestamps, weights;
3. Directionality
  • Neo4j Relationships Are Directed
    • But can be traversed in either direction;
    • (a)-[:KNOWS]->(b) - a knows b;
  • GraphQL Hides Direction
    • type User { friends: [User] };
    • Resolver determines which direction to traverse;
    • Can expose both directions if needed;
  • Bidirectional Access
    • type User { posts: [Post] };
    • type Post { author: User };
    • Same relationship, accessed from both sides;
4. Using @relationship Directive
  • Neo4j GraphQL Library
    • type User { posts: [Post] @relationship(type: "POSTED", direction: OUT) };
    • Explicitly maps GraphQL field to Neo4j relationship;
  • Benefits
    • Auto-generates resolvers;
    • Handles filtering, sorting, pagination;
    • Reduces boilerplate code;
