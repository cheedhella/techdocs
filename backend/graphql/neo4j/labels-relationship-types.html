1. Node Labels
  • Purpose
    • Categorize nodes into groups or types;
    • Enable efficient queries by filtering on labels;
    • Similar to table names in relational databases;
  • Examples
    • :Person, :Product, :Company, :City;
    • Convention: PascalCase, singular form;
  • Multiple Labels
    • A node can have multiple labels;
    • Example: :Person:Customer:VIP;
    • Useful for inheritance-like patterns;
2. Relationship Types
  • Purpose
    • Define the nature of connection between nodes;
    • Every relationship must have exactly one type;
    • Makes queries semantic and readable;
  • Examples
    • :FRIENDS_WITH, :WORKS_FOR, :PURCHASED, :LOCATED_IN;
    • Convention: UPPER_CASE with underscores;
    • Use verb or preposition to describe relationship;
  • Best Practices
    • Be specific - :MANAGES vs :WORKS_FOR;
    • Use consistent naming conventions;
    • Avoid generic types like :RELATED_TO;
3. Using Labels and Types in Queries
  • Filter by Label
    • MATCH (p:Person) RETURN p;
    • Find all Person nodes;
  • Filter by Relationship Type
    • MATCH (p:Person)-[:FRIENDS_WITH]->(friend) RETURN friend;
    • Find all friends of Person nodes;
  • Performance Benefits
    • Labels and types enable index usage;
    • Narrow search space for faster queries;
    • Essential for large graphs;
