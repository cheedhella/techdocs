1. Direct Type-to-Label Mapping
  • Basic Pattern
    • Each GraphQL type corresponds to a Neo4j label;
    • GraphQL: type User { id: ID!, name: String! };
    • Neo4j: (u:User {id: "123", name: "Alice"});
  • Conventions
    • Use same names for consistency;
    • GraphQL type = Neo4j label (PascalCase);
    • Makes code easier to understand and maintain;
2. Property Mapping
  • Scalar Fields
    • GraphQL scalars map to Neo4j property types;
    • String → String, Int → Integer, Boolean → Boolean;
    • ID → String (typically);
  • Custom Scalars
    • DateTime → Neo4j DateTime;
    • JSON → String (serialized);
    • Define custom scalar resolvers;
  • Computed Fields
    • GraphQL: fullName: String;
    • Not stored in Neo4j, computed from firstName + lastName;
    • Resolved in application layer;
3. Handling Multiple Labels
  • GraphQL Interfaces
    • interface Node { id: ID! };
    • type User implements Node { id: ID!, name: String! };
    • Neo4j: (u:Node:User {id: "123", name: "Alice"});
  • Union Types
    • union SearchResult = User | Post | Comment;
    • Query multiple node types at once;
    • Use __typename to distinguish;
4. ID Management
  • Best Practices
    • Always have an id field in GraphQL types;
    • Use UUID or unique constraint in Neo4j;
    • Consider using Neo4j's internal ID cautiously (can be reused);
  • Example
    • GraphQL: type User { id: ID! @id };
    • Neo4j: CREATE CONSTRAINT FOR (u:User) REQUIRE u.id IS UNIQUE;
