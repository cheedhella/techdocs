1. Queries
  • Purpose
    • Read operations - fetch data from the server;
    • Similar to GET requests in REST;
  • Example
    • query { user(id: "123") { name, email, posts { title } } }
    • Fetch user with nested posts in one request;
  • Features
    • Can fetch multiple resources in one query;
    • Specify exactly which fields to return;
    • Support arguments for filtering and pagination;
2. Mutations
  • Purpose
    • Write operations - create, update, delete data;
    • Similar to POST, PUT, DELETE in REST;
  • Example
    • mutation { createUser(name: "Alice", email: "alice@example.com") { id, name } }
    • Create user and return specific fields;
  • Characteristics
    • Execute sequentially (queries run in parallel);
    • Return the modified data;
    • Can perform multiple operations in one request;
3. Subscriptions
  • Purpose
    • Real-time updates - push data to clients;
    • Uses WebSocket for persistent connection;
  • Example
    • subscription { messageAdded { id, content, author { name } } }
    • Client receives updates when new messages are added;
  • Use Cases
    • Chat applications;
    • Live notifications;
    • Real-time dashboards;
    • Collaborative editing;
