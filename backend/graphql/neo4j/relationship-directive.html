1. What Is @relationship?
  • Purpose
    • Maps GraphQL fields to Neo4j relationships;
    • Specifies relationship type and direction;
    • Enables auto-generated relationship queries;
  • Syntax
    • @relationship(type: "RELATIONSHIP_TYPE", direction: OUT|IN|OUT_IN);
2. Basic Usage
  • Outgoing Relationship
    • type User { posts: [Post] @relationship(type: "POSTED", direction: OUT) };
    • (User)-[:POSTED]->(Post);
  • Incoming Relationship
    • type Post { author: User @relationship(type: "POSTED", direction: IN) };
    • (User)-[:POSTED]->(Post), queried from Post side;
  • Bidirectional
    • type User { friends: [User] @relationship(type: "FRIENDS_WITH", direction: OUT_IN) };
    • Matches relationships in either direction;
3. Relationship Properties
  • Edge Types
    • type User { actedIn: [Movie] @relationship(type: "ACTED_IN", direction: OUT, properties: "ActedIn") };
    • interface ActedIn @relationshipProperties { role: String!, year: Int };
  • Querying Properties
    • query { users { actedInConnection { edges { role, node { title } } } } };
    • Access relationship properties via Connection API;
4. Advanced Features
  • Filtering on Relationships
    • query { users { posts(where: {title_CONTAINS: "GraphQL"}) { title } } };
    • Filter related nodes;
  • Nested Mutations
    • mutation { createUsers(input: [{name: "Alice", posts: {create: [{title: "Hello"}]}}]) { users { name } } };
    • Create nodes and relationships in one operation;
  • Connect/Disconnect
    • mutation { updateUsers(where: {id: "123"}, connect: {posts: {where: {id: "456"}}}) { users { name } } };
    • Manage relationships without recreating nodes;
