1. Authentication vs Authorization
  • Authentication
    • Verifying who the user is;
    • Login, JWT tokens, sessions;
    • "Are you who you say you are?";
  • Authorization
    • Determining what user can access;
    • Permissions, roles, access control;
    • "Are you allowed to do this?";
2. Authentication Strategies
  • JWT (JSON Web Tokens)
    • Most common for GraphQL APIs;
    • Stateless, self-contained;
    • Passed in Authorization header;
  • Implementation
    • User logs in, receives JWT;
    • Client includes JWT in subsequent requests;
    • Server verifies JWT signature;
    • Extract user info from token;
  • Context Setup
    • Parse JWT in Apollo Server context function;
    • Add user info to context;
    • Available in all resolvers;
3. Authorization with @auth Directive
  • Neo4j GraphQL @auth
    • Declarative authorization in schema;
    • Rules defined at type or field level;
    • Automatically enforced;
  • Basic Example
    • type User @auth(rules: [{operations: [READ], allow: {id: "$jwt.sub"}}]) {
    • id: ID!
    • email: String!
    • };
    • Users can only read their own data;
  • Operations
    • READ, CREATE, UPDATE, DELETE;
    • Apply rules to specific operations;
4. Common Patterns
  • Public vs Private
    • Public: No @auth, anyone can access;
    • Private: @auth(rules: [{isAuthenticated: true}]);
  • Owner-Based
    • @auth(rules: [{allow: {owner: "$jwt.sub"}}]);
    • User can only access their own resources;
  • Role-Based
    • @auth(rules: [{roles: ["admin"]}]);
    • Only users with admin role can access;
  • Field-Level
    • type User { email: String! @auth(rules: [{allow: {id: "$jwt.sub"}}]) };
    • Protect sensitive fields;
