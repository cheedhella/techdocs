1. What Is Query Planning?
  • Definition
    • Process of determining how to execute a Cypher query;
    • Neo4j creates execution plan before running query;
    • Chooses optimal path through graph;
  • Why It Matters
    • Different plans have vastly different performance;
    • Understanding plans helps optimize queries;
    • Identify bottlenecks and missing indexes;
2. EXPLAIN and PROFILE
  • EXPLAIN
    • EXPLAIN MATCH (u:User) RETURN u;
    • Shows execution plan without running query;
    • No actual data retrieved;
  • PROFILE
    • PROFILE MATCH (u:User) RETURN u;
    • Runs query and shows actual execution statistics;
    • Includes row counts, database hits;
    • More accurate than EXPLAIN;
3. Reading Query Plans
  • Key Metrics
    • Rows - number of rows processed;
    • DB Hits - database operations performed;
    • Estimated Rows - planner's estimate;
  • Common Operators
    • NodeByLabelScan - scan all nodes with label;
    • NodeIndexSeek - use index to find nodes;
    • Expand - traverse relationships;
    • Filter - apply WHERE conditions;
  • What to Look For
    • High DB hits - potential performance issue;
    • Label scans instead of index seeks - missing index;
    • Large row counts early in plan - inefficient starting point;
4. Optimization Tips
  • Start with Indexed Properties
    • Use indexed fields in WHERE clauses;
    • Narrow search space early;
  • Filter Early
    • Apply filters before expansions;
    • Reduce rows to traverse;
  • Use LIMIT
    • Stop processing once enough results found;
    • Especially important for large graphs;
  • Avoid Cartesian Products
    • Connect all patterns in MATCH;
    • Unconnected patterns multiply row counts;
