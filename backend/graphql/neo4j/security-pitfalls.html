1. Common Vulnerabilities
  • Introspection in Production
    • Exposes entire schema to attackers;
    • Disable in production or restrict to authenticated users;
  • No Query Limits
    • Allows expensive, deeply nested queries;
    • Can DoS your server;
    • Implement depth and complexity limits;
  • Missing Authorization
    • Forgetting @auth on sensitive types/fields;
    • Data leaks;
    • Audit all types and fields;
2. Injection Attacks
  • Cypher Injection
    • Similar to SQL injection;
    • Never concatenate user input into Cypher;
    • Always use parameterized queries;
  • Safe
    • session.run('MATCH (u:User {id: $id}) RETURN u', {id: userId});
  • Unsafe
    • session.run(`MATCH (u:User {id: "${userId}"}) RETURN u`);
    • Vulnerable to injection;
3. Information Disclosure
  • Verbose Error Messages
    • Don't expose stack traces in production;
    • Don't reveal database structure;
    • Return generic errors to clients;
  • Timing Attacks
    • Different response times reveal information;
    • Example: "user not found" vs "wrong password";
    • Use constant-time comparisons;
4. Mitigation Strategies
  • Input Validation - Validate all user input;
  • Rate Limiting - Limit requests per user/IP;
  • Query Whitelisting - Only allow approved queries;
  • HTTPS Only - Encrypt all traffic;
  • Security Audits - Regular security reviews;
  • Monitoring - Log and alert on suspicious activity;
