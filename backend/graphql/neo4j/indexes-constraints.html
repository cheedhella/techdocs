1. Why Indexes?
  • Performance
    • Speed up queries that filter by properties;
    • Without indexes, Neo4j scans all nodes;
    • Essential for large graphs;
  • When to Use
    • Properties frequently used in WHERE clauses;
    • Properties used for lookups (id, email, username);
    • Starting points for graph traversals;
2. Creating Indexes
  • Single Property Index
    • CREATE INDEX FOR (u:User) ON (u.email);
    • Speeds up queries filtering by email;
  • Composite Index
    • CREATE INDEX FOR (u:User) ON (u.firstName, u.lastName);
    • Index on multiple properties;
  • Full-Text Index
    • CREATE FULLTEXT INDEX userSearch FOR (u:User) ON EACH [u.name, u.bio];
    • Enables text search capabilities;
3. Constraints
  • Uniqueness Constraint
    • CREATE CONSTRAINT FOR (u:User) REQUIRE u.email IS UNIQUE;
    • Ensures no duplicate emails;
    • Automatically creates an index;
  • Existence Constraint
    • CREATE CONSTRAINT FOR (u:User) REQUIRE u.name IS NOT NULL;
    • Ensures property always exists (Enterprise only);
  • Node Key
    • CREATE CONSTRAINT FOR (u:User) REQUIRE (u.id, u.email) IS NODE KEY;
    • Combination must be unique and exist (Enterprise only);
4. Managing Indexes and Constraints
  • List All
    • SHOW INDEXES;
    • SHOW CONSTRAINTS;
  • Drop Index
    • DROP INDEX index_name;
  • Drop Constraint
    • DROP CONSTRAINT constraint_name;
