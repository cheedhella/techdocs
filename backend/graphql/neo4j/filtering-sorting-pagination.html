1. Filtering
  • Basic Filters
    • users(where: {name: "Alice"}) - exact match;
    • users(where: {age: 25}) - numeric equality;
  • String Operators
    • name_CONTAINS: "ali" - substring match;
    • name_STARTS_WITH: "A" - prefix match;
    • name_ENDS_WITH: "e" - suffix match;
    • name_IN: ["Alice", "Bob"] - one of list;
  • Numeric Operators
    • age_GT: 18 - greater than;
    • age_GTE: 18 - greater than or equal;
    • age_LT: 65 - less than;
    • age_LTE: 65 - less than or equal;
  • Logical Operators
    • AND: [{age_GT: 18}, {age_LT: 65}] - both conditions;
    • OR: [{name: "Alice"}, {name: "Bob"}] - either condition;
    • NOT: {age: 25} - negation;
2. Sorting
  • Single Field
    • users(options: {sort: [{name: ASC}]}) - ascending;
    • users(options: {sort: [{age: DESC}]}) - descending;
  • Multiple Fields
    • users(options: {sort: [{lastName: ASC}, {firstName: ASC}]});
    • Sort by last name, then first name;
  • Sorting Related Data
    • users { posts(options: {sort: [{createdAt: DESC}]}) { title } };
    • Sort nested data;
3. Pagination
  • Offset-Based
    • users(options: {limit: 10, offset: 20});
    • Skip 20, return next 10;
    • Simple but has issues with data changes;
  • Cursor-Based (Relay)
    • users(first: 10, after: "cursor");
    • More stable for changing data;
    • Returns edges with cursor and node;
  • Connection Pattern
    • usersConnection { edges { cursor, node { name } }, pageInfo { hasNextPage } };
    • Full pagination metadata;
4. Combining All Three
  • Example Query
    • query {
    • users(
    • where: {age_GT: 18, name_CONTAINS: "a"},
    • options: {sort: [{name: ASC}], limit: 10, offset: 0}
    • ) { id, name, age }
    • };
  • Use Cases
    • Search results with filters;
    • Data tables with sorting and pagination;
    • Infinite scroll feeds;
