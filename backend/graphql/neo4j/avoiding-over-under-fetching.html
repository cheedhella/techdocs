1. The Problem
  • Over-Fetching
    • Getting more data than needed;
    • REST: GET /users returns all user fields;
    • Wastes bandwidth, slows down responses;
  • Under-Fetching
    • Not getting enough data in one request;
    • Need multiple API calls to get related data;
    • N+1 problem: one call for list, then one per item;
2. How GraphQL Solves This
  • Precise Field Selection
    • Client specifies exactly which fields to return;
    • { user { name, email } } - only name and email;
    • No over-fetching;
  • Nested Queries
    • Get related data in one request;
    • { user { name, posts { title, comments { text } } } };
    • No under-fetching, no multiple round trips;
3. Neo4j + GraphQL Benefits
  • Efficient Traversals
    • Neo4j follows relationships without JOINs;
    • GraphQL query maps directly to Cypher traversal;
    • One database query for nested GraphQL query;
  • Example
    • GraphQL: { user(id: "123") { name, posts { title } } };
    • Cypher: MATCH (u:User {id: "123"})-[:POSTED]->(p:Post) RETURN u.name, collect(p.title);
    • Single efficient query;
4. Best Practices
  • Design for Client Needs
    • Create schema based on actual use cases;
    • Group related data that's often requested together;
  • Use Fragments
    • Reusable field selections;
    • fragment UserInfo on User { name, email };
    • Keeps queries DRY;
  • Pagination
    • For large lists, use pagination;
    • { users(first: 10, after: "cursor") { edges { node } } };
    • Prevents fetching too much data;
  • DataLoader Pattern
    • Batch and cache database requests;
    • Prevents N+1 queries in resolvers;
    • Essential for performance;
