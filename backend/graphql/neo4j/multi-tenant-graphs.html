1. What Is Multi-Tenancy?
  • Definition
    • Multiple customers (tenants) share same application;
    • Data must be isolated between tenants;
    • Common in SaaS applications;
  • Requirements
    • Data isolation - tenants can't see each other's data;
    • Performance isolation - one tenant doesn't affect others;
    • Scalability - support many tenants;
2. Isolation Strategies
  • Database Per Tenant
    • Each tenant has own Neo4j database;
    • Complete isolation;
    • Expensive, harder to manage;
  • Graph Per Tenant (Shared Database)
    • All tenants in one database;
    • Add tenantId property to all nodes;
    • Filter by tenantId in all queries;
    • Most common approach;
  • Hybrid
    • Small tenants share database;
    • Large tenants get dedicated database;
    • Balance cost and isolation;
3. Implementation with GraphQL
  • Tenant Context
    • Extract tenantId from JWT or header;
    • Add to GraphQL context;
    • Available in all resolvers;
  • Automatic Filtering
    • Use @auth directive: @auth(rules: [{allow: {tenantId: "$jwt.tenantId"}}]);
    • Automatically filter by tenant;
    • Prevents data leaks;
  • Schema Design
    • type User { id: ID!, tenantId: ID!, name: String! };
    • Include tenantId in all types;
    • Index tenantId for performance;
4. Best Practices
  • Always Filter by Tenant - Never forget tenantId in queries;
  • Index tenantId - Critical for performance;
  • Test Isolation - Verify tenants can't access each other's data;
  • Monitor Per-Tenant Usage - Identify resource-heavy tenants;
  • Plan for Growth - Have migration path to dedicated databases;
