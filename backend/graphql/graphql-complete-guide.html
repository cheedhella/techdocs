3. GraphQL Schema Design

Best practices for designing GraphQL schemas:

  • Defining Types - Create meaningful, reusable types;
  • Query Type - Entry point for read operations;
  • Mutation Type - Entry point for write operations;
  • Input Types - Special types for mutation arguments;
  • Enums - Predefined set of values;
  • Interfaces - Shared fields across types;
  • Unions - One of several possible types;
4. Writing GraphQL Queries
# Basic Query
query {
  user(id: "123") {
    name
    email
  }
}

# Nested Query
query {
  user(id: "123") {
    name
    posts {
      title
      comments {
        text
        author {
          name
        }
      }
    }
  }
}

# With Aliases
query {
  user1: user(id: "123") { name }
  user2: user(id: "456") { name }
}

# With Fragments
fragment UserInfo on User {
  id
  name
  email
}

query {
  user(id: "123") {
    ...UserInfo
    posts { title }
  }
}

# With Variables
query GetUser($userId: ID!) {
  user(id: $userId) {
    name
    email
  }
}

# Pagination
query {
  posts(first: 10, after: "cursor") {
    edges {
      node { title }
      cursor
    }
    pageInfo {
      hasNextPage
      endCursor
    }
  }
}
5. Mutations in Depth
# Creating Data
mutation {
  createUser(input: {
    name: "Alice"
    email: "alice@example.com"
  }) {
    id
    name
  }
}

# Updating Data
mutation {
  updateUser(id: "123", input: {
    name: "Alice Smith"
  }) {
    id
    name
    updatedAt
  }
}

# Deleting Data
mutation {
  deleteUser(id: "123") {
    success
    message
  }
}

7. GraphQL Execution & Resolvers

Resolvers are functions that fetch data for each field:

const resolvers = {
  Query: {
    user: (parent, args, context, info) => {
      return context.db.getUserById(args.id);
    },
  },
  User: {
    posts: (parent, args, context) => {
      return context.db.getPostsByUserId(parent.id);
    },
  },
  Mutation: {
    createUser: (parent, args, context) => {
      return context.db.createUser(args.input);
    },
  },
};
  • parent - Result from parent resolver;
  • args - Arguments passed to field;
  • context - Shared across all resolvers (db, user, etc);
  • info - Query execution info;
