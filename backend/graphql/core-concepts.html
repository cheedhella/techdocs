Core GraphQL Concepts

1. Schema & Type System

The schema is the heart of GraphQL - it defines what data can be queried and how.

type User {
  id: ID!
  name: String!
  email: String!
  age: Int
  posts: [Post!]!
}

type Post {
  id: ID!
  title: String!
  content: String!
  author: User!
  published: Boolean!
}
  • Types - Define structure of your data;
  • Fields - Properties on types;
  • Relationships - Fields can reference other types;
2. Queries

Queries are read operations - fetching data from the server.

query GetUser {
  user(id: "123") {
    name
    email
    posts {
      title
      published
    }
  }
}
  • Specify exactly which fields you want;
  • Nest queries to get related data;
  • Single request for all data;
3. Mutations

Mutations are write operations - creating, updating, or deleting data.

mutation CreatePost {
  createPost(input: {
    title: "My First Post"
    content: "Hello GraphQL!"
    authorId: "123"
  }) {
    id
    title
    author {
      name
    }
  }
}
  • Modify data on the server;
  • Return the modified data;
  • Execute sequentially (queries run in parallel);
4. Subscriptions

Subscriptions enable real-time updates via WebSocket.

subscription OnPostAdded {
  postAdded {
    id
    title
    author {
      name
    }
  }
}
  • Push updates to clients;
  • Perfect for chat, notifications, live data;
  • Uses WebSocket protocol;
5. Fields & Arguments

Fields can accept arguments for filtering, pagination, etc.

query {
  posts(
    limit: 10
    offset: 0
    orderBy: CREATED_DESC
    where: { published: true }
  ) {
    id
    title
  }
}
  • Arguments customize field behavior;
  • Common uses: filtering, sorting, pagination;
  • Can have default values;
6. Scalars vs Object Types

Scalar Types - Primitive values that resolve to concrete data:

  • Int - 32-bit integer;
  • Float - Floating point number;
  • String - UTF-8 character sequence;
  • Boolean - true or false;
  • ID - Unique identifier (serialized as String);

Object Types - Complex types with fields:

type User {
  id: ID!        # Scalar
  name: String!  # Scalar
  age: Int       # Scalar
  posts: [Post!]! # Object type (list of Posts)
}

Custom Scalars - Define your own:

scalar DateTime
scalar Email
scalar URL

type User {
  createdAt: DateTime!
  email: Email!
  website: URL
}
7. Nullability (!)

The exclamation mark (!) indicates a field cannot be null.

type User {
  id: ID!           # Required, never null
  name: String!     # Required, never null
  email: String     # Optional, can be null
  age: Int          # Optional, can be null
  posts: [Post!]!   # Required list, items never null
  tags: [String]    # Optional list, items can be null
}
  • Field! - Field is required;
  • [Type!] - List items cannot be null;
  • [Type]! - List itself cannot be null;
  • [Type!]! - Neither list nor items can be null;
