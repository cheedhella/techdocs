What is Pattern Matching for instanceof?
Finalized in Java 16 (and standard in Java 17), Pattern Matching for instanceof removes the need for explicit casting after an instanceof check. It introduces a binding variable that automatically holds the casted value if the check passes.
Why use it?
  • Less Boilerplate: Eliminates the tedious and redundant type casting.
  • Safer Code: Reduces the risk of a ClassCastException.
  • Readability: Makes code cleaner and more focused on the actual logic.
How does scoping work for the binding variable?
The binding variable is only in scope where the compiler can guarantee the pattern has matched. This means it is available inside the if block, or even in the right-hand side of a short-circuiting && operator.
Can you show a simple example?
// Before Java 16
if (obj instanceof String) {
    String s = (String) obj; // Explicit cast
    System.out.println(s.length());
}

// With Pattern Matching
if (obj instanceof String s) {
    // 's' is automatically casted and in scope
    System.out.println(s.length());
}

// Scope rules with &&
if (obj instanceof String s && s.length() > 5) {
    System.out.println(s.toUpperCase());
}
When should you use Pattern Matching?
Whenever you are checking the type of an object using instanceof and subsequently using it as that type. It should become the standard way to perform type checks in your codebase.
