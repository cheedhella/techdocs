What are Sealed Classes?
Sealed Classes, finalized in Java 17, restrict which other classes or interfaces may extend or implement them. They allow the author of a class or interface to control the inheritance hierarchy.
Why use Sealed Classes?
  • Domain Modeling: Allows exhaustive modeling of business domains (Algebraic Data Types) by restricting the valid subtypes.
  • Security/Maintainability: Prevents unauthorized or unexpected extensions of an API.
  • Enhanced Switch: Enables exhaustive pattern matching in switch expressions without needing a default clause, because the compiler knows all possible subtypes.
How do you declare a Sealed Class?
Use the sealed modifier and specify allowed subclasses using the permits clause. The allowed subclasses must be either:
  • final (cannot be extended further)
  • sealed (allows further controlled extension)
  • non-sealed (opens the hierarchy back up to any subclass)
Can you show a simple Sealed Class example?
public abstract sealed class Shape 
    permits Circle, Rectangle, Square {
}

// Must declare as final, sealed, or non-sealed
public final class Circle extends Shape {
    public double radius;
}

public sealed class Rectangle extends Shape permits TransparentRectangle {
    public double width, height;
}

public non-sealed class Square extends Shape {
    public double side;
}

public final class TransparentRectangle extends Rectangle {
}
When should you use Sealed Classes?
Use them when you have a known, closed set of implementations for an interface or abstract class. For example, representing states in a state machine, abstract syntax trees (ASTs), or representing a specific type of event in an event-driven system.
