What is CyclicBarrier?
CyclicBarrier is a synchronization aid that allows a set of threads to all wait for each other to reach a common barrier point. It's called "cyclic" because it can be re-used after the waiting threads are released.
How does CyclicBarrier work?
  • It is initialized with the number of participating threads.
  • Each thread calls the await() method when it reaches the barrier.
  • The thread is blocked until all threads have called await().
  • Once the last thread arrives, the barrier is broken, an optional Runnable (barrier action) is executed, and all threads proceed.
  • The barrier automatically resets for the next cycle.
CountDownLatch vs CyclicBarrier
  • CountDownLatch: One or more threads wait for a number of events to occur. Once the count reaches 0, it cannot be reused.
  • CyclicBarrier: A fixed number of threads wait for each other to reach a common point. Once all threads arrive, the barrier trips and resets, allowing reuse.
Can you show a simple CyclicBarrier example?
import java.util.concurrent.CyclicBarrier;
import java.util.concurrent.BrokenBarrierException;

public class Example {
    public static void main(String[] args) {
        int threads = 3;
        Runnable barrierAction = () -> System.out.println("All parties have arrived. Proceeding to next phase!");
        CyclicBarrier barrier = new CyclicBarrier(threads, barrierAction);

        for (int i = 0; i < threads; i++) {
            new Thread(() -> {
                try {
                    System.out.println(Thread.currentThread().getName() + " is doing phase 1 work...");
                    Thread.sleep(1000);
                    
                    System.out.println(Thread.currentThread().getName() + " reached barrier.");
                    barrier.await(); // Wait for others
                    
                    System.out.println(Thread.currentThread().getName() + " is doing phase 2 work...");
                } catch (InterruptedException | BrokenBarrierException e) {
                    e.printStackTrace();
                }
            }).start();
        }
    }
}
When should you use CyclicBarrier?
It is useful in programs involving a fixed sized party of threads that must occasionally wait for each other, such as parallel iterative algorithms, multiplayer games, or multi-phase concurrent tasks.
