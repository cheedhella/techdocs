What is CopyOnWriteArrayList?
  • It is a thread-safe variant of ArrayList in Java where all mutative operations (add, set, remove, etc.) are implemented by making a fresh copy of the underlying array;
  • It’s designed for concurrent environments where reads happen much more frequently than writes.;
  • Whenever you modify the list (add, remove, set):
    • 👉 It creates a new copy of the underlying array
    • 👉 Applies the change to that new copy
    • 👉 Replaces the old array reference
  • Whereas:
    • 👉 Readers continue using the old array safely without locks
  • Key characteristics:
    • ✔ Thread-safe without explicit locks
    • No need for synchronized
    • Safe for multi-threaded reads
    • ✔ Iterators are safe (no ConcurrentModificationException)
    • Iterators work on a snapshot
    • They don’t see changes made after creation
    • ✔ Great for read-heavy scenarios
    • Many reads, few writes = ideal use case
    • ❌ Downsides (important)
      • 🚫 Expensive writes
      • Every modification = full array copy
      • Bad for frequent updates
    • 🚫 Memory overhead
    • Temporary copies consume extra memory
    • 🚫 Iterators are not “live”
    • They don’t reflect latest updates
Why use CopyOnWriteArrayList?
  • Thread Safety Without Locking Readers: Read operations (get, iterator) do not require any synchronization and are extremely fast.
  • Fail-Safe Iterators: Iterators operate on a snapshot of the array taken at the time the iterator was created. It will never throw ConcurrentModificationException.
How does CopyOnWriteArrayList work internally?
  • An internal reentrant lock is used to synchronize mutative operations.
  • When a modification is made, a lock is acquired, the existing array is copied into a new array, the modification is applied to the new array, and finally, the internal reference is swapped to point to the new array.
  • This means writes are expensive but reads are cheap and lock-free.
Can you show a simple CopyOnWriteArrayList example?

            import java.util.concurrent.CopyOnWriteArrayList;

            public class Example {
                public static void main(String[] args) {
                    CopyOnWriteArrayList list = new CopyOnWriteArrayList<>();
            
                    list.add("A");
                    list.add("B");
            
                    // Iterator will only see "A" and "B" (snapshot from creation)
                    for (String item : list) {
                        list.add("C"); // No ConcurrentModificationException, // Modifying while iterating
                        System.out.println(item);
                    }
            
                    System.out.println(list);
                }
            }

            output:
A
B
[A, B, C, C]


import java.util.Iterator;

public class Example {
    public static void main(String[] args) {
        CopyOnWriteArrayList<String> list = new CopyOnWriteArrayList<>();
        
        list.add("A");
        list.add("B");
        
        Iterator<String> iterator = list.iterator();
        
        // Modifying while iterating
        list.add("C"); 
        
        // Iterator will only see "A" and "B" (snapshot from creation)
        while (iterator.hasNext()) {
            System.out.println(iterator.next());
        }
    }
}
When should you use CopyOnWriteArrayList?
It is best suited for scenarios where reads vastly outnumber writes and where thread-safe traversal is critical. A classic example is maintaining a list of event listeners or observers in an application.
What are the trade-offs?
Cons:
  • Memory Overhead: Every write operation copies the entire array, which can lead to high memory consumption and GC overhead for large lists.
  • Stale Data: Iterators provide a snapshot, so they might not reflect the most recent modifications made by other threads.
