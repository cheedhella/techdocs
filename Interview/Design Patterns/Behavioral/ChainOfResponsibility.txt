Chain of Responsibility Design Pattern
	It consists of a source of requests and a chain of handlers(processing objects);
	Each request is passed along the chain until the request is handled OR  end of the chain is reached;
	Note that, a handler 
		- can handle the request completely;
		- can handle the request partially before passing it to the next one in the chain;
		- has no idea of the request and can pass the request to the next one in the chain;

	It creates a chain with all handlers and each handler in the chain maintains a reference to next handler.
	That way, clients instead of maintaining references to all handlers, they keep a single reference to the head of the chain.
	Head of the chain takes all requests from clients, it either processes the request or passes it next handler in the chain.
	If none of handlers are able to process the request, a default action is performed.

	Example: Exception Handling Mechanism in Java
		In case of any exception in a try block, it is passed through a chain of catch blocks until one of it handles the exception;
		If none of the handlers are able to process the exception, it is thrown to the caller;

	Example: ATM Money Dispenser
		When the user enters the amount to be dispensed, amount to be dispensed is passed through a chain of handlers;
		If the user enters 130 and there are handlers/dispensers for 100, 50, 20, 10, then it will dispense 1 * 100, 1 * 20, 1 * 10;
		As you see, based on the amount entered, a handler can process the request only partially, thus requiring more than 1 handler 
		to process the request completely;

	Example: Chain doesn't have to be linear, it can be a tree as well;
		The Orc King gives loud orders to his army. The closest one to react is the commander, then officer and then soldier. The commander, officer and soldier here form a chain of responsibility.
