Command Pattern
	It helps you in writing loosely coupled code by decoupling the requestor of a request from the object which actually handles that request. It also helps in queuing the requests and supporting undoable operations.

	Example 1:
		In Restaurant, waiter takes the order, which is a command from the custmer and then tells the chef that a new order 
		has come in and chef actually prepares the food as per order.

	Example 2:
		For eg, every Door supports 2 operations: OPEN and CLOSE.
		To open the door, Client can create an instance of Door and call open() method.
		Notice that the Client is tightly coupled to the Receiver.
		What if you want to replace Door with SlidingDoor, which implements a method called slideOpen() to open the door?
		Because, Client is tighly coupled with Receiver, You need to modify the Client as per the Receiver.
		Using Command Pattern, you can avoid this.
		How it does it? Encapsulate both the receiver and the receiving method in a command object.

	Example 3: In JDK
		All implementations of java.lang.Runnable
		All implementations of javax.swing.Action

Invoker - It knows about Command object only and doesn't care about the actual object which processes the request, which can be different.
