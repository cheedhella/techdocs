What is Consistent Hashing?

  • In a large scale distributed system, a single node can't accomidate all the data;
  • Even if a single node accomidate, you can't store all data in a single node; As, such system is not scalable; TODO: Why not scalable? check LRU cache;
  • So, to build a system with predictable performance, it is important to distribute data evenly across all the nodes;

  • There are 2 approaches to distribute data evenly acorss all the nodes:
    • Approach #1: Mod function
      • Node = Hash(key) % NumberOfNodes;
      • As long as number nodes remains same, it maps each key to the node correctly;
      • What happens if a Node dies? OR a new Node gets added, as part of scaling?
      • In that case, the mod function selects a wrong cache host, resulting in high number of cache misses;
      • So, Mod function is a poor choice!
      • With mod function, when a new server is added/removed, you can rehash all the keys, but that's a time consuming operation;

    • Approach #2: Consistent Hashing
      • Goal of consistent hashing is to map a key to same server, even if the number of servers change;
      • With consistent hashing, when a new node is added/removed, only a fraction of keys, k/n, needs to be remapped, where k=number of keys, n = number of servers;

      • It places all the nodes in virtual ring structure, called hash-ring, by using hash function on node name OR IP address;
      • Theoretically, each node owns a range of the hash-ring, and any requests mapped to that range, will be served by the underlying node;

      • How to map a request to a Node?
        • We hash each request, using the same hash function that we used to hash nodes and map it to the same range of values;
        • Identify that location on the ring and go clockwise from that location until a server is found;

      • What happens when you add a new Node?
        • We calculate a hash for the new node, it tells us the position on the ring where the new node lives;
        • Each new node owns all the cache items that live between the nearest counter clockwise neighbour and it; // it could be clockwise manner as well, doesn't matter;
        • New node takes over the responsibility of subset of keys from it's clockwise neighbour;
        • We only need to rehash the keys belonging to the clockwise node;
        • Nothing has changed for all other hosts; which is what we wanted, to minimize the number of keys to re-hash;

      • What happens when you remove a Node?
        • When a node fails, it's clockwise neighbour node takes the resposibility of the failed node range;
        • But that's it; It's just this one range, corresponding to the failed node, that needs to be re-assigned, while the rest of the hash-ring and request-node assignments still remain unaffected;

      • Issue with this design?
        • Conceptually, we are picking n random points on the ring; But, hash function can't partition the ring into equal sized segments, thus the load on each node is not even;
        • Even if the nodes are evenly spaced initially, when a node goes down, the load on it's clockwise neighbour increases;
      • Virtual Nodes
        • Virtual nodes are used to fix the above problem;
        • Each node can have one or more virtual nodes; They are appear at multiple locations on the ring;
        • With virtual nodes, each node handles multiple segments on the ring;

        • For eg, with 2 actual nodes and 3 virtual nodes per 1 node, we can have a total of 6 virtual nodes on the ring;
        • In real world systems, the number of virtual nodes are much larger than 3;
        • As the number of virtual nodes increases, the distribution of objects becomes more balanced;

        • Having more virtual nodes means taking more space to store metadata about virtual nodes;
        • This is a trade-off, we can tune the number of virtual nodes to fit our system requirements;

Applications

  • NoSQL databases such as Amazon dynamoDB, Apache Cassandra use consistent hashing for data partitioning;
  • Distributed Cache also uses consistent hashing for data partitioning;
  • CDN like Akamai uses consistent hashing to help distribute web content evenly among edge servers;
  • Load Balancing uses consistent hashing to uniformly distribute the requests across servers;
