1. Getting Started

What is npm?
npm (Node Package Manager) is the default package manager for Node.js. It consists of:
  • CLI Tool: Command-line interface for managing packages
  • Registry: Online database of public and private packages (npmjs.com)
  • Website: Browse and search packages
Key Features:
  • Install and manage dependencies
  • Run scripts and automate tasks
  • Publish and share packages
  • Manage project versions
  • Security auditing
npm vs yarn vs pnpm
Feature npm yarn pnpm
Speed Good Fast Fastest
Disk Space High High Low (symlinks)
Lockfile package-lock.json yarn.lock pnpm-lock.yaml
Workspaces Yes (v7+) Yes Yes
Default with Node Yes No No
When to use npm:
  • Default choice, comes with Node.js
  • Good for most projects
  • Best compatibility
When to use yarn:
  • Need faster installs
  • Better offline support
  • Prefer yarn.lock format
When to use pnpm:
  • Monorepos with many packages
  • Limited disk space
  • Strictest dependency resolution

dependencies vs devDependencies
dependencies:
  • Required for the app to run in production
  • Installed in production builds
  • Examples: react, express, lodash
devDependencies:
  • Only needed during development
  • Not installed in production (npm install --production)
  • Examples: typescript, jest, eslint, webpack
# Install as dependency (production)
npm install react express axios

# Install as devDependency (development only)
npm install -D typescript jest eslint prettier nodemon

# Install production dependencies only
npm install --production
# or
npm install --omit=dev

Version Specifiers (^, ~, exact)
# Exact version
"package": "1.2.3"
# Only installs 1.2.3

# Caret (^) - Compatible updates
"package": "^1.2.3"
# Allows: 1.2.3, 1.2.4, 1.3.0, 1.9.9
# Does NOT allow: 2.0.0
# Rule: Updates that don't change leftmost non-zero digit

# Tilde (~) - Patch updates only
"package": "~1.2.3"
# Allows: 1.2.3, 1.2.4, 1.2.9
# Does NOT allow: 1.3.0, 2.0.0
# Rule: Only patch version updates

# Wildcards
"package": "*"        # Any version (not recommended)
"package": "1.x"      # Any 1.x.x version
"package": "1.2.x"    # Any 1.2.x version

# Ranges
"package": ">=1.2.3"         # Greater than or equal
"package": ">=1.2.3 <2.0.0"  # Range
"package": "1.2.3 - 1.5.0"   # Between versions

# Latest
"package": "latest"   # Always latest (not recommended)

# Examples with semantic versioning
"react": "^18.2.0"
# 18.2.0 ✅  18.2.5 ✅  18.3.0 ✅  19.0.0 ❌

"react": "~18.2.0"
# 18.2.0 ✅  18.2.5 ✅  18.3.0 ❌  19.0.0 ❌

"react": "18.2.0"
# 18.2.0 ✅  18.2.5 ❌  18.3.0 ❌  19.0.0 ❌
Best Practices:
  • Use ^ for most dependencies (safe updates)
  • Use exact versions for critical packages
  • Use ~ when you only want bug fixes
  • Avoid * and latest in production
npm ci - Clean Install
# Clean install (CI/CD environments)
npm ci

# Differences from npm install:
# 1. Requires package-lock.json
# 2. Deletes node_modules before install
# 3. Never modifies package-lock.json
# 4. Faster and more reliable
# 5. Fails if package.json and package-lock.json are out of sync
When to use npm ci:
  • CI/CD pipelines (GitHub Actions, Jenkins)
  • Production deployments
  • Docker builds
  • When you want exact versions from lockfile
When to use npm install:
  • Local development
  • Adding new packages
  • Updating dependencies
# Example CI workflow
name: CI
on: [push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
      - run: npm ci          # Use ci, not install
      - run: npm test
package-lock.json
What is package-lock.json?
  • Automatically generated when npm modifies node_modules or package.json
  • Records exact versions of all installed packages and their dependencies
  • Ensures consistent installs across machines
  • Should be committed to version control
# Example package-lock.json structure
{
  "name": "my-app",
  "version": "1.0.0",
  "lockfileVersion": 3,
  "requires": true,
  "packages": {
    "": {
      "name": "my-app",
      "version": "1.0.0",
      "dependencies": {
        "react": "^18.2.0"
      }
    },
    "node_modules/react": {
      "version": "18.2.0",
      "resolved": "https://registry.npmjs.org/react/-/react-18.2.0.tgz",
      "integrity": "sha512-...",
      "dependencies": {
        "loose-envify": "^1.1.0"
      }
    }
  }
}
Best Practices:
  • ✅ Always commit package-lock.json
  • ✅ Use npm ci in CI/CD
  • ✅ Don't manually edit it
  • ❌ Don't add to .gitignore

npm version - Semantic Versioning

# Example: 1.2.3
# MAJOR: Breaking changes (1.x.x → 2.0.0)
# MINOR: New features, backwards compatible (1.2.x → 1.3.0)
# PATCH: Bug fixes (1.2.3 → 1.2.4)

# Bump patch version (1.0.0 → 1.0.1)
npm version patch

# Bump minor version (1.0.0 → 1.1.0)
npm version minor

# Bump major version (1.0.0 → 2.0.0)
npm version major

Security Best Practices
  • Regular audits: Run npm audit regularly
  • Keep dependencies updated: Use npm update
  • Use package-lock.json: Commit to version control
  • Review dependencies: Check before installing
  • Use npm ci in CI/CD: Reproducible builds
