              }, []);

              });

                  console.log("Component unmounted");
                };
              }, []);

useCallback 
    - useCallback is one of those hooks that seems unnecessary—until you hit performance issues or weird re-renders.
    - It remembers (memoizes) a function so React doesn’t recreate it on every render.
    - Why this matters?
        - In React, functions are recreated on every render:
        - function App() {
            const handleClick = () => {
              console.log("Clicked");
            };
          }
        - Most of the time, that’s fine.
        - But it becomes a problem when you pass that function to child components.
        - For eg,
            function Parent() {
                const [count, setCount] = useState(0);
            
                const handleClick = () => {
                console.log("Clicked");
                };
            
                return ;
            }
        - WHen count changes, the parent component re-renders, and the handleClick function is recreated.
        - Child thinks props changed and it re-renders unnecessarily;
        - Solution is useCallback;
            // handleClick is created only once and is memoized;
            import { useCallback } from "react";
            const handleClick = useCallback(() => {
            console.log("Clicked");
            }, []);
        
            // When the count changes, the handleClick function is recreated;
            const handleClick = useCallback(() => {
                console.log(count);
              }, [count]);
        
        - Without useCallback → new function every render
          With useCallback → same function unless dependencies change

1. What is the Virtual DOM and how does it work?
The Virtual DOM (VDOM) is a programming concept where an ideal, or "virtual", representation of a UI is kept in memory and synced with the "real" DOM by a library such as ReactDOM. This process is called reconciliation.

How it works:
  • When state or props change, React creates a new Virtual DOM tree.
  • React compares this new tree against the previous Virtual DOM tree (a process called "diffing").
  • React calculates the most efficient way to update the real DOM based on these differences.
  • Finally, it applies only those specific changes to the real DOM, minimizing expensive DOM manipulations.
2. What is the difference between a Functional Component and a Class Component?
  • Syntax: Class components require you to extend from React.Component and create a render function. Functional components are simply JavaScript functions that return JSX.
  • State & Lifecycle: Previously, only Class components could hold state and use lifecycle methods. With the introduction of React Hooks in v16.8, Functional components can now use state (via useState) and handle side effects (via useEffect).
  • Performance & Readability: Functional components are generally easier to read, write, and test. They also encourage better separation of concerns and logic reuse through custom hooks.
3. What are React Hooks? Can you name a few common ones?
Hooks are functions that let you "hook into" React state and lifecycle features from functional components. They do not work inside classes.

Common Hooks:
  • useState: Manages local state in a component.
  • useEffect: Performs side effects (data fetching, subscriptions).
  • useContext: Allows you to subscribe to React context without introducing nesting.
  • useRef: Returns a mutable ref object whose .current property is initialized to the passed argument.
  • useMemo & useCallback: Used for performance optimization.
4. Why do we need the 'key' prop when rendering lists in React?
Keys help React identify which items in a list have changed, been added, or been removed. They play a crucial role in the reconciliation process.
  • When items in a list change, React uses keys to match children in the original tree with children in the subsequent tree.
  • Without keys, React might unnecessarily re-render entire lists.
  • Keys should be unique and stable (like an ID from your data). Using array indices as keys is an anti-pattern.
5. What is the difference between Controlled and Uncontrolled Components?
  • Controlled Components: The form data is handled by the state within the React component. The input's value is driven by React state, and changes are handled by updating that state via an onChange event handler.
  • Uncontrolled Components: The form data is handled by the DOM itself. You use a ref (like useRef) to access the input's current value directly from the DOM when needed.
6. What is Prop Drilling and how can you avoid it?
Prop Drilling is the process of passing data from a parent component down to a deeply nested child component, passing it through several intermediate components that don't actually need the data themselves.

How to avoid it:
  • Context API: Create a context at the top level and consume it directly in the deeply nested component using useContext.
  • State Management Libraries: Use tools like Redux, Zustand, or Recoil.
  • Component Composition: Pass the child component itself as a prop to the intermediate components.
7. What is JSX?
JSX stands for JavaScript XML. It is a syntax extension for JavaScript that allows you to write HTML-like code inside JavaScript/React files. It makes writing React components easier and more expressive. Under the hood, Babel compiles JSX into standard JavaScript React.createElement() calls.
8. What is the difference between an Element and a Component in React?
  • Element: A plain JavaScript object that describes what you want to see on the screen in terms of the DOM nodes or other components. Elements are immutable. (e.g., <div>Hello</div>)
  • Component: A function or a class that optionally accepts inputs (props) and returns a React element. Components are the building blocks of a React application.
9. What is State in React?
State is a built-in React object that is used to contain data or information about the component. A component's state can change over time, and whenever it changes, the component re-renders to reflect the new data in the UI.
10. What are Props in React?
Props (short for properties) are read-only components that are used to pass data from one component to another, usually from parent to child. They are immutable, meaning a child component cannot modify the props it receives.
11. What is the difference between State and Props?
  • Props: Passed to a component from its parent. They are read-only (immutable) and allow components to be reusable.
  • State: Managed within the component itself. It is mutable and causes the component to re-render when updated.
12. What is React Fiber?
React Fiber is the core reconciliation algorithm introduced in React 16. Its main goal is to improve the suitability of React for areas like animation, layout, and gestures. Its headline feature is incremental rendering: the ability to split rendering work into chunks and spread it out over multiple frames, prioritizing important updates over less important ones.
13. How does React handle events?
React handles events using its own synthetic event system. It attaches a single event listener to the root of the document (event delegation) rather than attaching individual event listeners to each DOM node. When an event is triggered, React maps it to the correct component and invokes the provided handler.
14. What are Synthetic Events in React?
A Synthetic Event is a cross-browser wrapper around the browser's native event. It provides the same API as the native event (like stopPropagation() and preventDefault()) but works identically across all browsers.
15. What are Higher-Order Components (HOC)?
A Higher-Order Component is an advanced technique in React for reusing component logic. It is a function that takes a component and returns a new component with added data or functionality. Example: const EnhancedComponent = higherOrderComponent(WrappedComponent);.
16. What is a Render Prop?
The term "render prop" refers to a technique for sharing code between React components using a prop whose value is a function. A component with a render prop takes a function that returns a React element and calls it instead of implementing its own render logic.
17. What is the purpose of React.memo()?
React.memo() is a higher-order component that optimizes performance by memoizing the result of a functional component. If the component's props have not changed, React will skip rendering the component and reuse the last rendered result.
18. What is useMemo and when should you use it?
useMemo is a hook that memoizes a calculated value. It only recalculates the value when one of its dependencies changes. You should use it to optimize expensive calculations that do not need to run on every single render.
19. What is useCallback and when should you use it?
useCallback is a hook that returns a memoized version of a callback function. It only changes if one of the dependencies has changed. It is primarily used when passing callbacks to optimized child components (like those wrapped in React.memo) to prevent them from re-rendering unnecessarily.
20. What are Error Boundaries in React?
Error boundaries are React components that catch JavaScript errors anywhere in their child component tree, log those errors, and display a fallback UI instead of crashing the whole component tree. Currently, error boundaries can only be created using Class Components (implementing componentDidCatch or static getDerivedStateFromError).
21. What is the Context API?
The Context API is a built-in React feature that provides a way to share values (like themes, user data, or localization) between components without having to explicitly pass a prop through every level of the tree.
22. How does the Context API differ from Redux?
  • Context API: Built into React, simple to set up, good for low-frequency updates like themes or auth state. Not ideal for high-frequency state changes because any context change triggers a re-render of all consuming components.
  • Redux: A robust, external state management library. It uses a single store, reducers, and actions. It is heavily optimized for high-frequency updates and complex state architectures.
23. What are Portals in React?
Portals provide a first-class way to render children into a DOM node that exists outside the DOM hierarchy of the parent component. They are commonly used for modals, tooltips, and popovers to avoid z-index and CSS overflow clipping issues. Created using ReactDOM.createPortal(child, container).
24. What is StrictMode in React?
<React.StrictMode> is a tool for highlighting potential problems in an application. It does not render any visible UI. It activates additional checks and warnings for its descendants, such as identifying components with unsafe lifecycles, warning about legacy string ref API usage, and detecting unexpected side effects (by double-invoking render methods in development).
25. What is the useReducer hook?
useReducer is an alternative to useState. It is preferable when you have complex state logic that involves multiple sub-values or when the next state depends on the previous one. It accepts a reducer function of type (state, action) => newState, and returns the current state paired with a dispatch method.
26. What are the differences between useState and useReducer?
  • useState is ideal for simple, independent pieces of state (like booleans or strings).
  • useReducer is better for complex state objects or when state transitions follow specific rules or depend on previous state. It moves the state transition logic out of the component and into a pure reducer function.
27. How do you pass data from a child to a parent component?
Since React enforces a one-way data flow (parent to child), passing data upwards is achieved by passing a callback function from the parent to the child as a prop. The child component can then call this function, passing the required data as an argument.
28. What are React Fragments?
React Fragments (<React.Fragment> or the shorthand <></>) allow you to group a list of children without adding extra nodes (like a wrapper div) to the DOM.
29. Why can't browsers read JSX directly?
Browsers can only understand standard JavaScript objects and functions. JSX is a syntax extension that is not part of standard JavaScript. Before it runs in the browser, JSX must be compiled (usually by Babel) into standard React.createElement() calls.
30. What is the significance of the 'children' prop?
The children prop is a special prop that allows you to pass components as data to other components, just like you would pass plain text or variables. It is used to create wrapper components (like layouts or dialogs) where the parent doesn't need to know what children it is wrapping.
31. What is the difference between default export and named export in React?
  • Default Export: Allows you to export exactly one main value from a file. When importing, you can name it whatever you want. (import MyComp from './Component')
  • Named Export: Allows you to export multiple values from a file. When importing, you must use the exact same name inside curly braces. (import { MyComp, OtherComp } from './Component')
32. What is reconciliation in React?
Reconciliation is the process through which React updates the DOM. When a component's state changes, React has to calculate if it is necessary to update the DOM. It does this by creating a virtual DOM and comparing it with the current DOM (diffing algorithm).
33. How do you optimize a React application's performance?
Common optimization techniques include:
  • Using React.memo, useMemo, and useCallback to prevent unnecessary re-renders.
  • Code-splitting and Lazy Loading components using React.lazy and Suspense.
  • Virtualizing long lists (using libraries like react-window).
  • Using stable and unique keys for list items.
  • Avoiding inline functions and object literals in JSX if they cause child re-renders.
34. What is lazy loading in React?
Lazy loading is a technique that delays the loading of a component until it is actually needed. In React, this is achieved using React.lazy() combined with dynamic import(). It drastically reduces the initial bundle size of the application.
35. What is React Suspense?
<Suspense> is a component that lets you specify a fallback UI (like a loading spinner) while its child components are waiting for something to load, such as a lazily loaded component or data fetching (in modern React).
36. What is the significance of the useEffect dependency array?
The dependency array tells React when to re-run the useEffect block.
  • No array: Runs after every render.
  • Empty array []: Runs only once after the initial render (similar to componentDidMount).
  • Array with variables [var1, var2]: Runs initially, and whenever any of the specified variables change.
37. What are the rules of Hooks?
  • Only call Hooks at the top level: Don't call Hooks inside loops, conditions, or nested functions.
  • Only call Hooks from React functions: Call them from within React functional components or custom Hooks (not regular JavaScript functions).
38. What is a custom hook?
A custom hook is a JavaScript function whose name starts with "use" and that may call other Hooks. It is a mechanism to extract and reuse stateful logic between different components without changing the component hierarchy.
39. What replaces componentDidMount, componentDidUpdate, and componentWillUnmount in functional components?
The useEffect hook replaces all three.
  • componentDidMount: useEffect(() => {}, [])
  • componentDidUpdate: useEffect(() => {}, [dependency])
  • componentWillUnmount: Achieved by returning a cleanup function from the useEffect callback.
40. What is the difference between useLayoutEffect and useEffect?
  • useEffect runs asynchronously after the browser has painted the screen. Good for most side effects (data fetching, subscriptions).
  • useLayoutEffect runs synchronously immediately after React has performed all DOM mutations, but before the browser paints. Good for reading layout from the DOM and synchronously re-rendering to prevent flickering.
41. What is the difference between React and ReactDOM?
React is a library for defining components and calculating UI updates (the core logic). ReactDOM is a separate library responsible for taking those calculations and actually manipulating the browser's Document Object Model (DOM).
42. What is Concurrent Mode / Concurrent Rendering in React 18?
Concurrent Rendering is an under-the-hood mechanism introduced in React 18. It allows React to pause, abort, or resume rendering work. This means urgent tasks (like user typing) can interrupt non-urgent tasks (like rendering a large data chart), making the application feel much more responsive.
43. What is automatic batching in React 18?
Batching is when React groups multiple state updates into a single re-render for better performance. Before React 18, React only batched updates inside React event handlers. In React 18, automatic batching applies everywhere, including inside promises, setTimeout, and native event handlers.
44. What is useTransition in React 18?
useTransition is a hook that lets you mark state updates as "transitions" (non-urgent). React will prioritize urgent updates (like typing in an input) over transitions (like filtering a massive list), keeping the UI responsive.
45. What is useDeferredValue in React 18?
useDeferredValue is a hook that lets you defer updating a part of the UI. It is similar to debouncing or throttling, but integrated with React's concurrent rendering. It tells React to show the old value while calculating the new value in the background.
46. What are forwardRefs in React?
React.forwardRef is a method that allows a component to take a ref they received from above and pass it (or "forward" it) further down to a child component (usually a native DOM element). This is commonly used in reusable UI component libraries.
47. What is useImperativeHandle?
useImperativeHandle is a hook used in conjunction with forwardRef. It allows you to customize the instance value that is exposed to parent components when using refs. Instead of exposing an entire DOM node, you can expose only specific functions (like focus() or play()).
48. What is Server-Side Rendering (SSR)?
SSR is the process of rendering React components to HTML on the server and sending the fully populated HTML page to the client. This improves SEO and initial page load speed, as the browser can display the UI before downloading and executing the JavaScript bundle. Usually achieved with frameworks like Next.js.
49. What is Static Site Generation (SSG)?
SSG generates HTML pages at build time rather than on each request. When a user requests a page, the pre-built HTML is served instantly via a CDN. It provides the absolute fastest performance and is ideal for blogs, documentation, and e-commerce product pages. Supported heavily by Next.js.
50. How do you handle routing in React?
React does not have built-in routing. The industry standard is to use React Router (or rely on file-system routing if using Next.js). React Router allows you to define routes that map URLs to specific components, enabling single-page applications (SPAs) to have multiple logical pages without reloading the browser.
51. What are the benefits of using TypeScript with React?
TypeScript adds static typing to React. Benefits include: catching type errors at compile time rather than runtime, enforcing strict structures for component props and state, providing better IDE autocompletion and intellisense, and making large codebases easier to maintain and refactor.
52. How do you test React components?
React applications are typically tested using:
  • Jest: A JavaScript testing framework used as the test runner and assertion library.
  • React Testing Library (RTL): A library for testing React components in a way that resembles how users interact with the app (querying by text, roles, labels) rather than testing implementation details.
53. What is hydration in React?
Hydration is the process that occurs after Server-Side Rendering (SSR). The server sends static HTML to the browser, which the browser renders immediately. Then, React downloads the JavaScript bundle, attaches event listeners to the existing HTML elements, and makes the page fully interactive. This process of attaching functionality to static HTML is called hydration.
