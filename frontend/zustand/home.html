What is Zustand? - It is a state management library for React Applications; - There are many state management libraries available: Redux, Redux Toolkit, Context API, Zustand etc; - It is built on top of the Context API and uses the concept of stores to manage state; - A store is a container for a specific piece of state and any functions that modify that state; - You can create as many stores as you need, and they can be used throughout your application; Why is it needed - State Management Library vs useState? - When a component creates state using useState(), it is owned by that component; - If you want to share that state with child components, then you need to pass that to child components; - If you want to share that state with grand children, then you need to pass it child first and child needs to pass it to grand children; - If you want to share that state with sibiling or other components, then you need to find a way; - With state management library, any component can store the state in the global store, which acts as a single source of truth and any other component can access it; Why Zustand? - Simple -- State logic stays clean and readble; - Central/Global State - State is centralized and shared between components; - If a component updates the state, then other components which uses that state also gets re-rendered; - Immutability - When updating the state using set(), always pass a new state object, rather than modifying the existing state directly; - When you pass a new state object to set(), zustand merges it into the store; old state object in the store remains intact; - Why is it important? -- Zustand uses shallow comparation, to check if the part of state they subscribed to has changed; -- If you update the old state directly, Zustand doesn't that anything changed and components might not re-render correctly; - Scalability -- You can split the state into multiple stores OR keep everyting in one place; - Async friendly -- Actions inside the state can synchrounous or asynchronous, without any additional libraries; -- For example, we can make an HTTP request to an endpoint from our action and update the state with the response; import { create } from 'zustand' import axios from 'axios' const useCounter = create((set) => ({ counter: 0, incrCounter: async () => { const { data } = await axios.get("/counter") set({ counter: data.counter }) }, })); - TypeScript support If you have nested state (like an object), you must also create a new object instead of mutating: const useUserStore = create((set) => ({ user: { name: 'Alice', age: 25 }, updateName: (newName) => set((state) => ({ user: { ...state.user, name: newName }, // copy + override })), })) - Small, fast, scalable, immutable, transient updates for often occurring state changes, memorized selectors, integration with immer; - Create and update complex state structures, handle asynchronous actions, share state between components; ---------------------------------------------------------------------------------------------------------------------------------------------------------------- npm install zustand Zustand unit testing - https://blog.peslostudios.com/blog/zustand-writing-tests-for-your-data-store/ https://learnersbucket.com/tutorials/react/micro-state-management-with-zustand-in-react/ https://tsh.io/blog/zustand-react/ - set vs get store function exposes few methods like getState(), setState(), and subscribe(). getState() is used to get the state in the store and setState() is used to update the state in the store. The state objects are immutable, updating the state properties directly won’t update the state and thus will not trigger the re-render. const state1 = store.getState(); state1.count = 2; // invalid, won't work; store.setState(state1); The store must be always updated with the new object, store.setState({count: 2}), it also accepts a callback function, which has the prevState as the argument, which can be used to create the new state, known as functional update. store.setState((prev) => ({ count: prev.count + 1 })); State can have more than 1 property; However, it is not necessary to update all the properties every time, setState merges the old state with the new state, thus we can specify the only property which we want to update. The last piece of the puzzle is the store.subscribe() method, it registers a callback function which is triggered every time the state is updated in store. store.subscribe(() => { console.log("state is updated"); }); store.setState({ message: 'Bye World!' }); //"state is updated" Optimizing re-rendering. import {create} from "zustand"; export const useCounterStore = create((set, get) => ( { pokemon: [], number: 123, increaseCounterNumber: () => set((state) => ({number: state.number + 1})), decreaseCounterNumber: () => set((state) => ({number: state.number - 1})), logNumber: () => { console.log(` Current number value equals ${get().number}`) }, fetchPokemon: async () => { await fetch('https://pokeapi.co/api/v2/pokemon') .then(response => response.json()) .then(data => set({pokemon: data.results})) } } )) You can easily use async/await inside the hook and simply call set() whenever the data is ready.
