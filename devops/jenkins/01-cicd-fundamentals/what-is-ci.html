What is CI (Continuous Integration)?

1. Definition
  • Continuous Integration (CI) is a development practice where developers merge their code changes into a shared repository frequently — ideally several times a day;
  • Each merge triggers an automated build and test to catch issues early;
  • The goal: detect integration problems as soon as possible, not at the end of a sprint;
2. The CI Workflow
Developer pushes code
    → CI server detects the change (webhook / poll)
        → Pulls latest code
            → Builds the application
                → Runs automated tests (unit, integration)
                    → Reports results (pass / fail)
                        → Notifies the team
3. Key Principles
  • Single source repository: All code lives in one version-controlled repo;
  • Automate the build: One command should build the entire project;
  • Self-testing build: Every build runs automated tests;
  • Commit frequently: Small, frequent commits reduce merge conflicts;
  • Fix broken builds immediately: A failing build is the team's top priority;
  • Keep the build fast: Feedback should come within minutes, not hours;
4. Benefits of CI
  • Catch bugs early — before they reach production;
  • Reduce integration problems — no more "it works on my machine";
  • Faster feedback loop for developers;
  • Always have a working, testable build;
  • Increased team confidence in code quality;
