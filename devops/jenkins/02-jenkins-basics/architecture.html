Jenkins Architecture (Controller, Agents)

1. Controller (Master)
  • The central brain of Jenkins;
  • Manages configuration, schedules jobs, dispatches builds to agents;
  • Serves the web UI;
  • Stores build results, logs, and plugin data;
  • Should NOT run builds directly in production (delegate to agents);
2. Agents (Nodes)
  • Machines that execute builds on behalf of the controller;
  • Can be physical machines, VMs, Docker containers, or Kubernetes Pods;
  • Connected to the controller via SSH, JNLP, or WebSocket;
  • Labeled for routing specific jobs (e.g., linux, docker, gpu);

4. Executors
  • Each agent has a configurable number of executors (build slots);
  • One executor = one concurrent build;
  • More executors = more parallel builds (limited by machine resources);
