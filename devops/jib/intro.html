Jib

1. What is Jib?
  • Jib is an open-source tool developed by Google that builds OCI-compliant docker images for Java applications;
  • It works as a Maven or Gradle plugin — no Dockerfile, no Docker daemon required - So, it is ideal choice for CI/CD environments;
  • It packages your application directly into a docker image and can push it to any registry (Docker Hub, GitHub Container Registry, ECR, GCR, etc.);
  • Alternatives: Buildpacks, Spotify Docker Maven Plugin, Fabric8.io;

Key features:

  • Smart Layering: Splits the app into layers — dependencies, snapshot dependencies, resources, classes; Only the changed layer is rebuilt on each build, making incremental builds fast;
  • Reproducible Builds: Images are deterministic, timestamp-independent, and consistent across environments;
  • OCI Compliant: Images run on Docker, Kubernetes, Podman, containerd — any OCI-compatible runtime;
  • Daemonless: Does not require a running Docker daemon to build images; Docker is only needed if you want to run the image locally;
2. Why use Jib?
  • No Dockerfile knowledge needed: Jib handles all image construction internally using sensible defaults for Java apps;
  • No Docker installation needed: Jib pushes directly to a registry without a local Docker daemon — ideal for CI/CD environments where Docker may not be available;
  • Faster builds: Because only changed layers are rebuilt, subsequent builds are significantly faster than a full docker build;
  • CI/CD friendly: Works seamlessly in GitHub Actions, Jenkins, GitLab CI, etc. — just set credentials and run mvn compile jib:build;
  • Secure by default: Encourages distroless base images and non-root users out of the box;
  • Maven/Gradle native: Fits naturally into existing Java build pipelines with no extra tooling;
3. How to use it?

Step 1 — Add the Jib plugin to your pom.xml:

<plugin>
  <groupId>com.google.cloud.tools</groupId>
  <artifactId>jib-maven-plugin</artifactId>
  <version>3.4.0</version>
  <configuration>
    <to>
      <image>docker.io/myrepo/myapp</image>
    </to>
  </configuration>
</plugin>

Step 2 — Build and push to a registry:

mvn compile jib:build

Or build to your local Docker daemon instead:

mvn compile jib:dockerBuild

Or override the image name directly from the CLI:

mvn compile jib:build -Dimage=docker.io/myrepo/myapp:v1.0
4. Docker Image vs OCI Image?
  • Docker image — proprietary format created by Docker Inc;
  • OCI image — open standard by the Open Container Initiative, backed by Google, Red Hat, Microsoft and others;
  • The key advantage of OCI is portability — an OCI image runs on Docker, Podman, Kubernetes, and containerd without any changes;
  • Jib produces OCI images by default, so your image is not tied to Docker and works on any OCI-compliant runtime;
  • Docker also adopted the OCI spec since Engine 1.10, so modern Docker images are OCI images — the difference in practice is almost none;
5. Jib vs Dockerfile?
Feature Jib Dockerfile
Requires Docker to build ❌ No ✅ Yes
Requires a Dockerfile ❌ No ✅ Yes
Java-optimized layering ✅ Automatic ❌ Manual
Incremental builds ✅ Yes — only changed layers rebuilt ⚠️ Depends on layer ordering
CI/CD friendly ✅ Excellent — no Docker daemon needed ⚠️ Needs Docker in CI environment
Custom OS setup ❌ Limited — base image only ✅ Full control (apt, yum, etc.)
Multi-language support ❌ Java only ✅ Any language
Learning curve ✅ Low — just Maven/Gradle config ⚠️ Need to know Dockerfile best practices
