1. Basic Plugin Setup

Add the Jib Maven plugin to your pom.xml:

<project>
    <build>
        <plugins>
            <plugin>
                <groupId>com.google.cloud.tools</groupId>
                <artifactId>jib-maven-plugin</artifactId>
                <version>3.4.0</version>
                <configuration>
                    <!-- Configuration goes here -->
                </configuration>
            </plugin>
        </plugins>
    </build>
</project>

Maven Goals:

  • mvn jib:build - Build and push to registry
  • mvn jib:dockerBuild - Build to local Docker daemon
  • mvn jib:buildTar - Build as a tarball

Automatic Execution with Maven Lifecycle

Bind Jib to Maven phases for automatic execution:

<plugin>
    <groupId>com.google.cloud.tools</groupId>
    <artifactId>jib-maven-plugin</artifactId>
    <version>3.4.0</version>
    <configuration>
        <!-- Your configuration -->
    </configuration>
    
    <!-- Bind to Maven lifecycle -->
    <executions>
        <execution>
            <phase>package</phase>
            <goals>
                <goal>build</goal>
            </goals>
        </execution>
    </executions>
</plugin>

With this configuration, running mvn package will automatically build and push your image.

Common Execution Phases:

  • package - Build image when creating JAR/WAR (most common)
  • install - Build image when installing to local Maven repo
  • deploy - Build image when deploying to remote Maven repo
  • verify - Build image during verification phase (after tests)

Multiple Executions:

<executions>
    <!-- Build to local Docker for testing -->
    <execution>
        <id>build-local</id>
        <phase>package</phase>
        <goals>
            <goal>dockerBuild</goal>
        </goals>
    </execution>
    
    <!-- Push to registry in deploy phase -->
    <execution>
        <id>push-registry</id>
        <phase>deploy</phase>
        <goals>
            <goal>build</goal>
        </goals>
    </execution>
</executions>
2. From Configuration (Base Image)

Configure the base image your application will be built on:

Default Base Images (if not specified):

  • JAR files: eclipse-temurin:17-jre (or latest available Java 17 JRE)
  • WAR files: jetty:11-jre17-alpine (Jetty servlet container)
<configuration>
    <from>
        <!-- Base image -->
        <image>eclipse-temurin:17-jre</image>
        
        <!-- Alternative: Use distroless for smaller, more secure images -->
        <!-- <image>gcr.io/distroless/java17-debian12</image> -->
        
        <!-- Authentication for private base images -->
        <auth>
            <username>${env.REGISTRY_USERNAME}</username>
            <password>${env.REGISTRY_PASSWORD}</password>
        </auth>
        
        <!-- Specify platform (for multi-arch) -->
        <platforms>
            <platform>
                <architecture>amd64</architecture>
                <os>linux</os>
            </platform>
            <platform>
                <architecture>arm64</architecture>
                <os>linux</os>
            </platform>
        </platforms>
    </from>
</configuration>

Popular Base Images:

  • eclipse-temurin:17-jre - OpenJDK 17 (recommended for most apps)
  • eclipse-temurin:21-jre - OpenJDK 21 (latest LTS)
  • gcr.io/distroless/java17-debian12 - Minimal distroless image (most secure)
  • amazoncorretto:17 - Amazon's OpenJDK distribution
  • azul/zulu-openjdk:17-jre - Azul's OpenJDK build
3. To Configuration (Target Image)

Configure where and how your built image will be stored:

<configuration>
    <to>
        <!-- Target image name -->
        <image>myregistry.io/myapp</image>
        
        <!-- Image tags -->
        <tags>
            <tag>latest</tag>
            <tag>${project.version}</tag>
            <tag>${git.commit.id.abbrev}</tag>
        </tags>
        
        <!-- Registry authentication -->
        <auth>
            <username>${env.DOCKER_USERNAME}</username>
            <password>${env.DOCKER_PASSWORD}</password>
        </auth>
        
        <!-- Credential helper (alternative to username/password) -->
        <credHelper>ecr-login</credHelper>
    </to>
</configuration>

Registry Examples:

  • Docker Hub: docker.io/username/myapp
  • GitHub Container Registry: ghcr.io/username/myapp
  • Amazon ECR: 123456789.dkr.ecr.us-east-1.amazonaws.com/myapp
  • Google Artifact Registry: us-docker.pkg.dev/project-id/repo/myapp
  • Azure Container Registry: myregistry.azurecr.io/myapp

Credential Helpers:

  • ecr-login - AWS ECR
  • gcr - Google Container Registry
  • osxkeychain - macOS Keychain
  • wincred - Windows Credential Manager
  • pass - Linux pass utility

Alternative Authentication Methods

Jib supports multiple ways to authenticate with registries:

1. Docker Config File (Recommended for Local Development):

# Login via Docker CLI - credentials saved to ~/.docker/config.json
docker login myregistry.io

# Jib automatically reads credentials from Docker config
mvn jib:build

2. Maven settings.xml (Recommended for CI/CD):

<!-- ~/.m2/settings.xml -->
<settings>
    <servers>
        <server>
            <id>docker.io</id>
            <username>${env.DOCKER_USERNAME}</username>
            <password>${env.DOCKER_PASSWORD}</password>
        </server>
        <server>
            <id>ghcr.io</id>
            <username>${env.GITHUB_ACTOR}</username>
            <password>${env.GITHUB_TOKEN}</password>
        </server>
        <server>
            <id>gcr.io</id>
            <username>_json_key</username>
            <password>${env.GOOGLE_APPLICATION_CREDENTIALS}</password>
        </server>
    </servers>
</settings>

3. Command-Line (For Quick Testing):

mvn jib:build \
  -Djib.to.auth.username=$USERNAME \
  -Djib.to.auth.password=$PASSWORD

4. Environment Variables (CI/CD):

<to>
    <auth>
        <username>${env.REGISTRY_USERNAME}</username>
        <password>${env.REGISTRY_PASSWORD}</password>
    </auth>
</to>

Authentication Priority Order:

  1. Explicit <auth> in pom.xml configuration
  2. Command-line properties (-Djib.to.auth.username)
  3. Maven settings.xml server credentials
  4. Credential helpers (ecr-login, gcr, etc.)
  5. Docker config file (~/.docker/config.json)
4. Container Configuration

Configure runtime container settings:

<configuration>
    <container>
        <!-- JVM Flags -->
        <jvmFlags>
            <jvmFlag>-Xms512m</jvmFlag>
            <jvmFlag>-Xmx1024m</jvmFlag>
            <jvmFlag>-XX:+UseG1GC</jvmFlag>
            <jvmFlag>-XX:MaxGCPauseMillis=100</jvmFlag>
            <jvmFlag>-Djava.security.egd=file:/dev/./urandom</jvmFlag>
        </jvmFlags>
        
        <!-- Main class (auto-detected if not specified) -->
        <mainClass>com.example.Application</mainClass>
        
        <!-- Application arguments -->
        <args>
            <arg>--spring.profiles.active=prod</arg>
            <arg>--server.port=8080</arg>
        </args>
        
        <!-- Exposed ports -->
        <ports>
            <port>8080</port>
            <port>8081</port>
        </ports>
        
        <!-- Environment variables -->
        <environment>
            <SPRING_PROFILES_ACTIVE>production</SPRING_PROFILES_ACTIVE>
            <JAVA_TOOL_OPTIONS>-XX:+UseContainerSupport</JAVA_TOOL_OPTIONS>
            <TZ>UTC</TZ>
        </environment>
        
        <!-- Labels (metadata) -->
        <labels>
            <maintainer>team@example.com</maintainer>
            <version>${project.version}</version>
            <description>My Spring Boot Application</description>
            <org.opencontainers.image.source>https://github.com/user/repo</org.opencontainers.image.source>
        </labels>
        
        <!-- Working directory -->
        <workingDirectory>/app</workingDirectory>
        
        <!-- User (run as non-root) -->
        <user>1000:1000</user>
        
        <!-- Image format -->
        <format>OCI</format> <!-- or Docker -->
        
        <!-- Creation time (for reproducibility) -->
        <creationTime>USE_CURRENT_TIMESTAMP</creationTime>
        <!-- or EPOCH_PLUS_SECOND for reproducible builds -->
        
        <!-- Volumes -->
        <volumes>
            <volume>/tmp</volume>
            <volume>/app/logs</volume>
        </volumes>
        
        <!-- Entrypoint (overrides default) -->
        <entrypoint>
            <shell>bash</shell>
            <option>-c</option>
            <arg>/app/startup.sh</arg>
        </entrypoint>
        
        <!-- File modification time -->
        <filesModificationTime>EPOCH_PLUS_SECOND</filesModificationTime>
        
        <!-- App root directory in container -->
        <appRoot>/app</appRoot>
    </container>
</configuration>

Key Configuration Options Explained:

  • jvmFlags: JVM memory settings, garbage collection, system properties
  • mainClass: Entry point class (auto-detected from manifest if not specified)
  • args: Command-line arguments passed to the application
  • ports: Exposed ports (metadata only, doesn't publish ports)
  • environment: Environment variables available at runtime
  • labels: OCI image labels for metadata and documentation
  • user: User ID and group ID to run as (security best practice)
  • format: OCI (recommended) or Docker format
  • creationTime: Image creation timestamp (affects reproducibility)
  • volumes: Mount points for persistent data
  • appRoot: Where application files are placed in the container
5. Extra Directories Configuration

Add additional files and directories to your image:

<configuration>
    <extraDirectories>
        <!-- Simple path -->
        <paths>
            <path>src/main/jib</path>
        </paths>
        
        <!-- Advanced: Multiple paths with different targets -->
        <paths>
            <path>
                <from>src/main/custom-files</from>
                <into>/app/config</into>
            </path>
            <path>
                <from>scripts</from>
                <into>/app/scripts</into>
                <includes>*.sh</includes>
                <excludes>test-*.sh</excludes>
            </path>
        </paths>
        
        <!-- Set permissions for files -->
        <permissions>
            <permission>
                <file>/app/scripts/startup.sh</file>
                <mode>755</mode>
            </permission>
            <permission>
                <file>/app/config/*</file>
                <mode>644</mode>
            </permission>
        </permissions>
    </extraDirectories>
</configuration>

Common Use Cases:

  • Add configuration files (application.yml, logback.xml)
  • Include startup scripts or health check scripts
  • Add SSL certificates or keystores
  • Include static resources or templates
  • Add monitoring agents (APM tools, Prometheus exporters)
6. Output Paths Configuration

Configure where Jib stores build artifacts:

<configuration>
    <outputPaths>
        <!-- Where to save the image digest -->
        <digest>${project.build.directory}/jib-image.digest</digest>
        
        <!-- Where to save the image ID -->
        <imageId>${project.build.directory}/jib-image.id</imageId>
        
        <!-- Where to save the image JSON -->
        <imageJson>${project.build.directory}/jib-image.json</imageJson>
        
        <!-- Tarball output location (for jib:buildTar) -->
        <tar>${project.build.directory}/jib-image.tar</tar>
    </outputPaths>
</configuration>

Why Use Output Paths:

  • Track image digests for deployment verification
  • Use image ID in subsequent CI/CD steps
  • Store image metadata for auditing
  • Generate SBOM (Software Bill of Materials)
7. Plugin Extensions

Extend Jib functionality with custom plugins:

<configuration>
    <pluginExtensions>
        <pluginExtension>
            <implementation>com.google.cloud.tools.jib.maven.extension.nativeimage.JibNativeImageExtension</implementation>
        </pluginExtension>
    </pluginExtensions>
</configuration>

Available Extensions:

  • Native Image Extension: Build GraalVM native images
  • Ownership Extension: Set file ownership in images
  • Layer Filter Extension: Customize layer creation
  • Custom Extensions: Create your own Jib extensions
Additional Configuration Options

Container Entrypoint Modes

<container>
    <!-- Default: Java mode (recommended) -->
    <entrypoint>INHERIT</entrypoint>
    
    <!-- Custom shell entrypoint -->
    <entrypoint>
        <shell>sh</shell>
        <option>-c</option>
        <arg>java $JAVA_OPTS -jar /app/app.jar</arg>
    </entrypoint>
    
    <!-- Exec form (no shell) -->
    <entrypoint>
        <exec>
            <arg>java</arg>
            <arg>-jar</arg>
            <arg>/app/app.jar</arg>
        </exec>
    </entrypoint>
</container>

Layering Configuration

<containerizingMode>exploded</containerizingMode>
<!-- Options: exploded (default), packaged -->

<!-- Custom layer configuration -->
<extraDirectories>
    <paths>
        <path>
            <from>target/dependencies</from>
            <into>/app/libs</into>
        </path>
    </paths>
</extraDirectories>

Build Configuration

<configuration>
    <!-- Allow insecure registries (not recommended for production) -->
    <allowInsecureRegistries>false</allowInsecureRegistries>
    
    <!-- Skip building the image (useful for multi-module projects) -->
    <skip>false</skip>
    
    <!-- Offline mode -->
    <offline>false</offline>
    
    <!-- Use only project cache -->
    <useOnlyProjectCache>false</useOnlyProjectCache>
    
    <!-- Send credentials over HTTP (insecure) -->
    <sendCredentialsOverHttp>false</sendCredentialsOverHttp>
</configuration>

Using Skip in Multi-Module Projects:

<!-- In parent pom.xml - skip by default -->
<plugin>
    <groupId>com.google.cloud.tools</groupId>
    <artifactId>jib-maven-plugin</artifactId>
    <version>3.4.0</version>
    <configuration>
        <skip>true</skip>
    </configuration>
</plugin>

<!-- In child module pom.xml - enable for specific modules -->
<plugin>
    <groupId>com.google.cloud.tools</groupId>
    <artifactId>jib-maven-plugin</artifactId>
    <configuration>
        <skip>false</skip>
        <to>
            <image>myregistry.io/${project.artifactId}</image>
        </to>
    </configuration>
</plugin>

<!-- Or skip from command line -->
<!-- mvn package -Djib.skip=true -->

9. Command-Line Overrides

Override pom.xml configuration from the command line:

# Override target image
mvn jib:build -Dimage=myregistry.io/myapp:v2.0

# Set JVM flags
mvn jib:build -Djib.container.jvmFlags=-Xmx1g,-Xms512m

# Set environment variables
mvn jib:build -Djib.container.environment=ENV=prod,DEBUG=false

# Set ports
mvn jib:build -Djib.container.ports=8080,9090

# Override base image
mvn jib:build -Djib.from.image=eclipse-temurin:21-jre

# Set main class
mvn jib:build -Djib.container.mainClass=com.example.Main

# Set creation time
mvn jib:build -Djib.container.creationTime=USE_CURRENT_TIMESTAMP

# Skip Jib execution
mvn package -Djib.skip=true

# Use specific credentials
mvn jib:build \
  -Djib.to.auth.username=$USERNAME \
  -Djib.to.auth.password=$PASSWORD

# Build to Docker daemon
mvn jib:dockerBuild -Dimage=myapp:local

# Build as tarball
mvn jib:buildTar -Djib.outputPaths.tar=target/myapp.tar

Common Command-Line Properties:

  • -Dimage - Target image name
  • -Djib.from.image - Base image
  • -Djib.to.tags - Image tags (comma-separated)
  • -Djib.container.jvmFlags - JVM flags (comma-separated)
  • -Djib.container.environment - Environment variables
  • -Djib.container.ports - Exposed ports
  • -Djib.container.user - Container user
  • -Djib.skip - Skip Jib execution
  • -Djib.allowInsecureRegistries - Allow HTTP registries
10. Best Practices & Recommendations

Security Best Practices

  • Use Distroless Images: Minimal attack surface, no shell or package managers
  • Run as Non-Root: Always set <user>nonroot:nonroot</user>
  • Never Hardcode Credentials: Use environment variables or credential helpers
  • Scan for Vulnerabilities: Integrate Trivy, Grype, or Snyk in CI/CD
  • Use Specific Tags: Avoid latest tag in production
  • Sign Images: Use Cosign or Notary for image signing

Performance Best Practices

  • Use Appropriate Base Image: JRE for runtime, not JDK
  • Optimize JVM Flags: Set memory limits matching container resources
  • Enable Container Support: -XX:+UseContainerSupport
  • Use Percentage-Based Memory: -XX:MaxRAMPercentage=75.0
  • Leverage Caching: Don't disable Jib's caching mechanism
  • Minimize Extra Files: Only include necessary files

Reproducibility Best Practices

  • Pin Base Image Versions: Use digest instead of tags
  • Set Creation Time: Use EPOCH_PLUS_SECOND for reproducible builds
  • Lock Dependencies: Use dependency lock files
  • Document Configuration: Comment your pom.xml settings

CI/CD Best Practices

  • Use Multi-Stage Tagging: Tag with version, commit SHA, and build number
  • Store Image Digests: Use outputPaths for deployment tracking
  • Implement Image Scanning: Scan before pushing to production
  • Use Credential Helpers: Avoid storing passwords in CI/CD
  • Cache Between Builds: Configure CI to cache Jib layers

Troubleshooting Configuration Issues

Enable Verbose Logging

mvn jib:build -X

Common Issues & Solutions

  • Authentication Failed:
    • Verify credentials in environment variables
    • Use credential helpers: <credHelper>ecr-login</credHelper>
    • Check registry URL format
  • Base Image Pull Failed:
    • Verify base image exists and is accessible
    • Check network connectivity and proxy settings
    • Add authentication if using private base image
  • Main Class Not Found:
    • Explicitly set <mainClass> in configuration
    • Verify the class has a main method
    • Check package name is correct
  • Out of Memory During Build:
    • Increase Maven memory: MAVEN_OPTS="-Xmx2g"
    • Use useOnlyProjectCache to reduce memory usage

Quick Reference Commands

mvn compile jib:buildTar
