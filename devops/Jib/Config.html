-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
from.image                       -> It specifies the base image, same as FROM in dockerfile; Defaults to adoptopenjdk:jre-8 for JARs, jetty for WARs;
from.auth.username/password      -> You can specify repo username/password in configuration;
                                    You can specify username/password from command line as well, using jib.from.auth.username and jib.from.auth.password; 
                                    Alternatively, run docker login, it saves credentials to ~/.docker/config.json; Once you login, jib autoatmically recognises you;
                                    Alternatively, you can specify it in .m2/settings.xml as well;

to.tags                         -> If you don't specify tag in to.image, then latest tag is not needed; It defaults to latest; YOu can give more than 1 tag;
to.auth.username/password       -> You can specify repo username/password in configuration OR from command line as well; jib.to.auth.username and jib.to.auth.password;

container.appRoot               -> Directory in the container, where out application files are copied; Defaults to /app, useful for war containers;
container.workingDirectory      ->
container.labels                -> Similar to LABELS in dockerfile, you can add 1 or more labels to an image;


Ports are equivalent to EXPOSE instruction in Docker to open up a port inside your container. 
Finally, the user or group the container will run as. The value can be a username along with an optional group name. It is a best practice to set this as something so your containers are not run as root.



You’ll also note there is no RUN command equivalent like you would typically use for something like an apt-get in a traditional Dockerfile. This is because the Jib team noted that these slow builds and should be done in a base image that you would use for your Jib image.
