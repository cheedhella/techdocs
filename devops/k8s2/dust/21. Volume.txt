Ephemeral Volumes
	- Ephemeral means short-lived; 
	- 2 types: emptyDir, hostPath;
	- emptyDir is nothing but an empty directory is created, when the Pod is created; It is destroyed, when the Pod is destroyed;
	- hostPath is file/directory that exists on the host/Node; Any content written by a Pod is available, as long as the Pod is running on that Node;

Why, on eath, anyone would need a storage which by nature is ephemral, and no longer exists when Pod is destroyed OR Node is down?
	- For storing intermediate results, in case of disk-based merge sort etc;
	- For checkpointing a long computation, for recovery from crashes;
--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
emptyDir Volume
	It is a temporary directory that is created, when the Pod is created;
	It is empty, when the Pod starts; It exists as long as the Pod is running;
	All containers in the Pod can read from and write to the files in it;
	By default, data is stored on the disk; You can change it to RAM for faster read/writes;
	Data written by a container is available to all other containers in the same Pod;
	It is deleted, when Pod is deleted or rescheduled;

When to use emptyDir volume?
	- Sharing files between the contains in the same Pod;
	- Temporary storage;




	
	It is created when the Pod is created and 
	
	
	exists as long as that Pod is running;
	When the Pod is removed from a node for any reason, the data in the emptyDir is deleted permanently;
	Initially, it is empty; 
	
	By default, data is saved to whatever medium backing the Node - disk or SSD or network storage, depending on environment;
	You can also set emptyDir.medium to Memory, which uses RAM for high performance;

	

Kubernetes supports many volume types: emptyDir, hostPath, configMap, secret, persistentVolumeClaim, etc.


# emptyDir volume - Disk based

> cat ed-demo-p1-v1.yaml 
apiVersion: v1
kind: Pod
metadata:
  name: ed-demo-p1
spec:
  containers:
    - image: nginx
      name: ed-demo-p1-v1
      volumeMounts:                   # Array of volumes that this container needs;
        - mountPath: /data            # Volume named ed-demo-p1-v1 will be mounted at /data inside this Container;
          name: ed-demo-p1-v1
  volumes:
    - name: ed-demo-p1-v1             # Name of volume;
      emptyDir: {}                    # {} object indicates to use default options(i.e, disk based storage);
---

# Demo - RAM as emptyDir volume
-------------------------------
> cat ed-demo-p2.yaml
apiVersion: v1
kind: Pod
metadata:
  name: ed-demo-p2
spec:
  containers:
    - image: nginx
      name: ed-demo-p2-c1
      volumeMounts:
        - mountPath: /cache
          name: ed-demo-p2-v1
  volumes:
    - name: ed-demo-p2-v1             # 
      emptyDir:
        medium: Memory                # K8s mounts a tmpfs (RAM-backed filesystem); 
                                      # While tmpfs is very fast, be aware that, unlike disks, tmpfs is cleared on node reboot; 
                                      # Any files you write count against your container’s memory limit;

> kubectl apply -f ed-demo-p2.yaml
pod/ed-demo-p2 created

> kubectl get pods
NAME                 READY   STATUS    RESTARTS   AGE
ed-demo-p2           1/1     Running   0          57s

> kubectl exec -it ed-demo-p2 -- /bin/bash

root@ed-demo-p2:/# mount | grep -i cache
tmpfs on /cache type tmpfs (rw,relatime,size=3935088k)


# Demo - data sharing - One container writes to emptyDir volume, another reads it!
----------------------------------------------------------------------------------
> cat ed-demo-p3.yaml
# Data in a emptyDir is shared b/w all containers in that Pod;
apiVersion: v1
kind: Pod
metadata:
  name: ed-demo-p3
spec:
  containers:
    - name: busybox-a
      command: ['tail', '-f', '/dev/null']
      image: busybox
      volumeMounts:
        - name: cache
          mountPath: /cache
    - name: busybox-b
      command: ['tail', '-f', '/dev/null']
      image: busybox
      volumeMounts:
        - name: cache
          mountPath: /cache
  volumes:
    - name: cache
      emptyDir: {}
	  
> kubectl apply -f ed-demo-p3.yaml 
pod/ed-demo-p3 created

> kubectl get pods
NAME                 READY   STATUS    RESTARTS      AGE
ed-demo-p3           2/2     Running   0             2m32s

> kubectl exec ed-demo-p3 --container busybox-a -- sh -c "echo 'Hello World' > /cache/hello.txt"

> kubectl exec ed-demo-p3 --container busybox-b -- cat /cache/hello.txt
Hello World

hostPath Volume
	It mounts a file or directory from the host filesystem onto your Pod; Any data written to hostPath volume is not available, if the Pod gets scheduled on a different node;
