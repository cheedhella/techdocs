release1 vs release2 vs release 3
	In release1, all data generated is stored in-memory and eventually pod gets out-of-memory soon; If you restart the pods, all historical data is gone!
	In release3, position-tracker is responsible for calculating the speeds of vehicles and for storing histories of the vehicles, in a mongo db;

# Step #6: Bring up MongoDB deployment!
---------------------------------------
> kubectl apply -f mongo-stack.yaml 
deployment.apps/mongodb-deployment created
service/fleetman-mongodb created

# Now, try restarting position-tracker pod, you should see Fleet Manager UI picking up the history from MongoDB;
--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
But, that's not enough! If the MongoDB container dies, ofcourse it gets restarted, but, data will die with it;
> kubectl delete -f <mongo-db-pod>


In this step, we are going to deploy a MongoDB container, which stores all of the data in some kind of directory, inside the Mongo container;
Now, the requirement is to store the history of vehicles permanently;
For that, we will setup a Persistent Volume, and instruct MongoDB to store data in that, where data is stored permanently;
Persistent Volume could be any storage such as AWS EBS(Elastic Block Storage) etc;

> kubectl apply -f 7.storage.yaml 
persistentvolumeclaim/mongo-pvc created
persistentvolume/local-storage created

> kubectl get pvc
NAME        STATUS   VOLUME          CAPACITY   ACCESS MODES   STORAGECLASS     AGE
mongo-pvc   Bound    local-storage   20Gi       RWO            mylocalstorage   2m28s
