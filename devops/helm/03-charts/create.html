Creating a Chart

1. helm create — Scaffold a New Chart
  • helm create <chart-name>
  • Generates a chart directory with the standard structure and commonly used files;
  • The default scaffold deploys an Nginx application with Deployment, Service, ServiceAccount, Ingress, and HPA;
  • > helm create hello-world
Creating hello-world

> ls -a hello-world/
.helmignore  Chart.yaml  charts/  templates/  values.yaml

> ls hello-world/templates/
NOTES.txt  _helpers.tpl  deployment.yaml  hpa.yaml  ingress.yaml  service.yaml  serviceaccount.yaml  tests/
2. Understanding the Generated Files
  • Chart.yaml — contains chart metadata: 
    apiVersion: v2
name: hello-world
description: A Helm chart for Kubernetes
type: application
version: 0.1.0
appVersion: "1.16.0"
  • values.yaml — default configuration. Templates reference these values via {{ .Values.<key> }}: 
    replicaCount: 1

image:
  repository: nginx
  pullPolicy: IfNotPresent
  tag: ""            # When empty, defaults to appVersion in Chart.yaml

serviceAccount:
  create: true
  annotations: {}
  name: ""

service:
  type: ClusterIP
  port: 80

ingress:
  enabled: false

autoscaling:
  enabled: false
  minReplicas: 1
  maxReplicas: 100
  targetCPUUtilizationPercentage: 80
  • image.tag — when left empty, the deployment template defaults to .Chart.AppVersion;
3. Customizing the Chart — Example: Deploy a Custom App
  • Say you have a Docker image myuser/myapp:2.0.0 on Docker Hub. Edit the generated chart:
  • Step 1: Update Chart.yaml 
    apiVersion: v2
name: myapp
description: My custom application chart
type: application
version: 0.1.0
appVersion: "2.0.0"
  • Step 2: Update values.yaml 
    replicaCount: 2

image:
  repository: myuser/myapp
  pullPolicy: IfNotPresent
  tag: "2.0.0"

service:
  type: ClusterIP
  port: 8080

ingress:
  enabled: true
  className: nginx
  hosts:
    - host: myapp.example.com
      paths:
        - path: /
          pathType: Prefix

resources:
  limits:
    cpu: 200m
    memory: 256Mi
  requests:
    cpu: 100m
    memory: 128Mi
  • Step 3: Customize templates as needed (e.g., add a ConfigMap, adjust health checks in deployment.yaml);
4. Validating the Chart
  • # Lint the chart — checks for errors and best practices
helm lint ./myapp

# Render templates locally without installing (dry run)
helm template myrelease ./myapp

# Render with custom values
helm template myrelease ./myapp -f production-values.yaml

# Dry run against the cluster (validates against k8s API server)
helm install myrelease ./myapp --dry-run --debug
5. Packaging the Chart
  • # Package the chart into a .tgz file
helm package ./myapp
# Successfully packaged chart and saved it to: /current/dir/myapp-0.1.0.tgz

# Package to a specific directory
helm package ./myapp -d /path/to/output/

# Package with a different app version
helm package ./myapp --app-version 2.1.0

# Package with a different chart version
helm package ./myapp --version 1.0.0
  • The output file name follows the format: <chart-name>-<chart-version>.tgz;
  • Files matching patterns in .helmignore are excluded;
6. Pushing to Docker Hub (OCI Registry)
  • Step 1: Login to Docker Hub 
    helm registry login registry-1.docker.io
# Username: myuser
# Password: ****
  • Step 2: Package the chart (if not already) 
    helm package ./myapp
# myapp-0.1.0.tgz
  • Step 3: Push to Docker Hub 
    helm push myapp-0.1.0.tgz oci://registry-1.docker.io/myuser
  • The chart will be stored at: oci://registry-1.docker.io/myuser/myapp with tag 0.1.0;
  • The chart name comes from Chart.yaml, the tag comes from the chart version;
  • You only specify the namespace in the URL, NOT the chart name or version;
  • Step 4: Verify it was pushed 
    # Pull it back to verify
helm pull oci://registry-1.docker.io/myuser/myapp --version 0.1.0

# Show chart info from registry
helm show chart oci://registry-1.docker.io/myuser/myapp --version 0.1.0
  • Step 5: Others can now install your chart 
    helm install myrelease oci://registry-1.docker.io/myuser/myapp --version 0.1.0
7. Pushing to Other OCI Registries
  • # AWS ECR
aws ecr get-login-password --region us-east-1 | helm registry login \
  --username AWS --password-stdin 123456789.dkr.ecr.us-east-1.amazonaws.com
helm push myapp-0.1.0.tgz oci://123456789.dkr.ecr.us-east-1.amazonaws.com

# GitHub Container Registry (GHCR)
echo $GITHUB_TOKEN | helm registry login ghcr.io --username myuser --password-stdin
helm push myapp-0.1.0.tgz oci://ghcr.io/myuser

# Azure ACR
helm registry login myregistry.azurecr.io --username myuser --password mypass
helm push myapp-0.1.0.tgz oci://myregistry.azurecr.io/charts

# Google Artifact Registry
gcloud auth print-access-token | helm registry login \
  -u oauth2accesstoken --password-stdin us-central1-docker.pkg.dev
helm push myapp-0.1.0.tgz oci://us-central1-docker.pkg.dev/myproject/myrepo
8. Pushing New Versions
  • When you update your chart, increment the version and push again:
  • Step 1: Update Chart.yaml version 
    version: 0.2.0        # bumped from 0.1.0
appVersion: "2.1.0"   # updated app version
  • Step 2: Package and push 
    helm package ./myapp
# myapp-0.2.0.tgz

helm push myapp-0.2.0.tgz oci://registry-1.docker.io/myuser
  • Both versions (0.1.0 and 0.2.0) now exist in the registry as separate tags;
  • Users can install any specific version using --version;
9. Complete Workflow — From Scratch to Docker Hub
  • # 1. Create the chart
helm create myapp

# 2. Customize Chart.yaml, values.yaml, and templates
#    (edit files as needed)

# 3. Lint and validate
helm lint ./myapp
helm template myrelease ./myapp

# 4. Test locally (install on local cluster)
helm install myrelease ./myapp
helm test myrelease

# 5. Package
helm package ./myapp

# 6. Login and push to Docker Hub
helm registry login registry-1.docker.io
helm push myapp-0.1.0.tgz oci://registry-1.docker.io/myuser

# 7. Verify
helm show chart oci://registry-1.docker.io/myuser/myapp --version 0.1.0

# 8. Logout
helm registry logout registry-1.docker.io
10. Quick Reference
  • helm create <name>                              # Scaffold a new chart
helm lint <chart-dir>                            # Validate chart structure and syntax
helm template <release> <chart-dir>              # Render templates locally
helm install <release> <chart-dir> --dry-run     # Validate against k8s API
helm package <chart-dir>                         # Package into .tgz
helm package <chart-dir> -d <output-dir>         # Package to specific directory
helm package <chart-dir> --app-version <ver>     # Override appVersion during packaging
helm registry login <registry>                   # Authenticate to OCI registry
helm push <tgz> oci://<registry>/<namespace>    # Push chart to OCI registry
helm registry logout <registry>                  # Logout from OCI registry
