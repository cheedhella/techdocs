Helm Linting

1. helm lint
  • It validates the chart for syntax errors, missing required fields and best practices;
  • It is recommended to run linting before pushing the chart to repository, installation, or upgrade;
  • Syntax: 
    helm lint
  • It’s commonly run in CI/CD pipelines before deploying helm charts;
  • Note: It never connects to k8s cluster, it does it's job on your local machine; Use --dry-run if needed;
2. What all does it check?
  • It checks the chart directory structure(for any missing files or directories);
  • It checks the syntax of all the YAML files(Chart.yaml, values.yaml, template YAML files etc);
  • It validates the syntax of all Go template expressions in the templates/ directory;
  • It checks Chart.yaml for required fields like name, version, and apiVersion;
  • It checks if the dependencies defined in Chart.yaml are present in the charts/ directory or not;
  • It checks if the dependencies are valid(such as version, repository, condition etc);
  • It converts the template files into k8s manifest files and checks the syntax of the generated k8s manifest files;
    • It checks the syntax of the generated k8s manifest files;
    • It checks each k8s object contains the required fields(such as apiVersion, kind, metadata, spec etc);
    • It ensures every k8s object is named as per DNS naming conventions(only alphanumeric, lowercase and hyphen characters); It should not exceed 253 characters;
  • It checks for below best practices and warns:
    • Missing icon, maintainers, description in Chart.yaml;
    • Chart version not following semantic versioning(MAJOR.MINOR.PATCH);
3. Options
  • --strict - It treats warnings as errors, so that best practices are enforced; It is useful in CI/CD pipelines;
  • --with-subcharts - It lints the chart and all its subcharts(dependencies);
  • -f values.yaml - It renders the templates with values.yaml and check their validity;
  • -n - Some templates(like .Release.Namespace) require namespace to be set; helm needs namespace to be set before linting; It doesn't check if the namespace exists in the cluster;
