Chart Overview

1. What is a Chart?
  • A chart is a package that contains everything(templates/YAML files, values, dependencies, etc) needed to deploy an application on a k8s cluster;
2. Why are Charts needed?
  • To run an application on k8s, you need to define many objects (Deployment, Service, ConfigMap, Secret, Ingress, PVC, etc.) in separate YAML files;
  • As the project grows, the number of YAML files increases and it becomes hard to maintain;
  • A chart bundles all these resource files into a single versioned package that can be deployed with one command;
  • Charts also allow parameterization — the same chart can be deployed with different configurations for dev, staging, and production by simply overriding values;
3. Chart Directory Structure
mychart/
├── .helmignore          # Files to ignore when packaging (like .gitignore)
├── Chart.yaml           # Chart metadata: name, version, appVersion, dependencies, etc.
├── Chart.lock           # Locked dependency versions (auto-generated by helm dependency update)
├── values.yaml          # Default configuration values for the templates
├── README.md            # Human-readable documentation
├── LICENSE              # License for the chart
│
├── charts/              # Dependency charts (.tgz packages or unpacked chart directories)
│
├── crds/                # Custom Resource Definitions (installed before templates are rendered)
│
└── templates/           # Kubernetes resource templates
    ├── deployment.yaml
    ├── service.yaml
    ├── ingress.yaml
    ├── hpa.yaml
    ├── serviceaccount.yaml
    ├── configmap.yaml
    ├── secret.yaml
    ├── NOTES.txt        # Post-install/upgrade instructions (rendered but not sent to k8s)
    ├── _helpers.tpl     # Reusable named templates and partials
    │
    └── tests/           # Test pods to verify the installation (run via helm test)
        └── test-connection.yaml
4. Chart.yaml

It contains metadata about the chart:

apiVersion: v2                    # v2 for Helm 3 charts (v1 for Helm 2)
name: mychart
description: A Helm chart for my application
type: application                 # application | library
version: 0.1.0                   # Chart version (SemVer) — increment on every chart change
appVersion: "1.0.0"              # Version of the application being deployed
keywords:
  - web
  - nginx
home: https://example.com
sources:
  - https://github.com/example/mychart
maintainers:
  - name: John Doe
    email: john@example.com
dependencies:
  - name: redis
    version: "18.x.x"
    repository: "https://charts.bitnami.com/bitnami"
    condition: redis.enabled

Key fields:

  • apiVersion — must be v2 for Helm 3 charts;
  • name — name of the chart;
  • type:
    • application (default) — can be deployed to a cluster;
    • library — provides utility functions only; cannot be installed on its own; application charts can depend on library charts;
  • version — version of the chart itself (SemVer: Major.Minor.Patch); must be incremented each time you change the chart, including its templates or appVersion;
  • appVersion — version of the application the chart deploys; informational only — Helm doesn't use it for anything;
    • Override at package time: helm package . --app-version 9.1.2
    • Override at install/upgrade time: helm upgrade <release> <chart> --set "image.tag=9.1.2"
  • dependencies — list of charts this chart depends on; downloaded to charts/ via helm dependency update;
5. values.yaml
  • Contains default configuration values for the chart's templates;
  • Templates reference values using {{ .Values.<key> }};
  • You never need to edit the template files — just change values;
# values.yaml
replicaCount: 1

image:
  repository: nginx
  tag: "1.25.3"
  pullPolicy: IfNotPresent

service:
  type: ClusterIP
  port: 80

ingress:
  enabled: false

resources:
  limits:
    cpu: 100m
    memory: 128Mi
  requests:
    cpu: 100m
    memory: 128Mi

autoscaling:
  enabled: false
  minReplicas: 1
  maxReplicas: 10
  targetCPUUtilizationPercentage: 80

How to override values:

# Override with a file
helm install myrelease mychart -f custom-values.yaml

# Override individual values
helm install myrelease mychart --set replicaCount=3 --set service.type=NodePort

# Multiple value files (later files take precedence)
helm install myrelease mychart -f base.yaml -f production.yaml
6. templates/ Directory
  • Contains Kubernetes resource templates (Deployment, Service, Ingress, HPA, etc.);
  • Templates combined with values.yaml produce valid k8s manifest files;
  • Helm runs each file through the Go template rendering engine;
  • Files starting with _ (e.g., _helpers.tpl) do NOT produce k8s manifest output — they contain reusable named templates;

Key files in templates/:

  • deployment.yaml — defines the desired state of the application: replicas, rolling updates, scaling, health checks, resource limits;
  • service.yaml — defines a stable network endpoint for accessing the deployment;
  • ingress.yaml — provides routing rules for incoming external traffic;
  • hpa.yaml — sets up automatic scaling based on resource utilization;
  • serviceaccount.yaml — creates a k8s service account for the application;
  • NOTES.txt — rendered like other templates, but output is printed to the user after install/upgrade (not sent to k8s); useful for displaying access instructions;
  • _helpers.tpl — reusable template snippets (e.g., generating labels, fullname); included by other templates using {{ include "mychart.fullname" . }};
  • tests/ — contains test pod definitions run by helm test to verify an installation;
7. charts/ Directory
  • Contains dependency charts — either as .tgz packages or unpacked chart directories;
  • Populated by helm dependency update, which reads the dependencies section in Chart.yaml and downloads them here;
  • You can also manually place chart directories here;
# Download dependencies declared in Chart.yaml
helm dependency update ./mychart

# List current dependencies
helm dependency list ./mychart
8. .helmignore
  • Works like .gitignore — specifies files to exclude when packaging the chart with helm package;
  • One pattern per line;
# .helmignore
.git
.gitignore
*.swp
*.bak
.idea/
.vscode/
9. Chart Types
Type Description
Application Chart Default type; can be deployed to a cluster; contains templates that produce k8s resources;
Library Chart Provides reusable template helpers only; cannot be deployed on its own; other charts depend on it;
Subchart A chart included as a dependency inside another chart's charts/ directory;
Umbrella Chart A chart that groups multiple subcharts together for deploying a multi-component application;
Parent Chart The main chart that includes subcharts; it can override subchart values in its own values.yaml;
10. Chart Versioning
  • Charts follow Semantic Versioning (SemVer): Major.Minor.Patch;
  • version (in Chart.yaml) — the chart's own version; increment whenever you change anything in the chart;
  • appVersion (in Chart.yaml) — the version of the application being deployed; informational, not used by Helm;
  • These two versions are independent — you can bump chart version without changing appVersion and vice versa;
# Example: Chart at version 2.3.1 deploying app version 5.0.0
version: 2.3.1
appVersion: "5.0.0"
11. Chart.lock
  • Auto-generated by helm dependency update;
  • Locks the exact versions of dependencies that were resolved;
  • Ensures reproducible builds — running helm dependency build uses Chart.lock to download the exact same versions;
# Chart.lock (auto-generated, do not edit)
dependencies:
- name: redis
  repository: https://charts.bitnami.com/bitnami
  version: 18.1.2
digest: sha256:abc123def456
generated: "2026-03-01T10:00:00Z"
helm dependency update ./mychart   # Resolves deps, downloads to charts/, updates Chart.lock
helm dependency build ./mychart    # Downloads deps using exact versions from Chart.lock
