Chart Management

1. Installing a Chart — helm install
  • # Install from OCI registry (Docker Hub, ECR, GHCR, etc.)
helm install myrelease oci://registry-1.docker.io/myuser/myapp --version 0.1.0

# Install from a traditional Helm repository
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update
helm install myrelease bitnami/nginx

# Install from a local chart directory
helm install myrelease ./myapp

# Install from a .tgz package
helm install myrelease myapp-0.1.0.tgz

# Install from a direct URL
helm install myrelease https://charts.bitnami.com/bitnami/nginx-15.2.3.tgz
  • myrelease is the release name — a unique identifier for this deployment;
  • You can install the same chart multiple times with different release names;
  • Each install creates a new release tracked by Helm (stored as a k8s Secret);
2. Install Options
  • # Override values with a file
helm install myrelease oci://registry-1.docker.io/myuser/myapp -f custom-values.yaml

# Override individual values
helm install myrelease oci://registry-1.docker.io/myuser/myapp --set replicaCount=3

# Override multiple values
helm install myrelease oci://registry-1.docker.io/myuser/myapp \
  --set service.type=NodePort --set service.port=8080

# Install into a specific namespace (creates namespace if --create-namespace is used)
helm install myrelease oci://registry-1.docker.io/myuser/myapp \
  -n production --create-namespace

# Auto-generate release name
helm install oci://registry-1.docker.io/myuser/myapp --generate-name

# Wait for all resources to be ready before marking as successful
helm install myrelease oci://registry-1.docker.io/myuser/myapp --wait --timeout 5m

# Dry run — render and validate without actually installing
helm install myrelease oci://registry-1.docker.io/myuser/myapp --dry-run --debug
3. Listing Releases — helm list
  • # List releases in current namespace
helm list

# List releases in all namespaces
helm list --all-namespaces
helm list -A

# List releases in a specific namespace
helm list -n production

# List all releases including failed, pending, superseded
helm list --all

# Filter by release name
helm list --filter "myapp.*"

# Output in different formats
helm list -o yaml
helm list -o json
  • Output columns: NAME, NAMESPACE, REVISION, UPDATED, STATUS, CHART, APP VERSION;
4. Viewing Release Details
  • # Show status of a release
helm status myrelease

# Show the computed values (merged defaults + overrides)
helm get values myrelease

# Show all computed values including defaults
helm get values myrelease --all

# Show the rendered manifest (all k8s resources)
helm get manifest myrelease

# Show the release notes (NOTES.txt output)
helm get notes myrelease

# Show all information about a release
helm get all myrelease

# Show hooks
helm get hooks myrelease
5. Upgrading a Release — helm upgrade
  • # Upgrade to a new chart version
helm upgrade myrelease oci://registry-1.docker.io/myuser/myapp --version 0.2.0

# Upgrade with new values
helm upgrade myrelease oci://registry-1.docker.io/myuser/myapp -f new-values.yaml

# Upgrade with overridden values
helm upgrade myrelease oci://registry-1.docker.io/myuser/myapp --set replicaCount=5

# Reuse existing values and only change specific ones
helm upgrade myrelease oci://registry-1.docker.io/myuser/myapp --reuse-values --set image.tag=2.1.0

# Install if release doesn't exist, upgrade if it does
helm upgrade --install myrelease oci://registry-1.docker.io/myuser/myapp --version 0.2.0

# Upgrade from a local chart
helm upgrade myrelease ./myapp

# Wait for upgrade to complete
helm upgrade myrelease oci://registry-1.docker.io/myuser/myapp --wait --timeout 5m
  • Each upgrade increments the release revision number;
  • --reuse-values keeps the previous values and only applies the new overrides;
  • --install (or -i) makes it idempotent — useful in CI/CD pipelines;
6. Release History — helm history
  • # View release history
helm history myrelease

# Output:
# REVISION  UPDATED                   STATUS      CHART         APP VERSION  DESCRIPTION
# 1         2026-03-01 10:00:00       superseded  myapp-0.1.0   1.0.0        Install complete
# 2         2026-03-01 12:00:00       superseded  myapp-0.1.0   1.0.0        Upgrade complete
# 3         2026-03-01 14:00:00       deployed    myapp-0.2.0   2.0.0        Upgrade complete

# Limit output
helm history myrelease --max 5
  • Every install, upgrade, and rollback creates a new revision;
  • Each revision is stored as a k8s Secret in the release's namespace;
7. Rolling Back — helm rollback
  • # Rollback to the previous revision
helm rollback myrelease

# Rollback to a specific revision
helm rollback myrelease 1

# Rollback with wait
helm rollback myrelease 2 --wait --timeout 5m
  • Rollback creates a new revision (it does not delete history);
  • E.g., if you're on revision 3 and rollback to revision 1, Helm creates revision 4 which is identical to revision 1;
  • # After rolling back revision 3 to revision 1:
# REVISION  STATUS      DESCRIPTION
# 1         superseded  Install complete
# 2         superseded  Upgrade complete
# 3         superseded  Upgrade complete
# 4         deployed    Rollback to 1
8. Uninstalling a Release — helm uninstall
  • # Uninstall a release
helm uninstall myrelease

# Uninstall in a specific namespace
helm uninstall myrelease -n production

# Keep release history (allows rollback even after uninstall)
helm uninstall myrelease --keep-history

# Dry run
helm uninstall myrelease --dry-run
  • Removes all k8s resources associated with the release;
  • Removes release history (Secrets) unless --keep-history is used;
  • Does NOT remove CRDs (Custom Resource Definitions) — those must be deleted manually;
  • Does NOT remove PVCs (PersistentVolumeClaims) by default — data is preserved;
9. Testing a Release — helm test
  • # Run tests defined in templates/tests/
helm test myrelease

# Run tests with timeout
helm test myrelease --timeout 5m

# View test logs
helm test myrelease --logs
  • Tests are pod definitions in templates/tests/ with the annotation helm.sh/hook: test;
  • A test passes if the pod exits with code 0;
  • Useful for verifying connectivity, configuration, or basic functionality after install/upgrade;
10. Inspecting Charts Before Installing
  • # Show chart metadata (Chart.yaml)
helm show chart oci://registry-1.docker.io/myuser/myapp --version 0.1.0

# Show default values (values.yaml)
helm show values oci://registry-1.docker.io/myuser/myapp --version 0.1.0

# Show README
helm show readme oci://registry-1.docker.io/myuser/myapp --version 0.1.0

# Show everything (chart + values + readme)
helm show all oci://registry-1.docker.io/myuser/myapp --version 0.1.0

# Save default values to a file for customization
helm show values oci://registry-1.docker.io/myuser/myapp --version 0.1.0 > my-values.yaml
11. Pulling Charts for Offline / Local Use
  • # Pull a chart .tgz to current directory
helm pull oci://registry-1.docker.io/myuser/myapp --version 0.1.0

# Pull and extract
helm pull oci://registry-1.docker.io/myuser/myapp --version 0.1.0 --untar

# Pull from traditional repository
helm pull bitnami/nginx

# Pull a specific version
helm pull bitnami/nginx --version 15.2.3

# Pull to a specific directory
helm pull bitnami/nginx -d /path/to/charts/
12. Rendering Templates Locally — helm template
  • # Render all templates
helm template myrelease ./myapp

# Render with custom values
helm template myrelease ./myapp -f production-values.yaml

# Render a specific template
helm template myrelease ./myapp -s templates/deployment.yaml

# Render from OCI registry
helm template myrelease oci://registry-1.docker.io/myuser/myapp --version 0.1.0

# Render with --set overrides
helm template myrelease ./myapp --set replicaCount=3
  • Renders templates locally without connecting to a k8s cluster;
  • Useful for debugging templates and seeing the final YAML before deploying;
  • Unlike --dry-run, this doesn't validate against the k8s API server;
13. Managing Dependencies
  • # List dependencies declared in Chart.yaml
helm dependency list ./myapp

# Download/update dependencies to charts/ directory
helm dependency update ./myapp

# Build dependencies from Chart.lock (exact versions)
helm dependency build ./myapp
  • helm dependency update resolves dependencies from Chart.yaml, downloads .tgz files to charts/, and updates Chart.lock;
  • helm dependency build uses Chart.lock for reproducible builds;
14. Searching for Charts
  • # Search Artifact Hub (public charts)
helm search hub nginx
helm search hub nginx --max-col-width 80

# Search configured repositories
helm search repo nginx
helm search repo nginx --versions           # All versions
helm search repo nginx --devel              # Include pre-release versions
helm search repo nginx --version "^15.0.0"  # SemVer constraint
  • helm search hub searches Artifact Hub (public);
  • helm search repo searches locally configured repositories (uses cached index.yaml);
  • OCI registries do NOT support helm search — use the registry's UI or API;
15. Release Lifecycle Summary
  • # Search / Discover
helm search hub <keyword>
helm search repo <keyword>

# Inspect
helm show chart <chart>
helm show values <chart>

# Install
helm install <release> <chart>

# Monitor
helm list
helm status <release>
helm get values <release>
helm get manifest <release>

# Test
helm test <release>

# Upgrade
helm upgrade <release> <chart>

# History
helm history <release>

# Rollback
helm rollback <release> <revision>

# Uninstall
helm uninstall <release>
16. Common Flags Reference
  • Flag Works With Description
    -f / --values install, upgrade, template Specify a values file to override defaults
    --set install, upgrade, template Override individual values on the command line
    --version install, upgrade, pull, show, template Specify the chart version to use
    -n / --namespace all commands Specify the k8s namespace
    --create-namespace install, upgrade Create the namespace if it doesn't exist
    --wait install, upgrade, rollback, uninstall Wait for resources to be ready
    --timeout install, upgrade, rollback, uninstall, test Time to wait for operation (default 5m0s)
    --dry-run install, upgrade, uninstall Simulate the operation without executing
    --debug install, upgrade, template Output debug information
    --reuse-values upgrade Reuse previous release values and merge overrides
    --install / -i upgrade Install if release doesn't exist (idempotent)
    --keep-history uninstall Preserve release history after uninstall
    --generate-name install Auto-generate a release name
