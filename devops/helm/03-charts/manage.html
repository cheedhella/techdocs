Chart Management

1. helm install
  • It is used to deploy a chart to a k8s cluster;
  • In other words, it is used to create a release(or running instance of the chart);
  • Syntax: 
    helm install  oci://// --version
  • Login: 
    helm registry login registry-1.docker.io -u cheedhella -p
  • Install: 
    helm install my-nginx-1 oci://registry-1.docker.io/bitnamicharts/nginx --version 15.5.2
2. helm install options
  • --generate-name - It auto generates the release name;
  • --version - It specifies the version of the chart to install; If not provided, it defaults to latest version; Best practice is to always specify the version explicitly;
  • -n - It specifies the namespace to install the chart in; If specified namespace does not exist, command will fail; If not provided, it defaults to default namespace;
  • --create-namespace - It creates the namespace, if it doesn't exist;
  • -f values-file.yaml - It specifies values file with custom values; It overrides the default values of the chart; You can pass multiple files; Later files override earlier files; Eg: -f values-file1.yaml -f values-file2.yaml;
  • --set - Override values inline; Eg: --set replicaCount=3 --set image.tag=v2.0;
  • --wait - Wait for the resources to be ready, before marking the release as successful;
  • --timeout - It specifies the wait time limit(default 5m);
  • --atomic - It is used to rollback the installation(cleanup resources), if it fails;
  • --dry-run - Simulate the installation without installing the chart;
  • --debug - Show detailed output (use with dry-run for troubleshooting);
3. What happens internally, when you run 'helm install' command?
  • It downloads the chart from the registry and stores it in local cache;
  • Helm reads:
    • Chart.yaml
    • values.yaml
    • templates/
  • It merges:
    • Default values
    • User-provided values (--set or -f)
  • It renders templates
  • It creates k8s resources;
  • It stores the release metadata in a k8s secret, in the same namespace as the release, in the cluster;
4. Where Does helm install Store Downloaded Charts?
  • Run: 'helm env' and look for HELM_DATA_HOME variable;
  • It defaults to ~/.cache/helm/;
5. helm list
  • Release is nothing but a running instance of a chart;
  • It lists all the active(deployed) releases in the current namespace;
  • Eg: 
    NAME      NAMESPACE   REVISION  UPDATED                   STATUS    CHART         APP VERSION
my-nginx-1  default     1         2026-03-03 10:00:00 UTC  deployed  nginx-15.5.2   1.24.0
  • Status values:
    • deployed - installation is successful, application is healthy and usable;
    • failed - install/upgrade failed, due to invalid values, image pull errors,RBAC errors etc;
    • pending-install - installation is in-progress;
    • pending-upgrade - upgrade is in-progress;
    • pending-rollback - rollback is in-progress;
    • superseded - When you upgrade, helm creates a new revision, marks it as deployed and marks the old release as superseded(not active/running); superseded releases are not deleted, so that you can rollback to them if you want;
    • uninstalling - uninstallation is in-progress;
    • uninstalled - release has been uninstalled successfully; If you install again with same name, it will be a new release; As history is preserved, you can rollback the uninstalled release if you want; You can also remove history, while uninstalling: helm uninstall myapp --keep-history=false
  • Options:
    • -n - It lists the releases in specified namespace;
    • -A - It lists the releases in all namespaces;
    • --all - It lists all the releases including failed, pending, superseded, uninstalled;
    • --failed - It lists the failed releases;
    • --deployed - It lists the deployed releases;
    • --pending - It lists the pending releases;
    • --superseded - It lists the superseded releases;
    • --uninstalled - It lists the uninstalled releases;
    • --uninstalling - It lists the uninstalling releases;
    • --filter - It filters the releases by name; Eg: --filter "myapp.*", --filter "^myapp$";
5. helm upgrade
  • It upgrades the release to a new chart version OR template OR values;
    • \
  • Each upgrade increments the release revision number;
  • Syntax: 
    helm upgrade  oci://// --version
  • Upgrade chart version: helm upgrade my-nginx-1 bitnami/nginx --version 15.5.2
  • Upgrade with new values: helm upgrade my-nginx-1 bitnami/nginx -f prod-values.yaml
  • Override specific values: helm upgrade my-nginx-1 bitnami/nginx --set replicaCount=3 --set image.tag=v2.0
  • Upgrade with install(if release doesn't exist, it installs it; else, it upgrades it): helm upgrade --install my-nginx-2 bitnami/nginx --version 15.5.2
  • Upgrade with reuse values(Reuse the existing release values and apply only the new overrides you specify): helm upgrade my-nginx-1 bitnami/nginx --reuse-values --set replicaCount=3
  • Options:
    • --install - It installs the release if it doesn't exist; If it exists, it upgrades it; Makes it idempotent, useful in CI/CD pipelines;
    • --atomic - It rolls back the upgrade if it fails;
    • --version - It specifies the version of the chart to upgrade to; If not provided, it defaults to latest version;
    • -f - It specifies the values file to use for the upgrade; If not provided, it uses the default values;
    • --set - It specifies the values to override; Eg: --set replicaCount=3 --set image.tag=v2.0;
    • --reuse-values - It reuses the previous values; Eg: --reuse-values;
    • --wait - It waits for the upgrade to complete; Eg: --wait;
    • --timeout - It specifies the wait time limit; Eg: --timeout 5m;
    • --debug - It shows the debug information; Eg: --debug;
6. What happens internally, when you run 'helm upgrade' command?
  • It downloads the chart from the registry and stores it in local cache;
  • Helm reads:
    • Chart.yaml

  • It merges:
    • Default values
    • User-provided values (--set or -f)
  • It renders templates
  • It creates k8s resources;
  • It stores the release metadata in a k8s secret, in the same namespace as the release, in the cluster;
6. helm history
  • It shows the revision history of a release, allowing you track install/upgrade operations and perform rollback if needed;
  • Each time you install, upgrade, or rollback a release, it creates a new revision;
  • Each revision is stored as a k8s Secret in the release's namespace;
  • Syntax: 
    helm history
  • Output: 
    REVISION  UPDATED                   STATUS      CHART         APP VERSION  DESCRIPTION
1         2026-03-01 10:00:00       superseded  myapp-0.1.0   1.0.0        Install complete
2         2026-03-01 12:00:00       superseded  myapp-0.1.0   1.0.0        Upgrade complete
3         2026-03-01 14:00:00       deployed    myapp-0.2.0   2.0.0        Upgrade complete
  • Options:
    • -n - It specifies the namespace to show the history in; Eg: -n production;
    • --max - It specifies the maximum number of revisions to show; Eg: --max 5;
  • Eg: 
    helm history my-nginx-1
7. helm rollback
  • It is used to rollback the release to a previous revision;
  • It helps in recovering from failed upgrades or broken deployments;
  • It creates a new revision, it doesn't reuse the previous revision number;
  • Syntax: 
    helm rollback
8. helm uninstall
  • It deletes all the k8s resources associated with the release and marks the release as uninstalled;
  • It removes release history (Secrets) unless --keep-history is used;
  • It does NOT remove CRDs (Custom Resource Definitions) — those must be deleted manually;
  • It does NOT remove PVCs (PersistentVolumeClaims) by default — data is preserved;
  • By default, helm list will not show the uninstalled releases;
  • Syntax: 
    helm uninstall
  • Options:
    • -n - It specifies the namespace to uninstall the release in; Eg: -n production;
    • --keep-history - It deletes k8s resources, but keeps the release history, allowing you to rollback to the uninstalled release if needed;
7. helm status
  • It shows the status of the release;
  • It shows the details of the release;
  • It shows the resources of the release;
4. Viewing Release Details
  • # Show status of a release
helm status myrelease

# Show the computed values (merged defaults + overrides)
helm get values myrelease

# Show all computed values including defaults
helm get values myrelease --all

# Show the rendered manifest (all k8s resources)
helm get manifest myrelease

# Show the release notes (NOTES.txt output)
helm get notes myrelease

# Show all information about a release
helm get all myrelease

# Show hooks
helm get hooks myrelease
9. Testing a Release — helm test
  • # Run tests defined in templates/tests/
helm test myrelease

# Run tests with timeout
helm test myrelease --timeout 5m

# View test logs
helm test myrelease --logs
  • Tests are pod definitions in templates/tests/ with the annotation helm.sh/hook: test;
  • A test passes if the pod exits with code 0;
  • Useful for verifying connectivity, configuration, or basic functionality after install/upgrade;
10. Inspecting Charts Before Installing
  • # Show chart metadata (Chart.yaml)
helm show chart oci://registry-1.docker.io/myuser/myapp --version 0.1.0

# Show default values (values.yaml)
helm show values oci://registry-1.docker.io/myuser/myapp --version 0.1.0

# Show README
helm show readme oci://registry-1.docker.io/myuser/myapp --version 0.1.0

# Show everything (chart + values + readme)
helm show all oci://registry-1.docker.io/myuser/myapp --version 0.1.0

# Save default values to a file for customization
helm show values oci://registry-1.docker.io/myuser/myapp --version 0.1.0 > my-values.yaml
11. Pulling Charts for Offline / Local Use
  • # Pull a chart .tgz to current directory
helm pull oci://registry-1.docker.io/myuser/myapp --version 0.1.0

# Pull and extract
helm pull oci://registry-1.docker.io/myuser/myapp --version 0.1.0 --untar

# Pull from traditional repository
helm pull bitnami/nginx

# Pull a specific version
helm pull bitnami/nginx --version 15.2.3

# Pull to a specific directory
helm pull bitnami/nginx -d /path/to/charts/
12. Rendering Templates Locally — helm template
  • # Render all templates
helm template myrelease ./myapp

# Render with custom values
helm template myrelease ./myapp -f production-values.yaml

# Render a specific template
helm template myrelease ./myapp -s templates/deployment.yaml

# Render from OCI registry
helm template myrelease oci://registry-1.docker.io/myuser/myapp --version 0.1.0

# Render with --set overrides
helm template myrelease ./myapp --set replicaCount=3
  • Renders templates locally without connecting to a k8s cluster;
  • Useful for debugging templates and seeing the final YAML before deploying;
  • Unlike --dry-run, this doesn't validate against the k8s API server;
13. Managing Dependencies
  • # List dependencies declared in Chart.yaml
helm dependency list ./myapp

# Download/update dependencies to charts/ directory
helm dependency update ./myapp

# Build dependencies from Chart.lock (exact versions)
helm dependency build ./myapp
  • helm dependency update resolves dependencies from Chart.yaml, downloads .tgz files to charts/, and updates Chart.lock;
  • helm dependency build uses Chart.lock for reproducible builds;
14. Searching for Charts
  • # Search Artifact Hub (public charts)
helm search hub nginx
helm search hub nginx --max-col-width 80

# Search configured repositories
helm search repo nginx
helm search repo nginx --versions           # All versions
helm search repo nginx --devel              # Include pre-release versions
helm search repo nginx --version "^15.0.0"  # SemVer constraint
  • helm search hub searches Artifact Hub (public);
  • helm search repo searches locally configured repositories (uses cached index.yaml);
  • OCI registries do NOT support helm search — use the registry's UI or API;
15. Release Lifecycle Summary
  • # Search / Discover
helm search hub <keyword>
helm search repo <keyword>

# Inspect
helm show chart <chart>
helm show values <chart>

# Install
helm install <release> <chart>

# Monitor
helm list
helm status <release>
helm get values <release>
helm get manifest <release>

# Test
helm test <release>

# Upgrade
helm upgrade <release> <chart>

# History
helm history <release>

# Rollback
helm rollback <release> <revision>

# Uninstall
helm uninstall <release>
