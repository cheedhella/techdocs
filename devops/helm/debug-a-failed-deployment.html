Tips to Debug a Failed Deployment

1. What is a Hook?
  • Check the release status: helm status <release-name>
  • List all resources created by the release: kubectl get all -l app.kubernetes.io/instance= helm get manifest <release-name>
  • Get all pods created by the release: kubectl get pods -l app.kubernetes.io/instance=
  • Get container logs: kubectl logs <pod-name> -c <container-name>
  • Inspect failed jobs: kubectl get jobs
  • Check failed hooks: kubectl get jobs -l 'helm.sh/hook-succeeded=false'
  • Get failed hooks logs: kubectl logs <job-name> -c <container-name>
  • Get all events(Events often reveal the root cause of the failure): kubectl get events --sort-by=.lastTimestamp
  • Get all services created by the release: kubectl get services -l app.kubernetes.io/instance=
  • Get all deployments created by the release: kubectl get deployments -l app.kubernetes.io/instance=
  • Get all statefulsets created by the release: kubectl get statefulsets -l app.kubernetes.io/instance=
  • Get all configmaps created by the release: kubectl get configmaps -l app.kubernetes.io/instance=
  • Get all secrets created by the release: kubectl get secrets -l app.kubernetes.io/instance=
  • Get all volumes created by the release: kubectl get volumes -l app.kubernetes.io/instance=
  • Get all nodes created by the release: kubectl get nodes -l app.kubernetes.io/instance=
  • Get all namespaces created by the release: kubectl get namespaces -l app.kubernetes.io/instance=
    • pull image from registry: helm pull oci://registry.example.com/charts/mychart, docker pull nginx:latest

2. Common Reasons for Failed Deployment
    | Issue | Symptom | | ---------------- | ------------------------ | | Invalid template | Helm install fails | | Missing values | Template rendering error | | Image pull error | `ImagePullBackOff` | | Bad probes | `CrashLoopBackOff` | | Hook job failure | install stuck | | RBAC issues | permission denied |
      • ErrImagePull → first pull attempt failed
      • ImagePullBackOff → Kubernetes is retrying with exponential delay
      • Both indicate they can't pull the image from the registry and k8s is backing off(waiting before retrying);
      • Common causes:
        • Wrong image name or tag
        • Image doesn't exist in the registry
        • Private registry without credentials - helm registry login registry-1.docker.io
        • Network issues
      • CrashLoopBackOff → Pod is restarting continuously due to application crashes
      • Common causes:
        • Application code is buggy
        • Configuration issues
    • manifest unknown → Wrong tag
      • toomanyrequests → Pull rate limit
      • Pull rate limit is a common issue when pulling images from a registry;
      • You can try again later or use a different registry(use a different registry like quay.io);

3. Remove a failed deployment
  • Uninstall the release: helm uninstall my-release -n my-namespace
  • Verify the release is removed: helm list -A -n my-namespace
  • Sometimes, resources remain after uninstall, due to:
    • helm.sh/resource-policy: keep
    • Failed hooks
    • Manual resources
  • Get all resources created by the release: kubectl get all -l app.kubernetes.io/instance=my-release
  • Delete the resources: kubectl delete all -l app.kubernetes.io/instance=my-release -n my-namespace
  • Remove failed hook jobs: kubectl get jobs, kubectl delete jobs -l 'helm.sh/hook-succeeded=false' -n my-namespace
4. What happens if a PVC is created but no PV exists?
  • If dynamic provisioning is enabled, K8s will automatically create a PV and bind it to the PVC;
  • If dynamic provisioning is disabled, the PVC will stay in Pending state; Pod will stay in Pending state, Pods cannot start until the PVC is bound to a PV;;
  • > kubectl describe pvc 
    Events:
      Type     Reason              Message
      ----     ------              -------
      Warning  ProvisioningFailed  no persistent volumes available
