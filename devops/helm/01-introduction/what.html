1. What is Helm?
  • Helm is a package manager(like apt/yum) for Kubernetes based applications;
2. Why Helm is needed?
  • If you want to run your application on k8s cluster, you need to define so many objects such as deployment, service, configmap, secrets, ingress, PVC etc in YAML files;
  • As the project grows, the number of YAML files also increases and it becomes hard to maintain;
  • This is where Helm comes to the rescue!
  • It bundles/package the k8s resource files into a single versioned package(called helm chart) that can be easily(with just 1 command) deployed on any k8s cluster;
3. What are the other benefits of Helm?
  • Parameterized YAML files
    • You can parameterize k8s resource files, which can be reused across many applications, thus reducing maintanance burden;
    • This makes it easy to deploy the same application with different configurations in different environments such as development, staging and production; You can override the default values in the values.yaml file;
  • Manage entire lifecycle of an application
    • You can install/upgrade/uninstall the application using a single command;
  • Keep track of history
    • You can rollback to any state at any point in time;
    • Without Helm, there is no way to track version of the application deployed in the cluster; To rollback, you have to manually revert the changes made to the multiple YAML files;
  • Out-of-box charts are available for many applications
    • Artifact Hub has free to use charts for many applications, so there is no need to build solutions from scratch;
4. New Terms
  • Chart
    • It is a package that contains everything to install the application in the k8s cluster;
    • Every chart contains the following files and directories:
      • Chart.yaml - chart metadata(name, type, version, app version, description, dependencies etc);
      • values.yaml - default configuration for the chart;
      • crds/ - Optional, It contains Custom Resource Definitions that should be installed before templates are rendered;
      • templates/ - It contains all the k8s manifest template files(deployment, service, ingress, HPA etc);
      • templates/_helpers.tpl - It contains all reusable/helper templates and partials;
      • templates/NOTES.txt - Post-installation instructions;
      • charts/ - It contains 1 or more packages(.tgz) or unpacked chart directories, that your main chart depends on;
      • README.md - Human-readable documentation;
      • LICENSE - License for the chart;
      • .helmignore - Files to ignore when packaging the chart;
  • Release
    • It is an instance of a chart deployed to a k8s cluster;
    • It is created when you install a chart;
    • It is identified by a unique name and version;
    • It is stored in the k8s cluster as a secret;
    • It is used to track the history of the chart deployments;
    • It is used to rollback to a previous version of the chart;
    • It is used to upgrade the chart to a new version;
    • It is used to uninstall the chart;
    • It is used to get the status of the chart;
  • Repository
    • It is a artifact server which hosts a collection of charts/packages;
    • You can use it manage(store, get, list, update, remove) charts;
    • It is also used to share charts with others;
  • Secrets
    • It is a storage for secrets;
    • It is used to store and manage secrets;
    • It is used to share secrets with others;
    • It is used to get secrets from remote repositories;
    • It is used to add remote repositories;
  • Helm CLI
    • It is a command line tool that you install on your local machine or CI/CD system;
    • It is used to manage charts, repositories, releases, secrets etc;
  • Template
    • It is a blueprint for your k8s YAML resource files(deployment, service, ingress, HPA etc);
    • It is written in the Helm template language, which is based on the Go template language and Sprig template functions;
    • Each template file looks very similar to the Kubernetes resource definition which it is;
    • Any file that begins with _ doesn't output a k8s manifest file;
    • Eg of Template: "Dear [Name], your balance is [Amount]."; Values: {"Name": "John", "Amount": 100}; Output: "Dear John, your balance is 100";
    • Purpose: If you have 50 microservices that all look 90% the same, you don't want 50 different Deployment files; You create one template that defines how a "generic service" looks, and then you just provide a tiny unique values.yaml file for each service;
  • Templating Engine
    • It is a tool that takes template and values, generates final YAML files by replacing placeholders with values;
  • Parent Chart
    • It is the main chart that includes subcharts;
  • Subchart
    • It is a chart that is included as a dependency inside another chart;
    • Subchart = dependency that exists locally inside charts/ directory;
  • Dependent Chart
    • It is a chart that is declared as a dependant in parent chart's Chart.yaml;
    • This is just a declaration — nothing is downloaded yet;
    • When you run helm dependency update, helm downloads the dependant charts to charts/ directory;
  • Library Chart
    • It is a reusable chart that only provides template helpers (not installable on its own);
  • Umbrella Chart
    • It is a chart that groups multiple subcharts together;
