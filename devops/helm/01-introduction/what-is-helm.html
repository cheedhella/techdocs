What is Helm?

1. What is Helm?
  • Helm is the package manager for Kubernetes — think of it as apt/yum for Kubernetes;
  • It allows you to define, install, and upgrade even the most complex Kubernetes applications using Helm Charts;
  • A Helm Chart is a collection of YAML files that describe a related set of Kubernetes resources;
  • Helm simplifies deployment by packaging all resources (Deployments, Services, ConfigMaps, etc.) into a single, versioned unit;
2. Key Components
  • Helm CLI: Command-line tool to interact with Kubernetes clusters and manage charts;
  • Charts: Pre-configured Kubernetes resource templates packaged together;
  • Releases: An instance of a chart running in a Kubernetes cluster;
  • Repositories: Collections of charts that can be shared and distributed;
3. What Problems Does Helm Solve?
  • Complexity Management: Managing dozens of YAML files for a single application becomes unwieldy — Helm packages them all together;
  • Reusability: Create once, deploy anywhere with different configurations;
  • Versioning: Track changes to your application deployments with semantic versioning;
  • Rollbacks: Easily rollback to previous versions if something goes wrong;
  • Templating: Use variables and logic to generate Kubernetes manifests dynamically;
  • Dependency Management: Charts can depend on other charts (e.g., your app depends on MySQL, Redis);
4. Helm Versions
  • Helm v2: Required Tiller (server-side component) running in the cluster — deprecated and no longer supported;
  • Helm v3: Removed Tiller for security and simplicity — client-only architecture, uses Kubernetes RBAC directly;
  • Always use Helm v3 for new projects;
5. Real-World Example

Instead of managing these files separately:

deployment.yaml
service.yaml
configmap.yaml
secret.yaml
ingress.yaml
hpa.yaml

You create a single Helm chart and deploy with:

helm install myapp ./mychart

And upgrade with:

helm upgrade myapp ./mychart --set image.tag=v2.0

And rollback if needed:

helm rollback myapp 1
