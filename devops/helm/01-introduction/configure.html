Configuring Helm CLI with a Kubernetes Cluster

1. How Helm Connects to Kubernetes

Helm uses the same configuration as kubectl. It reads the kubeconfig file to determine which cluster to talk to. By default, this file lives at ~/.kube/config.

If kubectl can reach your cluster, Helm can too — no extra setup is needed.

# Confirm kubectl connectivity first
kubectl cluster-info
kubectl get nodes
2. Using the Default Kubeconfig

Most Kubernetes tools (minikube, kind, EKS, GKE, AKS) automatically write a context into ~/.kube/config when you create or authenticate to a cluster.

# View current kubeconfig
kubectl config view

# See the active context (this is what Helm will use)
kubectl config current-context

# List all available contexts
kubectl config get-contexts

If the correct context is active, Helm is already configured:

# This will use the current kubectl context
helm list
3. Switching Between Clusters (Contexts)

When you have multiple clusters configured, switch between them using kubectl config use-context. Helm will automatically follow the active context.

# List contexts
kubectl config get-contexts

# CURRENT   NAME              CLUSTER           AUTHINFO          NAMESPACE
# *         docker-desktop    docker-desktop    docker-desktop
#           minikube          minikube          minikube
#           eks-production    eks-production    eks-admin

# Switch to a different cluster
kubectl config use-context minikube

# Helm now targets minikube
helm list
4. Pointing Helm to a Specific Kubeconfig File

If your cluster config lives outside ~/.kube/config, tell Helm where to find it with the --kubeconfig flag or the KUBECONFIG environment variable.

Using the --kubeconfig flag:

helm list --kubeconfig /path/to/custom-kubeconfig.yaml
helm install myapp ./chart --kubeconfig /path/to/custom-kubeconfig.yaml

Using the KUBECONFIG environment variable:

# Set for the current shell session
export KUBECONFIG=/path/to/custom-kubeconfig.yaml

# Helm and kubectl both respect this
helm list
kubectl get pods

Merging multiple kubeconfig files:

# Combine multiple kubeconfig files into one view
export KUBECONFIG=~/.kube/config:/path/to/cluster2-config:/path/to/cluster3-config

# All contexts from all files are now available
kubectl config get-contexts
helm list
5. Targeting a Specific Context Without Switching

Use the --kube-context flag to run a single Helm command against a specific context without changing the global default.

# Deploy to production without switching context
helm install myapp ./chart --kube-context eks-production

# List releases on staging
helm list --kube-context eks-staging

# Upgrade on a specific cluster
helm upgrade myapp ./chart --kube-context gke-dev --set image.tag=v2.0
6. Overriding the Target Namespace

By default, Helm deploys to the namespace set in the current context (or default). Override it with --namespace / -n.

# Install into a specific namespace
helm install myapp ./chart --namespace production

# Create the namespace if it doesn't exist
helm install myapp ./chart --namespace production --create-namespace

# List releases across all namespaces
helm list --all-namespaces
7. Configuring Helm for Managed Kubernetes Services

Amazon EKS:

# Update kubeconfig for an EKS cluster
aws eks update-kubeconfig --name my-cluster --region us-east-1

# Verify
kubectl config current-context
helm list

Google GKE:

# Fetch credentials for a GKE cluster
gcloud container clusters get-credentials my-cluster --zone us-central1-a --project my-project

# Verify
kubectl config current-context
helm list

Azure AKS:

# Merge AKS credentials into kubeconfig
az aks get-credentials --resource-group myResourceGroup --name myAKSCluster

# Verify
kubectl config current-context
helm list

DigitalOcean DOKS:

# Save kubeconfig for a DOKS cluster
doctl kubernetes cluster kubeconfig save my-cluster

# Verify
kubectl config current-context
helm list
8. Configuring Helm for Local Clusters

Minikube:

# Start minikube (auto-configures kubeconfig)
minikube start

# Helm is ready to use
helm list

kind (Kubernetes in Docker):

# Create a cluster (auto-configures kubeconfig)
kind create cluster --name my-cluster

# Verify context
kubectl config current-context
# kind-my-cluster

helm list

Docker Desktop:

# Enable Kubernetes in Docker Desktop Settings → Kubernetes → Enable
# Context is automatically configured as "docker-desktop"

kubectl config use-context docker-desktop
helm list

k3d (k3s in Docker):

# Create a cluster
k3d cluster create my-cluster

# Context is automatically set
helm list
9. Connecting via an API Server URL Directly

Use --kube-apiserver and --kube-token to connect directly to a cluster API without a kubeconfig file. This is common in CI/CD pipelines.

# Using API server URL with a bearer token
helm list \
  --kube-apiserver https://k8s-api.example.com:6443 \
  --kube-token "$KUBE_TOKEN"

# With a CA certificate for TLS verification
helm install myapp ./chart \
  --kube-apiserver https://k8s-api.example.com:6443 \
  --kube-token "$KUBE_TOKEN" \
  --kube-ca-file /path/to/ca.crt
10. Helm Environment Variables

Helm respects several environment variables that control its behavior:

# Where Helm stores configuration (defaults to ~/.config/helm)
export HELM_CONFIG_HOME=~/.config/helm

# Where Helm stores cached data (defaults to ~/.cache/helm)
export HELM_CACHE_HOME=~/.cache/helm

# Where Helm stores local data (defaults to ~/.local/share/helm)
export HELM_DATA_HOME=~/.local/share/helm

# Override the Kubernetes namespace
export HELM_NAMESPACE=production

# Override the kubeconfig context
export HELM_KUBECONTEXT=eks-production

# Set a custom kubeconfig path
export KUBECONFIG=~/.kube/custom-config

View current Helm environment settings:

helm env
11. Verifying Helm-to-Cluster Connectivity

After configuration, verify everything works end to end:

# 1. Check Helm version (client-side only)
helm version

# 2. List releases (requires cluster connectivity)
helm list

# 3. Search and install a test chart
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update
helm install test-nginx bitnami/nginx --namespace default

# 4. Confirm the release
helm list
kubectl get pods

# 5. Clean up
helm uninstall test-nginx
