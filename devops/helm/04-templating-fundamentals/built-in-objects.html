Built-in Objects (.Values, .Chart, .Release)

1. What are Built-in Objects?
  • Built-in objects are predefined variables available in all Helm templates;
  • Provide access to chart metadata, values, release information, and more;
  • Accessed using dot notation: .Values, .Chart, .Release, etc.;
2. The .Values Object

Contains values from values.yaml and overrides from --set or -f:

# values.yaml
replicaCount: 3
image:
  repository: nginx
  tag: "1.21"

# In template:
replicas: {{ .Values.replicaCount }}
image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
3. The .Chart Object

Contains metadata from Chart.yaml:

Field Description Example
.Chart.Name Chart name myapp
.Chart.Version Chart version 1.0.0
.Chart.AppVersion Application version 2.0.1
.Chart.Description Chart description My application chart
.Chart.Keywords Chart keywords [web, backend]
.Chart.Home Project home URL https://example.com
.Chart.Maintainers List of maintainers [{name: "John", email: "..."}] 
# In template:
app.kubernetes.io/name: {{ .Chart.Name }}
app.kubernetes.io/version: {{ .Chart.AppVersion }}
helm.sh/chart: {{ .Chart.Name }}-{{ .Chart.Version }}
4. The .Release Object

Contains information about the current release:

Field Description Example
.Release.Name Release name myapp-prod
.Release.Namespace Namespace for release production
.Release.IsUpgrade True if upgrade true/false
.Release.IsInstall True if install true/false
.Release.Revision Revision number 3
.Release.Service Service rendering release Helm 
# In template:
metadata:
  name: {{ .Release.Name }}-deployment
  namespace: {{ .Release.Namespace }}
  labels:
    app.kubernetes.io/instance: {{ .Release.Name }}
    app.kubernetes.io/managed-by: {{ .Release.Service }}
5. The .Capabilities Object

Information about Kubernetes cluster capabilities:

# Check Kubernetes version
{{- if .Capabilities.KubeVersion.GitVersion }}
# Running on Kubernetes {{ .Capabilities.KubeVersion }}
{{- end }}

# Check API versions
{{- if .Capabilities.APIVersions.Has "networking.k8s.io/v1/Ingress" }}
apiVersion: networking.k8s.io/v1
{{- else }}
apiVersion: networking.k8s.io/v1beta1
{{- end }}

# Available fields:
.Capabilities.KubeVersion.Version      # e.g., "1.24"
.Capabilities.KubeVersion.Major        # e.g., "1"
.Capabilities.KubeVersion.Minor        # e.g., "24"
.Capabilities.APIVersions              # Set of API versions
6. The .Template Object

Information about the current template being executed:

.Template.Name       # Name of current template file
.Template.BasePath   # Path to templates directory

# Example usage:
{{- define "mychart.labels" -}}
# Generated from {{ .Template.Name }}
app: {{ .Chart.Name }}
{{- end }}
7. The .Files Object

Access non-template files in the chart:

# Read a file
{{ .Files.Get "config/app.properties" }}

# Get file as bytes
{{ .Files.GetBytes "data/image.png" | b64enc }}

# Check if file exists
{{- if .Files.Get "optional-config.yaml" }}
# File exists
{{- end }}

# Glob pattern matching
{{- range $path, $_ := .Files.Glob "config/*.yaml" }}
{{ $path }}: |
{{ $.Files.Get $path | indent 2 }}
{{- end }}
8. Complete Example
apiVersion: apps/v1
kind: Deployment
metadata:
  # Using .Release
  name: {{ .Release.Name }}-deployment
  namespace: {{ .Release.Namespace }}
  labels:
    # Using .Chart
    app.kubernetes.io/name: {{ .Chart.Name }}
    app.kubernetes.io/version: {{ .Chart.AppVersion | quote }}
    helm.sh/chart: {{ .Chart.Name }}-{{ .Chart.Version }}
    # Using .Release
    app.kubernetes.io/instance: {{ .Release.Name }}
    app.kubernetes.io/managed-by: {{ .Release.Service }}
spec:
  # Using .Values
  replicas: {{ .Values.replicaCount }}
  selector:
    matchLabels:
      app.kubernetes.io/name: {{ .Chart.Name }}
      app.kubernetes.io/instance: {{ .Release.Name }}
  template:
    metadata:
      labels:
        app.kubernetes.io/name: {{ .Chart.Name }}
        app.kubernetes.io/instance: {{ .Release.Name }}
    spec:
      containers:
      - name: {{ .Chart.Name }}
        # Using .Values
        image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
        imagePullPolicy: {{ .Values.image.pullPolicy }}
        ports:
        - containerPort: {{ .Values.service.port }}
9. Accessing Nested Values
# values.yaml
database:
  host: mysql.example.com
  port: 3306
  credentials:
    username: admin
    password: secret

# In template:
env:
- name: DB_HOST
  value: {{ .Values.database.host }}
- name: DB_PORT
  value: {{ .Values.database.port | quote }}
- name: DB_USER
  value: {{ .Values.database.credentials.username }}
- name: DB_PASS
  valueFrom:
    secretKeyRef:
      name: {{ .Release.Name }}-db-secret
      key: password
10. Best Practices
  • Use .Release.Name for uniqueness: Ensures resources don't conflict;
  • Use .Chart.AppVersion as default: {{ .Values.image.tag | default .Chart.AppVersion }};
  • Always quote version strings: {{ .Chart.AppVersion | quote }};
  • Use .Capabilities for compatibility: Check API versions before using them;
  • Namespace awareness: Always use .Release.Namespace for cross-references;
