2. Declaring Variables
  • Use := to declare and assign; use = to reassign an existing variable: 
    {{- $name := .Values.name }}
{{- $port := .Values.service.port }}

metadata:
  name: {{ $name }}
  annotations:
    port: {{ $port | quote }}
  • Variables start with $ — this is required;
  • They simplify templates by avoiding repeated long expressions;
3. Scope Rules
  • Variables declared outside a block are accessible inside the block;
  • Variables declared inside a block (if, range, with) are not accessible outside it;
  • Example — variable declared inside if is not available after end: 
    {{- if .Values.ingress.enabled }}
  {{- $host := .Values.ingress.host }}
  host: {{ $host }}
{{- end }}
# $host is NOT accessible here — it's out of scope
  • Fix — declare the variable before the block: 
    {{- $host := "" }}
{{- if .Values.ingress.enabled }}
  {{- $host = .Values.ingress.host }}
{{- end }}
# $host IS accessible here
annotation: {{ $host }}
4. How with Changes Scope
  • with re-scopes . to the specified value — inside the block, . is no longer the root context: 
    {{- with .Values.resources }}
resources:
  limits:
    cpu: {{ .limits.cpu }}
    memory: {{ .limits.memory }}
{{- end }}
# Inside the block: . = .Values.resources
# .limits.cpu works because . is already the resources map
  • This means .Release.Name or .Values.image are not directly accessible inside a with block;
5. How range Changes Scope
  • range re-scopes . to the current iteration element: 
    # values.yaml
ports:
  - name: http
    port: 80
  - name: https
    port: 443

# template
{{- range .Values.ports }}
- name: {{ .name }}
  containerPort: {{ .port }}
{{- end }}
# Inside the loop: . = current port object
# .name and .port work because . is each port map
  • .Release.Name is not accessible via . inside the loop;
6. The $ Root Variable
  • $ always refers to the root context — the same scope that . has at the top level of the template;
  • Use $ to access built-in objects when . has been re-scoped by with or range: 
    {{- range .Values.ports }}
- name: {{ .name }}
  containerPort: {{ .port }}
  # Need release name? Use $ to escape the range scope:
  release: {{ $.Release.Name }}
  image: {{ $.Values.image.repository }}
{{- end }}
  • Same pattern with with: 
    {{- with .Values.resources }}
resources:
  {{- toYaml . | nindent 2 }}
# Access something outside the with block:
# releaseName: {{ $.Release.Name }}
{{- end }}
7. range with Index/Key Variables
  • For lists — range can capture the index and value: 
    {{- range $index, $port := .Values.ports }}
# port {{ $index }}: {{ $port.name }} on {{ $port.port }}
{{- end }}
# $index = 0, 1, 2, ...
# $port = the list element
  • For maps — range captures key and value: 
    # values.yaml
env:
  APP_ENV: production
  LOG_LEVEL: info

# template
{{- range $key, $val := .Values.env }}
- name: {{ $key }}
  value: {{ $val | quote }}
{{- end }}
# Output:
# - name: APP_ENV
#   value: "production"
# - name: LOG_LEVEL
#   value: "info"
8. Passing Context to Named Templates
  • When calling a named template via include, you pass it a context (usually . or $): 
    # _helpers.tpl
{{- define "myapp.labels" -}}
app.kubernetes.io/name: {{ .Chart.Name }}
app.kubernetes.io/instance: {{ .Release.Name }}
{{- end }}

# deployment.yaml — pass the root context
labels:
  {{- include "myapp.labels" . | nindent 4 }}
  • Inside a range or with block, pass $ instead of . so the helper sees the full root context: 
    {{- range .Values.services }}
  labels:
    {{- include "myapp.labels" $ | nindent 4 }}
{{- end }}
  • You can also pass a custom dict: 
    {{- include "myapp.container" (dict "root" $ "container" .) }}
