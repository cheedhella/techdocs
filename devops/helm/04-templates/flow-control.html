Flow Control

1. Overview
  • Go templates provide four control structures: if/else, with, range, and define/template;
  • All blocks end with {{ end }};
1.1 Whitespace Trimming — {{- and -}}
  • YAML is whitespace-sensitive — extra blank lines from control blocks can break output;
  • Hyphens inside delimiters eat the whitespace (including newlines) on that side:
    • {{- expr }} — trims whitespace/newlines before the tag
    • {{ expr -}} — trims whitespace/newlines after the tag
    • {{- expr -}} — trims both sides

2. if / else if / else
  • Conditionally include or exclude blocks of YAML;
  • Falsy values (evaluate to false): false, 0, "", nil, empty list [], empty map {};
  • Basic syntax: 
    {{- if CONDITION }}
  # rendered when CONDITION is truthy
{{- else if OTHER_CONDITION }}
  # rendered when OTHER_CONDITION is truthy
{{- else }}
  # rendered when all conditions are falsy
{{- end }}
2.1 if
  • # values.yaml
production: true

# template
{{ if .Values.production }}
env: production
{{ end }}

# Output:
env: production
2.2 if / else
  • # values.yaml
production: true

# template
{{ if .Values.production }}
env: production
{{ else }}
env: development
{{ end }}

# Output:
env: production
2.3 if / else if / else
  • # values.yaml
service:
  type: NodePort

# template
{{ if eq .Values.environment "prod" }}
env: production
{{ else if eq .Values.environment "stage" }}
env: staging
{{ else }}
env: development
{{ end }}
3. with
  • with sets the scope (.) to the specified object — and the block is skipped if the value is empty/nil;
  • Combines scoping + conditional in one construct;
  • Basic syntax: 
    {{- with PIPELINE }}
  # . is now PIPELINE's value
  # block is skipped if PIPELINE is empty
{{- end }}
3.1 with — Resources Block
  • # values.yaml
resources:
  limits:
    cpu: 500m
    memory: 512Mi
  requests:
    cpu: 250m
    memory: 256Mi

# template
{{- with .Values.resources }}
resources:
  {{- toYaml . | nindent 2 }}
{{- end }}

# Output:
resources:
  limits:
    cpu: 500m
    memory: 512Mi
  requests:
    cpu: 250m
    memory: 256Mi
  • If resources is not set in values.yaml, the entire block is omitted;
3.2 with — Accessing Root Context via $
  • Inside with, . is re-scoped — use $ to access root objects: 
    {{- with .Values.nodeSelector }}
nodeSelector:
  {{- toYaml . | nindent 2 }}
  release: {{ $.Release.Name }}
{{- end }}
3.3 with / else
  • with supports else — the else block runs when the value is empty: 
    {{- with .Values.customAnnotations }}
annotations:
  {{- toYaml . | nindent 2 }}
{{- else }}
annotations:
  app: {{ $.Release.Name }}
{{- end }}
4. range
  • Iterates over lists or maps; inside the loop, . is the current element;
  • Basic syntax: 
    # Iterate a list
{{- range PIPELINE }}
  # . = current element
{{- end }}

# With index variable
{{- range $index, $element := PIPELINE }}
  # $index = 0, 1, 2...
  # $element = current element
{{- end }}

# Iterate a map
{{- range $key, $val := PIPELINE }}
  # $key = map key
  # $val = map value
{{- end }}
4.1 range — Iterating a List
  • # values.yaml
ports:
  - name: http
    containerPort: 8080
  - name: metrics
    containerPort: 9090

# template
ports:
{{- range .Values.ports }}
  - name: {{ .name }}
    containerPort: {{ .containerPort }}
{{- end }}

# Output:
ports:
  - name: http
    containerPort: 8080
  - name: metrics
    containerPort: 9090
4.2 range — Iterating a Map (Environment Variables)
  • # values.yaml
env:
  APP_ENV: production
  LOG_LEVEL: info
  DB_HOST: postgres.default.svc

# template
env:
{{- range $key, $val := .Values.env }}
  - name: {{ $key }}
    value: {{ $val | quote }}
{{- end }}

# Output:
env:
  - name: APP_ENV
    value: "production"
  - name: DB_HOST
    value: "postgres.default.svc"
  - name: LOG_LEVEL
    value: "info"
  • Map keys are iterated in alphabetical order;
4.3 range — Using $ for Root Access
  • {{- range .Values.containers }}
- name: {{ .name }}
  image: "{{ $.Values.image.registry }}/{{ .image }}:{{ .tag }}"
  # $.Values.image.registry comes from root context
  # .image and .tag come from the current container element
{{- end }}
4.4 range — Generating Multiple Resources
  • Use range to generate multiple complete k8s resources from a single template file: 
    # values.yaml
configMaps:
  - name: app-config
    data:
      APP_MODE: production
  - name: db-config
    data:
      DB_HOST: localhost

# template
{{- range .Values.configMaps }}
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{ $.Release.Name }}-{{ .name }}
data:
  {{- range $k, $v := .data }}
  {{ $k }}: {{ $v | quote }}
  {{- end }}
{{- end }}
  • The --- YAML document separator is needed between resources;
4.5 range — Fixed List (list function)
  • Create a list inline with the list function: 
    {{- range list "http" "https" "grpc" }}
- {{ . }}
{{- end }}
# Output:
# - http
# - https
# - grpc
4.6 range — until (numeric loop)
  • until N generates a list [0, 1, ..., N-1]: 
    {{- range $i := until 3 }}
worker-{{ $i }}:
  replicas: 1
{{- end }}
# Output:
# worker-0:
#   replicas: 1
# worker-1:
#   replicas: 1
# worker-2:
#   replicas: 1
5. Nesting Control Structures
  • Control structures can be nested freely: 
    {{- range .Values.services }}
{{- if .enabled }}
---
apiVersion: v1
kind: Service
metadata:
  name: {{ $.Release.Name }}-{{ .name }}
spec:
  type: {{ .type | default "ClusterIP" }}
  ports:
    {{- range .ports }}
    - port: {{ .port }}
      targetPort: {{ .targetPort }}
      {{- if eq $.Values.service.type "NodePort" }}
      nodePort: {{ .nodePort }}
      {{- end }}
    {{- end }}
  selector:
    app: {{ $.Release.Name }}
{{- end }}
{{- end }}
