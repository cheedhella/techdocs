helm template

1. helm template
  • During dry run, Helm contacts Kubernetes API Server for validating the templates(generated k8s manifest files); So, you must have valid k8s cluster credential to execute a dry run;
  • If you don’t have credentials for the Kubernetes server, you can use the helm template command to generate template YAML;
  • As Helm does not contact the API server, output of the commands --dry-run and template can differ;
2. What happens when you run helm template command?
  • It loads the chart(Chart.yaml, templates/, values.yaml) from the given path;
  • It combines configuration values in this order and produces a final merged values.yaml
    • values.yaml defined in the chart;
    • values.yaml defined in the parent chart;
    • -f values.yaml files;
    • --set CLI overrides;
  • It processes the all the files in templates/ folder;
  • Processes the templates in the templates/ folder and prints the fully rendered k8s manifest files to stdout;
3. helm template command
  • Syntax: 
    helm template [RELEASE_NAME] [CHART] [flags]
    • It is used to preview k8s manifest files(in templates/ directory) before installation;
    • Chart.yaml is mandatory for helm template to work; templates directory holds the templates; values.yaml holds the default values for the templates; Additional values files can be used to override values defined in values.yaml;
  • Options:
    • -f values.yaml - you can override the default values defined in values.yaml; You can pass multiple files; Later files override earlier files;
    • --set - override values inline; helm converts values to numbers, whenever possible; Eg: --set replicaCount=3 --set image.tag=v2.0;
    • --set-string - override values as strings;
    • --namespace - Used to specify namespace for rendered templates;
    • --output-dir - Instead of writing manifests to stdout, it writes to a directory;
    • --show-only template/deployment.yaml - Used to render only specific templates;
    • --include-crds - CRDs are not rendered by default, it is used to include CRDs;
    • --kube-version - Used to simulate cluster version; This is useful to check if the templates are compatible with the cluster version;
    • --api-versions - Used to add API versions; This is useful to check if the templates are compatible with the API versions;
4. helm template vs dry run
  • Use helm template:
    • When you don't have k8s cluster credential
    • In CI/CD pipelines
    • Debugging templates
  • Use helm install --dry-run, in other cases:
    • When you have k8s cluster credential
    • Validating against the cluster
    • Checking API compatibility
