Templates

1. What is a Template?
  • Template is nothing but a parameterized k8s manifest file;
  • Instead of writing static YAML files, helm lets to you create reusable templates that generate k8s manifest files dynamically based on the input values;
  • Templates are written in the Helm template language, which is based on the Go template language and Sprig template functions;
  • Templates are stored in the templates/ directory of the chart;
  • Templates are combined with values.yaml to generate the final k8s manifest files;
2. Purpose of Templates?
    It makes charts:
  • Reusable
    • Say, if your deployment file looks same for multiple services, you can reuse the same template for all of them;
    • So that you don't have to write the same deployment file for multiple services;
    • Rather, you can use same template for multiple services;
  • Configurable
    • Template can behave differently based on the values;
    • Example: 
      {{ if .Values.ingress.enabled }}
apiVersion: networking.k8s.io/v1
kind: Ingress
{{ end }}
  • Environment-aware
    • Templates separate the configuration from infrastructure code;
    • You can change the configuration without editing the template;
    • So, Instead of writing multiple YAML files for different environments(dev, staging, prod), you can write one template and have separate values.yaml file for each environment;
