values.yaml Explained

1. What is values.yaml?
  • The values.yaml file contains default configuration values for a chart;
  • Separates configuration from templates, making charts reusable;
  • Values can be overridden during installation/upgrade;
  • Accessed in templates via .Values object;
2. Basic Structure
# Simple flat values
replicaCount: 2
imagePullPolicy: IfNotPresent

# Nested values (recommended)
image:
  repository: nginx
  tag: "1.21"
  pullPolicy: IfNotPresent

service:
  type: ClusterIP
  port: 80
  targetPort: 8080

resources:
  limits:
    cpu: 500m
    memory: 512Mi
  requests:
    cpu: 250m
    memory: 256Mi
3. Using Values in Templates

values.yaml:

replicaCount: 3
image:
  repository: nginx
  tag: "1.21"

templates/deployment.yaml:

apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ .Release.Name }}
spec:
  replicas: {{ .Values.replicaCount }}
  template:
    spec:
      containers:
      - name: app
        image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
4. Data Types
# Strings
name: "myapp"
version: '1.0'

# Numbers
replicaCount: 3
port: 8080

# Booleans
enabled: true
debug: false

# Lists
tags:
  - production
  - web
  - backend

# Maps/Objects
database:
  host: mysql.example.com
  port: 3306
  name: mydb

# Multi-line strings
config: |
  server {
    listen 80;
    server_name example.com;
  }
5. Overriding Values

Using --set:

# Single value
helm install myapp ./chart --set replicaCount=5

# Nested value
helm install myapp ./chart --set image.tag=v2.0

# Multiple values
helm install myapp ./chart --set replicaCount=5 --set image.tag=v2.0

# List values
helm install myapp ./chart --set tags[0]=prod --set tags[1]=web

Using values file:

# Create custom-values.yaml
replicaCount: 5
image:
  tag: "v2.0"

# Use it
helm install myapp ./chart -f custom-values.yaml
6. Environment-Specific Values

values-dev.yaml:

replicaCount: 1
image:
  tag: "latest"
resources:
  limits:
    cpu: 200m
    memory: 256Mi

values-prod.yaml:

replicaCount: 5
image:
  tag: "v1.0.0"
resources:
  limits:
    cpu: 1000m
    memory: 1Gi
autoscaling:
  enabled: true

Usage:

helm install myapp ./chart -f values-dev.yaml
helm install myapp ./chart -f values-prod.yaml
7. Conditional Configuration
# Enable/disable features
ingress:
  enabled: false
  className: nginx
  hosts:
    - host: example.com
      paths:
        - path: /
          pathType: Prefix

autoscaling:
  enabled: false
  minReplicas: 2
  maxReplicas: 10

# In template:
{{- if .Values.ingress.enabled }}
apiVersion: networking.k8s.io/v1
kind: Ingress
...
{{- end }}
8. Default Values with Fallbacks
# values.yaml
image:
  repository: nginx
  # tag is optional, defaults to Chart.appVersion

# In template:
image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
9. Global Values

Global values are accessible to all charts and subcharts:

# values.yaml
global:
  imageRegistry: myregistry.example.com
  storageClass: fast-ssd

# Accessible in any chart/subchart
image: "{{ .Values.global.imageRegistry }}/myapp:1.0"
10. Complex Values Example
replicaCount: 2

image:
  repository: myapp
  tag: "1.0.0"
  pullPolicy: IfNotPresent
  pullSecrets:
    - name: regcred

service:
  type: ClusterIP
  port: 80
  annotations:
    service.beta.kubernetes.io/aws-load-balancer-type: nlb

ingress:
  enabled: true
  className: nginx
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
  hosts:
    - host: myapp.example.com
      paths:
        - path: /
          pathType: Prefix
  tls:
    - secretName: myapp-tls
      hosts:
        - myapp.example.com

resources:
  limits:
    cpu: 1000m
    memory: 1Gi
  requests:
    cpu: 500m
    memory: 512Mi

autoscaling:
  enabled: true
  minReplicas: 2
  maxReplicas: 10
  targetCPUUtilizationPercentage: 80
  targetMemoryUtilizationPercentage: 80

env:
  - name: DATABASE_URL
    value: "postgres://db:5432/mydb"
  - name: REDIS_URL
    value: "redis://redis:6379"

configMap:
  data:
    app.properties: |
      server.port=8080
      logging.level=INFO
11. Best Practices
  • Use nested structure: Group related values together;
  • Provide sensible defaults: Chart should work with default values;
  • Document values: Add comments explaining each value;
  • Use consistent naming: camelCase for value names;
  • Make features optional: Use enabled flags for optional features;
  • Avoid hardcoding: Put all configuration in values.yaml;
