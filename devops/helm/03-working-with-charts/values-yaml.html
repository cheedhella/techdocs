values.yaml Explained

1. What is values.yaml?
  • Contains default configuration values for a chart's templates;
  • Separates configuration from templates — you change behaviour by overriding values, not by editing templates;
  • Values can be overridden at install/upgrade time via --set or -f custom-values.yaml;
  • Accessed in templates via the .Values object (e.g., {{ .Values.replicaCount }});
2. Basic Structure
  • Use nested keys to group related values: 
    replicaCount: 2

image:
  repository: nginx
  tag: "1.21"
  pullPolicy: IfNotPresent

service:
  type: ClusterIP
  port: 80
  targetPort: 8080

resources:
  limits:
    cpu: 500m
    memory: 512Mi
  requests:
    cpu: 250m
    memory: 256Mi
3. Using Values in Templates
  • Given this values.yaml: 
    replicaCount: 3
image:
  repository: nginx
  tag: "1.21"
  • Reference values in templates/deployment.yaml: 
    apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ .Release.Name }}
spec:
  replicas: {{ .Values.replicaCount }}
  template:
    spec:
      containers:
      - name: app
        image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
4. YAML Data Types
  • # Strings
name: "myapp"

# Numbers
replicaCount: 3
port: 8080

# Booleans
enabled: true

# Lists
tags:
  - production
  - web

# Maps
database:
  host: mysql.example.com
  port: 3306

# Multi-line strings
config: |
  server {
    listen 80;
    server_name example.com;
  }
5. Overriding Values
  • Using --set on the command line: 
    # Single value
helm install myapp ./chart --set replicaCount=5

# Nested value
helm install myapp ./chart --set image.tag=v2.0

# Multiple values
helm install myapp ./chart --set replicaCount=5 --set image.tag=v2.0

# List values
helm install myapp ./chart --set tags[0]=prod --set tags[1]=web
  • Using a custom values file (-f): 
    # custom-values.yaml
replicaCount: 5
image:
  tag: "v2.0"

# Use it
helm install myapp ./chart -f custom-values.yaml
  • Multiple value files — later files take precedence: 
    helm install myapp ./chart -f base.yaml -f production.yaml
  • Precedence order (highest wins): --set > last -f file > earlier -f files > default values.yaml;
6. Environment-Specific Values
  • Create separate files per environment:
    • values-dev.yaml — low resources, latest tag, single replica;
    • values-prod.yaml — high resources, pinned tag, autoscaling enabled;
  • values-dev.yaml: 
    replicaCount: 1
image:
  tag: "latest"
resources:
  limits:
    cpu: 200m
    memory: 256Mi
  • values-prod.yaml: 
    replicaCount: 5
image:
  tag: "v1.0.0"
resources:
  limits:
    cpu: 1000m
    memory: 1Gi
autoscaling:
  enabled: true
  • Deploy: 
    helm install myapp ./chart -f values-dev.yaml
helm install myapp ./chart -f values-prod.yaml
7. Conditional Configuration
  • Use enabled flags to make features optional: 
    # values.yaml
ingress:
  enabled: false
  className: nginx
  hosts:
    - host: example.com
      paths:
        - path: /
          pathType: Prefix

autoscaling:
  enabled: false
  minReplicas: 2
  maxReplicas: 10
  • Guard the resource in the template with if: 
    {{- if .Values.ingress.enabled }}
apiVersion: networking.k8s.io/v1
kind: Ingress
...
{{- end }}
8. Default Values with Fallbacks
  • Use the default function to fall back when a value is not set: 
    # values.yaml — tag is optional
image:
  repository: nginx
  # tag: ""

# template — falls back to Chart.appVersion
image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
9. Global Values
  • Values under the global key are accessible to the parent chart and all sub-charts: 
    # parent values.yaml
global:
  imageRegistry: myregistry.example.com
  storageClass: fast-ssd

# accessible in any chart/subchart template
image: "{{ .Values.global.imageRegistry }}/myapp:1.0"
  • Useful for sharing configuration across a chart and its dependencies (e.g., a common image registry or domain);
10. Comprehensive Example
  • replicaCount: 2

image:
  repository: myapp
  tag: "1.0.0"
  pullPolicy: IfNotPresent
  pullSecrets:
    - name: regcred

service:
  type: ClusterIP
  port: 80
  annotations:
    service.beta.kubernetes.io/aws-load-balancer-type: nlb

ingress:
  enabled: true
  className: nginx
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
  hosts:
    - host: myapp.example.com
      paths:
        - path: /
          pathType: Prefix
  tls:
    - secretName: myapp-tls
      hosts:
        - myapp.example.com

resources:
  limits:
    cpu: 1000m
    memory: 1Gi
  requests:
    cpu: 500m
    memory: 512Mi

autoscaling:
  enabled: true
  minReplicas: 2
  maxReplicas: 10
  targetCPUUtilizationPercentage: 80

env:
  - name: DATABASE_URL
    value: "postgres://db:5432/mydb"
  - name: REDIS_URL
    value: "redis://redis:6379"

configMap:
  data:
    app.properties: |
      server.port=8080
      logging.level=INFO
