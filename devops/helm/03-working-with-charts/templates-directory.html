templates/ Directory

1. What is the templates/ directory?
  • Contains Go-template files that Helm renders into Kubernetes manifests;
  • During helm install / helm upgrade, Helm processes every .yaml and .tpl file through the Go template engine, injects values, and sends the resulting YAML to the k8s API server;
  • Files starting with _ (e.g., _helpers.tpl) are not rendered as standalone manifests — they only define reusable named templates;
  • NOTES.txt is rendered but its output is printed to the terminal, not sent to Kubernetes;
2. Standard Files
  • templates/
├── _helpers.tpl           # named template definitions
├── deployment.yaml        # Deployment
├── service.yaml           # Service
├── serviceaccount.yaml    # ServiceAccount
├── ingress.yaml           # Ingress (usually conditional)
├── hpa.yaml               # HorizontalPodAutoscaler (usually conditional)
├── configmap.yaml         # ConfigMap
├── secret.yaml            # Secret
├── NOTES.txt              # post-install/upgrade message
└── tests/
    └── test-connection.yaml   # helm test pod
  • You can add any number of extra files — each .yaml file produces one or more k8s resources;
3. _helpers.tpl
  • Defines reusable named templates via {{- define "name" }} … {{- end }};
  • Other templates include them via {{ include "name" . }};
  • Typical definitions: 
    {{- define "myapp.name" -}}
{{- default .Chart.Name .Values.nameOverride | trunc 63 | trimSuffix "-" }}
{{- end }}

{{- define "myapp.fullname" -}}
{{- if .Values.fullnameOverride }}
{{- .Values.fullnameOverride | trunc 63 | trimSuffix "-" }}
{{- else }}
{{- printf "%s-%s" .Release.Name (include "myapp.name" .) | trunc 63 | trimSuffix "-" }}
{{- end }}
{{- end }}

{{- define "myapp.labels" -}}
helm.sh/chart: {{ printf "%s-%s" .Chart.Name .Chart.Version | replace "+" "_" }}
app.kubernetes.io/name: {{ include "myapp.name" . }}
app.kubernetes.io/instance: {{ .Release.Name }}
app.kubernetes.io/managed-by: {{ .Release.Service }}
{{- end }}

{{- define "myapp.selectorLabels" -}}
app.kubernetes.io/name: {{ include "myapp.name" . }}
app.kubernetes.io/instance: {{ .Release.Name }}
{{- end }}
4. deployment.yaml
  • Defines the application workload — image, replicas, ports, probes, resources: 
    apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "myapp.fullname" . }}
  labels:
    {{- include "myapp.labels" . | nindent 4 }}
spec:
  replicas: {{ .Values.replicaCount }}
  selector:
    matchLabels:
      {{- include "myapp.selectorLabels" . | nindent 6 }}
  template:
    metadata:
      labels:
        {{- include "myapp.selectorLabels" . | nindent 8 }}
    spec:
      containers:
        - name: {{ .Chart.Name }}
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
          imagePullPolicy: {{ .Values.image.pullPolicy }}
          ports:
            - containerPort: {{ .Values.service.port }}
          {{- with .Values.resources }}
          resources:
            {{- toYaml . | nindent 12 }}
          {{- end }}
5. service.yaml
  • Exposes the Deployment as a stable network endpoint: 
    apiVersion: v1
kind: Service
metadata:
  name: {{ include "myapp.fullname" . }}
  labels:
    {{- include "myapp.labels" . | nindent 4 }}
spec:
  type: {{ .Values.service.type }}
  ports:
    - port: {{ .Values.service.port }}
      targetPort: {{ .Values.service.port }}
      protocol: TCP
  selector:
    {{- include "myapp.selectorLabels" . | nindent 4 }}
6. Conditional Resources (ingress, hpa)
  • Guard optional resources with {{- if }} so they are only created when enabled in values: 
    {{- if .Values.ingress.enabled }}
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: {{ include "myapp.fullname" . }}
  {{- with .Values.ingress.annotations }}
  annotations:
    {{- toYaml . | nindent 4 }}
  {{- end }}
spec:
  ingressClassName: {{ .Values.ingress.className }}
  rules:
    {{- range .Values.ingress.hosts }}
    - host: {{ .host }}
      http:
        paths:
          {{- range .paths }}
          - path: {{ .path }}
            pathType: {{ .pathType }}
            backend:
              service:
                name: {{ include "myapp.fullname" $ }}
                port:
                  number: {{ $.Values.service.port }}
          {{- end }}
    {{- end }}
{{- end }}
7. NOTES.txt
  • Rendered like any template but output is printed to the terminal after helm install / helm upgrade;
  • Not sent to Kubernetes — purely informational;
  • Typically shows how to access the deployed application: 
    Thank you for installing {{ .Chart.Name }}!

Your release is named {{ .Release.Name }}.

To access your application:

  export POD_NAME=$(kubectl get pods -n {{ .Release.Namespace }} \
    -l "app.kubernetes.io/instance={{ .Release.Name }}" \
    -o jsonpath="{.items[0].metadata.name}")

  kubectl port-forward $POD_NAME 8080:{{ .Values.service.port }}

  echo "Visit http://127.0.0.1:8080"
8. tests/ Directory
  • Contains pod definitions annotated with "helm.sh/hook": test;
  • Executed via helm test <release> after installation;
  • Typical test — curl the Service to verify a successful response: 
    apiVersion: v1
kind: Pod
metadata:
  name: "{{ include "myapp.fullname" . }}-test"
  annotations:
    "helm.sh/hook": test
spec:
  restartPolicy: Never
  containers:
    - name: curl
      image: curlimages/curl:latest
      command: ['curl', '--fail', '{{ include "myapp.fullname" . }}:{{ .Values.service.port }}']
9. Template Rendering Order
  • CRDs in crds/ are installed first (plain YAML, no templating);
  • All files in templates/ are rendered through the Go template engine;
  • Files starting with _ contribute named templates but produce no output;
  • NOTES.txt output goes to terminal only;
  • All other rendered YAML is sent to the k8s API server in a single batch;
10. Common Patterns
  • toYaml — convert a values block to YAML (useful for resources, annotations): 
    {{- with .Values.resources }}
resources:
  {{- toYaml . | nindent 2 }}
{{- end }}
  • nindent — indent rendered output by N spaces (critical for correct YAML nesting);
  • with — scope a block to a value; the block is skipped if the value is empty: 
    {{- with .Values.nodeSelector }}
nodeSelector:
  {{- toYaml . | nindent 2 }}
{{- end }}
  • range — iterate over lists or maps: 
    {{- range .Values.env }}
- name: {{ .name }}
  value: {{ .value | quote }}
{{- end }}
  • include vs template — prefer include over template because include returns a string that can be piped to functions like nindent;
