Chart.yaml Explained

1. What is Chart.yaml?
  • The main descriptor file for a Helm chart — every chart must have one;
  • Contains metadata: name, version, description, dependencies, maintainers;
  • Must be valid YAML;
2. Complete Example
  • apiVersion: v2
name: myapp
version: 1.2.3
appVersion: "2.0.1"
description: A Helm chart for my application
type: application
keywords:
  - web
  - backend
home: https://myapp.example.com
sources:
  - https://github.com/myorg/myapp
maintainers:
  - name: John Doe
    email: john@example.com
    url: https://github.com/johndoe
icon: https://example.com/images/myapp-icon.png
deprecated: false
kubeVersion: ">=1.20.0 <1.28.0"
dependencies:
  - name: mysql
    version: "9.3.4"
    repository: https://charts.bitnami.com/bitnami
    condition: mysql.enabled
annotations:
  category: ApplicationServer
  licenses: Apache-2.0
3. Required Fields
  • apiVersion — must be v2 for Helm 3 (v1 was for Helm 2);
  • name — chart name; must match the directory name;
  • version — chart version (SemVer: Major.Minor.Patch); must be incremented on every change;
4. Optional Fields
  • appVersion — version of the application being deployed; purely informational — Helm does not use it;
  • description — one-line description;
  • type — application (default) or library;
  • keywords — list of keywords for searching in repositories;
  • home — project home page URL;
  • sources — list of source code URLs;
  • maintainers — list with name, email, and optional url;
  • icon — URL to an SVG or PNG icon;
  • deprecated — true to mark the chart as deprecated;
  • kubeVersion — compatible Kubernetes version constraint;
  • dependencies — list of sub-charts this chart depends on;
  • annotations — arbitrary key-value metadata;
5. version vs appVersion
  • version — version of the chart (changes when templates, values, or structure change);
  • appVersion — version of the application the chart deploys;
  • They are independent — you can bump one without the other: 
    # Chart v1.0.0, App v1.20 — initial release
version: 1.0.0
appVersion: "1.20"

# Chart unchanged, app updated → only appVersion changes
version: 1.0.0
appVersion: "1.21"

# Template changed, app unchanged → only version changes
version: 1.1.0
appVersion: "1.21"
6. Chart Type
  • application (default) — installable chart that renders Kubernetes resources;
  • library — provides reusable template helpers only; cannot be installed directly; used as a dependency by application charts: 
    apiVersion: v2
name: common-helpers
type: library
version: 1.0.0
7. kubeVersion Constraints
  • Prevents installation on incompatible clusters; Helm checks before install/upgrade: 
    # Minimum version
kubeVersion: ">=1.20.0"

# Range
kubeVersion: ">=1.20.0 <1.28.0"

# Multiple constraints (OR)
kubeVersion: ">=1.20.0 <1.28.0 || >=1.29.0"
8. Dependencies
  • Declares sub-charts this chart needs; downloaded to charts/ via helm dependency update: 
    dependencies:
  - name: mysql
    version: "9.3.4"
    repository: https://charts.bitnami.com/bitnami
    condition: mysql.enabled
    tags:
      - database
    import-values:
      - data
    alias: db

  - name: redis
    version: "~17.3.0"
    repository: https://charts.bitnami.com/bitnami
    condition: redis.enabled
  • name — dependency chart name;
  • version — SemVer range constraint;
  • repository — chart repo URL;
  • condition — values.yaml path that enables/disables this dependency;
  • tags — group-enable/disable multiple dependencies at once;
  • alias — alternate name (useful when depending on the same chart twice);
  • import-values — import values from child chart into parent;
9. Annotations
  • Arbitrary metadata consumed by tools and repositories (e.g., Artifact Hub): 
    annotations:
  category: Database
  licenses: Apache-2.0
  artifacthub.io/changes: |
    - kind: added
      description: Support for custom configurations
    - kind: fixed
      description: Fixed service port mapping
  artifacthub.io/links: |
    - name: Documentation
      url: https://docs.example.com
10. Deprecated Charts
  • Set deprecated: true and note the replacement in the description: 
    apiVersion: v2
name: oldapp
version: 2.0.0
deprecated: true
description: "DEPRECATED — use newapp chart instead"
  • Helm will show a warning when users try to install a deprecated chart;
