OCI Registry

1. What is an OCI Registry?
  • OCI stands for Open Container Initiative — a standard for container image formats and distribution;
  • An OCI registry is a container registry (like Docker Hub, AWS ECR, GCR, ACR, GitHub Container Registry) that can also store Helm charts;
  • Instead of using a traditional Helm repository (HTTP server + index.yaml), you push charts directly to a container registry using the OCI protocol;
  • OCI support was introduced as experimental in Helm 3.0 and became stable/GA in Helm 3.8+;
2. OCI Registry vs Traditional Helm Repository
Traditional Repository OCI Registry
Protocol HTTP/HTTPS OCI Distribution Spec (same as Docker images)
Discovery index.yaml Registry API (no index.yaml needed)
helm repo add Required Not used — you reference oci:// URLs directly
helm repo update Required Not used
helm search helm search repo Not supported — use registry UI or API to browse
Authentication Basic auth / token via repo URL helm registry login (uses Docker-style auth)
Push Upload .tgz + regenerate index.yaml helm push
Storage Separate chart server Same registry as your container images
3. Authentication — helm registry login / logout
# Login to a registry
helm registry login registry.example.com
# Prompts for username and password

# Login with credentials inline
helm registry login registry.example.com --username myuser --password mypass

# Login to Docker Hub
helm registry login registry-1.docker.io

# Login to AWS ECR
aws ecr get-login-password --region us-east-1 | helm registry login \
  --username AWS --password-stdin 123456789.dkr.ecr.us-east-1.amazonaws.com

# Login to GitHub Container Registry (GHCR)
echo $GITHUB_TOKEN | helm registry login ghcr.io --username <github-user> --password-stdin

# Logout
helm registry logout registry.example.com
  • Credentials are stored in ~/.config/helm/registry/config.json (same format as Docker's config.json);
  • If you're already logged in via docker login, Helm can reuse those credentials;
4. Pushing a Chart — helm push

Step 1: Package the chart

helm package ./mychart
# Creates mychart-0.1.0.tgz

Step 2: Push to an OCI registry

helm push mychart-0.1.0.tgz oci://registry.example.com/charts
  • The chart is stored at oci://registry.example.com/charts/mychart with tag 0.1.0;
  • The chart name comes from Chart.yaml, the tag comes from the chart version;
  • You do NOT specify the chart name or version in the URL — only the "namespace/path";

Examples with different registries:

# Docker Hub
helm push mychart-0.1.0.tgz oci://registry-1.docker.io/mynamespace

# AWS ECR
helm push mychart-0.1.0.tgz oci://123456789.dkr.ecr.us-east-1.amazonaws.com

# GitHub Container Registry
helm push mychart-0.1.0.tgz oci://ghcr.io/myorg

# Google Artifact Registry
helm push mychart-0.1.0.tgz oci://us-central1-docker.pkg.dev/myproject/myrepo
5. Pulling a Chart — helm pull
# Pull a specific version
helm pull oci://registry.example.com/charts/mychart --version 0.1.0
# Downloads mychart-0.1.0.tgz to the current directory

# Pull and untar
helm pull oci://registry.example.com/charts/mychart --version 0.1.0 --untar
6. Installing from an OCI Registry
# Install directly from OCI registry
helm install myrelease oci://registry.example.com/charts/mychart --version 0.1.0

# Install from Docker Hub
helm install myrelease oci://registry-1.docker.io/bitnamicharts/nginx

# With custom values
helm install myrelease oci://registry.example.com/charts/mychart --version 0.1.0 -f values.yaml
  • Helm does NOT use index.yaml for OCI — it communicates directly with the registry API;
  • No need for helm repo add or helm repo update;
7. Inspecting a Chart in OCI Registry — helm show
# Show chart metadata
helm show chart oci://registry.example.com/charts/mychart --version 0.1.0

# Show default values
helm show values oci://registry.example.com/charts/mychart --version 0.1.0

# Show README
helm show readme oci://registry.example.com/charts/mychart --version 0.1.0

# Show everything
helm show all oci://registry.example.com/charts/mychart --version 0.1.0
8. Listing Tags in a Registry
  • helm search does NOT work with OCI registries;
  • To list available versions/tags, you need to use the registry's API or UI;
# Using the OCI Distribution API (works with most registries)
curl -s https://registry.example.com/v2/charts/mychart/tags/list

# Using crane (a popular container registry CLI tool)
crane ls registry.example.com/charts/mychart

# For Docker Hub
curl -s https://registry.hub.docker.com/v2/repositories/bitnamicharts/nginx/tags/?page_size=25

# For AWS ECR
aws ecr describe-images --repository-name mychart --query 'imageDetails[].imageTags'

# For GHCR
gh api /user/packages/container/mychart/versions
9. Helm Template / Upgrade with OCI
# Template rendering
helm template myrelease oci://registry.example.com/charts/mychart --version 0.1.0

# Upgrade a release
helm upgrade myrelease oci://registry.example.com/charts/mychart --version 0.2.0
10. Common OCI Registry Providers
Provider OCI URL Prefix
Docker Hub oci://registry-1.docker.io/<namespace>
AWS ECR oci://<account-id>.dkr.ecr.<region>.amazonaws.com
Google Artifact Registry oci://<region>-docker.pkg.dev/<project>/<repo>
Azure ACR oci://<registry>.azurecr.io
GitHub GHCR oci://ghcr.io/<owner>
Harbor oci://<harbor-host>/<project>
11. Quick Reference
# Authentication
helm registry login <registry>
helm registry logout <registry>

# Push
helm package ./mychart
helm push mychart-0.1.0.tgz oci://<registry>/<path>

# Pull
helm pull oci://<registry>/<path>/<chart> --version <ver>

# Install
helm install <release> oci://<registry>/<path>/<chart> --version <ver>

# Inspect
helm show chart oci://<registry>/<path>/<chart> --version <ver>
helm show values oci://<registry>/<path>/<chart> --version <ver>

# Upgrade
helm upgrade <release> oci://<registry>/<path>/<chart> --version <ver>

# Template
helm template <release> oci://<registry>/<path>/<chart> --version <ver>
