Listing and Managing Releases

1. Listing Releases
# List releases in current namespace
helm list

# List releases in specific namespace
helm list --namespace production

# List releases in all namespaces
helm list --all-namespaces

# Short form
helm ls -A
2. Helm List Output
NAME      NAMESPACE   REVISION  UPDATED                   STATUS    CHART         APP VERSION
myapp     default     3         2026-02-26 10:30:15 UTC  deployed  myapp-1.0.0   1.0
  • NAME: Release name;
  • NAMESPACE: Kubernetes namespace;
  • REVISION: Current revision number (increments on upgrade);
  • UPDATED: Last update timestamp;
  • STATUS: deployed, failed, pending-install, pending-upgrade, uninstalling;
  • CHART: Chart name and version;
  • APP VERSION: Application version from Chart.yaml;
3. Filtering Releases
# Filter by status
helm list --deployed
helm list --failed
helm list --pending

# Filter by name (regex)
helm list --filter '^my'

# Show all releases (including uninstalled)
helm list --all

# Show only uninstalled releases
helm list --uninstalled
4. Getting Release Details

Release status:

helm status myapp

# Output includes:
# - Release metadata
# - Resources deployed
# - NOTES.txt content
# - Last deployment time

Release values:

# Show user-supplied values
helm get values myapp

# Show all values (including defaults)
helm get values myapp --all

# Output as JSON
helm get values myapp -o json

Release manifest:

# Show rendered Kubernetes manifests
helm get manifest myapp

# Save to file
helm get manifest myapp > manifest.yaml

Release notes:

# Show NOTES.txt from last deployment
helm get notes myapp

Release hooks:

# Show hooks used in release
helm get hooks myapp
5. Release History
# View revision history
helm history myapp

# Output:
REVISION  UPDATED                   STATUS      CHART         APP VERSION  DESCRIPTION
1         Mon Feb 26 10:00:00 2026  superseded  myapp-1.0.0   1.0          Install complete
2         Mon Feb 26 10:15:00 2026  superseded  myapp-1.1.0   1.1          Upgrade complete
3         Mon Feb 26 10:30:00 2026  deployed    myapp-1.2.0   1.2          Upgrade complete

# Show maximum number of revisions
helm history myapp --max 5
6. Release Status Values
Status Description
deployed Successfully installed and running
failed Installation or upgrade failed
pending-install Installation in progress
pending-upgrade Upgrade in progress
pending-rollback Rollback in progress
superseded Replaced by a newer revision
uninstalling Uninstallation in progress
uninstalled Successfully uninstalled
7. Comparing Releases
# Get manifest for specific revision
helm get manifest myapp --revision 1 > rev1.yaml
helm get manifest myapp --revision 2 > rev2.yaml

# Compare with diff
diff rev1.yaml rev2.yaml

# Or use helm-diff plugin
helm plugin install https://github.com/databus23/helm-diff
helm diff revision myapp 1 2
8. Managing Multiple Releases
# List all releases across all namespaces
helm list -A

# List releases with specific label
kubectl get secrets -l owner=helm -A

# Count releases per namespace
helm list -A | awk '{print $2}' | sort | uniq -c
9. Release Metadata

Helm stores release information as Kubernetes Secrets:

# View release secrets
kubectl get secrets -l owner=helm

# Secret naming: sh.helm.release.v1.<release-name>.v<revision>
kubectl get secret sh.helm.release.v1.myapp.v3 -o yaml

# Decode release data
kubectl get secret sh.helm.release.v1.myapp.v3 -o jsonpath='{.data.release}' | base64 -d | base64 -d | gunzip
10. Best Practices
  • Use meaningful release names: frontend-prod instead of release-1;
  • Namespace isolation: Deploy to appropriate namespaces (dev, staging, prod);
  • Track revisions: Regularly check helm history to understand deployment timeline;
  • Clean up old revisions: Use --history-max to limit stored revisions;
  • Document changes: Use --description flag during upgrades;
# Limit revision history
helm upgrade myapp ./chart --history-max 5

# Add description
helm upgrade myapp ./chart --description "Updated to v2.0 with new features"
