What is a Container?
    It is a running instance of an image; 
    You can create, start, stop, restart, pause, resume, delete a container;
    
    By default, a container is isolated from other containers and it's host machine;
    You can connect a container to one or more networks, attach storage OR even create a new image based on it's current state;

docker run <options> <image> <command> <args>                       # It pulls the image if needed and creates a container; command -> cmd to run inside the container;
    Options:
        -d                              -> Runs the container in background mode, by detaching the terminal from container;
        -name <name>                    -> By default, container name is auto-generated; If you want, you can provide a name explicitly;
        -p <HostPort:ContainerPort>     -> It maps specified port on host to container port; Any requests to <HostIP:HostPort> are routed to <ContainerIP:ContainerPort>;
        -v                              -> It mounts a directory on host filesystem in the container file system;
        -env                            -> It is used to setup environment variables inside the container;
        -env-file                       -> File of environment variables;
        -it                             -> It opens interative session, so that you can interact with the container's CLI;
                                        -> Press Ctrl + PQ to exit the container, without killing it;
                                        -> Press Ctrl + C to kill and exit the container;
        --rm                            -> A stopped/exited container continue to exist and you can again start is using docker start;
                                        -> In case, if you don't need it ever, use this option to automatically remove the stopped/exited container, thus saving disk space;

SIGSTOP is the pause signal. The only behaviour is to pause the process. The shell uses pausing (and its counterpart, resuming via SIGCONT) to implement job control.

    Now that we have an image pulled locally, we can use the docker container run command to launch a container from it.
    docker container run tells the Docker daemon to start a new container. 
    The -it flags tell Docker to make the container interactive and to attach the current shell to the container’s terminal (we’ll get more specific about this in the chapter on containers). 
    Next, the command tells Docker that we want the container to be based on the ubuntu:latest image
    Finally, we tell Docker which process we want to run inside of the container. For the Linux example, we’re running a Bash shell. 
    Press Ctrl-PQ to exit the container without terminating it. This will land your shell back at the terminal of your Docker host.
    In a previous step, you pressed Ctrl-PQ to exit from the container. Doing this from inside of a container will exit you from the container without killing it.

    You can attach your shell to the terminal of a running container with the docker container exec command. As the container from the previous steps is still running, let’s make a new connection to it.

A Docker image is made up of multiple layers. 
An image is a read-only template with instructions for creating a Docker container. 
Often, an image is based on another image, with some additional customization. 
For example, you may build an image which is based on the ubuntu image, but installs the Apache web server and your application, as well as the configuration details needed to make your application run.

You might create your own images or you might only use those created by others and published in a registry. 
To build your own image, you create a Dockerfile with a simple syntax for defining the steps needed to create the image and run it. 
Each instruction in a Dockerfile creates a layer in the image. 
When you change the Dockerfile and rebuild the image, only those layers which have changed are rebuilt. This is part of what makes images so lightweight, small, and fast, when compared to other virtualization technologies.

Ways to Create an Image:
a) Take image from the docker hub.
b) Create image from docker file.
c) Create image from existing docker containers.

spring-boot-maven-plugin
	By default, this plugin is added to every spring boot project created using https://start.spring.io;

	It provides many features:
		- It collects all the jars on the classpath and builds a single, runnable uber-jar, which makes it more convenient to execute and transport your service;
		- We would want to run the applications in place without building a JAR or a WAR;
		- We would want to build a JAR and a WAR for later deployment;

	It provides several goals:
		- run 				-> It is used to run your spring boot application in-place; You can pass several parameters to it;
		- build-image 		-> It is used to build docker image from jar or war file;
		- repackage 		-> It is used to create executable jar, which contains all dependencies and can be run with java -jar;
		- start, stop 		-> integrate your Spring Boot application to the integration-test phase;


How to create a Docker Image for Spring Boot Applications?
	Starting Spring Boot 2.3, it is very easy to create docker image for spring boot applications;
	You can use spring-boot-maven-plugin;
		<build>
			<plugins>
				<plugin>
					<groupId>org.springframework.boot</groupId>
					<artifactId>spring-boot-maven-plugin</artifactId>
					<configuration>
						<!-- name of the image that we want to create! in28min is my docker id! -->
						<image>in28min/mmv2-${project.artifactId}:${project.version}</image> 		
						<!-- spring-boot-maven-plugin makes use of lot of docker images, while building an image; -->
						<!-- Default pullPolicy: always; It pulls images, whether it is present or not in your local; -->
						<!-- As a optimization, change it to IF_NOT_PRESENT -->
						<pullPolicy>IF_NOT_PRESENT</pullPolicy>
					</configuration>
				</plugin>
			</plugins>
		</build>

		To build the docker image locally:
			Using Eclipse: Right click on project -> Run As -> Maven Build -> Goals -> spring-boot:build-image -DskipTests
			Using CLI: mvn spring-boot:build-image -DskipTests

		To create a container: docker run -p 8000:8000 in28min/mmv2-currency-exchange-service:0.0.1-SNAPSHOT

		# Once you find, everything is good, you can push the image to docker registry;
		docker push docker.io/in28min/mmv2-currency-exchange-service:0.0.1-SNAPSHOT
