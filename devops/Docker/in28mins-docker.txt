What is Docker?
	Docker is a platform/ecosystem, which is used to manage(create/publish/run/update) containerized applications;
	create and run containers;
	Ecosystem = Docker Client + Docker Server + Docker Machine + Docker Images + Docker Hub + Docker Compose;

Why Docker?
	As you saw earlier, you can develop microservices using many programming languages: Java, Python etc;
	But, how about deployment? You don't want different deployment procedures for different microservices;
	That's where docker comes into picture!
	---
	What you can do is, create docker image for each of the above service;
	Docker image contains everything for the service to run: runtime, jdk, python, nodejs, application code etc;
	Once you have created docker image, you can run it anywhere(your local, corporate datacenter, cloud);
	---
	In short, it makes it easy to install and run software, without worrying about dependencies;

Deploying a Spring Boot Application using Docker
	docker run in28min/todo-rest-api-h2:1.0.0.RELEASE 		# One simple command, you don't need to worry about anything else! that's the magic of Docker!!

How does it works?
	When you run 'docker run', docker downloads an image from Docker Hub: http://hub.docker.com/r/in28min/todo-rest-api-h2
	Docker Hub(hub.dockr.com) contains lot of Repositories; You can create a Repository of your own;
	Each Repository can have lot of appliations of different Versions/Tags;
	Docker Hub is a public registry; Typically, enterprises use their own private repositories, so that only authorized people can access it;

	In http://hub.docker.com/r/in28min/todo-rest-api-h2
		- hub.oracle.com is a Registry
		- in28min/todo-rest-api-h2 is a Repository
		- 1.0.0.RELEASE is the Version/Tag;

	Once it downloads the image, it executes it as an appllication; Running application is called Container;

	How to access the application?
		http://localhost:8080/hello-world-bean 	# You get an error: Site is unreachable!

	How to resovle the error?
		By default, any container that you run is part of bridge network in Docker;
		You can think of it like a docker internal network;
		Nobody can access it, unless you expose it onto the host system, where your container is running;
		To expose container port as a host port, use: -p {HostPort}:{ContainerPort}

		docker run -p 5000:5000 in28min/todo-rest-api-h2:1.0.0.RELEASE 
		Now, try accessing http://localhost:8080/hello-world-bean, you will get response!

# Container Related
# docker run is a shortcut to docker continer run;
docker run -p 5000:5000 -d in28min/todo-rest-api-h2:1.0.0.RELEASE  	# Run the container in the background(detached mode); It prints container ID;
docker logs <containerID> 											# It prints some latest logs;
docker logs -f <containerID> 										# It tails the logs;
docker container ls 												# List of all running containers
docker container ls -a												# List of all containers

docker container inspect <containerId> 	# Lot of details about container: when it was creted, image used, port bindings, volumes, status etc;
docker container pause <containerId> 	# To pause a running container! It won't respond to any requests!
docker container unpause <containerId> 	# To unpause a running container!
docker container stop <containerId> 	# To gracefully shutdown a running container!
docker container kill <containerId> 	# To stop a running container immediately! // kill -9
docker container prune; 				# It will remove all stopped containers;

# restart: always | no(default); 
# When docker is restarted, any stopped containers with restart policy always are started automatically!
# If you want to stop it from restarting: once you stop the container, prune it;
docker run -p 5000:5000 -d --restart=always in28min/todo-rest-api-h2:1.0.0.RELEASE

# CPU -> 100000 = 100%, 5000=5%
# You can specify the maximum memory and CPU that a container can consume!
docker run -p 5000:5000 -d -m 512m --cpu-quota 5000 in28min/todo-rest-api-h2:1.0.0.RELEASE
