How do I set up an Ansible environment?
    1. Create development environment;
        1.1 Run Ansible within a Docker Container;
            -- Why to use a docker container to build Ansible environment?
                --- Separates the Ansible environment from the infrastructure it aims to manage;
                --- Provides a consistent development experience for you and your team;
                --- Provides an immutable Ansible environment;
                --- Reduces management overhead (less infrastructure to manage);
            -- Steps
                --- Install Docker;
                    Docker is a container management tool; You can easily build, run, and deploy containers using Docker;
                --- Create a Dockerfile, for setting up Ansible environment; # Check Dockerfile.v1
                    A Dockerfile is a text document that contains all the commands a user could call on the command line to assemble an image;                
                --- Build a Docker image;
                    Before you run a container, you first need to create an image; You can use docker build command, to build an image from Dockerfile;
                    > sudo docker build -f ./Dockerfile.v1 -t cheedhella/ansible:latest .      # What is -t option? Tag consists of image name and tag; Docker uses tags to name and version the images; 
                    > sudo docker images                               # once docker build is completed, run docker images, to see if the image is created;
                --- Run a Docker container;
                    You can use 'docker run' to start a new container, using the newly build image;
                    > docker run cheedhella/ansible
                    > docker ps                 # What do you see? The container is not listed, right? It shows only running containers; A container needs to have a running process otherwise the container stops; Since the Ansible container isn’t doing anything, Docker stopped the container;
                    > docker ps --all           # You can see the exited container; Every time you run a container, docker assigns a new ID to it;
                    > docker run -it cheedhella/ansible    # Run the container interactively - You want to interact with the container rather than the container moving to the EXITED state, as it does when it has no work to do; It changes the command prompt from root@educative to root@<container-id>;
                    # ansible --version         # Check if Ansible is installed! 
                    # exit                      # Once you exit the container, it goes to STOPPED state;
                    # docker start --attach <container-id>      # You can start it again and attach it to the container;
                                                                # However, containers are meant to be disposable; Idea is that you should be able to start a new one, despite the state of the old container;
                    # docker run -it --rm ansible        # --rm removes the container, once it is STOPPED;
                -- Push a Docker Image to DockerHub;
                    In case you are returning to this lesson later than when you built the image, there is a chance that the image is destroyed, so you will have to run the build command again before executing the run command;
                    If you wish, you can push the image to docker hub, after you build it, for long term use; For this, you need to have an account in docker hub; 
                    Cloud platforms and other 3rd-party vendors provide options for private registries to store sensitive Docker images;
                    > docker login --username <DockerHub-UserName>              # Sign into DockerHub
                    > docker build -t <DockerHub-UserName>/ansible:latest .     # Add a repository name to image tag
                    > docker push <DockerHub-UserName>/ansible:latest           # Push the image;

        1.2 Mount volumes;
            -- Why?
                --- Docker allows you to mount a local directory to a directory inside the container;
                --- As Ansible is installed in the container, you can mount your ansible scripts and run them;
            -- How?
                > docker run -it cheedhella/ansible --rm --volume $(pwd):/ansible-repo ansible-repo                             # ${PWD} for Windows; --volume {host directory}:{container directory};
                > docker run -it --rm -v $(pwd)/ansible-repo:/ansible-repo -w /ansible-repo -d cheedhella/ansible          # One small inconvenience introduced by mounting a volume is that you have to change to the /ansible directory after starting the container. This can be resolved by using the --workdir option;
                > docker exec -it <container_id or name> bash
                ansible-repo# ls
                    Dockerfile.v1  adhoc  playbook

        1.3 Environment variables;
            -- Why?
                --- You can use environment variables to pass application configuration, such as AWS credentials;
            -- How?
                > docker run -it --rm --env "AWS_ACCESS_KEY_ID='<AWS_Access_Key_ID>'" --env "AWS_SECRET_ACCESS_KEY='<AWS_Secret_Access_Key>'" .
