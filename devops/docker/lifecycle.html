Docker — Container Lifecycle

1. Container States
  • A Docker container moves through a well-defined set of states from creation to removal;
  • Understanding these states is essential for managing containers correctly in production;

StateDescription
createdContainer has been created (docker create) but not yet started. Filesystem is set up; no process is running;
runningContainer process is actively executing. Entered via docker start or docker run;
pausedAll processes in the container are suspended via SIGSTOP. CPU is released but memory is retained;
stopped / exitedThe main process has terminated (either normally or via docker stop / docker kill). Container still exists on disk and can be restarted;
removedContainer has been deleted with docker rm. Its writable layer is gone permanently;
2. Creating a Container
  • docker run is the most common way — it pulls the image (if not cached), creates, and starts the container in one step;
  • docker create only prepares the container (allocates filesystem, sets config) without starting it; useful for pre-staging;
# Pull image + create + start (most common)
docker run nginx

# Run in background (detached)
docker run -d --name my-nginx nginx

# Run interactively with a shell
docker run -it ubuntu /bin/bash

# Run, then auto-remove when it exits
docker run --rm alpine echo "hello"

# Create only (do not start)
docker create --name my-nginx nginx

What happens internally when you run docker run -it ubuntu /bin/bash:

  • Docker checks the local image cache for ubuntu; if not found, pulls it from Docker Hub;
  • Docker Daemon creates a new container — sets up namespaces, cgroups, and a writable layer on top of the image;
  • Docker allocates a virtual network interface and assigns an IP address to the container;
  • Docker starts the container and executes /bin/bash;
  • Because -it was specified, your terminal's STDIN/STDOUT is attached to the container's shell;
  • When you type exit, the shell process ends, and the container moves to the exited state (but is not removed);
3. Starting & Stopping
CommandSignal SentBehaviour
docker stop <container>SIGTERM → (10 s grace) → SIGKILLGraceful shutdown — gives the app time to clean up, flush buffers, close connections;
docker kill <container>SIGKILL (default)Immediate, forceful termination — no cleanup time;
docker restart <container>SIGTERM → SIGKILL → startEquivalent to stop followed by start;
docker start <container>—Starts a previously stopped container, reusing its existing writable layer;
docker pause <container>SIGSTOPFreezes all processes; container stays in memory but uses no CPU;
docker unpause <container>SIGCONTResumes a paused container;
 
docker stop my-nginx            # graceful stop (waits up to 10 s)
docker stop -t 30 my-nginx      # extend grace period to 30 s
docker kill my-nginx            # immediate kill
docker restart my-nginx         # stop + start
docker start my-nginx           # start a stopped container
4. Interacting with a Running Container
  • docker exec — runs a new process inside an already-running container. The container must be in the running state;
  • docker attach — attaches your terminal to the container's main process (PID 1). Use Ctrl+P then Ctrl+Q to detach without stopping the container;
  • docker logs — reads the stdout/stderr of the container's main process without attaching to it;
# Open an interactive shell in a running container
docker exec -it my-nginx /bin/bash

# Run a one-off command
docker exec my-nginx ls /etc/nginx

# Run a command in a specific directory
docker exec --workdir /app my-nginx cat config.yaml

# Follow live logs
docker logs -f my-nginx

# Show last 50 lines with timestamps
docker logs -t --tail 50 my-nginx

# Attach to the main process (Ctrl+P Q to detach)
docker attach my-nginx
5. Inspecting Containers
# List running containers
docker ps

# List all containers (running + stopped)
docker ps -a

# List only container IDs
docker ps -q

# Filter by status
docker ps --filter status=exited

# Full JSON details (IP, mounts, env vars, etc.)
docker inspect my-nginx

# Running processes inside a container
docker top my-nginx

# Live CPU / memory / I/O stats
docker stats my-nginx

# Show port mappings
docker port my-nginx

# Show filesystem changes made inside the container
docker diff my-nginx
6. Copying Files
  • docker cp copies files between the host filesystem and a container (running or stopped);
  • You cannot copy directly between two containers — copy to the host first, then to the destination container;
  • Prefer using bind mounts or volumes for persistent data exchange rather than docker cp;
# Copy from host to container
docker cp ./config.yaml my-nginx:/etc/nginx/config.yaml

# Copy from container to host
docker cp my-nginx:/var/log/nginx/error.log ./error.log
7. Removing Containers
  • A stopped container still occupies disk space (its writable layer persists). Explicitly remove it when no longer needed;
  • You cannot remove a running container without the -f flag;
  • Use --rm on docker run to auto-remove the container as soon as it exits — ideal for one-off tasks;
# Remove a stopped container
docker rm my-nginx

# Force-remove a running container
docker rm -f my-nginx

# Remove all stopped containers
docker container prune

# Remove all stopped containers, unused networks, dangling images, and build cache
docker system prune

# Auto-remove on exit (use at creation time)
docker run --rm alpine echo "done"
8. Persisting Data — Volumes & Bind Mounts
  • A container's writable layer is ephemeral — all data written inside is lost when the container is removed;
  • To persist data, use volumes (managed by Docker) or bind mounts (a host directory mapped into the container);
TypeSyntaxBest For
Named volume-v my-vol:/app/dataPersistent app data managed by Docker; portable across containers
Bind mount-v /host/path:/container/pathSharing source code or config files from the host during development
tmpfs mount--tmpfs /tmpIn-memory temporary storage; not persisted to disk
 
# Named volume (Docker manages the storage location)
docker run -d -v my-data:/var/lib/mysql mysql

# Bind mount (host directory)
docker run -d -v $(pwd)/html:/usr/share/nginx/html nginx

# tmpfs (in-memory only)
docker run -d --tmpfs /tmp:size=100m nginx
