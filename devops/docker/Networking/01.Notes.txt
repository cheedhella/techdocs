Docker create unix socket to communicate, when docker daemon is started;
Verify it usng netstat and lsof commands:
# netstat -anp | grep docker
unix  2      [ ACC ]     STREAM     LISTENING     20890    1/systemd            /run/docker.sock
unix  2      [ ACC ]     STREAM     LISTENING     31912    2463/dockerd         /var/run/docker/metrics.sock
1st col: Protocol
2nd col: Reference count or no of times that is referred;
2rd col: In case of docker, ACC is the flag set for docker.sock;
4th col: Socket type -> UDP - DGRAM, TCP-STREAM;
5th col: State of the socket - LISTENING, CONNECTED state;
6th col: I-Node details;
7th col: PID shows the dockerd process-id details;
8th col: Path of socket in /var/run and /run/docker 


lsof shows the details of all open sockets;
lsof -U | grep docker -> 
dockerd     2463    root    3u  unix 0xffff990ec41e3600      0t0   31912 /var/run/docker/metrics.sock type=STREAM
dockerd     2463    root    4u  unix 0xffff990ec2f37600      0t0   20890 /run/docker.sock type=STREAM

When docker is installed, docker server by default creates a network interface called docker0;
It is used by docker containers to communicate with each other and with outside world;
Since this interface is bridge device, use brctl command to check if docker0 is configured;
use ifconfig, to check if docker0 interface is available;



iptables -> In linux, we use iptables to write rule and action for different packets arriving;
iptables -t nat -L -> Check all rules applied for docker to act;

for sending traffic, use pingc comand;
for capturing packet, use tcpdump or wireshark;
