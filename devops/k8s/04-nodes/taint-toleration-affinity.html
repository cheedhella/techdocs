Taint n Toleration

1. What is a Taint and Toleration?
  • Taint is like a no-entry sign on a node, unless Pods have a toleration(special pass that allows entry) to bypass the restriction;
  • They are used to ensure that Pods are not scheduled onto inappropriate pods;
  • Taint is like lock on the door of your hourse(node), restricting access to visitor(Pods);
  • Toleration is like keys that visitors(Pods) can carry, to bypass the locks(taints) and be scheduled on nodes;
2. Purpose of Taint and Toleration?
  • It is used for:
    • Keep certain pods away from certain nodes;
    • Reserve nodes for specific workloads(eg: GPU workloads);
    • You can use taint for evacuating a node for maintanance; But, 'kubectl drain' is more preferred way;
3. Taint Structure
  • Taint will have label(key-value pair) and effect: key=value:effect
  • effect
    • NoSchedule: Existing pods continue running; Only pods with matching toleration are allowed are allowed;
    • PreferNoSchedule: Scheduler prefers other nodes; If no other better option available, then may still run on this(soft rule);
    • NoExecute: Existing pods are evicted, if they don't tolerate; Only pods with matching toleration are allowed are allowed;
4. Toleration
  • A toleration is defined in the Pod spec and it tells k8s that: "Pod is ok with nodes with this taint - don't block or evict it";
  • 
# Node taint 
dedicated=gpu:NoSchedule

# Pod toleration
tolerations:
- key: "dedicated"
  operator: "Equal"
  value: "gpu"
  effect: "NoSchedule"

This Pod can be scheduled on above node;
5. Toleration Structure
  • key/value/effect in toleration must match with taint;
  • operator - It specifies how to match;
    • Equal: key + value must match; I accept nodes with this label(key + label) only;
    • Exists: Matches only key, ignores value; I am fine as long as label(same key) exists(with any value);
    • Exists without value: It matches all taints(any key, any value);
  • Taint will have label(key-value pair) and effect: key=value:effect

6. Taint & Toleration vs Affinity
  • Taint and tolerations are are used to prevent a Pod from being scheduled on to a node; They don't guaratee that a Pod will be scheduled on a specific tainted node; It is used to repel Pods from nodes; It is a mechanism for a node to reject certain pods;
  • Node Affinity is about attracting Pods to a set of nodes; It's a property of a pod that expresses a preference or requirement for certain nodes;
