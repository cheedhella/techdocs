Node Affinity and Anti-Affinity

1. What is Node Affinity?
  • An advanced version of nodeSelector with more expressive rules;
  • Supports required (hard) and preferred (soft) constraints;
  • Supports set-based operators: In, NotIn, Exists, DoesNotExist, Gt, Lt;
2. Required (Hard) Affinity
  • Pod MUST be scheduled on a matching node — otherwise it stays Pending;
spec:
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
          - matchExpressions:
              - key: topology.kubernetes.io/zone
                operator: In
                values:
                  - us-east-1a
                  - us-east-1b
3. Preferred (Soft) Affinity
  • Scheduler tries to place the Pod on a matching node but doesn't guarantee it;
  • weight (1–100) determines priority when multiple preferences exist;
spec:
  affinity:
    nodeAffinity:
      preferredDuringSchedulingIgnoredDuringExecution:
        - weight: 80
          preference:
            matchExpressions:
              - key: disktype
                operator: In
                values:
                  - ssd
        - weight: 20
          preference:
            matchExpressions:
              - key: zone
                operator: In
                values:
                  - us-east-1a
4. Anti-Affinity (Using NotIn / DoesNotExist)
  • To avoid certain nodes, use NotIn or DoesNotExist operators;
matchExpressions:
  - key: gpu
    operator: DoesNotExist    # Avoid GPU nodes
