Pod Affinity and Anti-Affinity

1. What is Pod Affinity?
  • Schedule Pods near other Pods (co-location) based on labels;
  • Useful when Pods need low-latency communication;
  • Example: Place the web frontend on the same node as the Redis cache;
2. Pod Affinity Example
spec:
  affinity:
    podAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        - labelSelector:
            matchExpressions:
              - key: app
                operator: In
                values:
                  - redis
          topologyKey: kubernetes.io/hostname
  • This Pod MUST be scheduled on a node that already runs a Pod with app=redis;
  • topologyKey defines the "domain" — hostname means same node;
3. Pod Anti-Affinity
  • Schedule Pods away from other Pods — for high availability;
  • Example: Spread replicas of the same app across different nodes;
spec:
  affinity:
    podAntiAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        - labelSelector:
            matchExpressions:
              - key: app
                operator: In
                values:
                  - myapp
          topologyKey: kubernetes.io/hostname

This ensures no two app=myapp Pods run on the same node.

4. Topology Keys
topologyKeyScope
kubernetes.io/hostnameSame node
topology.kubernetes.io/zoneSame availability zone
topology.kubernetes.io/regionSame region
