Labels and Selectors

1. What are Labels?
  • Key-value pairs attached to Kubernetes objects for identification and organization;
  • Do NOT affect behavior — they are purely metadata for selecting and filtering;
  • Example: app: nginx, env: production, tier: frontend;
metadata:
  labels:
    app: myapp
    env: production
    tier: frontend
    version: v2
2. Selectors
  • Equality-based: =, ==, !=
  • Set-based: in, notin, exists
# Equality-based
kubectl get pods -l app=nginx
kubectl get pods -l env!=production

# Set-based
kubectl get pods -l 'app in (nginx, redis)'
kubectl get pods -l 'tier notin (backend)'
kubectl get pods -l 'version'           # has the label
kubectl get pods -l '!canary'           # does NOT have the label

# Multiple conditions (AND)
kubectl get pods -l app=nginx,env=production
3. Selectors in Resources
# Service selector — routes traffic to matching Pods
spec:
  selector:
    app: myapp

# Deployment selector
spec:
  selector:
    matchLabels:
      app: myapp
    matchExpressions:
      - key: env
        operator: In
        values: ["staging", "production"]
4. Label Commands
# Add a label
kubectl label pod my-pod env=staging

# Update a label
kubectl label pod my-pod env=production --overwrite

# Remove a label
kubectl label pod my-pod env-

# Show labels
kubectl get pods --show-labels
5. Recommended Labels
labels:
  app.kubernetes.io/name: myapp
  app.kubernetes.io/instance: myapp-prod
  app.kubernetes.io/version: "1.2.3"
  app.kubernetes.io/component: frontend
  app.kubernetes.io/part-of: my-system
  app.kubernetes.io/managed-by: helm
