ConfigMap

1. What is a ConfigMap?
  • It is a k8s object that stores configuration as key-value pairs;
  • It is used to store non-sensitive configuration like database URL, username etc; For sensitive configuration like passwords and tokens, use Secret;
  • ConfigMaps are stored in the namespace in which they are created;
2. Why use a ConfigMap?
  • Runtime configuration
    • Almost every application can be fine-tuned through configuration;
    • Never store application configuration(like database URL, username, password etc) in the image/pod/deployment/server, separate it!
    • By separating the configuration from image, it allows us to change the configuration, without rebuilding the image OR redeploying;
  • Share configuration between pods
    • You can share configuration between multiple pods or containers;
  • Environment specific configuration
    • You can use different ConfigMaps for different environments(development, staging, production etc);

4. What happens when a ConfigMap is updated while Pods are running?
  • If ConfigMap is used as environment variables:
    • Environment variables are set when the container is started;
    • So, running pods don't get the udpated value;
    • Restart: kubectl rollout restart deployment <name>
  • If ConfigMap is used as a volume:
    • Files are updated automatically in the running pod(with around 1 min of delay);
    • But, the application must reload the file to get new config;
