Namespaces

1. What are Namespaces?
  • Virtual clusters within a physical cluster — provide logical isolation;
  • Used to divide cluster resources among multiple teams, projects, or environments;
  • Resource names must be unique within a namespace but not across namespaces;
2. Default Namespaces
NamespacePurpose
defaultFor objects with no namespace specified
kube-systemSystem components (CoreDNS, kube-proxy, etc.)
kube-publicPublicly accessible data (e.g., cluster info)
kube-node-leaseNode heartbeat leases for health detection
3. Namespaced vs Cluster-Scoped Resources
  • Namespaced: Pods, Services, Deployments, ConfigMaps, Secrets, Ingress;
  • Cluster-scoped: Nodes, PersistentVolumes, ClusterRoles, Namespaces;
# See which resources are namespaced
kubectl api-resources --namespaced=true
kubectl api-resources --namespaced=false
4. Commands
# Create a namespace
kubectl create namespace dev

# List namespaces
kubectl get namespaces

# Work in a specific namespace
kubectl get pods -n dev
kubectl apply -f deployment.yaml -n dev

# Set default namespace for current context
kubectl config set-context --current --namespace=dev

# Delete a namespace (deletes ALL resources inside!)
kubectl delete namespace dev
5. Namespace YAML
apiVersion: v1
kind: Namespace
metadata:
  name: dev
  labels:
    env: development
