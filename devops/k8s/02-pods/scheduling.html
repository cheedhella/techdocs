Resource Requests and Limits

1. Requests vs Limits
  • Request: The minimum amount of CPU/memory guaranteed to the container. Used by the scheduler to decide which node to place the Pod on;
  • Limit: The maximum amount of CPU/memory the container can use. If exceeded, the container is throttled (CPU) or killed (memory);
2. Example
apiVersion: v1
kind: Pod
metadata:
  name: resource-demo
spec:
  containers:
    - name: app
      image: myapp:v1
      resources:
        requests:
          memory: "128Mi"
          cpu: "250m"
        limits:
          memory: "256Mi"
          cpu: "500m"
3. CPU Units
  • 1 CPU = 1 vCPU / 1 hyperthread;
  • 100m = 100 millicores = 0.1 CPU;
  • 250m = 0.25 CPU (quarter of a core);
  • CPU is compressible — if a container exceeds its limit, it is throttled, not killed;
4. Memory Units
  • Specified in bytes: Ki, Mi, Gi (binary) or K, M, G (decimal);
  • Memory is incompressible — if a container exceeds its memory limit, it is OOMKilled;
5. QoS Classes
