Monitoring with Metrics Server and Prometheus

1. Metrics Server
  • A lightweight, in-cluster component that collects CPU and memory metrics from kubelets;
  • Required for kubectl top and Horizontal Pod Autoscaler;
  • NOT for long-term storage — it's a real-time snapshot;
# Install Metrics Server
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml

# Check node resource usage
kubectl top nodes

# Check Pod resource usage
kubectl top pods
kubectl top pods -A --sort-by=cpu
2. Prometheus
  • The industry-standard open-source monitoring and alerting system for Kubernetes;
  • Scrapes metrics from targets at regular intervals;
  • Stores time-series data with a powerful query language (PromQL);
  • Usually deployed with kube-prometheus-stack (Helm chart);
3. Prometheus Stack Components
ComponentPurpose
PrometheusScrapes and stores metrics
GrafanaVisualization dashboards
AlertmanagerHandles alerts (email, Slack, PagerDuty)
Node ExporterExports node-level hardware metrics
kube-state-metricsExports Kubernetes object state metrics
4. Exposing Application Metrics
  • Annotate your Pods so Prometheus discovers them:
metadata:
  annotations:
    prometheus.io/scrape: "true"
    prometheus.io/port: "9090"
    prometheus.io/path: "/metrics"
