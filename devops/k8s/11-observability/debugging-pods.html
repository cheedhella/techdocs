Debugging Pods and Troubleshooting

1. Troubleshooting Workflow
# Step 1: Check Pod status
kubectl get pods

# Step 2: Describe for details and events
kubectl describe pod my-pod

# Step 3: Check logs
kubectl logs my-pod
kubectl logs my-pod --previous    # If crashed

# Step 4: Check events
kubectl get events --sort-by='.lastTimestamp'

# Step 5: Exec into the container
kubectl exec -it my-pod -- /bin/sh
2. Common Issues and Solutions
StatusCommon CauseFix
PendingInsufficient resources, no matching nodeCheck events, add nodes, fix affinity/tolerations
ImagePullBackOffWrong image name, private registry, no authVerify image name, check imagePullSecrets
CrashLoopBackOffApp crashes on start, wrong command, missing configCheck logs (--previous), fix app or config
OOMKilledContainer exceeded memory limitIncrease memory limit or optimize app
CreateContainerConfigErrorMissing ConfigMap or SecretCreate the missing resource
3. Network Debugging
# Run a debug Pod with networking tools
kubectl run netdebug --image=nicolaka/netshoot -it --rm -- bash

# Inside the Pod:
curl http://my-service:80
nslookup my-service
ping 10.244.1.5
traceroute my-service
4. Node Troubleshooting
# Check node conditions
kubectl describe node worker-1

# Check node resource usage
kubectl top node worker-1

# Check system Pods on the node
kubectl get pods -A --field-selector spec.nodeName=worker-1
