Logging (kubectl logs, centralized logging)

1. Container Logging Basics
  • Containers should write logs to stdout and stderr;
  • The container runtime captures these and stores them on the node;
  • Default log location: /var/log/containers/ on the node;
  • Logs are lost when a Pod is deleted — centralized logging is essential for production;
2. kubectl logs
# View logs
kubectl logs my-pod

# Follow (stream) logs
kubectl logs -f my-pod

# Last N lines
kubectl logs my-pod --tail=50

# Logs since a time
kubectl logs my-pod --since=1h
kubectl logs my-pod --since-time="2024-01-01T00:00:00Z"

# Specific container (multi-container Pod)
kubectl logs my-pod -c sidecar

# Previous container (after a restart)
kubectl logs my-pod --previous

# All Pods with a label
kubectl logs -l app=myapp --all-containers=true
3. Centralized Logging Patterns
PatternDescription
Node-level agentDaemonSet (Fluentd/Fluent Bit) on each node, collects logs from /var/log

Direct from appApplication sends logs directly to the logging backend
4. Common Logging Stacks
  • EFK: Elasticsearch + Fluentd + Kibana;
  • ELK: Elasticsearch + Logstash + Kibana;
  • PLG: Promtail + Loki + Grafana (lightweight, popular);
  • Cloud native: CloudWatch (AWS), Stackdriver (GCP), Azure Monitor;
