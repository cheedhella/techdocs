kubectl debug and Ephemeral Containers

1. The Problem
  • Distroless and minimal container images lack debugging tools (no shell, no curl, no netstat);
  • You can't kubectl exec into a container that has no shell;
  • You don't want to add debugging tools to production images;
2. kubectl debug
  • Adds an ephemeral container to a running Pod for debugging;
  • The debug container shares the Pod's namespaces (network, PID);
  • Available since Kubernetes v1.25 (stable);
3. Usage
# Attach a debug container to an existing Pod
kubectl debug my-pod -it --image=busybox -- sh

# Debug with full networking tools
kubectl debug my-pod -it --image=nicolaka/netshoot -- bash

# Share process namespace (see processes from the target container)
kubectl debug my-pod -it --image=busybox --target=main -- sh

# Debug by creating a copy of the Pod
kubectl debug my-pod -it --image=busybox --copy-to=my-pod-debug -- sh

# Debug a node
kubectl debug node/worker-1 -it --image=busybox
4. Ephemeral Containers
  • Temporary containers added to a Pod after creation;
  • Cannot be restarted, have no ports, and lack probe support;
  • Designed exclusively for troubleshooting;
  • Visible in kubectl describe pod under "Ephemeral Containers";
