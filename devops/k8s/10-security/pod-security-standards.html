Pod Security Standards / Pod Security Admission

1. What are Pod Security Standards?
  • Three security profiles that define different levels of restrictiveness for Pods;
  • Replaced the deprecated PodSecurityPolicy (PSP) since Kubernetes v1.25;
  • Enforced by Pod Security Admission (PSA) controller;
2. Security Levels
LevelDescription
PrivilegedNo restrictions. Allows everything.
BaselinePrevents known privilege escalations. Allows most workloads.
RestrictedHeavily restricted. Best practice hardening for security-critical workloads.
3. Enforcement Modes
ModeBehavior
enforceRejects Pods that violate the policy
auditAllows but logs violations in the audit log
warnAllows but shows a warning to the user
4. Applying via Namespace Labels
# Apply restricted policy to a namespace
kubectl label namespace production \
  pod-security.kubernetes.io/enforce=restricted \
  pod-security.kubernetes.io/enforce-version=latest \
  pod-security.kubernetes.io/warn=restricted \
  pod-security.kubernetes.io/audit=restricted
5. What Restricted Level Requires
  • Must run as non-root;
  • Must drop ALL capabilities;
  • Must set allowPrivilegeEscalation: false;
  • Must use a non-root seccomp profile;
  • No hostNetwork, hostPID, hostIPC;
  • No privileged containers;
