Security Contexts (Pod and Container Level)

1. What is a Security Context?
  • Defines privilege and access control settings for Pods and containers;
  • Controls user/group IDs, Linux capabilities, filesystem permissions, SELinux, seccomp, AppArmor;
  • Can be set at Pod level (applies to all containers) or container level (overrides Pod level);
2. Pod-Level Security Context
spec:
  securityContext:
    runAsUser: 1000
    runAsGroup: 3000
    fsGroup: 2000
    runAsNonRoot: true
  • runAsUser: UID to run the container process;
  • runAsGroup: GID for the container process;
  • fsGroup: GID that owns mounted volumes;
  • runAsNonRoot: Refuse to start if running as root;
3. Container-Level Security Context
spec:
  containers:
    - name: app
      image: myapp:v1
      securityContext:
        allowPrivilegeEscalation: false
        readOnlyRootFilesystem: true
        capabilities:
          drop:
            - ALL
          add:
            - NET_BIND_SERVICE
4. Best Practices
  • Always set runAsNonRoot: true;
  • Set allowPrivilegeEscalation: false;
  • Use readOnlyRootFilesystem: true when possible;
  • Drop ALL capabilities and add only what's needed;
  • Never run containers as privileged (privileged: true) in production;
