Service Accounts

1. What is a Service Account?
  • An identity for processes running in Pods (not humans);
  • Used to authenticate Pods with the Kubernetes API and external services;
  • Every namespace has a default Service Account;
  • Pods are automatically assigned the default SA unless you specify one;
2. Creating and Using Service Accounts
# Create a Service Account
kubectl create serviceaccount my-sa -n dev

# Use in a Pod
apiVersion: v1
kind: Pod
metadata:
  name: my-pod
spec:
  serviceAccountName: my-sa
  containers:
    - name: app
      image: myapp:v1
3. Token Mounting
  • Kubernetes automatically mounts a projected token at /var/run/secrets/kubernetes.io/serviceaccount/;
  • Contains: token, ca.crt, namespace;
  • Since K8s 1.24, tokens are bound and time-limited (TokenRequest API);
  • To disable auto-mounting:
spec:
  automountServiceAccountToken: false
4. Granting Permissions
  • Service Accounts have no permissions by default — use RBAC to grant them;
# Grant pod-reader role to the SA
kubectl create rolebinding my-sa-binding \
  --role=pod-reader \
  --serviceaccount=dev:my-sa \
  -n dev
5. Image Pull Secrets
# Attach image pull secret to a Service Account
kubectl patch serviceaccount my-sa -n dev \
  -p '{"imagePullSecrets": [{"name": "regcred"}]}'

All Pods using this SA will automatically use the registry credentials.
