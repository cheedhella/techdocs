Ephemeral Volumes
	- Ephemeral means short-lived; 
	- 2 types: emptyDir, hostPath;
	- emptyDir is nothing but an empty directory is created, when the Pod is created; It is destroyed, when the Pod is destroyed;
	- hostPath is file/directory that exists on the host/Node; Any content written by a Pod is available, as long as the Pod is running on that Node;

Why, on eath, anyone would need a storage which by nature is ephemral, and no longer exists when Pod is destroyed OR Node is down?
	- For storing intermediate results, in case of disk-based merge sort etc;
	- For checkpointing a long computation, for recovery from crashes;
--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
emptyDir Volume
	It is a temporary directory that is created, when the Pod is created;
	It is empty, when the Pod starts; It exists as long as the Pod is running;
	All containers in the Pod can read from and write to the files in it;
	By default, data is stored on the disk; You can change it to RAM for faster read/writes;
	Data written by a container is available to all other containers in the same Pod;
	It is deleted, when Pod is deleted or rescheduled;

When to use emptyDir volume?
	- Sharing files between the contains in the same Pod;
	- Temporary storage;
