NodePort

1. What is NodePort?
  • It creates a ClusterIP as well;
  • In addition, it exposes the service on a specified port on every node in the cluster;
  • Service is accessible from outside the cluster via: <NodeIP>:<NodePort>;
  • You can use any node's IP, even when Pod is running on another node; kube-proxy routes the traffic to correct Pod;
  • Flow: User -> NodeIP:nodePort -> ClusterIP:port -> Pod:targetPort;
2. NodePort YAML
  • 
apiVersion: v1
kind: Service
metadata:
  name: my-nodeport-svc
spec:
  type: NodePort
  selector:
    app: myapp
  ports:
    - port: 80              # Cluster IP Internal Port, only internal services can access the service using this port(unless exposed using load balancer/ingress);
      targetPort: 8080      # Port on which pods are listening;
      nodePort: 30080       # External port on every node (optional — auto-assigned if omitted); Should be always in range 30000–32767;

4. Applications of NodePort service
  • Development and testing environments - Not recommended for production — use LoadBalancer or Ingress instead;
  • Ingress controllers often use NodePort under the hood: Internet → Ingress → NodePort → Service → Pods;
