New Terms

1. What is Image?
  • Image is a package that contains everything(OS, code, runtime(java, python etc), dependant libraries, configuration files etc) needed to run an application;
  • We don't need to worry about if the Java is installed or Python is installed etc;
  • Often, we create an image from another image as base image;
1. What is distroless image?
  • Distroless image is a minimal image that contains only the bare essentials to run an application;
  • It doesn't contain any package manager or shell;
  • It is smaller than a regular image, but it is more secure;
2. What is Container?
  • Container is a running instance of Image;
  • Containers are stateless and immutable - it makes containers reliable, scalable, easier to manage;
  • immutable - You can't make any changes to a running container; If you need a change, create new image and redeploy it;
  • stateless - All the state should be stored externally(in a volume or database), so that if a container crashes or restarts, it don't lose any data; It makes containers replacable and scalable;
3. What is Containerization?
  • Containerization is packaging an application and dependencies as an image and then running it as a container;
  • containerization -> application to docker image;
3. What is Pod?
  • Pod is the smallest unit of deployment(one or more containers);
4. What is ConfigMap?
  • This is used to store and inject environment variables to Pods.
5. What is Secret?
  • This is similar to a ConfigMap, but it’s used for more sensitive information like passwords.
4. What is Node?
  • Each machine in the cluster is a Node;
5. What is Cluster?
  • Cluster is a group/set of Nodes;
6. What is Namespace?
  • Namespace is a logical partition of a cluster;
7. What is Deployment?
  • Deployment is a controller that ensures that a desired number of Pods are running all the time;
  • It updaates the pods and their configuration;
  • Although it’s possible to operate on Pod, it’s not recommended. Instead, we can use Deployment, which will not only create a Pod but also take care of several application instances. With Deployment, we can specify how many Pods we would like to have. If a container stops (due to an error in the program), Kubernetes will automatically start a new one to make sure that the number of running Pods is the same as what was set.
8. What is Service?
  • Service is a way to expose the pods to the network;
    • They are designed to expose applications to other software either within or outside the Kubernetes cluster. The reason for this is that when a Pod is created, it gets its IP address. If there are two Pods of the same application, both of them receive a different IP address. Now, if any other application wants to reach one of them, it would need to know the IP address of one or both of the Pods, which is very inconvenient. Another issue is that Pods can be easily destroyed and recreated, and each time this happens, they get a different IP address, which makes it necessary for all the other applications connected with a killed Pod to update their IP address. Due to this problem, Services were introduced. They provide an abstraction that defines access to Pods so that addresses to applications can be static and will not change if a Pod is killed.
9. What is Ingress?
  • HTTP routing into cluster
  • These are for managing external access to applications in a cluster.
10. What is Volume?
  • These represent a directory in which files and data can persist.
8. What is K8s Administrator?
  • K8s Administrator is responsible for the overall health and performance of the K8s cluster;
9. What is K8s Developer?
  • K8s Developer is responsible for the development of the applications running in the K8s cluster;
