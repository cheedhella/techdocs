Nodes (Master vs Worker)

1. What is a Node?
  • A node is a machine (physical or virtual) in the Kubernetes cluster;
  • Each node has the services necessary to run Pods;
  • Nodes are managed by the control plane;
2. Master (Control Plane) Node
  • Runs the control plane components: API Server, etcd, Scheduler, Controller Manager;
  • By default, Pods are not scheduled on master nodes (taint: node-role.kubernetes.io/control-plane:NoSchedule);
  • In production, you typically have 3 or 5 master nodes for high availability;
  • An odd number ensures etcd quorum for leader election;
3. Worker Node
  • Runs application workloads — this is where your Pods live;
  • Runs kubelet, kube-proxy, and the container runtime;
  • Can be scaled horizontally — add more worker nodes to handle more workloads;
4. Managing Nodes
# List all nodes
kubectl get nodes

# View node details
kubectl describe node <node-name>

# Label a node
kubectl label node <node-name> disktype=ssd

# Cordon a node (prevent new Pods)
kubectl cordon <node-name>

# Drain a node (evict Pods gracefully)
kubectl drain <node-name> --ignore-daemonsets --delete-emptydir-data

# Uncordon a node
kubectl uncordon <node-name>
