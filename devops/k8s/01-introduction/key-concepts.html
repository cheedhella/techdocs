Key Concepts and Terminology

1. Cluster
  • A set of machines (nodes) that run containerized applications managed by Kubernetes;
  • Consists of at least one control plane (master) node and one or more worker nodes;
2. Node
  • A physical or virtual machine in the cluster;
  • Master Node: Runs control plane components (API Server, Scheduler, Controller Manager, etcd);
  • Worker Node: Runs application workloads (Pods) via kubelet and kube-proxy;
3. Pod
  • The smallest deployable unit in Kubernetes;
  • A Pod wraps one or more containers that share networking and storage;
  • Every Pod gets its own IP address;
4. Service
  • A stable network endpoint that exposes a set of Pods;
  • Pods are ephemeral — Services provide a permanent IP and DNS name;
  • Types: ClusterIP, NodePort, LoadBalancer, ExternalName;
5. Deployment
  • A controller that manages the desired state of Pods (replicas, image version, update strategy);
  • Handles rolling updates and rollbacks automatically;
6. Namespace
  • A way to logically partition a cluster into isolated groups;
  • Useful for multi-team environments — each team gets their own namespace;
  • Default namespaces: default, kube-system, kube-public, kube-node-lease;
7. Label and Selector
  • Labels: Key-value pairs attached to objects (Pods, Services, etc.) for identification;
  • Selectors: Used to filter and select objects based on their labels;
  • This is how Services know which Pods to route traffic to;
8. Manifest / YAML
  • Kubernetes resources are defined in YAML or JSON files called manifests;
  • Every manifest has: apiVersion, kind, metadata, and spec;
apiVersion: v1
kind: Pod
metadata:
  name: my-pod
spec:
  containers:
    - name: nginx
      image: nginx:latest
