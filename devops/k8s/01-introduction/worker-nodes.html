Worker Node Components

1. kubelet
  • An agent that runs on every worker node in the cluster;
  • Registers the node with the API Server and reports node status;
  • Watches the API Server for Pods assigned to its node;
  • Instructs the container runtime to pull images, start/stop containers;
  • Runs health checks (liveness, readiness, startup probes) and reports Pod status;
  • Does NOT manage containers that were not created by Kubernetes;
2. kube-proxy
  • A network proxy that runs on every node;
  • Maintains network rules that allow communication to Pods from inside or outside the cluster;
  • Implements the Kubernetes Service concept;
  • Uses iptables or IPVS to route traffic to the correct Pod;
  • Handles load balancing across Pod replicas behind a Service;
3. Container Runtime
  • The software responsible for actually running containers;
  • Kubernetes supports any runtime that implements the Container Runtime Interface (CRI);
  • Common runtimes:
RuntimeDescription
containerdIndustry standard, used by Docker under the hood. Most common.
CRI-OLightweight runtime built specifically for Kubernetes.
gVisor (runsc)Sandboxed runtime for enhanced security isolation.
Kata ContainersUses lightweight VMs for stronger isolation.
