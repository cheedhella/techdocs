Storage Class

1. What is a StorageClass?
  • It is a cluster-wide resource, which defines how to dynamically provision storage;
  • It is defined by admin and not by developers, as part of cluster setup;
  • Usually, admin defines multiple StorageClasses(fast SSD, standard HDD, etc) for different purposes;
  • No need for admins to pre-create PVs, as it is done dynamically;
2. How Static Provisioning works?
  • Setup Storage(like NFS)
    • Cluster Admin must setup a NFS server and export /data via NFS; OR
    • If company already has NAS/NFS server/On-prem storage, Cluster Admin exposes those disks via PV definitions;
    • Ensure that K8s node must be able to reach the NFS server;
  • Create PV - Cluster Admin manually creates PVs in advance;
  • All of it is usually done as part of cluster setup;
  • # pv-nfs.yaml -> PV created by Admin(points to an existing storage resource such as NFS, AWS EBS etc)
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pv-nfs
spec:
  capacity:
    storage: 10Gi
  accessModes:
    - ReadWriteOnce
  nfs:
    path: /data
    server: 192.168.1.100
  • Developers create PVCs requesting storage;
  • K8s binds the PVC to a matching PV;
3. How Dynamic Provisioning works?
  • Cluster Admin creates/defines a StorageClass; Developers don't do it;
  •           # sc-demo-p1.yaml
          apiVersion: storage.k8s.io/v1
          kind: StorageClass
          metadata:
            name: fast-storage
          provisioner: ebs.csi.aws.com
          parameters:
            type: gp3
  • Why Admin, why not developers? Because, It is a cluster-wide resource and usually only admin has permissions/RBAC and below knowledge of underlying storage;
    RequirementWhat it means
    Storage backendEBS, Ceph, NFS, GCE PD, etc.
    CSI driver installedKubernetes interface to storage
    Provisioner nameIdentifier of storage driver
    ParametersDisk type, IOPS, replication, etc.
    PoliciesReclaim policy, binding mode
  • User creates a PVC referencing the StorageClass;
  • K8s automatically provisions a PV, using provisioner specified in StorageClass and binds it to the PVC;
  • Pod starts using the storage via PVC;
4. How does Provisioner authenticates/authorizes itself with cloud provider?
  • Admin installs CSI driver(Eg: aws-ebs-csi-driver); It runs as a Pod in the cluster;
  • Admin create a IAM role/Service Account/secret to configure credentails;
  • Admin then setup the StorageClass;

6. StorageClass YAML
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: fast-ssd
provisioner: kubernetes.io/aws-ebs
parameters:
  type: gp3
  iopsPerGB: "10"
reclaimPolicy: Delete
allowVolumeExpansion: true
volumeBindingMode: WaitForFirstConsumer


  • A StorageClass YAML defines the storage type, provisioner, and policies used by Kubernetes to dynamically create PersistentVolumes when a PVC requests storage;
  • Provisioner
    • Name of the CSI driver, as defined by the driver vendor;
    • Storage systemProvisioner name
      AWS EBSebs.csi.aws.com
      Google Persistent Diskpd.csi.storage.gke.io
      Azure Diskdisk.csi.azure.com
      Ceph RBDrbd.csi.ceph.com
      NFS CSInfs.csi.k8s.io
  • Parameters
    • Different provisioners support different configuration options;
    • AWS EBS
        ParameterMeaning
        typedisk type
        iopsPerGBperformance
        encryptedenable encryption
        fsTypefilesystem on volume
    • Google Persistent Disk
        ParameterMeaning
        typeSSD disk
        replication-typemulti-zone replication
  • ReclaimPolicy
    • What happens to PV, when PVC a deleted?
      • Delete: PV and underlying storage are automatically deleted; Default value;
      • Retain: PV is kept after PVC deletion; Admin must manually clean up the storage; For databases, you must use this;
  • AllowVolumeExpansion
    • It allows PVC to grow in size, after it is created; Default value is true;
    • If you set it to false, you cannot grow the volume size after it is created;
  • VolumeBindingMode
    • When the PV is created/bound;
      • It specifies when the PV is created, for a PVC;
      • Immediate: PV is created when PVC is created; Default value;
      • WaitForFirstConsumer: PV is created, when the pod is scheduled; For databases, you must use this;
    • What is the use of WaitForFirstConsumer?
      • Most storage systems are location-dependant; For eg, in case of AWS EBS, a disk created in one zone cannot be used in another zone;
      • If you use Immediate, If you PV is created in one zone and pod is scheduled in another zone, it will fail to schedule the pod;
      • If you use WaitForFirstConsumer, it will create the PV in the zone of the pod, when the pod is scheduled;
7. Default StorageClass
  • A StorageClass annotated with storageclass.kubernetes.io/is-default-class: "true";
  • PVCs without a storageClassName will use the default;


# List StorageClasses
kubectl get sc
NAME                 PROVISIONER            DEFAULT
standard             ebs.csi.aws.com        No
fast-ssd (default)   ebs.csi.aws.com        Yes

# Annotate a StorageClass as default
kubectl patch storageclass  -p '{"metadata": {"annotations":{"storageclass.kubernetes.io/is-default-class":"true"}}}'

# Annotate a StorageClass as non-default
kubectl patch storageclass  -p '{"metadata": {"annotations":{"storageclass.kubernetes.io/is-default-class":"false"}}}'
