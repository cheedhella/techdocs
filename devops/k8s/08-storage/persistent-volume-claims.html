Persistent Volume Claims (PVC)

1. What is a PVC?
  • A request for storage by a user — like a Pod requesting CPU/memory;
  • The PVC is bound to a PV that matches its requirements (size, access mode, StorageClass);
  • Pods reference PVCs — they don't interact with PVs directly;
2. PVC YAML
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 5Gi
  storageClassName: manual
3. Using a PVC in a Pod
apiVersion: v1
kind: Pod
metadata:
  name: pod-with-pvc
spec:
  containers:
    - name: app
      image: myapp:v1
      volumeMounts:
        - name: storage
          mountPath: /data
  volumes:
    - name: storage
      persistentVolumeClaim:
        claimName: my-pvc
4. PV-PVC Binding
  • Kubernetes finds a PV that satisfies the PVC's requirements;
  • Binding is 1:1 — one PVC binds to exactly one PV;
  • If no matching PV exists, the PVC stays in Pending state;
  • With dynamic provisioning (StorageClass), a PV is created automatically;
5. Commands
# List PVCs
kubectl get pvc

# Describe
kubectl describe pvc my-pvc

# Delete PVC (may trigger PV reclaim policy)
kubectl delete pvc my-pvc
