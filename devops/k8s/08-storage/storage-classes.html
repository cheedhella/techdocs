Storage Classes and Dynamic Provisioning

1. What is a StorageClass?
  • Defines classes of storage available in the cluster (fast SSD, standard HDD, etc.);
  • Enables dynamic provisioning — PVs are created automatically when a PVC is created;
  • No need for admins to pre-create PVs;
2. StorageClass YAML
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: fast-ssd
provisioner: kubernetes.io/aws-ebs
parameters:
  type: gp3
  iopsPerGB: "10"
reclaimPolicy: Delete
allowVolumeExpansion: true
volumeBindingMode: WaitForFirstConsumer
3. Key Fields
FieldDescription
provisionerThe volume plugin that creates PVs (e.g., aws-ebs, gce-pd, csi driver)
parametersProvisioner-specific settings (disk type, IOPS, etc.)
reclaimPolicyDelete or Retain — what happens to PV when PVC is deleted
allowVolumeExpansionAllow PVCs to request more storage
volumeBindingModeImmediate or WaitForFirstConsumer
4. Dynamic Provisioning Flow
# 1. Admin creates a StorageClass
# 2. User creates a PVC referencing the StorageClass
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  accessModes:
    - ReadWriteOnce
  storageClassName: fast-ssd
  resources:
    requests:
      storage: 20Gi

# 3. Kubernetes automatically provisions a PV (e.g., AWS EBS volume)
# 4. PVC binds to the new PV
# 5. Pod uses the PVC
5. Default StorageClass
  • A StorageClass annotated with storageclass.kubernetes.io/is-default-class: "true";
  • PVCs without a storageClassName will use the default;
