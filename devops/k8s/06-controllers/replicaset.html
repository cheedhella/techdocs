ReplicaSet

1. What is a ReplicaSet?
  • ReplicaSet = Pod + self-healing + scaling;
  • A Pod, by itself, is not self-healing; In case of any failure, it won't recover on its own;
  • It means: If you create a Pod without Replicaset, then a new Pod won't be created, in case of any failure;

  • Replicaset ensures that a specified number of Pod replicas are running at all times; No need to monitor 24/7 manually;
  • If there are lesser number of pods than what is specified, may be a pod crashed, it spins up new pods;
  • If there are more number of pods than what is specified, may be you reduced the number of replicas, it deletes the pods;

  • It uses label selectors to identify which Pods it manages;
  • You rarely create ReplicaSets directly; Instead, use Deployments;
2. Benefits of ReplicaSet?
  • Fault tolerance - If a Pod fails, controller can detect and replace the failed replica with a new one;
  • Scalability - You can scale up or down the number of replicas;
  • High Availability - By running multiple replicas of a Pod, we can ensure that application remains available, even if one or more replicas fail;
3. ReplicaSet YAML Configuration
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: nginx-rs
  labels:                             # These labels belong to the ReplicaSet itself, not the Pods;
    app: nginx 
spec:
  replicas: 3                         # It specifies the desired number of replicas/pods;
  selector:                           # It selects the pods to monitor; It supports 2 types of selectors: matchLabels and matchExpressions;
    matchLabels:                      # It monitors all the Pods with both labels: app=nginx AND tier=frontend!
      app: nginx
      tier: frontend
  template:
    metadata:
      labels:                         # Assigns these lables to every pod created by the ReplicaSet! It should be superset of .spec.selector.matchLabels;
        app: nginx
        tier: frontend
    spec:
      containers:                     # Container configuration;
        - name: nginx
          image: nginx:1.25           # Image to use;
          ports:
            - containerPort: 80        # Port to expose;

Note: What if selector.matchLabels is different from template.metadata.Labels? To avoid creating Pods in a infinite loop, k8s rejects the ReplicaSet!

matchExpressions:                     # It supports more advanced selectors; If specify multiple expressions, all must be true for a pod to be selected;
  - key: app                          # It selects Pods with label: app = nginx OR app = frontend
    operator: In                      
    values:
    - nginx
    - frontend
  - key: team                         # It selects all the Pods whose team label is anything other than team1, team2;
    operator: NotIn
    values:
    - team1
    - tema2
  - key: env                         # It selects Pods with env label;
    operator: Exists
  - key: debug                       # It selects Pods without debug label;
    operator: DoesNotExist

    | Operator       | Meaning                             |
    | -------------- | ----------------------------------- |
    | `In`           | Label value must be in the list     |
    | `NotIn`        | Label value must NOT be in the list |
    | `Exists`       | Label key must exist                |
    | `DoesNotExist` | Label key must not exist            |
