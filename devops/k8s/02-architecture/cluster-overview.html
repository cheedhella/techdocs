Cluster Architecture Overview

1. What is a Kubernetes Cluster?
  • A Kubernetes cluster is a set of machines (physical or virtual) that work together to run containerized applications;
  • It has two main parts: the Control Plane (brain) and the Worker Nodes (muscle);
  • The control plane makes global decisions (scheduling, detecting failures) while worker nodes run the actual workloads;

3. Communication Flow
  • All communication goes through the API Server — it is the only component that talks to etcd;
  • kubectl sends requests to the API Server;
  • The Scheduler watches for unscheduled Pods and assigns them to nodes;
  • The kubelet on each node pulls the Pod spec from the API Server and runs containers;
  • kube-proxy manages network rules so Pods can communicate;
4. Desired State vs Actual State
  • You declare the desired state (e.g., "run 3 replicas of nginx");
  • Controllers continuously compare desired state with actual state;
  • If they differ, controllers take action to reconcile (e.g., start a new Pod if one crashed);
  • This is the control loop pattern — the heart of Kubernetes;
