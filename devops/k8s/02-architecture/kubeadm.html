kubeadm

1. What is kubeadm?
  • It is a tool that helps you in setting up the k8s cluster;
  • It is needed only during cluster setup, once cluster is formed, kubeadm is not needed;
  • It is not needed in managed k8s environments; Cloud providers replace it with their own system;
2. Setup kubeadm(on both master and worker nodes)
  1. System requirements: Linux machine with minimum 2 CPU, 2GB RAM;
  2. Disable swap: swapoff -a
  3. Install container runtime: such as docker, containerd;
  4. Install k8s tools: apt install kubeadm kubelet
3. Setup kubectl
  • Setup kubectl
4. Install CNI Plugin
  1. Without CNI plugin, cluster will not form(nodes will remain in NOT READY state);
  2. kubectl apply -f https://docs.projectcalico.org/manifests/calico.yaml - It creates a DaemonSet, that runs calico Pod on every node(both master and worker) node;
  3. You will see one CNI pod per node, like: > kubectl get pods -n kube-system
5. What kubeadm init does(on master nodes)?
  • CNI Plugins like calico require CIDR range: kubeadm init --pod-network-cidr=192.168.0.0/16
  • It does the following:
    • It sets up kubeconfig files;
    • It creates certificates(for secure communication);
    • These help in connecting kubelet with API server;
    • It generates YAML files of static pods in /etc/kubernetes/manifests/ folder;
    • It then restarts kubelet;
    • Prints kubeadm join command that you can run manually on worker nodes: kubeadm join :6443 --token --discovery-token-ca-cert-hash sha256:
      • 192.168.1.10 -> API Server IP Address;
      • 6443 -> API server port;
      • token -> It verifies worker; One time Password for joining; Any one worker node can use that token; Run this command on controller node, if you want another token: kubeadm token create --print-join-command
      • discovery-token-ca-cert-hash -> It verifies the identify of control plane node, thus avoiding man-in-middle attack; It is the SHA256 hash of the CA cert; worker node fetches certificate of master node, hashes it and compares it provided hash;
      • Compute digest manually: openssl x509 -pubkey -in /etc/kubernetes/pki/ca.crt | openssl rsa -pubin -outform der 2>/dev/null | openssl dgst -sha256 -hex
6. What kubeadm join does(on worker nodes)?
  • We need to SSH into each worker and run the same join command on every worker node manually;
  • When you run: kubeadm join --token ... --discovery-token-ca-cert-hash ..., it does following:
    • It sets up kubeconfig files;
    • It configures /etc/kubernetes/kubelet.conf(API server endpint and authentication/token details);
    • This configuration enables the communication b/w kubelet and API server;
    • It then restarts the kubelet;
  • Every node registers itself with cluster: ;
    • Starts and enables kubelet service, wcich is ready to talk to the cluster;
    • kubelet uses token to authenticate itself with API server;
