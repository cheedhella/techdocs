etcd

1. What is etcd?
  • It is a distributed key-value database, that stores entire cluster state;
  • Only API Server talks to etcd directly; Other components(Scheduler, controllers) go through API server;
2. What does etcd store?
  • All Kubernetes objects: Pods, Services, Deployments, ConfigMaps, Secrets;
  • Cluster configuration and state;
  • RBAC policies;
  • Service account tokens;
  • Lease information for leader election;
3. Key characterstics of etcd?
  • Distributed
    • Data is distributed and replicated across multiple nodes(only master master nodes);
  • Highly Available
    • Cluster with 3/5 master nodes is always highly available;
  • Strongly Consistent
    • It uses Raft consensus algorithm;
    • It ensures that there is one leader at any given time, that is incharge of making changes to the state and replicating the changes to followers;
    • State changes are committed only when replication is confirmed by majority of the nodes in the cluster;
    • It guarantees latest data is always correct; No stale reads;
  • Key-Value database
    • /registry/pods/nginx → pod definition
4. Monitoring etcd in Production
  • You can expose etcd metrics and monitor via: Prometheus and Grafana;
  • You can set alerts on:
    • Leader not presetn;
    • Too many leader changes;
    • High commit latency;
    • Followers lagging behind;
