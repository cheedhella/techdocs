Control Plane Components

1. kube-apiserver
  • The front door of the Kubernetes cluster — all communication goes through it;
  • Exposes the Kubernetes API via REST (HTTPS);
  • Authenticates and authorizes all requests (RBAC, certificates);
  • The only component that reads/writes to etcd;
  • Horizontally scalable — you can run multiple instances behind a load balancer;
2. etcd
  • A distributed, consistent key-value store that holds all cluster data;
  • Stores the entire cluster state: Pods, Services, ConfigMaps, Secrets, etc.;
  • Uses the Raft consensus algorithm for high availability;
  • Critical component — if etcd is lost, the entire cluster state is lost;
  • Always back up etcd regularly in production;
3. kube-scheduler
  • Watches for newly created Pods that have no node assigned;
  • Selects the best node for each Pod based on: resource requirements, affinity/anti-affinity rules, taints/tolerations, data locality;
  • Scoring process: Filtering (eliminate unfit nodes) → Scoring (rank remaining nodes) → Binding (assign Pod to top-scored node);
4. kube-controller-manager
  • Runs a collection of controller loops that regulate the state of the cluster;
  • Key controllers include:
ControllerResponsibility
Node ControllerMonitors node health, evicts Pods from unhealthy nodes
Replication ControllerEnsures the correct number of Pod replicas
Endpoints ControllerPopulates the Endpoints object (joins Services and Pods)
Service Account ControllerCreates default ServiceAccounts for new namespaces
Job ControllerWatches Jobs and creates Pods to run tasks to completion
5. cloud-controller-manager
  • Runs controllers that interact with the underlying cloud provider (AWS, Azure, GCP);
  • Handles cloud-specific logic: Load Balancers, Nodes, Routes, Volumes;
  • Only present when running Kubernetes on a cloud platform;
