kubelet

1. What is kubelet?
  • It is an agent(systemd daemon) that runs on every node(both master and worker) in the cluster;
  • It is responsible for the following things:
    • On startup, it reads the manifest files in /etc/kubernetes/manifests/ and creates those static pods; It is empty in worker node;
    • It also continues monitoring the health of those static pods; If you delete a static pod, it gets recreated automatically by kubelet on that node; If you delete manifest file, then kubelet deletes that pod and it is gone permanently!
    • On startup, kubelet registers the node, by creating Node object(like hostname, CPU/memory, labels like region or instance type, network info) and saving it to API server;
    • It continously watches events from API server for Pods assigned to this node;
    • It pulls the image and uses container rumtimes(like docker, containerd) to start/stop/restart(if they crash) containers;
    • It performs health checks: Liveness, Readiness; If a container fails, it restarts it automatically;
    • Reports Node health, Node metrics(CPU and Memory usage) and Pod status to master node(leader);
2. Why kubelet is needed on master nodes?
  • On master node, kubelet runs API server, scheduler, controler manager as static pods;
  • Ensures those pods are healthy;
  • Reports node status, pods status to master node(leader);

3. What is a static pod?
  • These pods are created automatically without involving API server initially;
  • These are defined in the manifest files(/etc/kubernetes/manifests) and managed by kubelet;
  • Eg: API server, Scheduler, Controller manager;
