emptyDir

1. What is a emptyDir?
  • It is a temporary directory that is created, when a Pod is assigned to a node;
  • It starts empty and all containers in the Pod can read and write to it;
  • emptyDir is deleted, when the Pod is restarted or deleted or rescheduled to a different node;
  • Data in the emptyDir volume survives even if the containers are restarted or deleted;
  • Data in the emptyDir volume is lost, when the Pod is restarted or deleted or rescheduled to a different node;
  • Why, on eath, anyone would need a storage which by nature is ephemral, and no longer exists when Pod is destroyed OR Node is down?
    • For storing intermediate results, in case of disk-based merge sort etc;
    • For checkpointing a long computation, for recovery from crashes;
2. Lifecycle of emptyDir?
Behavior Description
Created When Pod starts
Deleted When Pod is removed
Shared All containers in the Pod
Survives container restart Yes
Survives Pod restart No
3. emptyDir YAML configuration
  • emptyDir: {} or emptyDir: "" -> Directory is created under /var/lib/kubele in node filesystem;
  • emptyDir.medium: Memory -> This creates a tmpfs (RAM-backed filesystem);
  • emptyDir.sizeLimit: 1Gi -> Limits the maximum storage the volume can use;
4. emptyDir Demo
5. Applications of emptyDir
  • Sharing data between containers;
  • Log collection: Application container writes logs a file, sidecar container(like fluentbit) collects logs and pushes to centralized log server;
6. stdout log shipper
    1. Actually, stdout logger is preferred way of shipping application logs;
    2. There is a little chance of losing data in both cases, if log shipper is slow;
    3. Why is better than emptyDir volume?
        In case of emptyDir, logs are deleted when the pod is deleted/rescheduled;
        In case of stdout logger, logs will be there somewhere on the node - /var/log/containers/stdout-demo_default_logger-.log


    
# stdout-demo.yaml
apiVersion: v1
kind: Pod
metadata:
  name: stdout-demo
spec:
  containers:
  - name: logger
    image: busybox
    command:
    - sh
    - -c
    - |
      while true; do
        echo "Hello from Kubernetes log $(date)"
        sleep 5
      done




> kubectl apply -f stdout-demo.yaml
> kubectl logs stdout-demo
Hello from Kubernetes log Thu Mar 12 10:12:01 UTC 2026
Hello from Kubernetes log Thu Mar 12 10:12:06 UTC 2026
Hello from Kubernetes log Thu Mar 12 10:12:11 UTC 2026
