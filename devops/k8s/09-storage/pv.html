Persistent Volume

1. What is a Persistent Volume?
  • It is a piece of storage provisioned by an admin or dynamically via StorageClass;
  • It is a cluster-level resource that can be made available to multiple Pods;
  • It has a lifecycle independent of any Pod — data persists even after the Pod is deleted;
  • It abstracts the underlying storage technology (NFS, AWS EBS, GCE PD, etc.) from the application;
2. PV Lifecycle Status
PhaseDescription
AvailablePV is provisioned by the administrator or dynamically by the StorageClass, but not yet bound to a PVC;
BoundPV is bound to a PVC;
ReleasedPVC is deleted, but PV still exists;
FailedPV reclaim or cleanup failed; PV is not usable;
3. PV Yaml Configuration
apiVersion: v1
kind: PersistentVolume
metadata:
    name: pv-example
spec:
    capacity:
      storage: 10Gi
    accessModes:
    - ReadWriteOnce
    storageClassName: standard
    persistentVolumeReclaimPolicy: Retain
    volumeMode: Filesystem
    hostPath:
    path: /mnt/data

  • capacity.storage
    • It specifies total storage available in the volume;
  • accessModes - It specifies how the volume can be used by the Pods;
    • ReadWriteOnce: The volume can be mounted as read-write by a single node;
    • ReadOnlyMany: The volume can be mounted as read-only by many nodes;
    • ReadWriteMany: The volume can be mounted as read-write by many nodes;
    • ReadWriteOncePod: The volume can be mounted as read-write by one pod;
  • storageClassName - It specifies the name of the StorageClass to use;
  • persistentVolumeReclaimPolicy - It specifies the policy to use when the PVC is deleted; Possible values are: Delete(default), Retain;
  • volumeMode - It specifies the type of the volume; Possible values are: filesystem(default), block;
  •                   # PV YAML
                  apiVersion: v1
                  kind: PersistentVolume
                  metadata:
                    name: pv-example
                  spec:
                    capacity:
                      storage: 10Gi
                    accessModes:
                    - ReadWriteOnce
                    storageClassName: standard
                    persistentVolumeReclaimPolicy: Retain
                    volumeMode: Filesystem
                    hostPath:
                    path: /mnt/data
                  spec:
                    containers:
                      - name: my-container
                        volumeMounts:
                          - name: my-volume
                            mountPath: /data
                  volumes:
                    - name: my-volume
                      persistentVolumeClaim:
                        claimName: my-pvc
  • In production clusters, PVs YAML is rarely written manually because dynamic provisioning via StorageClasses automatically creates PVs
4. Choosing the Right Mode
  • RWO: Databases (MySQL, PostgreSQL) — single writer;
  • ROX: Shared configuration files, static assets;
  • RWX: Shared file uploads, CMS content, logs — multiple writers;
  • RWOP: When you need to ensure only one Pod writes (stricter than RWO);
