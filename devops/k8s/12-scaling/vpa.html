Vertical Pod Autoscaler (VPA)

1. What is VPA?
  • Automatically adjusts CPU and memory requests/limits for containers;
  • Unlike HPA (more replicas), VPA gives each Pod more resources;
  • VPA is a separate project — must be installed separately;
2. VPA Modes
ModeDescription
OffOnly provides recommendations, doesn't apply changes
InitialApplies recommendations only when Pods are created
AutoAutomatically evicts and recreates Pods with updated resources
3. VPA YAML
apiVersion: autoscaling.k8s.io/v1
kind: VerticalPodAutoscaler
metadata:
  name: myapp-vpa
spec:
  targetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: myapp
  updatePolicy:
    updateMode: "Auto"
  resourcePolicy:
    containerPolicies:
      - containerName: app
        minAllowed:
          cpu: 100m
          memory: 128Mi
        maxAllowed:
          cpu: 2
          memory: 4Gi
4. VPA vs HPA
FeatureHPAVPA
ScalesNumber of Pods (horizontal)Resources per Pod (vertical)
Pod disruptionNo — adds/removes PodsYes — recreates Pods with new resources
Best forStateless, scalable appsStateful apps, right-sizing
Can combine?Not on the same metric — use HPA on CPU, VPA on memory
5. View Recommendations
kubectl describe vpa myapp-vpa

# Shows:
# Recommendation:
#   Container: app
#     Lower Bound:  cpu: 100m, memory: 200Mi
#     Target:       cpu: 250m, memory: 400Mi
#     Upper Bound:  cpu: 500m, memory: 800Mi
