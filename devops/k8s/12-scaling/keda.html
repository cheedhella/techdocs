KEDA — Event-Driven Autoscaling

1. What is KEDA?
  • Kubernetes Event-Driven Autoscaling — a CNCF project;
  • Extends HPA with the ability to scale based on external event sources;
  • Can scale to/from zero replicas — unlike native HPA;
  • Supports 60+ scalers: Kafka, RabbitMQ, AWS SQS, Azure Queue, Prometheus, Cron, etc.;
2. How It Works
  • KEDA acts as a Kubernetes metrics adapter;
  • It polls external event sources and feeds metrics to HPA;
  • When there are no events, KEDA can scale to 0 replicas;
  • When events arrive, it scales from 0 → 1 (activation), then HPA handles further scaling;
3. ScaledObject Example
apiVersion: keda.sh/v1alpha1
kind: ScaledObject
metadata:
  name: rabbitmq-scaler
spec:
  scaleTargetRef:
    name: worker-deployment
  minReplicaCount: 0
  maxReplicaCount: 30
  triggers:
    - type: rabbitmq
      metadata:
        queueName: tasks
        queueLength: "5"
      authenticationRef:
        name: rabbitmq-auth

This scales the worker deployment based on the RabbitMQ queue length — 1 Pod per 5 messages.
