Horizontal Pod Autoscaler (HPA)

1. What is HPA?
  • Automatically scales the number of Pod replicas based on observed metrics;
  • Scales up when load increases, scales down when load decreases;
  • Requires Metrics Server (or a custom metrics adapter);
  • Checks metrics every 15 seconds by default;
2. Create HPA
# Imperative
kubectl autoscale deployment myapp \
  --min=2 \
  --max=10 \
  --cpu-percent=70

# Declarative YAML
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: myapp-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: myapp
  minReplicas: 2
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
    - type: Resource
      resource:
        name: memory
        target:
          type: Utilization
          averageUtilization: 80
3. How It Works
  • HPA controller calculates: desiredReplicas = ceil(currentReplicas × (currentMetric / targetMetric));
  • Example: 3 replicas at 90% CPU, target 70% → ceil(3 × (90/70)) = ceil(3.86) = 4 replicas;
  • Cooldown periods prevent flapping (scale-up: 0s, scale-down: 5min by default);
4. Prerequisites
  • Metrics Server must be installed;
  • Pods must have resource requests set (HPA uses requests as the baseline);
5. Commands
# List HPAs
kubectl get hpa

# Describe (shows current metrics and events)
kubectl describe hpa myapp-hpa

# Delete
kubectl delete hpa myapp-hpa
