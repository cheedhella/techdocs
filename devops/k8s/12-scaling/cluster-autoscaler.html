Cluster Autoscaler

1. What is the Cluster Autoscaler?
  • Automatically adjusts the number of nodes in the cluster;
  • Scales up: Adds nodes when Pods are Pending due to insufficient resources;
  • Scales down: Removes underutilized nodes (when Pods can be rescheduled elsewhere);
  • Works with cloud providers: AWS (ASG), Azure (VMSS), GCP (MIG);
2. How It Works
  • Scale up trigger: A Pod is in Pending state because no node has enough resources;
  • Cluster Autoscaler checks if adding a node from a node group would help;
  • If yes, it requests a new node from the cloud provider;
  • Scale down trigger: A node's utilization is below a threshold (~50%) for 10+ minutes;
  • All Pods on the node can be safely moved elsewhere;
3. Configuration
# Key flags
--scale-down-utilization-threshold=0.5     # Scale down if under 50% utilized
--scale-down-delay-after-add=10m           # Wait after scale-up
--scale-down-unneeded-time=10m             # Node must be unneeded for 10min
--max-node-provision-time=15m              # Timeout for node provisioning
--skip-nodes-with-local-storage=false
--skip-nodes-with-system-pods=true
4. Preventing Scale-Down
  • Annotate Pods that should not be evicted:
metadata:
  annotations:
    cluster-autoscaler.kubernetes.io/safe-to-evict: "false"
  • Nodes with non-replicated Pods (standalone Pods) won't be scaled down;
  • Nodes with Pods using local storage won't be scaled down by default;
5. Scaling Layers
Application Load ↑
    → HPA scales Pods (more replicas)
        → Pods go Pending (no room)
            → Cluster Autoscaler adds Nodes
                → Pods get scheduled
