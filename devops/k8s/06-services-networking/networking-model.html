Kubernetes Networking Model

1. Fundamental Rules
  • Every Pod gets its own unique IP address;
  • Pods on any node can communicate with all Pods on any other node without NAT;
  • Agents on a node (kubelet, kube-proxy) can communicate with all Pods on that node;
  • Containers within the same Pod share the network namespace — communicate via localhost;
2. Four Levels of Networking
LevelDescription
Container-to-ContainerSame Pod, via localhost
Pod-to-PodDirect IP communication, no NAT
Pod-to-ServiceVia Service abstraction (ClusterIP)
External-to-ServiceVia NodePort, LoadBalancer, or Ingress
3. CNI (Container Network Interface)
  • Kubernetes does NOT implement networking itself — it uses CNI plugins;
  • The CNI plugin is responsible for assigning IPs and enabling Pod-to-Pod communication;
  • Popular CNI plugins:
PluginFeatures
CalicoBGP-based routing, network policies, widely used
FlannelSimple overlay network, easy to set up
CiliumeBPF-based, advanced security, observability
Weave NetMesh overlay, encryption support
4. Pod IP Lifecycle
  • Pod IPs are ephemeral — they change when a Pod is recreated;
  • Never hardcode Pod IPs — use Services for stable endpoints;
