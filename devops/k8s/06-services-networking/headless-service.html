Headless Service

1. What is a Headless Service?
  • A Service with clusterIP: None — no virtual IP is allocated;
  • DNS queries return the individual Pod IPs instead of a single Service IP;
  • No load balancing by kube-proxy — clients connect directly to Pods;
2. When to Use
  • StatefulSets: Each Pod needs its own DNS record;
  • Client-side load balancing: Application handles its own service discovery;
  • Databases: Need to connect to a specific replica (e.g., primary vs read replica);
3. Headless Service YAML
apiVersion: v1
kind: Service
metadata:
  name: mysql-headless
spec:
  clusterIP: None
  selector:
    app: mysql
  ports:
    - port: 3306
      targetPort: 3306
4. DNS Behavior
  • Regular Service: DNS returns the ClusterIP;
  • Headless Service: DNS returns A records for each Pod;
  • With StatefulSet: Each Pod gets a DNS name like mysql-0.mysql-headless.default.svc.cluster.local;
# Query DNS for a headless service
nslookup mysql-headless.default.svc.cluster.local

# Returns multiple A records:
# Address: 10.244.1.5
# Address: 10.244.2.3
# Address: 10.244.1.8
