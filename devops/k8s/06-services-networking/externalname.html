ExternalName Service

1. What is ExternalName?
  • Maps a Service to an external DNS name (CNAME record);
  • No proxying — DNS resolves directly to the external host;
  • No selector, no ClusterIP, no ports;
  • Useful for referencing external services (databases, APIs) with an internal name;
2. ExternalName YAML
apiVersion: v1
kind: Service
metadata:
  name: my-database
spec:
  type: ExternalName
  externalName: db.prod.example.com
  • Pods can now connect to my-database and it resolves to db.prod.example.com;
  • If the external endpoint changes, just update the Service — no app changes needed;
3. Use Cases
  • Referencing an external RDS database via a Kubernetes Service name;
  • Migration: Gradually move from external service to in-cluster service — just change the Service type;
  • Abstracting cross-namespace services;
