Restart Policies

1. What are Restart Policies?
  • Defined in spec.restartPolicy — tells Kubernetes what to do when a container exits;
  • Applies to all containers in the Pod;
2. Types
PolicyBehaviorUse Case
AlwaysAlways restart the container (default)Long-running services (web servers, APIs)
OnFailureRestart only if container exits with non-zero codeJobs, batch processing
NeverNever restart the containerOne-shot tasks, debugging
3. CrashLoopBackOff
  • When a container keeps crashing, Kubernetes applies exponential backoff;
  • Delay between restarts: 10s, 20s, 40s, 80s, ..., up to 5 minutes;
  • Status shows CrashLoopBackOff — the container is in a restart loop;
  • Common causes: application error, missing config, wrong command, OOMKilled;
# Investigate a CrashLoopBackOff
kubectl describe pod my-pod        # Check Events section
kubectl logs my-pod --previous     # Logs from the previous crashed container
4. Example
apiVersion: v1
kind: Pod
metadata:
  name: job-pod
spec:
  restartPolicy: OnFailure
  containers:
    - name: worker
      image: busybox
      command: ['sh', '-c', 'echo "Processing..." && sleep 5']
