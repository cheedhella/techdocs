High Availability Clusters

1. What is HA in Kubernetes?
  • A cluster setup where no single point of failure can take down the cluster;
  • Requires multiple control plane nodes and distributed etcd;
2. HA Control Plane
  • Run 3 or 5 control plane nodes (odd number for etcd quorum);
  • Place a load balancer in front of the API Servers;
  • Each control plane runs: API Server, Controller Manager, Scheduler, etcd;
  • Only one Controller Manager and Scheduler are active (leader election);
3. etcd Topologies
TopologyDescription
Stackedetcd runs on each control plane node. Simpler but coupled.
Externaletcd runs on dedicated nodes. More resilient but complex.
  • Stacked: Fewer servers needed but losing a control plane node also loses an etcd member;
  • External: etcd is independent — a control plane node can fail without affecting etcd;
4. Worker Node HA
  • Spread worker nodes across multiple availability zones;
  • Use Pod Anti-Affinity to distribute replicas across zones/nodes;
  • Use Pod Disruption Budgets to prevent too many Pods from going down;
  • Use Topology Spread Constraints for even distribution;
5. HA Checklist
  • 3+ control plane nodes;
  • Load balancer for API Server;
  • etcd backups automated;
  • Worker nodes across multiple AZs;
  • Pod Disruption Budgets defined;
  • Resource requests/limits set;
  • Monitoring and alerting in place;
