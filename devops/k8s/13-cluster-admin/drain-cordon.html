Draining and Cordoning Nodes

1. Cordon
  • Marks a node as unschedulable — no new Pods will be placed on it;
  • Existing Pods continue running;
  • Useful before performing maintenance;
# Cordon a node
kubectl cordon worker-1

# Verify — STATUS shows SchedulingDisabled
kubectl get nodes

# Uncordon (allow scheduling again)
kubectl uncordon worker-1
2. Drain
  • Cordons the node AND evicts all Pods gracefully;
  • Pods managed by controllers (Deployment, ReplicaSet) are rescheduled on other nodes;
  • Standalone Pods (not managed by a controller) are deleted and NOT recreated;
# Drain a node
kubectl drain worker-1 --ignore-daemonsets --delete-emptydir-data

# Force drain (for standalone Pods)
kubectl drain worker-1 --ignore-daemonsets --delete-emptydir-data --force

# With grace period
kubectl drain worker-1 --ignore-daemonsets --grace-period=60
3. Common Flags
FlagPurpose
--ignore-daemonsetsSkip DaemonSet Pods (they can't be rescheduled)
--delete-emptydir-dataDelete Pods using emptyDir volumes (data will be lost)
--forceDelete standalone Pods not managed by a controller
--grace-periodSeconds to wait for graceful termination
--timeoutTotal time to wait for drain to complete
4. Pod Disruption Budgets (PDB)
  • Limits the number of Pods that can be voluntarily disrupted at the same time;
  • Drain respects PDBs — it won't evict Pods if it would violate the budget;
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: myapp-pdb
spec:
  minAvailable: 2          # OR: maxUnavailable: 1
  selector:
    matchLabels:
      app: myapp
