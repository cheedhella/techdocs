Backup and Restore (etcd)

1. Why Backup etcd?
  • etcd holds the entire cluster state — all objects, configs, secrets;
  • If etcd is corrupted or lost, the cluster becomes unrecoverable;
  • Regular backups are critical for disaster recovery;
2. Taking a Snapshot (Backup)
ETCDCTL_API=3 etcdctl snapshot save /backup/etcd-$(date +%Y%m%d).db \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key
3. Verifying a Snapshot
ETCDCTL_API=3 etcdctl snapshot status /backup/etcd-20240101.db --write-table

# Output:
# +----------+----------+------------+------------+
# |   HASH   | REVISION | TOTAL KEYS | TOTAL SIZE |
# +----------+----------+------------+------------+
# | 3f8a...  |   115200 |       1243 |    4.1 MB  |
# +----------+----------+------------+------------+
4. Restoring from a Snapshot
# Stop the API Server and etcd
# Restore to a new data directory
ETCDCTL_API=3 etcdctl snapshot restore /backup/etcd-20240101.db \
  --data-dir=/var/lib/etcd-restore

# Update etcd configuration to use the new data directory
# Restart etcd and API Server

# For kubeadm clusters, update the etcd pod manifest:
# /etc/kubernetes/manifests/etcd.yaml
# Change --data-dir to /var/lib/etcd-restore
5. Backup Best Practices
  • Automate backups with a CronJob or external scheduler;
  • Store backups in off-cluster storage (S3, GCS, Azure Blob);
  • Test restores regularly — a backup you can't restore is worthless;
  • Also backup Kubernetes manifests stored in Git (GitOps);
  • Consider tools like Velero for full cluster backup (etcd + persistent volumes);
