Service — ClusterIP

1. What is ClusterIP?
    Exposes a group of Pods using a stable internal IP address 👉 Makes them accessible only inside the cluster ➡️ An internal load balancer with a fixed IP and DNS name for a set of Pods Accessible within the cluster Not reachable from the internet ❗ Not exposed outside the cluster
  • The default Service type in Kubernetes;
  • Exposes the Service on a cluster-internal IP — only accessible from within the cluster;
  • Provides a stable IP and DNS name for a set of Pods;
  • Load balances traffic across all matching Pods;
When to Use ClusterIP Use ClusterIP when: Communication is between services within the cluster You're building microservices that only need internal connectivity You want to keep services private and not expose them externally Examples: databases, internal APIs, caching layers, message queues
2. ClusterIP YAML
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  type: ClusterIP
  selector:
    app: myapp
  ports:
    - port: 80
      targetPort: 8080
      protocol: TCP
  • port: The port the Service listens on;
  • targetPort: The port on the Pod to forward traffic to;
  • selector: Labels to match Pods;
3. How It Works
  • Kubernetes assigns a virtual IP (ClusterIP) to the Service;
  • kube-proxy creates iptables/IPVS rules to route traffic from ClusterIP to Pod IPs;
  • DNS record: <service-name>.<namespace>.svc.cluster.local;
  • Other Pods can reach this Service by name: curl http://my-service;
4. Commands
# Create a ClusterIP service
kubectl expose deployment myapp --port=80 --target-port=8080

# List services
kubectl get svc

# Describe
kubectl describe svc my-service

# View endpoints (Pod IPs behind the Service)
kubectl get endpoints my-service
