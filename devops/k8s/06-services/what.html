Service

1. What is a Service?
  • Each Pod gets a unique IP address within the cluster, when it is created;
  • But, Pods are not permanent, they get recreated(for many reasons), possibly with a different IP, on same or different Node;
  • So, we can't depend on this IP for inter-pod communication OR external communication;
  • That is where Service comes into picture;

  • Service provides consistent IP address and DNS name to a group of Pods, so that other components can reliably communicate with them;
2. Purpose of Service?
  • Stable IP and DNS
    • It provides a stable IP and DNS to a group of Pods;
  • Load Balancing
    • A Service doesn’t just forward traffic — it distributes it across Pods; It uses kube-proxy to handle routing;
  • Service Discovery
    • 👉 How one service (or Pod) finds and connects to another service without knowing its IP address.
    • ✔ Service discovery = finding services by name instead of IP
    • ..svc.cluster.local Stable IP address: A Service gets a virtual IP (VIP) that doesn't change DNS name: Each Service gets a DNS name for easy discovery Load balancing: Traffic is distributed across healthy pods Service discovery: Pods can find each other using Service names DNS Resolution in Kubernetes Kubernetes provides built-in DNS service discovery. Services can be reached using: Short name (same namespace): backend-service Fully qualified domain name: backend-service.default.svc.cluster.local The DNS format is: ..svc.cluster.local # From any pod in the default namespace curl http://backend-service:8080 # From a pod in a different namespace curl http://backend-service.default.svc.cluster.local:8080
3. How it works?
  • Pod makes a request: http://backend-service
  • K8s DNS (CoreDNS) resolves: backend-service → 10.96.0.10
  • Service takes the request and forwards it to one of the backend pods;
