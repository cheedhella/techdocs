Health Checks — Liveness, Readiness, and Startup Probes

1. Why Probes?
  • Kubernetes needs to know if your application is healthy and ready to serve traffic;
  • Without probes, Kubernetes assumes a container is ready as soon as its process starts;
  • Probes let you define custom health check logic;
2. Liveness Probe
  • Checks if the container is alive;
  • If it fails, Kubernetes restarts the container;
  • Use for: detecting deadlocks, hung processes;
livenessProbe:
  httpGet:
    path: /healthz
    port: 8080
  initialDelaySeconds: 15
  periodSeconds: 10
  failureThreshold: 3
3. Readiness Probe
  • Checks if the container is ready to accept traffic;
  • If it fails, the Pod is removed from Service endpoints (no traffic routed to it);
  • The container is NOT restarted — it just stops receiving traffic;
  • Use for: waiting for cache to warm, dependency availability;
readinessProbe:
  httpGet:
    path: /ready
    port: 8080
  initialDelaySeconds: 5
  periodSeconds: 5
4. Startup Probe
  • Checks if the application has started;
  • Disables liveness and readiness probes until it succeeds;
  • Use for: slow-starting applications (large JVM apps, etc.);
startupProbe:
  httpGet:
    path: /healthz
    port: 8080
  failureThreshold: 30
  periodSeconds: 10
5. Probe Methods
MethodDescription
httpGetHTTP GET request — success if status 200-399
tcpSocketTCP connection attempt — success if port is open
execRun a command — success if exit code is 0
grpcgRPC health check — success if status SERVING
