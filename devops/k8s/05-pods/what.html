Pod

1. What is a Pod?
  • Pod is a group of Containers deployed on the same host/VM;
  • It is the smallest deployable unit in k8s — not a container;
  • You can't create a container, without creating a Pod;
  • You almost never create Pods directly — Instead, use Deployment, StatefulSet etc;
  • Each Pod is assigned a unique IP address; All containers running inside that pod share that IP address, thus they need to be run on different ports;
  • A container can communicate with another container in the same pod, using localhost;
  • A container can communicate with another container in a different pod in the same Node, using IP address;
  • A container can communicate with another container in a different pod in a different Node but same cluster, How?;
  • All containers in a Pod share the port space(So, they need to be run on different ports), CPU/Memory/Storage(you can define limits at container level)
    • Port space: All containers in a Pod share the same port space; So, they need to be run on different ports;
    • CPU/Memory/Storage: You can define limits at container level;
    • Environment variables, ConfigMap and Secrets: Environment variables, Secrets and ConfigMaps mounted into a Pod are accessible to all containers;
    • Lifecycle: All containers in a Pod share the same lifecycle; They are scheduled together(on same node), started together, stopped together;
What causes a Pod to die/fail? There are lot of reasons why the life of a particular pod could come to an end: - Underlying node might have failed; - K8s has evicted that pod -- to better utilize the resources of the cluster; -- to prepare the node for shutdown/restart; - Deleted by mistake; 1.
