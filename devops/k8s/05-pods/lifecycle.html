Pod Lifecycle and Phases

1. Pod Phases
  • Kubelet monitors the containers running on the node and based on that, it reports pod's state to the K8s API server;
PhaseDescription
PendingPod is accepted by the cluster, but containers inside it are not yet running; May be the pod is not yet scheduled to a node OR image is yet to be pulled etc;
RunningPod moves to Running state, once all of it's containers are started and active;
SucceededPod moves to Succeeded state, when all of it's containers are terminated successfully(exit code 0) and are not restarted;
FailedPod moves to Failed state, when any of the container is terminated with failure code(non-zero exit code);
UnknownPod state cannot be determined. Usually a node communication issue.
2. Container States
  • Waiting: Container is not yet running (pulling image, applying secrets, etc.);
  • Running: Container is executing;
  • Terminated: Container has finished execution (either successfully or with an error);
# Check container state
kubectl get pod my-pod -o jsonpath='{.status.containerStatuses[0].state}'
3. Pod Conditions
  • PodScheduled: Pod has been scheduled to a node;
  • Initialized: All init containers have completed;
  • ContainersReady: All containers in the Pod are ready;
  • Ready: Pod is ready to serve traffic (passes readiness probe);
4. Common Status Values (kubectl get pods)
StatusMeaning
ContainerCreatingPulling image or setting up the container
RunningAll containers are running
CrashLoopBackOffContainer keeps crashing and K8s is backing off restarts
