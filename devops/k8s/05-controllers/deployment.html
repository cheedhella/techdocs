Deployment

1. What is a Deployment?
  • The most common way to run stateless applications in Kubernetes;
  • A Deployment manages a ReplicaSet, which in turn manages Pods;
  • Provides declarative updates — change the spec and Kubernetes handles the rest;
  • Supports rolling updates, rollbacks, scaling, and pause/resume;
2. Deployment YAML
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 1
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
        - name: nginx
          image: nginx:1.25
          ports:
            - containerPort: 80
          resources:
            requests:
              cpu: 100m
              memory: 128Mi
            limits:
              cpu: 250m
              memory: 256Mi
3. Deployment Strategies
StrategyDescription
RollingUpdateGradually replaces old Pods with new ones (default). Zero downtime.
RecreateKills all old Pods first, then creates new ones. Brief downtime.
  • maxSurge: Max number of extra Pods above desired count during update;
  • maxUnavailable: Max number of Pods that can be unavailable during update;
4. Common Commands
# Create
kubectl create deployment nginx --image=nginx:1.25 --replicas=3

# Apply from file
kubectl apply -f deployment.yaml

# Scale
kubectl scale deployment nginx-deployment --replicas=5

# Update image
kubectl set image deployment/nginx-deployment nginx=nginx:1.26

# View status
kubectl rollout status deployment/nginx-deployment

# View history
kubectl rollout history deployment/nginx-deployment
