Rolling Updates and Rollbacks

1. Rolling Update
  • The default update strategy for Deployments;
  • Gradually replaces old Pods with new ones — zero downtime;
  • Kubernetes creates a new ReplicaSet and scales it up while scaling down the old one;
# Trigger a rolling update by changing the image
kubectl set image deployment/myapp myapp=myapp:v2

# Or edit the deployment
kubectl edit deployment myapp

# Or apply an updated manifest
kubectl apply -f deployment.yaml
2. Monitoring a Rollout
# Watch rollout progress
kubectl rollout status deployment/myapp

# View rollout history
kubectl rollout history deployment/myapp

# View a specific revision
kubectl rollout history deployment/myapp --revision=2
3. Rollback
# Rollback to the previous version
kubectl rollout undo deployment/myapp

# Rollback to a specific revision
kubectl rollout undo deployment/myapp --to-revision=3
4. Pause and Resume
  • Pause a rollout to make multiple changes without triggering intermediate updates;
# Pause
kubectl rollout pause deployment/myapp

# Make changes
kubectl set image deployment/myapp myapp=myapp:v3
kubectl set resources deployment/myapp -c=myapp --limits=cpu=500m

# Resume (triggers a single rollout with all changes)
kubectl rollout resume deployment/myapp
5. Revision History Limit
  • spec.revisionHistoryLimit controls how many old ReplicaSets to keep (default: 10);
  • Old ReplicaSets are needed for rollbacks — set to 0 to disable rollback;
