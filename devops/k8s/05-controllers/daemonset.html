DaemonSet

1. What is a DaemonSet?
  • It ensure that a Pod runs on every node(or subset of nodes that meet specified conditions);
  • When you create a DaemonSet:
    • K8s schedules the Pod on each node in the cluster;
    • If a new node joins, k8s automatically adds the Pod to that node;
    • If a node is removed, Pod on that node is automatically removed;
    • If you delete a DaemonSet, k8s deletes all the Pods created by DaemonSet;
2. Usecases
    It is used for running background services that must be present on each node, such as:
    • Log collectors such as fluentd;
    • Monitoring agents such prometheus node exporter etc;
    • Network plugins such calico, kube-proxy etc;
    • Storage daemons such as GlusterFS, Ceph;
3. DaemonSet YAML
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: example-daemonset
  namespace: default
  labels:
    app: node-agent

spec:
  selector:
    matchLabels:
      app: node-agent

  updateStrategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 1

  minReadySeconds: 10
  revisionHistoryLimit: 5

  template:
    metadata:
      labels:
        app: node-agent

    spec:
      nodeSelector:
        node-type: worker

      tolerations:
      - key: "node-role.kubernetes.io/control-plane"
        operator: "Exists"
        effect: "NoSchedule"

      affinity:
        nodeAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            nodeSelectorTerms:
            - matchExpressions:
              - key: node-type
                operator: In
                values:
                - worker

      containers:
      - name: agent
        image: nginx:latest
4. Running on Specific Nodes
  • spec.selector.matchLabels - It specifies which Pods belong to DaemonSet and should be managed by it; It must match with labels defined in template.metadata.labels;
  • template.metadata.labels - Each Pod created by the DaemonSet gets these labels;
  • updateStrategy
    • It controls how Pods are updated when daemonset changes;
    • RollingUpdate 
      • 
updateStrategy:
  type: RollingUpdate
  rollingUpdate:
    maxUnavailable: 1

It updates each node gradually; It ensures Only 1 node down at a time;
    • OnDelete 
      • 
updateStrategy:
  type: OnDelete

Pods update only when manually deleted;
  • minReadySeconds - It specifies how long a pod must stay ready before considered available;
  • revisionHistoryLimit - It specifies how many old DaemonSet versions to keep?
  • spec.nodeSelector - DaemonSets usually run on specific nodes, not always all nodes;
  • spec.tolerations - By default, DeamonSets runs pods only on worker nodes and if you need to run on Controlplane, we need to add tolerations;
  • spec.affinity - https://devopscube.com/kubernetes-daemonset/
