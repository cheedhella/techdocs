CronJob

1. What is a CronJob?
  • It creates a Job based on a cron schedule - similar to cron in linux OS;
  • Each scheduled execution creates a new Job;
2. Purpose of CronJob?
  • Database backup;
  • Log cleanup;
2. CronJob YAML
apiVersion: batch/v1
kind: CronJob
metadata:
  name: nightly-backup
spec:
  schedule: "0 2 * * *"
  concurrencyPolicy: Forbid
  successfulJobsHistoryLimit: 3
  failedJobsHistoryLimit: 1
  jobTemplate:
    spec:
      template:
        spec:
          restartPolicy: OnFailure
          containers:
            - name: backup
              image: myapp:backup
              command: ["./backup.sh"]
3. Cron Expression Format
  • schedule - It defines when to create the Job;
  • 
It has 5 Fields:

* * * * *
│ │ │ │ │
│ │ │ │ └ Day of week (0–7, Sunday=0)
│ │ │ └── Month (1–12)
│ │ └──── Day of month (1–31)
│ └────── Hour (0–23)
└──────── Minute (0–59)

Field Meaning:

| Field        | Range | Meaning         |
| ------------ | ----- | --------------- |
| Minute       | 0–59  | minute of hour  |
| Hour         | 0–23  | hour of day     |
| Day of month | 1–31  | date            |
| Month        | 1–12  | month           |
| Day of week  | 0–7   | Sunday = 0 or 7 |


Meaning of Special Chars:
*   Every value/minute;
,   List of values;
-   Range of values;
/   step/interval;

# Examples:
* * * * *        # Every minute
"*/5 * * * *"    # Every 5 minutes
0 * * * *        # Every hour
0 */2 * * *      # Every 2 hours
"0 * * * *"      # Every hour
"0 2 * * *"      # Daily at 2 AM
"0 0 * * *"      # Daily midnight
"0 0 * * 0"      # Every Sunday at midnight
"0 0 1 * *"      # First day of every month
0 8,12,16 * * *     # 08:00, 12:00, 16:00 
0 9-17 * * *        # every hour 9 AM – 5 PM
30 14 * * 1-5       # 2:30 PM every weekday
4. CronJob settings
  • timeZone
    • It specifies which timezone the cron schedule should use;
    • It defaults to timezone of the kube-controller-manager(often UTC);
    • Timezone names follow the IANA timezone database;
    • Always set timeZone, to avoid unexpected schedule shifts;
  • concurrencyPolicy
    • It controls what what happens if the previous Job is still running;
    • Allow - Multiple Jobs can run concurrently; Default;
    • Forbid - Skip new Job if previous one is still running;
    • Replace - Cancel the running Job and start a new one;
  • startingDeadlineSeconds
    • It specified max time k8s wait to start a missed scheduled job;
    • For eg, if a job is scheduled at 10 AM and Controller is down until 10:02 and deadline is 60 seconds, then the job will not run;
  • successfulJobsHistoryLimit - Defaults to 3;
    • It specifies the number of successful job history entires to retain;
  • failedJobsHistoryLimit - Defaults to 1;
    • It specifies the number of failed job history entires to retain;
