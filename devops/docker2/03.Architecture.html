Docker Architecture
	Docker follows Client Server Architecture;
	Client issues a command, while server does the heavy lifting;
	These components can run same machine OR communicate over network;

Docker Server/Daemon/Host
	- Once you install docker on a machine(Physical or Virtual), it becomes Docker Server/Host/Daemon;
	- It manages Images, Containers, Volumes and Networks;
		-- Pushing the locally created image to Image Registry;
		-- Pulling an image from Image Registry;
		-- Managing the local images;
		-- Managing the containers;

Docker API 
	- A client running on another server can't talk to the server directly;
	- Docker Server exposes API to client;

Docker Client
	- Server where we are running docker commands; 
	- It calls docker API to send request to Docker Server;

Docker Engine
	- Docker Client + Docker Server/Daemon;

Docker Registry
	- It is a repository of docker images;
	- Docker Hub is the default public registry, but users can also create private registries;
	- Commands like docker pull and docker push interact with these registries to download and upload images, respectively;

Question:
	- How to setup docker cli and server on 2 different machines?
	- You can use the docker version command, to test that the client and daemon (server) are running and talking to each other;
