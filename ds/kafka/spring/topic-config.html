cleanup.policy - compact | delete | compact,delete
  • It defines the cleanup mechanism for a topic;
  • compact
    • In a compacte topic, Kafka retains the latest record for each key indefinitely — unless you delete it with a tombstone;
  • delete - default
    • In a delete topic, kafka cleans up the records based on time or size; Cleanup is triggered: when retention.ms is exceeded or retention.bytes is exceeded;
    • retention.ms limits how long Kafka keeps data, and retention.bytes limits how much data it keeps — Kafka deletes old segments when either limit is exceeded;
  • compact,delete
    • It means latest is not permanent anymore; Kafka keeps latest value per key; But deletes it once it exceeds retention time;
retention.ms - Defaults to 7 days;
  • It specifies how long to keep the records in a topic(when cleanup.policy=delete is in-effect);
  • Once data is older than this time, Kafka marks it for deletion;
  • -1 means keep forever (unless size limit applies);
retention.bytes - Defaults to -1(unlimited);
  • It specifies limits the total size of data per partition;
  • When the partition size exceeds this value, kafka deletes oldest log segments first;

What is Compact Topic?
  • Every message written to compact topic must have a key;
  • A topic where Kafka keeps only the latest record for each key, instead of keeping all records forever;
  • Compaction is asynchronous (not immediate);
  • Consumers may see old records until compaction runs;
  • Tombstone messages (key + null value) delete keys after compaction;
